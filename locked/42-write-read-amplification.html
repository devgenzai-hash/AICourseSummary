Write/Read Amplification

Understanding the hidden cost multipliers in storage engines — why writing 1 byte of logical data can trigger 10–100 bytes of physical I/O, and how to tune the trade-off between read speed, write speed, and space usage.

💡 Real-World Analogy

Imagine you’re moving into a new house with an extremely organized closet system. To store 1 new box, you must first rearrange 10 existing boxes so everything stays perfectly sorted — that’s write amplification. Your closet is easy to search (grab any item instantly), but every new addition costs disproportionate effort. Alternatively, you could just toss boxes into the garage unsorted (fast writes), but finding something later means digging through 10 piles — that’s read amplification. You can’t avoid both penalties simultaneously; you must choose which cost to pay.

What is Write Amplification?

Write Amplification Factor (WAF) is the ratio of actual physical bytes written to the logical bytes the application intended to write:

  • WAF = Physical Writes / Logical Writes
  • WAF of 1.0 means no amplification — ideal but rarely achievable
  • LSM-Trees typically have WAF of 10–30x due to compaction
  • B-Trees have WAF of 2–5x due to page splits and WAL logging
  • SSDs add another layer — erasing a 256KB block to rewrite 4KB is 64x amplification

Read Amplification

Read amplification measures how many physical reads are needed to satisfy one logical read:

  • B-Tree: 1 read per level (typically 3–4 for billions of rows)
  • LSM-Tree: must check each level — MemTable + L0 + L1 + … + Ln
  • Bloom filters reduce LSM read amplification by skipping levels that don’t contain the key
  • Worst case for LSM without bloom filters: check all levels (10+ reads per lookup)

Space Amplification

Space amplification is the ratio of actual disk space used to the logical data size:

  • B-Tree: pages are ~50–70% full on average (due to splits and fragmentation)
  • LSM-Tree: duplicate keys exist across levels until compaction merges them
  • Space amp is worst during compaction (temporarily 2x the data)

The RUM Conjecture

The RUM Conjecture states that an access method can optimize for at most two of three costs — you always pay a penalty on the third:

Optimized For Penalty Example
Read + Update High Memory/Space B-Tree with many indexes (fast reads, fast updates, but large footprint)
Read + Memory Slow Updates Sorted arrays (compact, fast binary search, but O(n) inserts)
Update + Memory Slow Reads LSM-Tree (fast writes, compact after compaction, but multi-level reads)

LSM-Tree Compaction & Write Amplification

LSM-Trees buffer writes in memory (MemTable), then flush sorted runs to disk. Compaction merges overlapping runs to maintain read performance — but each merge rewrites data that hasn’t logically changed:

Aspect Leveled Compaction (LCS) Size-Tiered (STCS) Universal/FIFO
Write Amplification High (10–30x) Low (2–5x) Lowest (1–2x)
Read Amplification Low (1 file per level) High (multiple files per level) Highest
Space Amplification Low (~10% overhead) High (up to 2x during compaction) Low
Best For Read-heavy, limited disk Write-heavy workloads Time-series, TTL data
Used By RocksDB (default), LevelDB Cassandra (default) RocksDB FIFO mode

B-Tree Page Splits

B-Tree write amplification comes from page splits and the Write-Ahead Log (WAL):

  • Inserting into a full page requires splitting it into two half-full pages
  • The parent node must be updated with the new child pointer
  • WAL must log the entire page for crash recovery (8KB page for a 100-byte insert)
  • Random insertions cause more splits than sequential insertions

SSD Write Amplification

SSDs add a hardware layer of write amplification because flash memory cannot overwrite in place:

  • Flash erases in large blocks (128–512KB) but writes in small pages (4–16KB)
  • Modifying 4KB requires: read entire block → erase block → rewrite block
  • TRIM command tells SSD which blocks are no longer used, reducing garbage collection overhead
  • Wear leveling distributes writes evenly to prevent premature cell death
  • Total WAF = Software WAF × Hardware WAF (compounds multiplicatively)

LSM-Tree Compaction Simulation

import math

class LSMTreeSimulator:
    """Simulates LSM-Tree compaction to demonstrate write amplification.

    Models leveled compaction where each level is T times larger
    than the previous. Data flows L0 → L1 → L2 → ... → Ln.
    Each compaction rewrites data, amplifying total physical writes.
    """

    def __init__(self, size_ratio: int = 10, memtable_size_mb: int = 64):
        self.size_ratio = size_ratio      # T: level size multiplier
        self.memtable_size = memtable_size_mb
        self.levels = []                  # (current_size_mb, capacity_mb)
        self.logical_writes_mb = 0
        self.physical_writes_mb = 0
        self.compaction_count = 0

    def _level_capacity(self, level: int) -> int:
        """Level i capacity = memtable_size * T^(i+1)."""
        return self.memtable_size * (self.size_ratio ** (level + 1))

    def flush_memtable(self):
        """Flush memtable to L0, triggering cascading compactions."""
        flush_size = self.memtable_size
        self.logical_writes_mb += flush_size
        self.physical_writes_mb += flush_size  # Initial flush write

        # Ensure L0 exists
        if not self.levels:
            cap = self._level_capacity(0)
            self.levels.append([flush_size, cap])
            return

        # Add to L0
        self.levels[0][0] += flush_size

        # Cascade compactions if level overflows
        for i in range(len(self.levels)):
            if self.levels[i][0] > self.levels[i][1]:
                overflow = self.levels[i][0] - self.levels[i][1]
                self.levels[i][0] = self.levels[i][1]

                # Merge into next level (rewrite both)
                merge_cost = self.levels[i][1] + overflow
                self.physical_writes_mb += merge_cost
                self.compaction_count += 1

                if i + 1 >= len(self.levels):
                    cap = self._level_capacity(i + 1)
                    self.levels.append([overflow, cap])
                else:
                    self.levels[i + 1][0] += overflow

    def get_write_amplification(self) -> float:
        if self.logical_writes_mb == 0:
            return 0
        return self.physical_writes_mb / self.logical_writes_mb

    def simulate(self, num_flushes: int):
        """Run simulation for N memtable flushes."""
        for _ in range(num_flushes):
            self.flush_memtable()

        print(f"=== LSM-Tree Write Amplification ===")
        print(f"Size ratio (T): {self.size_ratio}")
        print(f"Memtable size: {self.memtable_size} MB")
        print(f"Flushes: {num_flushes}")
        print(f"Logical writes: {self.logical_writes_mb:,} MB")
        print(f"Physical writes: {self.physical_writes_mb:,} MB")
        print(f"Write Amplification Factor: {self.get_write_amplification():.1f}x")
        print(f"Compactions triggered: {self.compaction_count}")
        print(f"Number of levels: {len(self.levels)}")
        for i, (size, cap) in enumerate(self.levels):
            print(f"  L{i}: {size:,} / {cap:,} MB")

class BTreePageSplitSim:
    """Simulates B-Tree page splits to measure write amplification.

    Each page holds a fixed number of keys. Inserting into a full
    page triggers a split: one page becomes two, parent updated.
    WAL logs entire pages for crash safety.
    """

    def __init__(self, page_size_kb: int = 8, keys_per_page: int = 200):
        self.page_size_kb = page_size_kb
        self.keys_per_page = keys_per_page
        self.pages = [0]  # keys in each page
        self.total_splits = 0
        self.logical_writes_kb = 0
        self.physical_writes_kb = 0
        self.key_size_bytes = 40

    def insert(self, n_keys: int):
        """Insert n keys, tracking page splits and WAL writes."""
        for _ in range(n_keys):
            self.logical_writes_kb += self.key_size_bytes / 1024

            # Find page with space (simplified: random page)
            import random
            page_idx = random.randint(0, len(self.pages) - 1)

            if self.pages[page_idx] >= self.keys_per_page:
                # Page split: write 2 new pages + update parent
                half = self.pages[page_idx] // 2
                self.pages[page_idx] = half
                self.pages.append(half + 1)
                self.total_splits += 1
                # Physical: 2 pages written + parent page + WAL
                self.physical_writes_kb += self.page_size_kb * 3
            else:
                self.pages[page_idx] += 1
                # Physical: dirty page + WAL entry
                self.physical_writes_kb += self.page_size_kb * 2

    def report(self):
        waf = self.physical_writes_kb / max(self.logical_writes_kb, 1)
        print(f"\n=== B-Tree Write Amplification ===")
        print(f"Page size: {self.page_size_kb} KB")
        print(f"Total pages: {len(self.pages)}")
        print(f"Page splits: {self.total_splits}")
        print(f"Logical writes: {self.logical_writes_kb:.0f} KB")
        print(f"Physical writes: {self.physical_writes_kb:,.0f} KB")
        print(f"Write Amplification Factor: {waf:.1f}x")

🏭 Industry Practice

RocksDB Tuning: Level compaction (default) gives WAF of ~10×T where T is the size ratio. Universal compaction reduces WAF to ~2x but increases space amplification. Facebook tunes RocksDB with level_compaction_dynamic_level_bytes=true and carefully sets max_bytes_for_level_base to minimize amplification for their SSD fleet.

Cassandra Compaction: STCS (Size-Tiered) is write-optimized with low WAF but high space amp (needs 50% free disk for compaction). LCS (Leveled) trades higher WAF for predictable read latency and lower space amp. TWCS (Time-Window) is ideal for time-series — no rewrite of old windows.

SSD Wear: Enterprise SSDs report WAF via SMART attributes. A database WAF of 20x on an SSD with hardware WAF of 3x means effective WAF of 60x. This directly impacts SSD lifespan (rated in total bytes written / TBW). Overprovisioning (leaving 10–20% unpartitioned) helps the SSD controller reduce garbage collection amplification.

LevelDB: Original LSM implementation by Google. Fixed leveled compaction with size ratio 10. Each level is 10x the previous. Theoretical WAF = T × (num_levels - 1). For 5 levels with T=10, worst-case WAF = 40x. RocksDB improved on this with concurrent compaction and sub-compaction.

📋 Key Takeaways

  • Write amplification (WAF) = physical writes / logical writes — the hidden tax on every write
  • LSM-Trees trade high write amplification (compaction) for fast sequential write throughput
  • B-Trees have moderate WAF from page splits and WAL, but lower read amplification
  • The RUM Conjecture: optimize Read, Update, or Memory — you always sacrifice one
  • SSD WAF compounds with software WAF — total amplification can exceed 50x
  • Choosing compaction strategy (leveled vs size-tiered) is the most impactful tuning decision

🧠 Mental Model

Think of amplification as a tax. Every storage engine imposes taxes on reads, writes, and space. You choose which taxes to pay. LSM-Trees pay heavy write taxes for cheap read/space. B-Trees balance the load. The RUM conjecture guarantees you can never avoid all taxes simultaneously.

⚠️ Common Mistakes

  • Ignoring compaction during capacity planning: Teams provision disk for logical data size but forget that compaction temporarily needs 2x space (STCS) or 10% overhead (LCS). Running out of disk during compaction causes write stalls or data loss. Always reserve 50% free space for STCS or 20% for LCS.
  • Using leveled compaction for write-heavy workloads: Leveled compaction rewrites data 10–30x. For ingestion pipelines (IoT, logs), this kills throughput and wears SSDs prematurely. Switch to size-tiered or FIFO compaction for append-heavy patterns where read latency is less critical.
  • Not accounting for SSD WAF in lifetime calculations: If your database has WAF=20 and the SSD has WAF=3, you’re writing 60x the logical data. A 1TB SSD rated for 1000 TBW will last only 1000/(daily_write_GB × 60) days. Monitor SMART attributes and adjust compaction aggressiveness accordingly.
  • Benchmarking only throughput, not amplification: A system may show high write throughput initially, but compaction debt accumulates. When compaction catches up, latency spikes and throughput crashes. Always measure sustained throughput over hours, not burst performance over minutes.
