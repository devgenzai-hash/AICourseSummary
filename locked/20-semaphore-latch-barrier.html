System Design/ Semaphore, Latch & Barrier

Semaphore, Latch & Barrier

Coordination primitives that control how many threads can access a resource (semaphore), wait for one-time events (latch), or synchronize at a meeting point (barrier).

Intermediate Pattern Code
Three Real-World Analogies

Semaphore (Parking Lot): A parking lot with 5 spots. Cars enter if spots available, wait if full. Each car leaving frees one spot.

Latch (Starting Gate): A race starting gate. All runners wait behind it. When the announcer fires the gun (count reaches zero), everyone runs. Gate never closes again.

Barrier (Meeting Point): A hiking group agrees to wait at the summit for everyone. Nobody continues until ALL members arrive. Then everyone descends together.

Semaphore: Limited Access

import threading, time

# Semaphore(n) = allow up to n threads simultaneously
# Mutex is just Semaphore(1)
connection_pool = threading.Semaphore(3)  # Max 3 DB connections

def query_database(thread_id):
    with connection_pool:  # Only 3 threads here at once
        print(f"Thread {thread_id}: connected")
        time.sleep(1)  # Simulate query
        print(f"Thread {thread_id}: done")

# 10 threads, but only 3 run concurrently
threads = [threading.Thread(target=query_database, args=(i,)) for i in range(10)]
for t in threads: t.start()
for t in threads: t.join()

CountDownLatch: Wait for N Events

import threading

class CountDownLatch:
    def __init__(self, count):
        self._count = count
        self._lock = threading.Lock()
        self._event = threading.Event()

    def count_down(self):
        with self._lock:
            self._count -= 1
            if self._count <= 0:
                self._event.set()

    def wait(self):
        self._event.wait()

# Example: main thread waits for all workers to initialize
latch = CountDownLatch(3)

def service(name):
    time.sleep(1)  # Initialize
    print(f"{name} ready!")
    latch.count_down()  # Signal "I'm ready"

for name in ["DB", "Cache", "Queue"]:
    threading.Thread(target=service, args=(name,)).start()

latch.wait()  # Block until all 3 services ready
print("All services initialized! Starting server...")

Barrier: Everyone Waits for Everyone

import threading

# Built-in Python barrier
barrier = threading.Barrier(4)  # Wait for 4 threads

def parallel_phase(thread_id):
    # Phase 1: each thread does independent work
    print(f"T{thread_id}: Phase 1 (computing...)")
    time.sleep(thread_id * 0.5)

    # BARRIER: wait for ALL threads to finish Phase 1
    barrier.wait()  # Blocks until all 4 arrive

    # Phase 2: everyone proceeds together
    print(f"T{thread_id}: Phase 2 (all synchronized!)")

threads = [threading.Thread(target=parallel_phase, args=(i,)) for i in range(4)]
for t in threads: t.start()
for t in threads: t.join()

Comparison

PrimitivePurposeReusable?Who waits?
SemaphoreLimit concurrent access to NYesThread trying to acquire when count=0
LatchWait for N events to happenNo (one-shot)Threads calling wait()
BarrierSynchronize N threads at a pointYes (resets)All threads until last arrives

Industry Usage

  • Connection pooling — Semaphore limits concurrent DB/HTTP connections
  • Rate limiting — Semaphore controls requests per second
  • MapReduce — Barrier at end of map phase; all mappers finish before reduce starts
  • Microservice startup — Latch: wait for all dependencies before accepting traffic

📝 Summary

  • Semaphore(N): allow up to N threads concurrently (generalized mutex)
  • CountDownLatch: block until N events occur (one-shot, not reusable)
  • Barrier: all N threads wait until the last one arrives, then all proceed
  • Semaphore for resource limiting, latch for startup coordination, barrier for phase sync
  • Python has built-in Semaphore and Barrier; CountDownLatch needs custom implementation

🧠 Mental Model

SEMAPHORE(3): [T1 in] [T2 in] [T3 in] | T4 waits | T5 waits T1 exits → T4 enters Always max 3 inside. LATCH(3): Count: 3 → 2 → 1 → 0 → [OPEN!] All waiters released. Cannot close again. BARRIER(4): T1 arrives → wait T2 arrives → wait T3 arrives → wait T4 arrives → ALL GO! (last one triggers release)

❌ Common Beginner Mistakes

  • Semaphore release without acquire — Increases count beyond max! Always pair acquire/release.
  • Barrier with wrong count — If count is 5 but only 4 threads call wait(), hangs forever.
  • Using latch when barrier needed — Latch is one-shot. For repeated synchronization, use barrier.
  • Not handling BrokenBarrierError — If one thread crashes at barrier, others get this exception.

🏋 Hands-On Exercise

  1. Use Semaphore(3) to limit concurrent file downloads to 3 at a time out of 20.
  2. Implement CountDownLatch: main waits for 5 worker threads to finish initialization.
  3. Use Barrier for parallel matrix computation: each thread computes its portion, barrier syncs, then next phase.
  4. Combine: Semaphore for resource limits + Barrier for phase synchronization in a pipeline.
