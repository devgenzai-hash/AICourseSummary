Intermediate Resilience Pattern

Backpressure

How systems signal overload upstream — preventing cascading failures when producers outpace consumers.

💡 Real-World Analogy

Think of a highway on-ramp with traffic lights. When the freeway is congested, the ramp meter turns red — forcing cars to wait before merging. Without this signal, cars flood onto the highway and gridlock everyone. The ramp meter is backpressure: it tells upstream traffic “slow down, I can’t handle more right now.” The key insight is that the signal flows backward — from consumer (highway) to producer (on-ramp).

What Is Backpressure?

Backpressure is a mechanism that allows a downstream system (consumer) to signal an upstream system (producer) to slow down or stop sending data. Without backpressure, a fast producer overwhelms a slow consumer, causing memory exhaustion, increased latency, or complete system collapse.

Why Producers Overwhelm Consumers

  • Speed mismatch: Producer generates data faster than consumer can process it
  • Burst traffic: Sudden spikes in requests exceed steady-state capacity
  • Resource contention: Consumer shares resources (CPU, I/O, network) with other work
  • Downstream dependencies: Consumer is blocked waiting on a slow database or API

Backpressure Strategies

There are four primary strategies for handling producer-consumer speed mismatches:

Strategy Mechanism Data Loss Latency Impact Use Case
Buffering Queue messages in bounded buffer None (until full) Increases under load Bursty but bounded traffic
Dropping Discard excess messages Yes (controlled) Minimal Metrics, video frames, sensor data
Blocking Block producer until consumer catches up None Producer stalls Critical data, small pipelines
Signaling Notify producer to reduce rate None Slight increase Reactive streams, TCP flow control

Bounded Queue with Backpressure Signaling

The core implementation pattern: a bounded queue that signals producers when capacity is reached.

import threading
import time
from collections import deque
from enum import Enum

class PressureLevel(Enum):
    NORMAL = "normal"
    WARNING = "warning"
    CRITICAL = "critical"

class BackpressureQueue:
    """Bounded queue with backpressure signaling."""

    def __init__(self, max_size: int = 100,
                 warn_threshold: float = 0.7,
                 critical_threshold: float = 0.9):
        self._queue = deque()
        self._max_size = max_size
        self._warn = int(max_size * warn_threshold)
        self._critical = int(max_size * critical_threshold)
        self._lock = threading.Lock()
        self._not_full = threading.Condition(self._lock)
        self._not_empty = threading.Condition(self._lock)

    @property
    def pressure(self) -> PressureLevel:
        """Current backpressure level."""
        size = len(self._queue)
        if size >= self._critical:
            return PressureLevel.CRITICAL
        elif size >= self._warn:
            return PressureLevel.WARNING
        return PressureLevel.NORMAL

    def put(self, item, block: bool = True,
            timeout: float = None) -> bool:
        """Add item. Blocks if full (when block=True)."""
        with self._not_full:
            if len(self._queue) >= self._max_size:
                if not block:
                    return False  # Signal: queue full
                # Block producer until space available
                self._not_full.wait(timeout=timeout)
                if len(self._queue) >= self._max_size:
                    return False

            self._queue.append(item)
            self._not_empty.notify()
            return True

    def get(self, timeout: float = None):
        """Remove and return item. Blocks if empty."""
        with self._not_empty:
            while not self._queue:
                self._not_empty.wait(timeout=timeout)
                if not self._queue:
                    return None
            item = self._queue.popleft()
            self._not_full.notify()  # Wake blocked producers
            return item

Producer-Consumer with Adaptive Backpressure

A producer that adjusts its rate based on backpressure signals from the queue:

import random

class AdaptiveProducer:
    """Producer that slows down under backpressure."""

    def __init__(self, queue: BackpressureQueue,
                 base_rate: float = 0.01):
        self._queue = queue
        self._base_rate = base_rate
        self._current_delay = base_rate
        self._running = False

    def _adjust_rate(self):
        """Slow down or speed up based on pressure."""
        pressure = self._queue.pressure
        if pressure == PressureLevel.CRITICAL:
            self._current_delay = self._base_rate * 10
        elif pressure == PressureLevel.WARNING:
            self._current_delay = self._base_rate * 3
        else:
            self._current_delay = self._base_rate

    def run(self, num_items: int = 1000):
        self._running = True
        for i in range(num_items):
            if not self._running:
                break
            self._adjust_rate()
            item = {"id": i, "data": random.random()}
            success = self._queue.put(item, block=False)
            if not success:
                # Queue full — wait and retry
                time.sleep(self._current_delay * 5)
                self._queue.put(item, block=True, timeout=5.0)
            time.sleep(self._current_delay)

    def stop(self):
        self._running = False


class Consumer:
    """Slow consumer that processes items."""

    def __init__(self, queue: BackpressureQueue,
                 process_time: float = 0.05):
        self._queue = queue
        self._process_time = process_time
        self._processed = 0

    def run(self):
        while True:
            item = self._queue.get(timeout=2.0)
            if item is None:
                break
            # Simulate slow processing
            time.sleep(self._process_time)
            self._processed += 1

TCP Flow Control as Backpressure

TCP’s sliding window protocol is the canonical example of backpressure in networking. The receiver advertises its available buffer space (receive window) in every ACK packet. When the window shrinks to zero, the sender stops transmitting.

TCP Mechanism Backpressure Equivalent Effect
Receive window (rwnd) Buffer capacity signal Tells sender how much data receiver can accept
Window size = 0 Queue full / block Sender stops transmitting entirely
Window update ACK Resume signal Receiver processed data, sender can resume
Congestion window (cwnd) Network-level backpressure Limits rate based on network capacity

Reactive Streams & Demand Signaling

Reactive Streams (used in RxJava, Project Reactor, Akka Streams) formalize backpressure as a demand signal. The subscriber tells the publisher exactly how many items it can accept via request(n).

from abc import ABC, abstractmethod

class Subscriber(ABC):
    """Reactive Streams subscriber with demand signaling."""

    @abstractmethod
    def on_subscribe(self, subscription):
        pass

    @abstractmethod
    def on_next(self, item):
        pass

    @abstractmethod
    def on_complete(self):
        pass


class Subscription:
    """Controls demand between publisher and subscriber."""

    def __init__(self, publisher, subscriber):
        self._publisher = publisher
        self._subscriber = subscriber
        self._demand = 0
        self._cancelled = False

    def request(self, n: int):
        """Subscriber requests n more items."""
        self._demand += n
        self._publisher.drain(self)

    def cancel(self):
        self._cancelled = True


class Publisher:
    """Emits items only when demand exists."""

    def __init__(self, items):
        self._items = list(items)
        self._index = 0

    def subscribe(self, subscriber: Subscriber):
        sub = Subscription(self, subscriber)
        subscriber.on_subscribe(sub)

    def drain(self, subscription: Subscription):
        while (subscription._demand > 0
               and self._index < len(self._items)
               and not subscription._cancelled):
            subscription._subscriber.on_next(
                self._items[self._index])
            self._index += 1
            subscription._demand -= 1
        if self._index >= len(self._items):
            subscription._subscriber.on_complete()

🏭 Industry Practice

Kafka Consumer Lag: When Kafka consumers fall behind, the “consumer lag” metric grows. Teams set alerts on lag and scale consumer instances. Kafka doesn’t block producers — it uses bounded retention (time or size) as implicit backpressure.

RxJava/Project Reactor: Both implement the Reactive Streams spec with operators like onBackpressureBuffer(), onBackpressureDrop(), and onBackpressureLatest() to choose the strategy per pipeline stage.

Node.js Streams: Node’s readable streams return false from write() when the internal buffer is full. The producer should stop writing until the 'drain' event fires.

TCP Window Scaling: Modern TCP uses window scaling (RFC 7323) to support windows up to 1 GB, enabling high-throughput links while still providing backpressure via zero-window probes.

📋 Key Takeaways

  • Backpressure is a feedback mechanism from consumer to producer saying “slow down”
  • Four strategies: buffer, drop, block, or signal — choose based on data criticality
  • Unbounded queues are not backpressure — they just delay the crash (OOM)
  • TCP flow control is the most widely deployed backpressure system in the world
  • Reactive Streams formalize backpressure as explicit demand signaling
  • Monitor queue depth and consumer lag as early warning indicators

🧠 Mental Model

Think of backpressure as water flowing through pipes of different diameters. The narrowest pipe (slowest consumer) determines system throughput. Without a valve (backpressure), pressure builds until a pipe bursts (OOM/crash). With a valve, the source reduces flow to match the narrowest point.

  PRODUCER              BOUNDED QUEUE              CONSUMER
  (fast)                 (buffer)                  (slow)

⚠️ Common Mistakes

  • Using unbounded queues as a “solution”: An unbounded queue doesn’t solve the problem — it converts a fast crash into a slow memory leak. Eventually the process runs out of memory. Always use bounded buffers with explicit overflow strategies.
  • Ignoring backpressure in async pipelines: Chaining async tasks without demand control can create millions of pending futures. Each stage must respect the pace of its downstream — not just fire events as fast as possible.
  • Applying backpressure too late: If you only react when the queue is 100% full, the system is already degraded. Set thresholds at 70% (warning) and 90% (critical) to give the producer time to decelerate gracefully.
  • Blocking the event loop: In single-threaded systems (Node.js, asyncio), blocking for backpressure freezes the entire application. Use non-blocking signals (returning false, emitting events) instead of thread-based blocking.
