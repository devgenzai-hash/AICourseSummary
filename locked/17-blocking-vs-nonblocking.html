Blocking vs Non-Blocking I/O

Should your thread wait for data or check and move on? The choice that determines whether your server handles 100 or 100,000 connections.

Intermediate Concept Code
Waiting for a Package

Blocking: You sit by the door all day waiting for the delivery. You cannot do anything else until it arrives.

Non-blocking: You check the door, see nothing, and go back to work. Check again in 5 minutes. Repeat.

Async (event-driven): You put a doorbell on. You do other work freely. When the package arrives, the bell rings and you go get it.

I/O Models Compared

ModelThread does while waitingMax connectionsComplexity
BlockingNothing (sleeps)~1000 (one thread per conn)Simple
Non-blocking pollChecks repeatedly (busy wait)~10KMedium
I/O MultiplexingWaits for ANY of many sockets~100K (select/poll/epoll)Complex
Async (event loop)Processes other events~1MHighest

Blocking I/O (Traditional)

import socket, threading

def handle_client(conn):
    while True:
        data = conn.recv(1024)  # BLOCKS until data arrives
        if not data: break
        conn.sendall(data.upper())  # BLOCKS until sent
    conn.close()

# One thread per connection — doesn't scale past ~1000
server = socket.socket()
server.bind(("0.0.0.0", 8080))
server.listen()
while True:
    conn, addr = server.accept()  # BLOCKS until new connection
    threading.Thread(target=handle_client, args=(conn,)).start()

Non-Blocking with Select (I/O Multiplexing)

import select, socket

server = socket.socket()
server.setblocking(False)
server.bind(("0.0.0.0", 8080))
server.listen()

sockets = [server]

while True:
    # Wait for ANY socket to be ready (single thread, many connections!)
    readable, _, _ = select.select(sockets, [], [], 1.0)
    for sock in readable:
        if sock is server:
            conn, addr = server.accept()
            conn.setblocking(False)
            sockets.append(conn)
        else:
            data = sock.recv(1024)
            if data:
                sock.sendall(data.upper())
            else:
                sockets.remove(sock)
                sock.close()

Async I/O (Modern Approach)

import asyncio

async def handle_client(reader, writer):
    while True:
        data = await reader.read(1024)  # Non-blocking read
        if not data: break
        writer.write(data.upper())
        await writer.drain()  # Non-blocking write
    writer.close()

async def main():
    server = await asyncio.start_server(handle_client, "0.0.0.0", 8080)
    async with server:
        await server.serve_forever()
# Handles 100K+ connections with ONE thread!
asyncio.run(main())

Industry Choices

  • Nginx — Event-driven, non-blocking (handles 10K+ connections per worker)
  • Apache — Traditional blocking (one thread per connection, prefork/worker MPM)
  • Node.js — Single-threaded event loop (non-blocking I/O)
  • Go — Goroutines with non-blocking I/O under the hood (feels blocking, scales like non-blocking)

📝 Summary

  • Blocking: thread sleeps until I/O completes. Simple but wastes threads.
  • Non-blocking poll: check and retry. Wastes CPU cycles.
  • I/O multiplexing (select/epoll): one thread monitors many connections efficiently.
  • Async/event loop: one thread handles thousands of connections via callbacks/coroutines.
  • Blocking = ~1K connections. Async = ~100K+ connections.
  • Go gives the best of both: blocking syntax with non-blocking performance.

🧠 Mental Model

BLOCKING (1 thread per connection): Thread 1: ── [wait for data] ────── [process] ── [wait] ── Thread 2: ── [wait for data] ── [process] ── [wait] ────── (1000 connections = 1000 threads = 1GB RAM) ASYNC (1 thread, many connections): Event Loop: check A → nothing. check B → data! process B. check C → data! process C. check A → data! process A. (100K connections = 1 thread = minimal RAM)

❌ Common Beginner Mistakes

  • Blocking calls in async code — One blocking call halts ALL connections on that event loop.
  • Thread-per-connection at scale — Works for 100 connections, crashes at 10K.
  • Busy-waiting (polling without sleep) — Burns 100% CPU doing nothing useful.
  • Not using epoll/kqueue — select() is O(n) per call. epoll is O(1). Huge difference at scale.

🏋 Hands-On Exercise

  1. Build a blocking echo server. Test with 100 simultaneous connections (telnet/nc).
  2. Build the same with asyncio. Compare resource usage.
  3. Implement a select-based server that handles multiple clients with one thread.
  4. Benchmark: measure max connections before performance degrades for each approach.
