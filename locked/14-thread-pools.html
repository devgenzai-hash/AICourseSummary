System Design/ Thread Pools

Thread Pools

Instead of creating a new thread for every task (expensive!), keep a pool of reusable worker threads ready to go. The backbone of every web server.

Intermediate Pattern Code
A Taxi Stand

A thread pool is like a taxi stand at an airport:

  • There are 10 taxis waiting (worker threads in the pool)
  • Passengers arrive (tasks/requests) and take the next available taxi
  • When the ride is done, the taxi returns to the stand (thread returns to pool)
  • If all 10 are busy, passengers wait in line (task queue)

You don't build a new taxi for every passenger — that would be absurd. Same with threads.

Why Thread Pools?

ApproachCostProblem
New thread per task~1ms + 1MB stack per thread10K requests = 10GB RAM + OS overwhelmed
Thread pool (fixed)Threads created once, reusedBounded resources, predictable performance

Python ThreadPoolExecutor

from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def fetch_url(url):
    time.sleep(1)  # Simulate network I/O
    return f"Response from {url}"

urls = [f"https://api.example.com/page/{i}" for i in range(20)]

# Without pool: 20 seconds (sequential)
# With pool of 5: 4 seconds (5 concurrent)
with ThreadPoolExecutor(max_workers=5) as executor:
    futures = {executor.submit(fetch_url, url): url for url in urls}
    for future in as_completed(futures):
        url = futures[future]
        result = future.result()
        print(f"{url}: {result}")

# Using map() for simpler cases
with ThreadPoolExecutor(max_workers=10) as executor:
    results = list(executor.map(fetch_url, urls))
    print(f"Got {len(results)} results")

Pool Sizing: How Many Threads?

The Golden Rules

CPU-bound work: threads = number of CPU cores
I/O-bound work: threads = cores * (1 + wait_time/compute_time)
Example: 4 cores, I/O takes 10x longer than compute → 4 * (1 + 10) = 44 threads

import os, multiprocessing

# CPU-bound: use ProcessPoolExecutor with core count
from concurrent.futures import ProcessPoolExecutor
cpu_count = os.cpu_count()  # e.g., 8

with ProcessPoolExecutor(max_workers=cpu_count) as executor:
    results = list(executor.map(heavy_computation, data))

# I/O-bound: use ThreadPoolExecutor with higher count
with ThreadPoolExecutor(max_workers=cpu_count * 10) as executor:
    results = list(executor.map(fetch_url, urls))

Custom Thread Pool Implementation

import threading
from queue import Queue

class SimpleThreadPool:
    def __init__(self, num_workers):
        self.task_queue = Queue()
        self.workers = []
        for _ in range(num_workers):
            t = threading.Thread(target=self._worker, daemon=True)
            t.start()
            self.workers.append(t)

    def _worker(self):
        while True:
            task = self.task_queue.get()
            if task is None: break
            func, args = task
            try:
                func(*args)
            except Exception as e:
                print(f"Task error: {e}")
            finally:
                self.task_queue.task_done()

    def submit(self, func, *args):
        self.task_queue.put((func, args))

    def shutdown(self):
        for _ in self.workers:
            self.task_queue.put(None)
        for t in self.workers:
            t.join()

Industry Usage

  • Nginx — Worker process pool (not threads, but same concept)
  • Java Tomcat — Default 200-thread pool for handling HTTP requests
  • Node.js libuv — 4-thread pool for file I/O operations
  • PostgreSQL — Connection pool (pgbouncer) limits concurrent connections

📝 Summary

  • Thread pools reuse a fixed number of threads instead of creating new ones per task
  • Avoids thread creation overhead (1ms + 1MB per thread)
  • CPU-bound: pool size = number of cores
  • I/O-bound: pool size = cores * (1 + wait/compute ratio)
  • Python: ThreadPoolExecutor for I/O, ProcessPoolExecutor for CPU
  • All web servers, databases, and network services use thread/process pools

🧠 Mental Model

THREAD POOL: Task Queue: [T1] [T2] [T3] [T4] [T5] [T6] ... ↓ ↓ ↓ Workers: [W1] [W2] [W3] [W4] (idle) ↓ ↓ ↓ running running running W1 finishes → picks up T4 from queue W2 finishes → picks up T5 from queue SIZING: CPU-bound: workers = cores (more = context switch overhead) I/O-bound: workers = cores * (1 + IO_time/CPU_time)

❌ Common Beginner Mistakes

  • Too many threads — 1000 threads for CPU-bound work = massive context switching overhead.
  • Too few threads — 2 threads for I/O-bound work with 100ms latency = most time spent waiting.
  • Not handling exceptions — Unhandled exception in a pool thread kills that worker silently.
  • Using ThreadPool for CPU-bound in Python — GIL means no parallelism. Use ProcessPoolExecutor.

🏋 Hands-On Exercise

  1. Build a custom thread pool (queue + worker threads). Submit 100 tasks.
  2. Benchmark ThreadPoolExecutor with 1, 4, 16, 64 workers fetching 100 URLs.
  3. Show that ProcessPoolExecutor is faster for CPU-bound work (compute Fibonacci).
  4. Implement graceful shutdown: finish current tasks, reject new ones, then stop.
