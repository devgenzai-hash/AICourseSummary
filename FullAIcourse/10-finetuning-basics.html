Fine-Tuning Basics & Continued Pre-Training

Fine-tuning is how you adapt a general model to YOUR specific task. This is the most important skill for an LLM engineer. Learn the concepts, types, and when to use each approach.

🏠 Daily Life Analogy

Pre-training = General education (school K-12). You learn reading, math, science, history — broad knowledge.

Fine-tuning = Specialized training (medical school). You already know general science, now you focus on becoming a doctor. You don't forget everything else — you just become specialized.

Continued Pre-training = College before med school. You read medical textbooks to build domain knowledge, but haven't done hands-on practice yet.

Types of Model Adaptation

MethodWhat It DoesData NeededWhen to UseCost
PromptingTell model what to do in the promptNoneQuick prototyping, simple tasksFree
RAGGive model external knowledge at query timeDocumentsWhen model needs current/private infoLow
Continued Pre-training (CPT)Feed domain text to build knowledge100K+ raw textsModel lacks domain knowledgeMedium
Supervised Fine-tuning (SFT)Teach model to follow specific patterns1K-100K pairsNeed consistent format/behaviorMedium
Preference Alignment (DPO/RLHF)Teach model which answers are better10K-100K pairsAfter SFT, to improve qualityMedium-High

Supervised Fine-Tuning (SFT) — Your Main Tool

SFT is the most common type of fine-tuning. You show the model examples of ideal behavior and it learns to replicate them.

When to Fine-Tune vs Just Prompt:

Fine-Tune When...Just Prompt When...
You need consistent output formatFormat can vary a bit
You have domain-specific knowledgeGeneral knowledge is sufficient
Prompting alone doesn't hit quality barA good prompt gets 90%+ accuracy
You process 1000s of requests/day (save tokens)Low volume (prompt is cheaper)
You need specific tone/personalityGeneric helpful assistant works
Latency matters (shorter prompts = faster)Latency isn't critical

Continued Pre-Training (CPT)

When a model doesn't know enough about your domain (legal, medical, your company's products), you feed it raw text to build knowledge BEFORE fine-tuning.

# Continued Pre-Training: Feed domain knowledge
# This is like giving the model a textbook to read

from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments
from trl import SFTTrainer
from datasets import load_dataset

# Load base model (not instruct version!)
model_name = "meta-llama/Llama-3.1-8B"  # Base, not Instruct
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype="auto", device_map="auto")
tokenizer = AutoTokenizer.from_pretrained(model_name)

# Your domain corpus — just raw text
# Could be: medical papers, legal documents, your wiki, product docs
domain_data = load_dataset("json", data_files="domain_texts.jsonl", split="train")
# Each example: {"text": "Full text of a document..."}

training_args = TrainingArguments(
    output_dir="./cpt-output",
    num_train_epochs=2,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=8,
    learning_rate=2e-5,  # Lower than SFT (we don't want to change too much)
    warmup_ratio=0.05,
    bf16=True,
    save_strategy="steps",
    save_steps=500,
)

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=domain_data,
    dataset_text_field="text",  # Just raw text, no instruction format
    max_seq_length=2048,
    tokenizer=tokenizer,
)

trainer.train()
trainer.save_model("./my-domain-model")

SFT with TRL (Industry Standard)

# Supervised Fine-Tuning — The method you'll use 90% of the time
from transformers import AutoModelForCausalLM, AutoTokenizer, TrainingArguments, BitsAndBytesConfig
from trl import SFTTrainer
from peft import LoraConfig
from datasets import load_dataset
import torch

# 1. Load model with QLoRA (fits on single GPU)
model_name = "meta-llama/Llama-3.1-8B-Instruct"

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto",
)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

# 2. LoRA configuration (train only 1-2% of parameters)
lora_config = LoraConfig(
    r=16,                  # Rank — higher = more capacity but more VRAM
    lora_alpha=32,          # Scaling factor
    lora_dropout=0.05,      # Regularization
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],  # Which layers to train
    task_type="CAUSAL_LM",
)

# 3. Load your dataset (ChatML format)
dataset = load_dataset("json", data_files="my_dataset.jsonl", split="train")

# 4. Training arguments
training_args = TrainingArguments(
    output_dir="./sft-output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,  # Effective batch = 4 * 4 = 16
    learning_rate=2e-4,
    lr_scheduler_type="cosine",
    warmup_ratio=0.1,
    bf16=True,
    logging_steps=10,
    save_strategy="epoch",
    evaluation_strategy="epoch",
    push_to_hub=False,
)

# 5. Create trainer and train!
trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    peft_config=lora_config,
    tokenizer=tokenizer,
    max_seq_length=2048,
)

print("🚀 Starting fine-tuning...")
trainer.train()

# 6. Save the trained adapter
trainer.save_model("./my-finetuned-model")
print("✅ Done! Model saved.")

The Complete Fine-Tuning Pipeline

🧠 The Full Picture

1. Choose base model (Llama 3.1 8B Instruct)
2. Prepare dataset (clean → format → validate → split)
3. Configure training (LoRA + hyperparameters)
4. Train (monitor loss curve)
5. Evaluate (compare base vs fine-tuned)
6. Deploy (merge LoRA → quantize → serve)

Choosing Your Base Model:

Your ConstraintRecommended BaseWhy
Single consumer GPU (24GB)Llama 3.1 8B / Qwen 2.5 7BFits in VRAM with QLoRA
Cloud GPU (A100 80GB)Llama 3.1 70BBest quality at this scale
Edge/mobile deploymentPhi-3 3.8B / Gemma 2 2BSmall enough for phones/laptops
Code-focusedDeepSeek-Coder / CodeLlamaPre-trained on code
MultilingualQwen 2.5 / AyaStrong non-English performance

🏭 Industry Standards

  • TRL (Transformer Reinforcement Learning) — HuggingFace's library. Industry standard for SFT, DPO, RLHF. Use SFTTrainer.
  • Axolotl — Popular config-driven training framework. Good for non-Python people (YAML config).
  • LLaMA-Factory — Chinese-origin, GUI-based fine-tuning. Very beginner-friendly.
  • QLoRA is the default — Unless you have 8×A100s, you're using QLoRA (4-bit quantized + LoRA adapters).
  • 3 epochs is typical — For SFT, 2-4 epochs. More = overfitting risk.
  • Learning rate 2e-4 — Standard for LoRA fine-tuning. Use cosine scheduler with warmup.
  • Always evaluate before and after — Run the same test prompts on base vs fine-tuned model.

📝 Summary

  • Fine-tuning = taking a pre-trained model and adapting it to your specific task
  • CPT → domain knowledge, SFT → behavior/format, DPO → quality improvement
  • Use QLoRA (4-bit + LoRA) to fine-tune on a single GPU
  • TRL's SFTTrainer is the industry standard tool
  • Start with prompting/RAG, only fine-tune when those aren't enough
  • Pipeline: Choose model → Prepare data → Configure → Train → Evaluate → Deploy

❌ Beginner Mistakes to Avoid

  • Fine-tuning when prompting would work — Try few-shot prompting first. Only fine-tune if quality/cost demands it.
  • Using base model when you should use Instruct — For SFT, start with the Instruct variant. For CPT, use base.
  • Training too many epochs — Watch your eval loss. If it starts going UP, you're overfitting. Stop.
  • Not comparing to baseline — Always test the original model first so you can measure improvement.
  • Skipping data quality — 80% of fine-tuning failures are data problems, not training problems.

🏋️ Exercise: Your First Fine-Tune

  1. Create a small dataset (20-50 examples) for a specific task (e.g., customer support bot for a pizza shop)
  2. Format it in ChatML (messages with system/user/assistant)
  3. If you have a GPU: Run the SFT code above with GPT-2 (small enough for any GPU)
  4. If no GPU: Use Google Colab free tier (T4 GPU) or sign up for a RunPod spot instance (~$0.50/hr)
  5. Compare outputs: base model vs fine-tuned on 5 test prompts
  6. Bonus: Try OpenAI's fine-tuning API (no GPU needed, costs ~$5 for small datasets)
