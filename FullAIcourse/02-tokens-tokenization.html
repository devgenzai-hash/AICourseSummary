Tokens, Tokenization & Context Windows

Before an AI can read your text, it needs to break it into pieces called "tokens". This chapter explains what tokens are, how tokenization works, and why context windows limit what AI can process.

🏠 Daily Life Analogy

Tokens are like Lego bricks. You can't build a Lego house with "walls" — you need individual bricks. Similarly, AI can't process "sentences" directly — it needs to break them into smaller pieces (tokens) first. Common words like "the" are single bricks, while rare words like "cryptocurrency" might be split into multiple bricks: "crypt" + "o" + "currency".

Context window is like your desk size. Imagine you're writing an essay and you can only fit 10 pages on your desk at once. If someone gives you 50 pages of reference material, you can only look at 10 at a time. That's the context window — the amount of text the AI can "see" at once.

What Are Tokens?

A token is the smallest unit of text that an AI model works with. It's NOT always a word. It could be:

  • A whole word: "hello" → 1 token
  • Part of a word: "unhappiness" → "un" + "happiness" = 2 tokens
  • A single character: "a" → 1 token
  • Punctuation: "!" → 1 token
  • A space: " " → often part of the next token
💡 Rule of Thumb

In English, 1 token ≈ 4 characters or ¾ of a word. So 100 tokens ≈ 75 words. A typical page of text is ~500 tokens.

⚠️ Why This Matters Financially

API pricing is per-token, not per-word. GPT-4o costs ~$2.50 per million input tokens. If your tokenization is inefficient (e.g., non-English text uses more tokens for the same content), you pay more.

How Tokenization Works

Tokenization is the process of converting text into tokens. The most common algorithm is BPE (Byte Pair Encoding).

BPE Algorithm (Simplified):

  1. Start with individual characters: ["h", "e", "l", "l", "o"]
  2. Find the most common pair: "l" + "l" appears a lot → merge into "ll"
  3. Now vocabulary includes "ll" as one token
  4. Repeat: find next common pair, merge it
  5. Continue until vocabulary reaches target size (e.g., 32,000 tokens)

The result: common words become single tokens, rare words get split into pieces.

Context Windows

The context window (also called "context length") is the maximum number of tokens a model can process in a single conversation — including both your input AND the model's output.

Context Window Sizes (2024-2026):

💡 Why Context Windows Matter
  • Chatbots: The entire conversation history must fit in the context window
  • Document analysis: You can only analyze documents that fit in the window
  • Code: The model can only see code files that fit in the window
  • Cost: Longer contexts = more tokens = more money
  • Quality: Models tend to "forget" info in the middle of very long contexts ("lost in the middle" problem)

Production Code

Counting Tokens with tiktoken (OpenAI's Tokenizer)

# pip install tiktoken
import tiktoken

# Get the tokenizer for GPT-4o
enc = tiktoken.encoding_for_model("gpt-4o")

# Encode text to tokens
text = "Hello, how are you doing today?"
tokens = enc.encode(text)
print(f"Text: '{text}'")
print(f"Tokens: {tokens}")
print(f"Token count: {len(tokens)}")

# See what each token looks like
for token in tokens:
    print(f"  {token} → '{enc.decode([token])}'")

# Decode tokens back to text
decoded = enc.decode(tokens)
print(f"Decoded: '{decoded}'")

# --- Production use case: Estimate cost ---
def estimate_cost(text, model="gpt-4o"):
    """Estimate API cost for a given text."""
    enc = tiktoken.encoding_for_model(model)
    token_count = len(enc.encode(text))

    # GPT-4o pricing (as of 2025)
    prices = {
        "gpt-4o": {"input": 2.50, "output": 10.00},  # per million tokens
        "gpt-4o-mini": {"input": 0.15, "output": 0.60},
    }

    cost_per_token = prices[model]["input"] / 1_000_000
    cost = token_count * cost_per_token
    return {"tokens": token_count, "cost_usd": cost}

# Example
doc = open("my_document.txt").read()
result = estimate_cost(doc)
print(f"Document: {result['tokens']} tokens, ${result['cost_usd']:.4f}")

Using HuggingFace Tokenizers

# pip install transformers
from transformers import AutoTokenizer

# Load Llama 3.1 tokenizer
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

text = "Fine-tuning a large language model requires careful data preparation."

# Tokenize
tokens = tokenizer.encode(text)
print(f"Token IDs: {tokens}")
print(f"Token count: {len(tokens)}")

# See individual tokens
token_strings = tokenizer.convert_ids_to_tokens(tokens)
print(f"Token strings: {token_strings}")

# Check if text fits in context window
max_length = tokenizer.model_max_length  # e.g., 131072 for Llama 3.1
print(f"Max context: {max_length} tokens")
print(f"Fits: {len(tokens) < max_length}")

# --- Truncation for production ---
def safe_tokenize(text, tokenizer, max_tokens=4096):
    """Tokenize text, truncating if too long."""
    encoded = tokenizer.encode(
        text,
        max_length=max_tokens,
        truncation=True,
        return_tensors="pt"
    )
    if len(tokenizer.encode(text)) > max_tokens:
        print(f"⚠️ Text truncated from {len(tokenizer.encode(text))} to {max_tokens} tokens")
    return encoded

Visualizing Tokenization

# A useful debugging tool — see exactly how text gets tokenized
def visualize_tokens(text, tokenizer):
    """Print a colored visualization of token boundaries."""
    tokens = tokenizer.encode(text)
    colors = ['\033[42m', '\033[43m', '\033[44m', '\033[45m', '\033[46m']
    reset = '\033[0m'

    result = ""
    for i, token in enumerate(tokens):
        decoded = tokenizer.decode([token])
        color = colors[i % len(colors)]
        result += f"{color}{decoded}{reset}"

    print(f"Original: {text}")
    print(f"Tokenized ({len(tokens)} tokens): {result}")
    print(f"Tokens: {[tokenizer.decode([t]) for t in tokens]}")

visualize_tokens("Tokenization is fascinating!", tokenizer)

🏭 Industry Standards

  • Always count tokens before sending to API — Avoids hitting limits and unexpected costs
  • Reserve tokens for output — If context is 128K, don't use all 128K for input; leave room for the response
  • Use tiktoken for cost estimation — Build cost calculators into your apps before launching
  • Chunking for long documents — Split documents into overlapping chunks that fit the context window (covered in RAG chapter)
  • Token-aware truncation — Never cut text at arbitrary character positions; always cut at token boundaries
  • Non-English costs more — Chinese, Japanese, Hindi text uses 2-3x more tokens than English for same content

📝 Summary

  • Tokens are the smallest pieces of text an AI model processes — not always full words
  • Tokenization uses algorithms like BPE to build a vocabulary of common text pieces
  • Context window = maximum tokens the model can see at once (input + output combined)
  • 1 token ≈ 4 characters ≈ ¾ word in English
  • API pricing is per-token — always estimate costs before production use
  • Different models use different tokenizers — tokens are NOT universal across models

🧠 Mental Model

"Hello world" → Tokenizer → [15496, 995] → Model → [Next Token ID] → Detokenizer → "Hi"

Tokenizer = translator between human language and model language (numbers).
Context window = how many numbers the model can hold in its "hands" at once.

❌ Beginner Mistakes to Avoid

  • Assuming 1 word = 1 token — It's not. "unbelievable" might be 3 tokens.
  • Forgetting output counts toward context — A 4096-token window means input + output together, not just input.
  • Using wrong tokenizer for cost estimates — GPT-4o's tokenizer ≠ Llama's tokenizer. Same text = different token counts.
  • Not handling truncation — If input exceeds context, the API errors out or silently truncates. Always check.
  • Ignoring special tokens — Models add hidden tokens like [BOS], [EOS], [PAD] that count toward the limit.
