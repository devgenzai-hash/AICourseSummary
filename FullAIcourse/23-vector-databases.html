Vector Databases

Where do you store millions of embeddings so you can search them in milliseconds? Vector databases. The backbone of every RAG system and semantic search application.

🏠 Daily Life Analogy

Regular database = a library card catalog. Search by title, author, ISBN — exact matches only. Ask for "books about feeling lost in life" and it returns nothing.

Vector database = a librarian who understands meaning. Ask for "books about feeling lost in life" and they hand you "The Alchemist", "Into the Wild", and "Siddhartha" — because they understand the MEANING, not just keywords.

ChromaDB (Best for Starting)

# pip install chromadb
import chromadb
from chromadb.utils import embedding_functions

# Create persistent database
client = chromadb.PersistentClient(path="./my_vector_db")

# Use a sentence-transformer for embeddings
embedding_fn = embedding_functions.SentenceTransformerEmbeddingFunction(
    model_name="all-MiniLM-L6-v2"
)

# Create a collection
collection = client.get_or_create_collection(
    name="knowledge_base",
    embedding_function=embedding_fn,
    metadata={"hnsw:space": "cosine"}  # cosine similarity
)

# Add documents (embeddings generated automatically)
collection.add(
    ids=["doc1", "doc2", "doc3", "doc4"],
    documents=[
        "Python is a programming language known for readability",
        "JavaScript runs in web browsers and Node.js",
        "Rust provides memory safety without garbage collection",
        "Go was created by Google for concurrent programming",
    ],
    metadatas=[
        {"category": "python", "year": 1991},
        {"category": "javascript", "year": 1995},
        {"category": "rust", "year": 2015},
        {"category": "go", "year": 2009},
    ]
)

# Semantic search
results = collection.query(
    query_texts=["What language is best for beginners?"],
    n_results=2,
)
print(results["documents"])  # Returns Python and Go (readable/simple)

# Filter by metadata
results = collection.query(
    query_texts=["fast systems programming"],
    n_results=2,
    where={"year": {"$gte": 2010}},  # Only modern languages
)
print(results["documents"])  # Returns Rust

Qdrant (Best for Production)

# pip install qdrant-client
# Docker: docker run -p 6333:6333 qdrant/qdrant
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams, PointStruct
from sentence_transformers import SentenceTransformer

# Connect
client = QdrantClient(url="http://localhost:6333")
embedder = SentenceTransformer("all-MiniLM-L6-v2")

# Create collection
client.create_collection(
    collection_name="docs",
    vectors_config=VectorParams(
        size=384,  # Embedding dimension (depends on model)
        distance=Distance.COSINE,
    ),
)

# Add documents
documents = [
    "Our API rate limit is 100 requests per minute",
    "Authentication uses JWT tokens with 24-hour expiry",
    "Database backups run every 6 hours",
]
embeddings = embedder.encode(documents)

client.upsert(
    collection_name="docs",
    points=[
        PointStruct(id=i, vector=emb.tolist(), payload={"text": doc, "source": "api_docs"})
        for i, (doc, emb) in enumerate(zip(documents, embeddings))
    ]
)

# Search
query = "How often can I call the API?"
query_vector = embedder.encode(query).tolist()

results = client.search(
    collection_name="docs",
    query_vector=query_vector,
    limit=3,
)
for result in results:
    print(f"Score: {result.score:.3f} | {result.payload['text']}")

pgvector (PostgreSQL Extension)

# If you're already using PostgreSQL, pgvector is the simplest addition
# pip install psycopg2-binary pgvector
import psycopg2
from pgvector.psycopg2 import register_vector
import numpy as np

# Connect to PostgreSQL
conn = psycopg2.connect("postgresql://localhost/mydb")
register_vector(conn)

# Create table with vector column
cur = conn.cursor()
cur.execute("""
    CREATE EXTENSION IF NOT EXISTS vector;
    CREATE TABLE IF NOT EXISTS documents (
        id SERIAL PRIMARY KEY,
        content TEXT,
        embedding vector(384),  -- 384-dim embeddings
        metadata JSONB
    );
    CREATE INDEX ON documents USING ivfflat (embedding vector_cosine_ops);
""")

# Insert with embedding
embedding = embedder.encode("Your document text here")
cur.execute(
    "INSERT INTO documents (content, embedding, metadata) VALUES (%s, %s, %s)",
    ("Your document text here", embedding.tolist(), '{"source": "manual"}')
)

# Semantic search with SQL!
query_embedding = embedder.encode("how to authenticate")
cur.execute("""
    SELECT content, 1 - (embedding <=> %s::vector) AS similarity
    FROM documents
    ORDER BY embedding <=> %s::vector
    LIMIT 5
""", (query_embedding.tolist(), query_embedding.tolist()))

for row in cur.fetchall():
    print(f"Similarity: {row[1]:.3f} | {row[0][:80]}")

conn.commit()

Choosing the Right Vector DB:

ScenarioRecommendationWhy
Learning/prototypingChromaDBZero setup, embedded, great docs
Small production apppgvectorAlready have Postgres, no new infra
Serious productionQdrantFast, great filtering, easy to scale
Managed, zero-opsPineconeNo infrastructure to manage, just works
Enterprise scale (billions)Milvus / WeaviateProven at massive scale
In-memory, researchFAISSFastest search, no network overhead

🏭 Industry Standards

  • ChromaDB for prototypes, Qdrant/Pinecone for production — Start simple, scale when needed.
  • pgvector if you're already on Postgres — Avoids adding new infrastructure.
  • Always store metadata with vectors — Source, timestamp, category — enables filtering.
  • Cosine similarity is the default — Works well for normalized embeddings (most embedding models).
  • HNSW index for fast search — All modern vector DBs use HNSW (Hierarchical Navigable Small World).
  • Embedding model matters more than DB choice — A better embedding model improves results more than switching databases.

📝 Summary

  • Vector databases store embeddings and enable fast semantic search
  • ChromaDB = easiest to start, embedded, great for learning
  • Qdrant = best open-source for production (fast, filtering, scalable)
  • pgvector = add vector search to existing PostgreSQL
  • Pinecone = fully managed, zero infrastructure
  • All support: add vectors, semantic search, metadata filtering

❌ Beginner Mistakes to Avoid

  • Different embedding models for indexing vs search — You MUST use the same model for both!
  • Not persisting the database — Use PersistentClient (ChromaDB) or a proper server (Qdrant).
  • Over-engineering for small data — Under 10K documents? ChromaDB or even FAISS in-memory is fine.
  • Ignoring metadata filters — "Find docs about auth from last 30 days" is much more useful than just semantic search.
  • Not benchmarking retrieval quality — Create a test set of queries + expected results. Measure precision/recall.
