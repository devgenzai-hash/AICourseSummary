LoRA & QLoRA: Efficient Fine-Tuning

How to fine-tune a 7-billion-parameter model on a single GPU? LoRA makes it possible by training only 1-2% of the parameters. QLoRA adds 4-bit quantization to cut memory usage by 75%. This is THE technique for practical fine-tuning.

🏠 Daily Life Analogy

Full fine-tuning = Renovating an entire house. You repaint every wall, replace every floor, redo every room. Expensive, slow, and you might accidentally ruin something good.

LoRA = Adding sticky notes to a textbook. The textbook (base model) stays unchanged. You just add small notes (adapters) on specific pages that modify the meaning. Tiny, cheap, and reversible.

QLoRA = Same sticky notes, but the textbook is compressed. You shrink the textbook to 1/4 its size (4-bit quantization) THEN add your notes. Even cheaper.

The Problem LoRA Solves

MethodVRAM for 7B ModelTrainable ParametersTraining Speed
Full fine-tuning~56 GB (needs 4×A100)7B (100%)Slow
LoRA~18 GB (single A100)~50M (0.7%)Fast
QLoRA~6 GB (single RTX 3060!)~50M (0.7%)Medium

How LoRA Works

Instead of updating all 7 billion parameters, LoRA freezes the entire model and adds tiny "adapter" matrices to specific layers. Only these small matrices are trained.

The Math (Simplified):

# Original weight matrix W (frozen, not trained)
# Shape: [4096 × 4096] = 16.7 million parameters

# LoRA adds two small matrices:
# A: [4096 × 16]  = 65,536 parameters  (down-projection)
# B: [16 × 4096]  = 65,536 parameters  (up-projection)

# Total LoRA params for this layer: 131,072 (vs 16.7M original)
# That's 0.8% of the original! 

# During forward pass:
# output = W·x + (B·A)·x × (alpha/r)
#          ^frozen  ^trainable adapter

import torch

# Conceptual example
hidden_size = 4096
r = 16  # LoRA rank (the "r" in LoRA)

# Original weight (frozen)
W = torch.randn(hidden_size, hidden_size)  # 16.7M params

# LoRA adapters (trainable)
A = torch.randn(hidden_size, r)  # 65K params
B = torch.randn(r, hidden_size)  # 65K params

# Forward pass with LoRA
x = torch.randn(1, hidden_size)
output = x @ W + (x @ A @ B) * (32 / r)  # alpha/r scaling

Key LoRA Parameters:

ParameterWhat It ControlsTypical ValuesGuidance
r (rank)Size of adapter matrices (capacity)8, 16, 32, 64Higher = more capacity but more VRAM
lora_alphaScaling factor for adapter output16, 32, 64Usually 2× the rank
lora_dropoutRegularization0.0, 0.05, 0.1Use 0.05 for most cases
target_modulesWhich layers get adaptersq,k,v,o_projAttention layers + gate/up/down for best results

QLoRA: LoRA + 4-bit Quantization

QLoRA = Load the base model in 4-bit precision (saves 75% memory) + train LoRA adapters in full precision on top.

# Complete QLoRA training setup
import torch
from transformers import (
    AutoModelForCausalLM, AutoTokenizer,
    TrainingArguments, BitsAndBytesConfig
)
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer
from datasets import load_dataset

# ===== 1. Quantization Config (4-bit) =====
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",          # NormalFloat4 — best for LLMs
    bnb_4bit_compute_dtype=torch.bfloat16,  # Compute in bf16 for speed
    bnb_4bit_use_double_quant=True,     # Quantize the quantization constants too
)

# ===== 2. Load Model in 4-bit =====
model_name = "meta-llama/Llama-3.1-8B-Instruct"

model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=bnb_config,
    device_map="auto",
    attn_implementation="flash_attention_2",  # Speed boost if supported
)
model = prepare_model_for_kbit_training(model)

tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "right"

# ===== 3. LoRA Configuration =====
lora_config = LoraConfig(
    r=16,                      # Start with 16, increase if underfitting
    lora_alpha=32,              # 2x rank is standard
    lora_dropout=0.05,
    bias="none",
    target_modules=[            # All attention + MLP layers
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj"
    ],
    task_type="CAUSAL_LM",
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# Output: "trainable params: 41,943,040 || all params: 8,030,261,248 || trainable%: 0.52%"

# ===== 4. Load Dataset =====
dataset = load_dataset("json", data_files="my_dataset.jsonl", split="train")

# ===== 5. Training Arguments =====
training_args = TrainingArguments(
    output_dir="./qlora-output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    lr_scheduler_type="cosine",
    warmup_ratio=0.1,
    bf16=True,
    logging_steps=10,
    save_strategy="epoch",
    optim="paged_adamw_8bit",  # Memory-efficient optimizer
    gradient_checkpointing=True,  # Trade compute for memory
    max_grad_norm=0.3,
)

# ===== 6. Train! =====
trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
    max_seq_length=2048,
    packing=True,  # Pack short examples together for efficiency
)

trainer.train()
trainer.save_model("./my-qlora-adapter")
print("✅ Training complete! Adapter saved.")

Using Your Trained Adapter:

# Load base model + your trained adapter for inference
from peft import PeftModel
from transformers import AutoModelForCausalLM, AutoTokenizer

# Load base model
base_model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B-Instruct",
    torch_dtype=torch.float16,
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

# Load YOUR trained adapter on top
model = PeftModel.from_pretrained(base_model, "./my-qlora-adapter")

# Generate!
messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "Hello!"}
]
inputs = tokenizer.apply_chat_template(messages, return_tensors="pt").to(model.device)
output = model.generate(inputs, max_new_tokens=200)
print(tokenizer.decode(output[0], skip_special_tokens=True))

🏭 Industry Standards

  • QLoRA is the default — 90%+ of fine-tuning projects use QLoRA. It's the sweet spot of quality/cost.
  • r=16, alpha=32 — Standard starting point. Increase r if model underfits, decrease if overfits.
  • Target all linear layers — Best results come from targeting q/k/v/o_proj + gate/up/down_proj.
  • Adapter size: 20-100 MB — Your fine-tuned "model" is just a tiny file you load on top of the base model.
  • PEFT library — HuggingFace's library for LoRA/QLoRA. Industry standard.
  • Merge before deployment — Merge adapter into base model for faster inference (no overhead).
  • Multiple adapters — You can train different adapters for different tasks and swap them at inference time.

📝 Summary

  • LoRA = freeze base model, add small trainable adapters (~50MB for a 7B model)
  • QLoRA = LoRA but base model loaded in 4-bit (saves 75% VRAM)
  • You can fine-tune an 8B model on a single consumer GPU with QLoRA
  • Key params: r (rank), alpha (scaling), target_modules (which layers)
  • Quality is 93-99% of full fine-tuning at a fraction of the cost
  • Use PEFT library + TRL's SFTTrainer for implementation

🧠 Mental Model

Full Fine-tuning: Update ALL 7 billion parameters (expensive)
LoRA: Freeze 7B params + train 50M adapter params (cheap)
QLoRA: Compress 7B to 4-bit + train 50M adapter params (cheapest)

Base Model (14GB, frozen) + Adapter (50MB, trained) = Your custom model

❌ Beginner Mistakes to Avoid

  • Rank too high — r=64 or r=128 with only 1000 examples = overfitting. Start with r=8 or r=16.
  • Only targeting attention layers — Include MLP layers (gate/up/down_proj) for significantly better results.
  • Forgetting to prepare_model_for_kbit_training() — Required step for QLoRA. Without it, gradients won't flow correctly.
  • Wrong padding side — For causal LMs, use padding_side="right". Wrong side = degraded training.
  • Not merging for deployment — LoRA adds latency during inference. Merge the adapter before serving.
