GPU & VRAM Basics

Which GPU should you buy? How much VRAM do you actually need? Can you run a 70B model on your machine? This chapter gives you the formulas and real-world numbers to answer these questions.

🏠 Daily Life Analogy

VRAM = your kitchen counter space. A bigger counter (more VRAM) lets you prepare more dishes at once. If your recipe needs 16 GB of counter space but you only have 8 GB, you can't cook that dish — no matter how good your stove (compute) is.

GPU compute = your stove's BTUs. More compute power = faster cooking. But if the ingredients don't fit on the counter (VRAM), the stove doesn't matter.

Multi-GPU = multiple kitchens. Split the meal prep across kitchens. Each kitchen needs to communicate (interconnect bandwidth), which adds overhead.

VRAM Calculation Formulas

# VRAM Calculator: How much memory do you need?
import math

class VRAMCalculator:
    """Calculate VRAM requirements for inference and training."""
    
    def inference_vram(
        self,
        params_billions: float,
        precision: str = "fp16",
        context_length: int = 4096,
        batch_size: int = 1,
        num_layers: int = None,
        num_kv_heads: int = None,
        head_dim: int = 128,
    ) -> dict:
        """Calculate VRAM needed for inference."""
        
        # Bytes per parameter
        precision_map = {
            "fp32": 4, "fp16": 2, "bf16": 2,
            "int8": 1, "int4": 0.5, "q4_k_m": 0.5625
        }
        bytes_per_param = precision_map[precision]
        
        # Model weights
        model_size_gb = (params_billions * 1e9 * bytes_per_param) / (1024**3)
        
        # KV Cache (if layer info provided)
        kv_cache_gb = 0
        if num_layers and num_kv_heads:
            # 2 (K+V) × layers × seq_len × kv_heads × head_dim × 2 bytes × batch_size
            kv_cache_bytes = 2 * num_layers * context_length * num_kv_heads * head_dim * 2 * batch_size
            kv_cache_gb = kv_cache_bytes / (1024**3)
        
        # Overhead (activation memory, CUDA context, etc.)
        overhead_gb = 1.5  # ~1-2 GB typical overhead
        
        total = model_size_gb + kv_cache_gb + overhead_gb
        
        return {
            "model_weights": round(model_size_gb, 1),
            "kv_cache": round(kv_cache_gb, 1),
            "overhead": overhead_gb,
            "total_gb": round(total, 1),
        }
    
    def training_vram(
        self,
        params_billions: float,
        method: str = "qlora",
        batch_size: int = 4,
        seq_length: int = 2048,
    ) -> dict:
        """Calculate VRAM needed for training."""
        
        # Training multipliers
        multipliers = {
            "full_fp32": 18,    # weights(4) + gradients(4) + optimizer(8) + activations(2)
            "full_fp16": 10,    # Mixed precision training
            "lora_fp16": 3,     # Base model(2) + LoRA overhead(1)
            "qlora": 1.5,       # 4-bit base + LoRA overhead
        }
        
        bytes_per_param = multipliers[method]
        base_gb = (params_billions * 1e9 * bytes_per_param) / (1024**3)
        
        # Activation memory (scales with batch size and seq length)
        activation_gb = (batch_size * seq_length * params_billions * 0.001)
        
        total = base_gb + activation_gb + 2.0  # +2 GB overhead
        
        return {
            "method": method,
            "base_memory": round(base_gb, 1),
            "activations": round(activation_gb, 1),
            "total_gb": round(total, 1),
        }

# Example calculations
calc = VRAMCalculator()

print("=== INFERENCE VRAM ===")
print("Llama 3.1 8B (FP16):", calc.inference_vram(8, "fp16", num_layers=32, num_kv_heads=8))
print("Llama 3.1 8B (Q4):", calc.inference_vram(8, "int4", num_layers=32, num_kv_heads=8))
print("Llama 3.1 70B (Q4):", calc.inference_vram(70, "int4", num_layers=80, num_kv_heads=8))
print()
print("=== TRAINING VRAM ===")
print("8B QLoRA:", calc.training_vram(8, "qlora"))
print("8B Full FP16:", calc.training_vram(8, "full_fp16"))
print("70B QLoRA:", calc.training_vram(70, "qlora"))

Multi-GPU Strategies

# Multi-GPU loading with transformers
from transformers import AutoModelForCausalLM

# Automatic: splits model across all available GPUs
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-70B-Instruct",
    device_map="auto",  # Automatically distribute layers
    torch_dtype="auto",
)

# Manual: specify which layers go where
device_map = {
    "model.embed_tokens": 0,           # GPU 0
    "model.layers.0": 0,               # GPU 0
    "model.layers.1": 0,               # GPU 0
    # ... layers 2-39 on GPU 0
    "model.layers.40": 1,              # GPU 1
    # ... layers 40-79 on GPU 1
    "model.norm": 1,                   # GPU 1
    "lm_head": 1,                      # GPU 1
}

# CPU offloading (when VRAM is insufficient)
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-70B-Instruct",
    device_map="auto",
    offload_folder="./offload",  # Overflow to CPU/disk
    torch_dtype="auto",
)
# Warning: CPU offloading is MUCH slower (10-100x) but works!

🏭 Industry Standards

  • H100 is the current king — 3x faster than A100 for training, 2x for inference. H200 for memory-heavy workloads.
  • 24 GB is the sweet spot for hobbyists — RTX 4090 or M4 Max lets you run/fine-tune most 7-13B models.
  • QLoRA makes training accessible — Fine-tune 7B models on a single 16GB GPU, 70B on 48GB.
  • Apple Silicon for local inference — M3/M4 Max with 64-128GB unified memory runs 70B quantized models smoothly with MLX.
  • Tensor Parallelism for inference — Split one model across GPUs for lower latency (used in production).
  • Pipeline Parallelism for training — Split layers across GPUs, process micro-batches in pipeline.
  • Always calculate VRAM before buying/renting — Use the formula: params × bytes_per_param + KV cache + overhead.

📝 Summary

  • VRAM formula: params (B) × bytes_per_param + KV_cache + overhead
  • FP16: params × 2 bytes. INT4: params × 0.5 bytes
  • Training needs 3-18x more VRAM than inference (gradients, optimizer states)
  • QLoRA makes training affordable: 8B on 16GB GPU, 70B on 48GB
  • Multi-GPU: use device_map="auto" or DeepSpeed for distribution
  • Cloud GPUs: RunPod/Lambda for training, Modal for serverless inference

🧠 Mental Model

VRAM Budget = Model Weights + KV Cache + Activations + Overhead

Inference: 8B FP16 → 16 GB + 2 GB cache + 1.5 GB = ~20 GB
Inference: 8B Q4 → 4 GB + 2 GB cache + 1.5 GB = ~8 GB ← fits 4060!
Training: 8B QLoRA → 6 GB base + 4 GB activations + 2 GB = ~12 GB
Training: 8B Full → 80 GB weights+grads+optimizer = needs A100!

❌ Beginner Mistakes to Avoid

  • Buying based on TFLOPS alone — VRAM matters more than compute for LLMs. A 4090 (24GB) beats a 4080 (16GB) for AI.
  • Forgetting KV cache in calculations — The model fits, but crashes when you start generating long sequences.
  • Not considering batch size — Batch size multiplies KV cache memory. Batch of 8 = 8x the cache.
  • Buying consumer GPUs for training — Cloud is often cheaper: $2/hr × 10 hours = $20 vs $1,600 GPU that sits idle.
  • Ignoring interconnect for multi-GPU — 2× RTX 4090 over PCIe is much slower than NVLink-connected A100s.
