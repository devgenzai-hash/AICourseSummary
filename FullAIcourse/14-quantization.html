Quantization & GGUF Format

How to shrink a 14GB model to 4GB and still get 90%+ quality? Quantization! This chapter covers the techniques that make it possible to run powerful AI models on laptops and phones.

🏠 Daily Life Analogy

Quantization = compressing a high-res photo to JPEG. A raw photo might be 50MB. A JPEG version is 2MB. You lose some quality, but it's barely noticeable for most uses — and now it fits on your phone.

FP32 → INT4 = going from a grand piano to a ukulele. The piano has more range and detail, but the ukulele can still play great music and fits in a backpack.

What Is Quantization?

Quantization reduces the precision of model weights from 32-bit or 16-bit floating point numbers to smaller integers (8-bit, 4-bit, or even 2-bit). Less precision = smaller file = less memory = faster inference.

The Precision Ladder:

FormatBits per Parameter7B Model SizeQuality LossUse Case
FP32 (full)32 bits28 GBNone (baseline)Training only
FP16/BF16 (half)16 bits14 GBNegligibleGPU inference, training
INT88 bits7 GB~1-2%Production serving
INT4 / NF44 bits3.5 GB~3-5%Local/edge deployment
Q4_K_M (GGUF)~4.5 bits avg4.1 GB~2-4%llama.cpp / Ollama
Q2_K (GGUF)~2.5 bits avg2.5 GB~10-20%Extreme compression

Quantization Methods

1. Post-Training Quantization (PTQ)

Quantize after training is done. No retraining needed. Most common approach.

2. GPTQ (GPU-optimized)

# GPTQ: Fast GPU quantization using AutoGPTQ
from transformers import AutoModelForCausalLM, AutoTokenizer, GPTQConfig

model_name = "meta-llama/Llama-3.1-8B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)

# Quantization config
gptq_config = GPTQConfig(
    bits=4,               # 4-bit quantization
    dataset="c4",          # Calibration dataset
    tokenizer=tokenizer,
    group_size=128,        # Quantize in groups of 128
)

# Load and quantize (takes ~30 min on A100)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    quantization_config=gptq_config,
    device_map="auto"
)

# Save quantized model
model.save_pretrained("./llama-8b-gptq-4bit")
tokenizer.save_pretrained("./llama-8b-gptq-4bit")
print("✅ Model quantized and saved!")

3. AWQ (Activation-Aware Quantization)

# AWQ: Better quality than GPTQ, newer method
from transformers import AutoModelForCausalLM, AwqConfig

awq_config = AwqConfig(
    bits=4,
    fuse_max_seq_len=2048,
    do_fuse=True,  # Fuse layers for speed
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B-Instruct",
    quantization_config=awq_config,
    device_map="auto"
)
# AWQ models are faster than GPTQ at inference time

GGUF Format (For CPU/llama.cpp)

GGUF is THE format for running models on CPU or with llama.cpp/Ollama. It uses sophisticated mixed-precision quantization.

GGUF Quantization Levels:

QuantBits7B SizeQualitySpeedRecommendation
Q2_K2.5~2.5 GBPoorFastestDon't use (too much loss)
Q3_K_M3.5~3.3 GBOKFastWhen RAM is very limited
Q4_K_M4.5~4.1 GBGoodFastBest balance (recommended!)
Q5_K_M5.5~5.0 GBVery GoodMediumWhen you have extra RAM
Q6_K6.5~5.9 GBExcellentMediumNear-lossless
Q8_08.0~7.2 GBNear-perfectSlowerMaximum quality quantization
✅ Recommended: Q4_K_M

For most use cases, Q4_K_M gives you the best quality-to-size ratio. It's what most people use for local inference with Ollama/llama.cpp.

Converting to GGUF:

# Convert a HuggingFace model to GGUF format
# Requires: pip install llama-cpp-python
# Or use the llama.cpp conversion script:

# Step 1: Clone llama.cpp
# git clone https://github.com/ggerganov/llama.cpp
# cd llama.cpp

# Step 2: Convert HF model to GGUF (FP16 first)
# python convert_hf_to_gguf.py ./my-model/ --outtype f16 --outfile model-f16.gguf

# Step 3: Quantize to desired level
# ./llama-quantize model-f16.gguf model-Q4_K_M.gguf Q4_K_M

# Now you can use it with Ollama:
# Create a Modelfile:
# FROM ./model-Q4_K_M.gguf
# ollama create my-model -f Modelfile
# ollama run my-model

Using Quantized Models with Python:

# Method 1: GPTQ/AWQ models with transformers
from transformers import AutoModelForCausalLM, AutoTokenizer

# Load a pre-quantized model from HuggingFace
model = AutoModelForCausalLM.from_pretrained(
    "TheBloke/Llama-2-7B-Chat-GPTQ",  # Pre-quantized!
    device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained("TheBloke/Llama-2-7B-Chat-GPTQ")

# Method 2: GGUF models with llama-cpp-python
from llama_cpp import Llama

# Load GGUF model (runs on CPU!)
llm = Llama(
    model_path="./models/llama-3.1-8b-instruct-Q4_K_M.gguf",
    n_ctx=4096,        # Context window
    n_threads=8,       # CPU threads
    n_gpu_layers=35,   # Offload layers to GPU (0 for CPU-only)
)

# Generate
output = llm.create_chat_completion(
    messages=[
        {"role": "user", "content": "Explain quantum computing in simple terms"}
    ],
    max_tokens=500,
    temperature=0.7
)
print(output["choices"][0]["message"]["content"])

🏭 Industry Standards

  • GGUF is the standard for local deployment — Ollama, LM Studio, llama.cpp all use GGUF.
  • Q4_K_M is the default recommendation — Best quality/size tradeoff for most models.
  • AWQ > GPTQ for serving — AWQ gives faster inference with comparable quality.
  • TheBloke / bartowski on HuggingFace — These users provide pre-quantized models. Don't quantize yourself unless needed.
  • Mixed-precision quantization — Keep attention layers at higher precision, compress FFN layers more aggressively.
  • Always benchmark after quantization — Run your specific task and verify quality didn't drop too much.

📝 Summary

  • Quantization = reducing number precision to shrink model size and memory usage
  • 4-bit quantization: 75% smaller with ~3-5% quality loss
  • GGUF = format for llama.cpp/Ollama (CPU-friendly)
  • GPTQ/AWQ = formats for GPU inference
  • Q4_K_M = best default choice for GGUF
  • Use pre-quantized models from HuggingFace when possible

🧠 Mental Model

Original: 7B × 2 bytes (FP16) = 14 GB ← needs expensive GPU
Quantized: 7B × 0.5 bytes (4-bit) = 3.5 GB ← runs on a laptop!

Quality tradeoff: FP16 (100%) → Q8 (99%) → Q5 (97%) → Q4 (95%) → Q2 (80%)

❌ Beginner Mistakes to Avoid

  • Quantizing too aggressively — Q2 destroys quality for most models. Stick to Q4_K_M or above.
  • Using GPTQ models on CPU — GPTQ is GPU-only. Use GGUF for CPU inference.
  • Quantizing before fine-tuning — Fine-tune first, then quantize the result. (Exception: QLoRA quantizes for training.)
  • Not benchmarking — Always test quantized model on YOUR task. Some tasks are more sensitive to precision loss.
  • Quantizing yourself when pre-quantized exists — Check HuggingFace first. Someone probably already did it.
