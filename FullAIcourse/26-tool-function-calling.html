Tool & Function Calling

LLMs can't check the weather, query databases, or send emails on their own. Tool calling gives them "hands" — the ability to invoke real functions and use the results in their responses.

🏠 Daily Life Analogy

Function calling = a doctor writing prescriptions. The doctor (AI) decides what medicine you need, writes a prescription (function call with parameters), then the pharmacist (your code) actually fills it. The doctor doesn't hand you pills directly.

The AI says: "I need to call get_weather(city='London')" — your code runs it, gets the result, and sends it back for the AI to use in its answer.

How Tool Calling Works

🧠 The Tool Calling Loop

User: "What's the weather in Tokyo?"
    ↓
AI thinks: "I need weather data. I'll call get_weather."
    ↓
AI returns: tool_call(name="get_weather", args={"city": "Tokyo"})
    ↓
YOUR CODE: runs get_weather("Tokyo") → {"temp": 22, "condition": "sunny"}
    ↓
You send result back to AI
    ↓
AI: "It's 22°C and sunny in Tokyo right now! 🌞"

OpenAI-Style Function Calling

# Works with OpenAI, Ollama, Groq, Together — all OpenAI-compatible APIs
import json
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

# Step 1: Define your tools with JSON Schema
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current weather for a city",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {
                        "type": "string",
                        "description": "City name, e.g., 'London'"
                    },
                    "units": {
                        "type": "string",
                        "enum": ["celsius", "fahrenheit"],
                        "description": "Temperature units"
                    }
                },
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "search_database",
            "description": "Search for products in the database",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "Search query"},
                    "max_results": {"type": "integer", "description": "Max results to return"}
                },
                "required": ["query"]
            }
        }
    }
]

# Step 2: Implement the actual functions
def get_weather(city: str, units: str = "celsius") -> dict:
    """Real implementation would call a weather API."""
    # Simulated response
    return {"city": city, "temp": 22, "condition": "partly cloudy", "units": units}

def search_database(query: str, max_results: int = 5) -> list:
    """Real implementation would query your DB."""
    return [{"name": "Widget Pro", "price": 29.99}, {"name": "Widget Basic", "price": 9.99}]

# Function registry
TOOL_FUNCTIONS = {
    "get_weather": get_weather,
    "search_database": search_database,
}

# Step 3: The tool calling loop
def chat_with_tools(user_message: str) -> str:
    messages = [{"role": "user", "content": user_message}]
    
    # First call: AI decides if it needs tools
    response = client.chat.completions.create(
        model="llama3.1:8b",
        messages=messages,
        tools=tools,
        tool_choice="auto",  # "auto" | "none" | specific function
    )
    
    msg = response.choices[0].message
    
    # If no tool calls, return direct response
    if not msg.tool_calls:
        return msg.content
    
    # Process each tool call
    messages.append(msg)  # Add assistant message with tool calls
    
    for tool_call in msg.tool_calls:
        func_name = tool_call.function.name
        func_args = json.loads(tool_call.function.arguments)
        
        print(f"🔧 Calling: {func_name}({func_args})")
        
        # Execute the function
        result = TOOL_FUNCTIONS[func_name](**func_args)
        
        # Add result to messages
        messages.append({
            "role": "tool",
            "tool_call_id": tool_call.id,
            "content": json.dumps(result)
        })
    
    # Second call: AI uses the results to answer
    final_response = client.chat.completions.create(
        model="llama3.1:8b",
        messages=messages,
    )
    
    return final_response.choices[0].message.content

# Test it!
print(chat_with_tools("What's the weather in Tokyo?"))
print(chat_with_tools("Find me some widgets under $20"))
print(chat_with_tools("Hello, how are you?"))  # No tool call needed

Multiple Tool Calls in One Response

# AI can call multiple tools at once (parallel tool calls)

# User: "Compare the weather in London and Paris"
# AI generates TWO tool calls:
#   tool_call_1: get_weather(city="London")
#   tool_call_2: get_weather(city="Paris")

# Your code runs both, sends both results back
# AI then compares them in its answer

def handle_parallel_tools(message):
    """Handle AI responses with multiple parallel tool calls."""
    response = client.chat.completions.create(
        model="llama3.1:8b",
        messages=[{"role": "user", "content": message}],
        tools=tools,
        tool_choice="auto",
    )
    
    msg = response.choices[0].message
    
    if msg.tool_calls:
        print(f"AI wants to call {len(msg.tool_calls)} tools")
        for tc in msg.tool_calls:
            print(f"  - {tc.function.name}({tc.function.arguments})")
    
    return msg

Production Tool System

# Robust tool system with validation, error handling, and security
import json
import inspect
from typing import Callable, Any
from functools import wraps
from openai import OpenAI

class ToolRegistry:
    """Production-grade tool management for AI assistants."""
    
    def __init__(self):
        self.tools = {}  # name → {func, schema, config}
        self.call_history = []
    
    def register(self, description: str, parameters: dict, requires_confirmation: bool = False):
        """Decorator to register a function as a tool."""
        def decorator(func: Callable):
            self.tools[func.__name__] = {
                "func": func,
                "schema": {
                    "type": "function",
                    "function": {
                        "name": func.__name__,
                        "description": description,
                        "parameters": parameters,
                    }
                },
                "requires_confirmation": requires_confirmation,
            }
            return func
        return decorator
    
    def get_tool_schemas(self) -> list:
        """Get all tool schemas for the API call."""
        return [t["schema"] for t in self.tools.values()]
    
    def execute(self, name: str, arguments: dict) -> str:
        """Safely execute a tool and return result as string."""
        if name not in self.tools:
            return json.dumps({"error": f"Unknown tool: {name}"})
        
        tool = self.tools[name]
        
        # Security check
        if tool["requires_confirmation"]:
            print(f"⚠️ Tool '{name}' requires confirmation!")
            # In production: wait for user approval
        
        try:
            result = tool["func"](**arguments)
            self.call_history.append({"tool": name, "args": arguments, "success": True})
            return json.dumps(result, default=str)
        except Exception as e:
            self.call_history.append({"tool": name, "args": arguments, "success": False, "error": str(e)})
            return json.dumps({"error": f"Tool execution failed: {str(e)}"})

# Create registry and register tools
registry = ToolRegistry()

@registry.register(
    description="Get current weather for a city",
    parameters={
        "type": "object",
        "properties": {
            "city": {"type": "string", "description": "City name"}
        },
        "required": ["city"]
    }
)
def get_weather(city: str) -> dict:
    return {"city": city, "temp": 22, "condition": "sunny"}

@registry.register(
    description="Send an email to a recipient",
    parameters={
        "type": "object",
        "properties": {
            "to": {"type": "string", "description": "Recipient email"},
            "subject": {"type": "string"},
            "body": {"type": "string"}
        },
        "required": ["to", "subject", "body"]
    },
    requires_confirmation=True  # Dangerous action!
)
def send_email(to: str, subject: str, body: str) -> dict:
    return {"status": "sent", "to": to}

# Full conversation loop with tools
def agent_loop(user_message: str, client: OpenAI, max_iterations: int = 5) -> str:
    messages = [{"role": "user", "content": user_message}]
    
    for _ in range(max_iterations):
        response = client.chat.completions.create(
            model="llama3.1:8b",
            messages=messages,
            tools=registry.get_tool_schemas(),
            tool_choice="auto",
        )
        
        msg = response.choices[0].message
        messages.append(msg)
        
        if not msg.tool_calls:
            return msg.content
        
        for tool_call in msg.tool_calls:
            result = registry.execute(
                tool_call.function.name,
                json.loads(tool_call.function.arguments)
            )
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result,
            })
    
    return "Max iterations reached."

🏭 Industry Standards

  • Always validate tool arguments — Never trust AI-generated parameters blindly. Validate types and ranges.
  • Require confirmation for dangerous actions — Sending emails, deleting data, making purchases must have human approval.
  • Set max iterations — Prevent infinite loops where AI keeps calling tools forever.
  • Log all tool calls — Essential for debugging, auditing, and cost tracking.
  • Timeout protection — If a tool takes too long, fail gracefully.
  • Models that support tools — GPT-4o, Claude 3.5, Llama 3.1+, Qwen 2.5, Mistral Large all support native tool calling.
  • Tool descriptions matter — Better descriptions = better tool selection by the model.

📝 Summary

  • Tool calling = AI decides what function to call, your code executes it
  • Define tools with JSON Schema (name, description, parameters)
  • The loop: User → AI → tool_call → execute → result → AI → answer
  • AI can call multiple tools in parallel when needed
  • Use a ToolRegistry for clean registration, validation, and execution
  • Always add safety checks for destructive actions

❌ Beginner Mistakes to Avoid

  • No error handling in tools — If your function throws, the AI gets confused. Always return clean error messages.
  • Trusting AI arguments — AI might hallucinate parameters. Validate everything server-side.
  • No iteration limit — AI can get stuck in loops calling tools repeatedly. Set max_iterations.
  • Vague tool descriptions — "Does stuff" → AI won't know when to use it. Be specific about purpose and inputs.
  • Exposing dangerous tools without confirmation — delete_user, send_money, etc. always need human approval.
