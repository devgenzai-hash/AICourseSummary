RAG Fundamentals

Retrieval-Augmented Generation (RAG) is how you make AI answer questions about YOUR data — your documents, your codebase, your company knowledge. The most important pattern in production AI.

🏠 Daily Life Analogy

RAG = an open-book exam. The student (LLM) doesn't need to memorize everything. Instead, they can look up relevant pages (retrieve) before answering the question (generate). Much more accurate than relying on memory alone!

Without RAG = a closed-book exam. The model can only use what it memorized during training. If the info isn't in training data (or is outdated), it either hallucinates or says "I don't know."

How RAG Works

🧠 RAG Pipeline

1. User asks: "What's our refund policy?"
2. RETRIEVE: Search your documents for relevant chunks
3. AUGMENT: Inject those chunks into the prompt
4. GENERATE: LLM answers using the provided context

Prompt = System instructions + Retrieved context + User question

Complete RAG System:

# Production-ready RAG system
# pip install openai chromadb sentence-transformers
from openai import OpenAI
import chromadb
from sentence_transformers import SentenceTransformer
from typing import Optional

class RAGSystem:
    """Complete RAG system with embedding, retrieval, and generation."""
    
    def __init__(
        self,
        llm_base_url: str = "http://localhost:11434/v1",
        llm_model: str = "llama3.1:8b",
        embed_model: str = "all-MiniLM-L6-v2",
        collection_name: str = "documents",
    ):
        # LLM client (works with Ollama, vLLM, OpenAI)
        self.llm = OpenAI(base_url=llm_base_url, api_key="local")
        self.llm_model = llm_model
        
        # Embedding model (runs locally)
        self.embedder = SentenceTransformer(embed_model)
        
        # Vector database
        self.chroma = chromadb.PersistentClient(path="./chroma_db")
        self.collection = self.chroma.get_or_create_collection(
            name=collection_name,
            metadata={"hnsw:space": "cosine"}
        )
    
    def add_documents(self, texts: list[str], metadata: Optional[list[dict]] = None):
        """Add documents to the vector store."""
        # Generate embeddings
        embeddings = self.embedder.encode(texts).tolist()
        
        # Store in ChromaDB
        ids = [f"doc_{i}" for i in range(len(texts))]
        self.collection.add(
            ids=ids,
            embeddings=embeddings,
            documents=texts,
            metadatas=metadata or [{} for _ in texts],
        )
        print(f"✅ Added {len(texts)} documents")
    
    def retrieve(self, query: str, top_k: int = 3) -> list[str]:
        """Retrieve most relevant documents for a query."""
        query_embedding = self.embedder.encode([query]).tolist()
        
        results = self.collection.query(
            query_embeddings=query_embedding,
            n_results=top_k,
        )
        return results["documents"][0]
    
    def generate(self, query: str, context: list[str]) -> str:
        """Generate answer using retrieved context."""
        context_text = "\n\n".join([f"[Document {i+1}]: {doc}" for i, doc in enumerate(context)])
        
        response = self.llm.chat.completions.create(
            model=self.llm_model,
            messages=[
                {"role": "system", "content": """You are a helpful assistant. Answer questions based ONLY on the provided context. 
If the context doesn't contain the answer, say "I don't have enough information to answer that."
Always cite which document number you're referencing."""},
                {"role": "user", "content": f"Context:\n{context_text}\n\nQuestion: {query}"},
            ],
            temperature=0.3,  # Low temperature for factual answers
            max_tokens=500,
        )
        return response.choices[0].message.content
    
    def query(self, question: str, top_k: int = 3) -> str:
        """Full RAG pipeline: retrieve + generate."""
        context = self.retrieve(question, top_k=top_k)
        answer = self.generate(question, context)
        return answer

# Usage
rag = RAGSystem()

# Add your documents
rag.add_documents([
    "Our refund policy allows returns within 30 days of purchase.",
    "Shipping is free for orders over $50.",
    "Premium members get 20% off all products.",
    "Contact support@company.com for order issues.",
])

# Query
answer = rag.query("What's the refund policy?")
print(answer)

Document Chunking

Large documents must be split into smaller chunks for effective retrieval. Chunk size is one of the most important decisions in RAG.

# Smart document chunking strategies
from typing import Generator

class DocumentChunker:
    """Multiple chunking strategies for RAG."""
    
    def fixed_size(self, text: str, chunk_size: int = 500, overlap: int = 50) -> list[str]:
        """Simple fixed-size chunking with overlap."""
        chunks = []
        start = 0
        while start < len(text):
            end = start + chunk_size
            chunks.append(text[start:end])
            start = end - overlap  # Overlap prevents cutting mid-sentence
        return chunks
    
    def by_sentences(self, text: str, sentences_per_chunk: int = 5) -> list[str]:
        """Chunk by sentence boundaries (better quality)."""
        sentences = text.replace("? ", "?|").replace(". ", ".|").replace("! ", "!|").split("|")
        chunks = []
        for i in range(0, len(sentences), sentences_per_chunk):
            chunk = " ".join(sentences[i:i + sentences_per_chunk])
            if chunk.strip():
                chunks.append(chunk.strip())
        return chunks
    
    def by_markdown_headers(self, text: str) -> list[str]:
        """Chunk by markdown headers (best for docs)."""
        chunks = []
        current_chunk = ""
        
        for line in text.split("\n"):
            if line.startswith("#") and current_chunk:
                chunks.append(current_chunk.strip())
                current_chunk = line + "\n"
            else:
                current_chunk += line + "\n"
        
        if current_chunk.strip():
            chunks.append(current_chunk.strip())
        return chunks

# Best practice: 200-500 tokens per chunk, with 10-20% overlap
chunker = DocumentChunker()
document = open("company_docs.md").read()
chunks = chunker.by_sentences(document, sentences_per_chunk=5)
print(f"Created {len(chunks)} chunks")

Chunking Guidelines:

Chunk SizeProsConsBest For
Small (100-200 tokens)Precise retrievalMay lack contextFAQ, definitions
Medium (200-500 tokens)Good balanceNone majorMost use cases (recommended)
Large (500-1000 tokens)More contextLess precise, more noiseLong-form content, legal docs

Advanced RAG Techniques

# Advanced RAG: Hybrid search + Reranking
from sentence_transformers import CrossEncoder

class AdvancedRAG(RAGSystem):
    """RAG with reranking for better results."""
    
    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        # Reranker: re-scores retrieved docs for relevance
        self.reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")
    
    def retrieve_and_rerank(self, query: str, top_k: int = 3, initial_k: int = 10) -> list[str]:
        """Retrieve more, then rerank to find the truly relevant ones."""
        # Step 1: Retrieve more candidates than needed
        candidates = self.retrieve(query, top_k=initial_k)
        
        # Step 2: Rerank with cross-encoder (more accurate but slower)
        pairs = [[query, doc] for doc in candidates]
        scores = self.reranker.predict(pairs)
        
        # Step 3: Return top-k by reranker score
        ranked = sorted(zip(scores, candidates), reverse=True)
        return [doc for _, doc in ranked[:top_k]]
    
    def query(self, question: str, top_k: int = 3) -> str:
        """Full pipeline with reranking."""
        context = self.retrieve_and_rerank(question, top_k=top_k)
        return self.generate(question, context)

RAG vs Fine-Tuning: When to Use What?

ApproachBest ForProsCons
RAGDynamic/changing data, company docsNo retraining, up-to-date, cites sourcesRetrieval quality depends on chunking
Fine-tuningNew behaviors, style, domain expertiseFaster inference, no retrieval stepExpensive, needs retraining for new data
RAG + Fine-tuningBest of both worldsDomain expertise + grounded in dataMost complex to maintain

🏭 Industry Standards

  • RAG is the #1 production pattern — 80%+ of enterprise AI apps use RAG.
  • Chunk size: 200-500 tokens — With 50-100 token overlap. Test what works for your data.
  • Retrieve 3-5 chunks — More than 5 often adds noise. Less than 3 may miss information.
  • Always rerank — Bi-encoder retrieval + cross-encoder reranking = significantly better accuracy.
  • Hybrid search — Combine semantic (embedding) + keyword (BM25) search for best results.
  • Low temperature for RAG answers — Use 0.1-0.3 to keep answers grounded in context.
  • Cite sources — Tell the model to reference which document it's using. Builds trust.

📝 Summary

  • RAG = Retrieve relevant docs → Put in prompt → Generate answer
  • Solves: hallucination, outdated knowledge, private data access
  • Chunking: 200-500 tokens, with overlap, respecting boundaries
  • Embedding: Convert text to vectors for semantic search
  • Reranking: Use cross-encoder to re-score candidates for better quality
  • RAG is preferred over fine-tuning for most knowledge-grounding tasks

❌ Beginner Mistakes to Avoid

  • Chunks too large — 2000-token chunks bury the answer in noise. Keep under 500.
  • No overlap — Without overlap, you cut sentences in half and lose meaning.
  • Using only semantic search — Add keyword search (BM25) for names, numbers, codes that embeddings miss.
  • High temperature — For RAG, use temp 0.1-0.3. High temp causes the model to ignore context.
  • Not telling the model to cite sources — Without instructions, the model will hallucinate beyond the context.
  • Not evaluating retrieval quality — If you retrieve wrong chunks, even the best LLM gives wrong answers.
