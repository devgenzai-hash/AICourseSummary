Frontend Concepts / Priority Hints

Priority Hints

Telling the browser which resources matter most — the fetchpriority attribute that overrides the browser's default resource prioritization, directly improving LCP and Core Web Vitals.

Intermediate Performance Resource Loading
🚑 Daily-Life Analogy: Hospital Triage

When multiple patients arrive at the ER simultaneously, triage determines who gets treated first. The browser does the same with network requests — CSS is "critical," images are "low." Priority Hints let you tell the triage nurse: "this specific image is actually the hero banner (LCP) — treat it as urgent" or "this script isn't needed yet — deprioritize it."

The Problem: Browser's Default Priorities Are Imperfect

Resource TypeDefault PriorityWhy It's Sometimes Wrong
CSS (in <head>)HighestUsually correct — render-blocking
Scripts (sync, in <head>)HighAnalytics/tracking scripts don't need this priority
Images (above fold)High (after layout)Browser doesn't know which image is LCP until late
Images (below fold)LowUsually correct
Fonts (discovered in CSS)High (late discovery)Can't be prioritized until CSS is parsed — too late
fetch() / XHRHighNot all fetches are equal — some are non-critical prefetches

Code: Using fetchpriority

<!-- ✅ Boost LCP image priority — browser fetches it earlier -->
<img src="/hero-banner.jpg" fetchpriority="high" alt="Hero">

<!-- ✅ Demote below-fold images that browser might over-prioritize -->
<img src="/carousel-slide-3.jpg" fetchpriority="low" loading="lazy" alt="">

<!-- ✅ Critical CSS/font preload at high priority -->
<link rel="preload" href="/critical-font.woff2" as="font" fetchpriority="high">

<!-- ✅ Non-critical script demoted -->
<script src="/analytics.js" fetchpriority="low" async></script>

<!-- ✅ In fetch() API -->
// Critical data that blocks render
fetch('/api/critical-data', { priority: 'high' });

// Prefetch for next page — low priority, don't compete with current page
fetch('/api/next-page-data', { priority: 'low' });

Real Impact on LCP

/*
  Without fetchpriority:
  1. Browser discovers <img> during parse
  2. Assigns "High" priority (since it's above-fold... but browser isn't sure yet)
  3. Image competes with other "High" resources (scripts, other images)
  4. LCP image loads in ~2.5s
  
  With fetchpriority="high":
  1. Browser sees fetchpriority="high" immediately during parse
  2. Assigns "Highest" internal priority (same as CSS/fonts)
  3. Image gets bandwidth priority over everything except render-blocking CSS
  4. LCP image loads in ~1.8s (700ms improvement!)
  
  Google case study: fetchpriority="high" on LCP image improved LCP by 1200ms
  on mobile connections.
*/

The Three Values

ValueEffectWhen to Use
fetchpriority="high"Boosts above default priority for this resource typeLCP image, critical above-fold content, hero fonts
fetchpriority="low"Lowers below default priorityBelow-fold images, analytics, prefetch, non-critical scripts
fetchpriority="auto"Browser decides (default)Everything else — let the browser's heuristics work

Where This Is Used in Production

  • Google Search — Uses fetchpriority="high" on the search results area and fetchpriority="low" on sidebar content, improving perceived load speed.
  • Etsy — Applied fetchpriority="high" to LCP product images, improving LCP by 4% across all pages.
  • Next.js Image component — Automatically applies fetchpriority="high" when you set the priority prop on <Image>.

Common Mistakes

  • Marking everything as high — If everything is high priority, nothing is. Use it surgically (1-2 resources per page).
  • Using fetchpriority="high" on below-fold content — Wastes bandwidth that should go to above-fold resources. Only boost what the user sees first.
  • Confusing fetchpriority with loading — loading="lazy" controls WHEN to start loading (on visibility). fetchpriority controls HOW URGENTLY to load it once started.
  • Not measuring impact — Always verify with Lighthouse or Web Vitals that the priority change actually improved LCP. Sometimes the default is already optimal.

✅ You Truly Understand Priority Hints When...

You can explain the difference between <link rel="preload"> (changes WHEN discovery happens) and fetchpriority="high" (changes HOW the browser prioritizes an already-discovered resource), and when you need both together.

🧪 Try This Challenge

Load a page with 5 images in Chrome DevTools. In the Network tab, add the "Priority" column. Observe default priorities. Then add fetchpriority="high" to one image and fetchpriority="low" to another. Reload and verify the priority column changes and the waterfall shifts.
