Streaming Fetch Response Handling

Instead of waiting for the entire response body to download before processing, streaming fetch lets you consume data chunk-by-chunk as it arrives from the network — enabling progressive rendering, real-time UI updates, and constant-memory processing of arbitrarily large responses.

Advanced Network Performance
📚 Analogy: Reading a Book vs Listening to a Podcast

response.json() is like waiting for the entire book to be printed, bound, and shipped before you can read page one. Streaming fetch is like listening to a podcast — you hear and process each sentence as it's spoken, reacting in real-time. You don't need the full transcript in memory to start understanding. For a 2-hour podcast (large API response), you'd never wait for the full download — you stream it.

The Problem: Buffering Entire Responses Blocks the UI

// Traditional fetch — buffers entire response before you can use it

// Scenario: AI chatbot response (tokens arrive over 3 seconds)
const response = await fetch('/api/chat', { method: 'POST', body });

// This waits for the ENTIRE response body to arrive
const data = await response.json();
// User sees nothing for 3 seconds, then the full answer appears at once
// Terrible UX — user thinks the app is frozen

renderMessage(data.text);

// Scenario: 50MB CSV download for client-side processing
const csv = await fetch('/reports/large.csv').then(r => r.text());
// Problem 1: 50MB string in memory (crashes on low-end devices)
// Problem 2: User sees nothing during the 10-second download
// Problem 3: No progress indication possible

// With streaming: process rows as they arrive, show progress, use ~1MB memory

The Mechanism: response.body is a ReadableStream

// fetch() returns a Response object whose .body is a ReadableStream
// This stream yields Uint8Array chunks as they arrive from the network

const response = await fetch('/api/stream');

// response.body is a ReadableStream<Uint8Array>
// It's already "streaming" — data arrives as the server sends it
// The question is: do you consume it all at once, or chunk by chunk?

// === METHOD 1: Manual reader loop ===
const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;

  // value is a Uint8Array chunk (raw bytes from the network)
  const text = decoder.decode(value, { stream: true });
  // { stream: true } tells TextDecoder not to flush — handles
  // multi-byte characters split across chunk boundaries

  appendToUI(text); // Update UI progressively
}

// === METHOD 2: pipeThrough with TransformStreams ===
const textStream = response.body
  .pipeThrough(new TextDecoderStream()); // bytes → text chunks

const reader2 = textStream.getReader();
// Now read() gives you string chunks instead of Uint8Array

// === METHOD 3: Async iteration (modern) ===
for await (const chunk of response.body) {
  // Direct async iteration over the stream
  // Note: not yet supported in all browsers (Safari lagging)
  processChunk(chunk);
}

Real Implementation: Streaming AI Chat Response

// The ChatGPT-style token-by-token streaming pattern
// Server sends Server-Sent Events (SSE) or newline-delimited JSON (NDJSON)

async function streamChat(prompt, onToken, { signal } = {}) {
  const response = await fetch('/api/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ prompt }),
    signal
  });

  if (!response.ok) throw new Error(`HTTP ${response.status}`);

  const reader = response.body
    .pipeThrough(new TextDecoderStream())
    .getReader();

  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += value;

    // Parse NDJSON: each line is a complete JSON object
    const lines = buffer.split('\n');
    buffer = lines.pop(); // Keep incomplete line for next iteration

    for (const line of lines) {
      if (!line.trim() || line.startsWith(':')) continue; // SSE comment
      if (line === 'data: [DONE]') return; // OpenAI stream end signal

      const json = JSON.parse(line.replace('data: ', ''));
      const token = json.choices?.[0]?.delta?.content;
      if (token) onToken(token); // Render token immediately
    }
  }
}

// React component using it
function ChatMessage({ prompt }) {
  const [text, setText] = useState('');

  useEffect(() => {
    const controller = new AbortController();

    streamChat(
      prompt,
      (token) => setText(prev => prev + token), // Append each token
      { signal: controller.signal }
    );

    return () => controller.abort(); // Cancel on unmount
  }, [prompt]);

  return <div className="message">{text}</div>;
}

Download Progress with Streaming

// Show download progress for large files using streaming

async function fetchWithProgress(url, onProgress) {
  const response = await fetch(url);

  // Content-Length header tells us the total size (if server sends it)
  const total = parseInt(response.headers.get('content-length'), 10);
  let loaded = 0;

  // Create a TransformStream that counts bytes passing through
  const progressStream = new TransformStream({
    transform(chunk, controller) {
      loaded += chunk.byteLength;
      onProgress({ loaded, total, percent: total ? loaded / total : 0 });
      controller.enqueue(chunk); // Pass chunk through unchanged
    }
  });

  // Pipe response through our progress counter
  const trackedBody = response.body.pipeThrough(progressStream);

  // Create new Response with the tracked stream
  const trackedResponse = new Response(trackedBody, {
    headers: response.headers,
    status: response.status
  });

  return trackedResponse;
}

// Usage
const response = await fetchWithProgress('/big-file.zip', ({ percent }) => {
  progressBar.style.width = `${percent * 100}%`;
});
const blob = await response.blob();

Streaming NDJSON Processing (Constant Memory)

// Process millions of JSON records without loading all into memory
// Server sends Newline-Delimited JSON: one JSON object per line

async function* streamNDJSON(url, { signal } = {}) {
  const response = await fetch(url, { signal });
  const reader = response.body
    .pipeThrough(new TextDecoderStream())
    .getReader();

  let buffer = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += value;
    const lines = buffer.split('\n');
    buffer = lines.pop(); // Incomplete line stays in buffer

    for (const line of lines) {
      if (line.trim()) {
        yield JSON.parse(line); // Yield one record at a time
      }
    }
  }

  // Don't forget the last line (no trailing newline)
  if (buffer.trim()) {
    yield JSON.parse(buffer);
  }
}

// Usage: process 10 million records using ~1KB of memory
let count = 0;
for await (const record of streamNDJSON('/api/export')) {
  await insertIntoIndexedDB(record);
  count++;
  if (count % 1000 === 0) updateProgress(count);
}
// Memory never exceeds a few KB regardless of total response size

Real-World Usage

  • ChatGPT / Claude / AI APIs — All LLM APIs stream tokens via SSE or NDJSON. The frontend appends each token to the message as it arrives, creating the typewriter effect users expect.
  • Large data exports — Exporting millions of rows from a dashboard. Streaming lets you write to a file (via File System Access API) or process rows without buffering the entire dataset.
  • Video/audio processing — Streaming fetch feeds MediaSource for adaptive bitrate playback, or pipes audio through Web Audio API for real-time visualization.
  • Server-Sent Events (SSE) polyfill — EventSource doesn't support POST or custom headers. Streaming fetch + NDJSON parsing gives you full SSE capabilities with any HTTP method.
  • Progressive image loading — Stream JPEG bytes and render progressively using createImageBitmap() on partial data, showing a blurry preview that sharpens as more data arrives.

Trade-offs & Alternatives

ApproachStrengthsWeaknesses
Streaming fetch (ReadableStream) Constant memory; progressive rendering; works with any fetch More complex code; must handle partial chunks; no random access
response.json() / response.text() Simple; one-liner; handles encoding automatically Buffers entire response; no progress; memory proportional to response
WebSocket Bidirectional; true push; low latency Different protocol; connection management; not cacheable by CDNs
EventSource (SSE) Built-in reconnection; simple API; auto-parsing GET only; no custom headers; no binary; limited browser control

Common Mistakes

  • Forgetting { stream: true } in TextDecoder — Multi-byte characters (emoji, CJK) can be split across chunks. Without { stream: true }, you get garbled text at chunk boundaries. Always use new TextDecoder().decode(chunk, { stream: true }) or TextDecoderStream.
  • Parsing incomplete JSON from a chunk — A single chunk might contain half a JSON object. Always buffer and split by newlines for NDJSON, or use a streaming JSON parser for regular JSON responses.
  • Consuming response.body after calling .json() or .text() — The body can only be consumed once. After response.json(), the stream is locked and exhausted. If you need both streaming and full-body access, use response.clone() before consuming.
  • Not handling network errors mid-stream — The stream can fail after headers arrive (connection dropped). Wrap your read loop in try/catch and handle partial data gracefully.
  • Updating React state on every single chunk — If chunks arrive very fast (every 10ms), calling setState on each one creates thousands of re-renders. Batch updates with requestAnimationFrame or accumulate chunks and flush at 60fps intervals.

✅ You Truly Understand Streaming Fetch When...

You can implement a complete streaming AI chat interface that: handles partial token boundaries correctly, shows progressive output in real-time, reports download progress, gracefully handles mid-stream disconnections with retry, cancels cleanly on user abort, and maintains constant memory usage regardless of response length — all without any streaming library.

🔗 Connect It

Streaming Fetch connects to: Backpressure in Streams (if you process chunks slowly, the browser pauses the TCP receive window), AbortController (cancelling mid-stream properly terminates the connection), and Streaming SSR (server uses the same ReadableStream API to send HTML progressively).
