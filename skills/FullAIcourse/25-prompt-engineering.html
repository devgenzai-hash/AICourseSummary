Prompt Engineering

The difference between a mediocre AI output and an amazing one is usually the prompt. Master the art and science of telling AI exactly what you want — and getting it consistently.

🏠 Daily Life Analogy

Prompt engineering = giving directions to a taxi driver. "Take me somewhere nice" gets unpredictable results. "Take me to the Italian restaurant on 5th Street, the one with the red awning, via Main Street to avoid traffic" gets exactly what you want.

System prompt = the job description. It tells the AI WHO it is, HOW to behave, and WHAT rules to follow — before the user even asks anything.

The Prompt Framework: CRAFT

LetterElementWhat It DoesExample
CContextBackground information"You are a senior Python developer at a fintech company"
RRoleWho the AI should be"Act as a code reviewer"
AActionWhat to do"Review this code for bugs and security issues"
FFormatOutput structure"Return JSON with fields: issue, severity, fix"
TTone/ConstraintsBoundaries and style"Be concise. Max 3 issues. No false positives."

Key Techniques

1. Few-Shot Prompting:

# Show examples of what you want
system_prompt = """Classify customer messages into categories.

Examples:
- "My order hasn't arrived" → shipping
- "I want my money back" → refund
- "The product broke after 2 days" → quality
- "How do I change my password?" → account

Respond with ONLY the category name."""

# The model now follows the pattern!
# Input: "I can't log into my account"
# Output: "account"

2. Chain-of-Thought (CoT):

# Make the model think step by step
prompt = """Solve this problem step by step:

A store has 3 shirts at $25 each and 2 pants at $40 each.
There's a 20% discount on the total.
How much does it cost?

Think through this step by step before giving the final answer."""

# Much better than: "What's the cost?" (often gets wrong answer)
# CoT forces the model to show its work, reducing errors.

3. System Prompt Engineering:

# Production-grade system prompt
SYSTEM_PROMPT = """You are an AI coding assistant for a Python web development team.

## Your Capabilities
- Write Python, JavaScript, SQL, and Shell scripts
- Debug code and suggest fixes
- Explain complex concepts simply
- Review code for security issues

## Rules
1. Always use Python 3.11+ syntax
2. Follow PEP 8 style
3. Include type hints in all function signatures
4. Add brief docstrings to functions
5. Never use deprecated libraries

## Output Format
- For code: wrap in ```python blocks
- For explanations: use bullet points
- For debugging: show the bug, explain why, provide the fix

## Constraints
- Never execute code or access external systems
- If unsure, say "I'm not sure" rather than guessing
- Keep responses under 500 words unless asked for more
- If the question is unrelated to coding, politely redirect"""

4. Structured Output Prompting:

# Force specific JSON output
prompt = """Analyze this code and return a JSON object with exactly this structure:

{
    "has_bugs": true/false,
    "bugs": [
        {
            "line": ,
            "issue": "",
            "severity": "low" | "medium" | "high" | "critical",
            "fix": ""
        }
    ],
    "overall_quality": 1-10
}

Code to analyze:
```python
def divide(a, b):
    return a / b
```

Return ONLY valid JSON, no other text."""

5. Prompt Chaining:

# Break complex tasks into steps, each with its own prompt
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

def chain_prompts(user_request: str) -> str:
    """Multi-step reasoning with prompt chaining."""
    
    # Step 1: Understand the request
    understanding = client.chat.completions.create(
        model="llama3.1:8b",
        messages=[{"role": "user", "content": f"""Analyze this request and identify:
1. What is the user asking for?
2. What are the key requirements?
3. What approach should we take?

Request: {user_request}"""}],
    ).choices[0].message.content
    
    # Step 2: Generate solution based on analysis
    solution = client.chat.completions.create(
        model="llama3.1:8b",
        messages=[{"role": "user", "content": f"""Based on this analysis:
{understanding}

Now write the actual code/solution. Be production-ready."""}],
    ).choices[0].message.content
    
    # Step 3: Review and refine
    final = client.chat.completions.create(
        model="llama3.1:8b",
        messages=[{"role": "user", "content": f"""Review this solution for bugs, edge cases, and improvements:
{solution}

Provide the final, corrected version."""}],
    ).choices[0].message.content
    
    return final

result = chain_prompts("Build a rate limiter for a FastAPI endpoint")
print(result)

Production Prompt Templates

# Reusable prompt templates with variables
from string import Template

PROMPT_TEMPLATES = {
    "code_review": Template("""Review this $language code.
Focus on: $focus_areas
Severity threshold: report only $min_severity and above.
Code:
```$language
$code
```
Return findings as a numbered list."""),

    "explain": Template("""Explain $topic to someone with $experience_level experience.
Use $analogy_style analogies.
Keep it under $max_words words.
Include one practical example."""),

    "convert": Template("""Convert this $source_format to $target_format.
Preserve all information. Handle edge cases.
Input:
$input_data"""),
}

# Usage
prompt = PROMPT_TEMPLATES["code_review"].substitute(
    language="python",
    focus_areas="security, performance",
    min_severity="medium",
    code="def login(user, pwd): return db.query(f'SELECT * FROM users WHERE name={user}')",
)
print(prompt)

🏭 Industry Standards

  • System prompts are your most valuable IP — Companies spend months refining system prompts. Treat them like code.
  • Version control your prompts — Track changes like code. A/B test different versions.
  • Temperature for different tasks — 0.0-0.3 for factual/code, 0.5-0.7 for creative, 0.8-1.0 for brainstorming.
  • Few-shot > zero-shot — Always provide 2-3 examples when possible. Dramatically improves consistency.
  • Structured output is mandatory for pipelines — Use JSON mode or outlines for any automated processing.
  • Chain-of-thought for complex reasoning — "Think step by step" improves math/logic accuracy by 30-50%.
  • Prompt injection defense — Always sanitize user input. Never put untrusted text directly in system prompts.

📝 Summary

  • CRAFT framework: Context, Role, Action, Format, Tone
  • Few-shot: Show examples of desired input/output
  • Chain-of-thought: "Think step by step" for complex reasoning
  • Structured output: Force JSON/specific format for automation
  • Prompt chaining: Break complex tasks into sequential prompts
  • Version control, test, and iterate on prompts like code

❌ Beginner Mistakes to Avoid

  • Vague prompts — "Make this better" → specify WHAT aspect to improve and HOW.
  • Too long system prompts — Over 2000 tokens in system prompt wastes context. Be concise.
  • No output format specification — If you don't tell the model the format, it'll choose randomly.
  • Prompt injection vulnerabilities — Never put user input directly into system prompts without sanitization.
  • Not testing with edge cases — Test prompts with adversarial inputs, empty inputs, very long inputs.
