Parameters & Training vs Inference

What does "7 billion parameters" actually mean? What's the difference between training a model and using it? This chapter demystifies these core concepts with simple explanations and real numbers.

🏠 Daily Life Analogy

Parameters = knobs on a mixing board. Imagine a music studio mixing board with 7 billion tiny knobs. Each knob is set to a specific position. Together, all those knob positions produce a particular "sound" (the model's behavior). Training = finding the right position for each knob. Inference = playing music with the knobs already set.

Training vs Inference = Learning to cook vs Actually cooking. Training is the years you spend learning recipes, practicing techniques, and making mistakes. Inference is when you actually cook a meal for someone. Training is slow and expensive; cooking (inference) is relatively fast.

What Are Parameters?

A parameter (also called a "weight") is a single number inside the model that was adjusted during training. Think of it as one tiny piece of learned knowledge.

  • Each parameter is a decimal number like: 0.0234 or -1.457
  • A 7B model has 7,000,000,000 of these numbers
  • Together, they encode everything the model "knows"
  • Stored as a file on disk (typically 14-28 GB for a 7B model)

💡 Size Formula

File size ≈ Parameters × Bytes per parameter
FP32 (full precision): 7B × 4 bytes = 28 GB
FP16 (half precision): 7B × 2 bytes = 14 GB
INT4 (quantized): 7B × 0.5 bytes = 3.5 GB ← This is how you run on a laptop!

Where Do Parameters Live?

Parameters are organized into specific layers inside the Transformer:

ComponentWhat It Stores% of Parameters
Embedding layerToken → vector mapping (vocabulary knowledge)~5%
Attention weightsQ, K, V, Output projection matrices~33%
Feed-forward layersIntermediate processing (knowledge storage)~60%
Layer normsNormalization parameters~1%
Output headFinal prediction layer~1%

Training: How Models Learn

Training is the process of finding the best value for each parameter. Here's how it works:

The Training Loop (Simplified):

  1. Forward pass: Feed text through the model, get a prediction
  2. Calculate loss: Measure how wrong the prediction was
  3. Backward pass: Calculate how each parameter contributed to the error
  4. Update parameters: Nudge each parameter slightly to reduce the error
  5. Repeat billions of times with different text

Key Training Concepts:

ConceptWhat It IsAnalogy
Loss functionMeasures how wrong the model isScore on a test (lower = better)
Learning rateHow big each adjustment step isHow fast you turn the steering wheel
EpochOne full pass through all training dataReading the entire textbook once
Batch sizeHow many examples per update stepHow many practice problems before checking answers
Gradient descentThe algorithm that adjusts parametersRolling a ball downhill to find the lowest valley
OverfittingModel memorizes training data instead of learning patternsMemorizing answers without understanding

Inference: Using the Model

Inference is using a trained model to generate text. It's the "easy" part — the model is frozen (parameters don't change) and just produces output.

Production Code

Inspecting Model Parameters

# See exactly what's inside a model
from transformers import AutoModelForCausalLM
import torch

# Load a small model
model = AutoModelForCausalLM.from_pretrained(
    "microsoft/phi-2",
    torch_dtype=torch.float16,
    device_map="cpu"  # Use CPU for inspection
)

# Count total parameters
total_params = sum(p.numel() for p in model.parameters())
print(f"Total parameters: {total_params:,}")
print(f"That's {total_params / 1e9:.1f}B parameters")

# See parameter breakdown by layer type
for name, param in model.named_parameters():
    if "layers.0" in name:  # Just first layer
        print(f"  {name}: {param.shape} ({param.numel():,} params)")

# Memory calculation
bytes_per_param = 2  # FP16 = 2 bytes
memory_gb = (total_params * bytes_per_param) / (1024**3)
print(f"Model size on disk: {memory_gb:.1f} GB (FP16)")
print(f"VRAM for inference: ~{memory_gb * 1.2:.1f} GB (model + overhead)")
print(f"VRAM for training: ~{memory_gb * 4:.1f} GB (model + gradients + optimizer)")

Simple Training Loop (PyTorch)

# Simplified training loop — this is what happens inside Trainer
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

# In real production, you'd use HuggingFace Trainer or TRL
# This is the underlying concept:

model = AutoModelForCausalLM.from_pretrained("gpt2")
tokenizer = AutoTokenizer.from_pretrained("gpt2")
optimizer = torch.optim.AdamW(model.parameters(), lr=5e-5)

# Training data
texts = [
    "The capital of France is Paris.",
    "Machine learning is a subset of AI.",
]

model.train()  # Enable training mode (activates dropout etc.)

for epoch in range(3):
    total_loss = 0
    for text in texts:
        # Step 1: Tokenize
        inputs = tokenizer(text, return_tensors="pt")
        inputs["labels"] = inputs["input_ids"].clone()

        # Step 2: Forward pass (get loss)
        outputs = model(**inputs)
        loss = outputs.loss  # How wrong the predictions are

        # Step 3: Backward pass (calculate gradients)
        loss.backward()

        # Step 4: Update parameters
        optimizer.step()
        optimizer.zero_grad()

        total_loss += loss.item()

    print(f"Epoch {epoch+1}, Avg Loss: {total_loss/len(texts):.4f}")

model.eval()  # Switch to inference mode
# Now use model.generate() for inference

Inference with Temperature & Sampling

# Different inference strategies affect output quality
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B-Instruct", torch_dtype=torch.float16, device_map="auto")
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

prompt = "Explain quantum computing in one sentence:"
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)

# Greedy decoding — always picks the highest probability token
# Best for: factual Q&A, deterministic outputs
output_greedy = model.generate(**inputs, max_new_tokens=50, do_sample=False)

# Temperature sampling — adds randomness
# Best for: creative writing, diverse outputs
output_creative = model.generate(
    **inputs,
    max_new_tokens=50,
    do_sample=True,
    temperature=0.8,    # Higher = more random (0.1-2.0)
    top_p=0.9,          # Nucleus sampling: only consider top 90% probability tokens
    top_k=50,           # Only consider top 50 tokens at each step
)

# Beam search — explores multiple paths
# Best for: translation, summarization
output_beam = model.generate(
    **inputs,
    max_new_tokens=50,
    num_beams=4,        # Explore 4 candidates at each step
    do_sample=False,
)

for name, output in [("Greedy", output_greedy), ("Creative", output_creative), ("Beam", output_beam)]:
    text = tokenizer.decode(output[0][inputs["input_ids"].shape[-1]:], skip_special_tokens=True)
    print(f"{name}: {text}\n")

🏭 Industry Standards

  • Pre-training — Done by Meta, Google, etc. on 10-15 trillion tokens. Costs $1M-$100M+. You'll never do this.
  • Fine-tuning — What YOU'll do. Takes an existing model and adapts it. Costs $10-$10,000.
  • Inference optimization — Where most engineering time goes. Reducing latency, cost, and improving throughput.
  • AdamW optimizer — Standard optimizer for LLM training (uses ~3x model memory for optimizer states)
  • Mixed precision (BF16) — Industry standard for training. Saves memory while maintaining quality.
  • Learning rate schedulers — Cosine schedule with warmup is standard (start low, go high, decay).
  • Gradient accumulation — Simulate larger batch sizes on limited hardware.

📝 Summary

  • Parameters = billions of numbers storing model knowledge (7B model = 7 billion numbers)
  • File size ≈ Parameters × 2 bytes (FP16) or × 0.5 bytes (INT4 quantized)
  • Training = adjusting all parameters to minimize prediction errors. Expensive, slow, done once.
  • Inference = using the frozen model to generate text. Cheap, fast, done millions of times.
  • Training needs ~4x more memory than inference (gradients + optimizer states)
  • You'll almost never pre-train from scratch — you'll fine-tune existing models

🧠 Mental Model

TRAINING (expensive, one-time):
Data → Model → Prediction → Wrong! → Adjust parameters → Repeat 1 trillion times

INFERENCE (cheap, per-request):
User prompt → Frozen Model → Next token → Next token → ... → Response

Training = building the factory. Inference = running the factory.

❌ Beginner Mistakes to Avoid

  • Thinking you need to train from scratch — 99.9% of projects use pre-trained models and fine-tune them.
  • Ignoring memory math — A 70B model needs ~140GB VRAM just for inference. Training needs ~560GB.
  • Not using model.eval() — Forgetting to switch to eval mode during inference causes different behavior (dropout still active).
  • Using temperature=0 for everything — Greedy decoding is great for factual answers but terrible for creative tasks.
  • Confusing model size with intelligence — A well-fine-tuned 8B beats a raw 70B at specific tasks.
