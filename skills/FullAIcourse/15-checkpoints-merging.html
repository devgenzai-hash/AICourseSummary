Checkpoints & Model Merging

How to save your training progress, pick the best checkpoint, merge LoRA adapters into base models, and even combine multiple fine-tuned models into one super-model.

🏠 Daily Life Analogy

Checkpoints = save points in a video game. You save your progress at regular intervals. If something goes wrong (model gets worse), you can reload a previous save.

LoRA merging = gluing a lens filter permanently onto a camera. The filter (LoRA) is separate, but merging makes it part of the camera (base model) — faster to use, no extra step.

Model merging = mixing paint colors. Blue model (good at code) + Yellow model (good at writing) = Green model (good at both). Sometimes the mix works, sometimes it becomes mud.

Working with Checkpoints

Understanding Training Checkpoints:

# Checkpoints are saved during training at regular intervals
# A typical training run produces:
# ./output/
#   checkpoint-100/   ← Step 100
#   checkpoint-200/   ← Step 200
#   checkpoint-300/   ← Step 300 (maybe this is the best!)
#   checkpoint-400/   ← Step 400 (started overfitting)

from transformers import TrainingArguments

# Configure checkpoint saving
training_args = TrainingArguments(
    output_dir="./output",
    save_strategy="steps",       # Save every N steps
    save_steps=100,              # Save every 100 steps
    save_total_limit=3,          # Keep only last 3 checkpoints (saves disk)
    load_best_model_at_end=True, # Auto-select best checkpoint at end
    evaluation_strategy="steps",
    eval_steps=100,
    metric_for_best_model="eval_loss",  # Lower is better
)

Resuming from a Checkpoint:

# If training crashes or you want to continue from a checkpoint
from trl import SFTTrainer

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    tokenizer=tokenizer,
)

# Resume from latest checkpoint
trainer.train(resume_from_checkpoint=True)

# Or from a specific checkpoint
trainer.train(resume_from_checkpoint="./output/checkpoint-200")

Merging LoRA Adapters

After training with LoRA/QLoRA, you have a small adapter file (~50MB). For deployment, you merge it into the base model for faster inference.

# Merge LoRA adapter into base model
from peft import PeftModel, AutoPeftModelForCausalLM
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

# Method 1: Using AutoPeftModelForCausalLM (easiest)
model = AutoPeftModelForCausalLM.from_pretrained(
    "./my-qlora-adapter",       # Your trained adapter directory
    torch_dtype=torch.float16,
    device_map="auto",
)
merged_model = model.merge_and_unload()  # Merge adapter into base

# Save the full merged model
merged_model.save_pretrained("./merged-model")
tokenizer = AutoTokenizer.from_pretrained("./my-qlora-adapter")
tokenizer.save_pretrained("./merged-model")

print("✅ Merged! Now you can deploy without PEFT library.")

# Method 2: Manual (more control)
base_model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B-Instruct",
    torch_dtype=torch.float16,
    device_map="auto"
)
model = PeftModel.from_pretrained(base_model, "./my-qlora-adapter")
model = model.merge_and_unload()
model.save_pretrained("./merged-model")

Model Merging (Combining Models)

Model merging combines parameters from multiple fine-tuned models into one model that has capabilities of all of them. It's like creating a superhero team in one body.

Merging Methods:

MethodHow It WorksQualityWhen to Use
Linear (LERP)Weighted average of parametersGoodCombining 2 similar models
SLERPSpherical interpolationBetterSmoother blending of 2 models
TIESTrim, Elect Sign, MergeGreatMerging 3+ models, reduces conflicts
DAREDrop And REscaleGreatSimilar to TIES, newer approach
Model StockGeometric mean of fine-tuned modelsGoodMany models, conservative merge

Merging with mergekit:

# mergekit is the industry standard for model merging
# pip install mergekit

# Create a merge config (YAML):
# merge_config.yaml
models:
  - model: meta-llama/Llama-3.1-8B-Instruct  # Base
    parameters:
      weight: 0.5
  - model: ./my-code-model  # Fine-tuned for code
    parameters:
      weight: 0.3
  - model: ./my-writing-model  # Fine-tuned for writing
    parameters:
      weight: 0.2

merge_method: linear  # or: slerp, ties, dare_ties
dtype: float16
# Run the merge
# mergekit-yaml merge_config.yaml ./merged-output --cuda

# For SLERP (2 models only, usually best quality)
# slerp_config.yaml
models:
  - model: ./model-A
  - model: ./model-B

merge_method: slerp
parameters:
  t: 0.5  # 0.0 = all A, 1.0 = all B, 0.5 = equal blend
dtype: float16

Merge in Python:

# Simple linear merge in Python (for understanding)
import torch
from transformers import AutoModelForCausalLM

def linear_merge(model_paths: list, weights: list, output_path: str):
    """Merge multiple models with weighted average."""
    assert len(model_paths) == len(weights)
    assert abs(sum(weights) - 1.0) < 0.01

    # Load first model as base
    merged = AutoModelForCausalLM.from_pretrained(
        model_paths[0], torch_dtype=torch.float16
    )
    merged_state = merged.state_dict()

    # Weighted sum of all models
    for key in merged_state:
        merged_state[key] = merged_state[key] * weights[0]

    for path, weight in zip(model_paths[1:], weights[1:]):
        model = AutoModelForCausalLM.from_pretrained(path, torch_dtype=torch.float16)
        state = model.state_dict()
        for key in merged_state:
            merged_state[key] += state[key] * weight
        del model  # Free memory

    merged.load_state_dict(merged_state)
    merged.save_pretrained(output_path)
    print(f"✅ Merged model saved to {output_path}")

# Usage: 60% base + 40% fine-tuned
linear_merge(
    ["meta-llama/Llama-3.1-8B-Instruct", "./my-finetuned"],
    [0.6, 0.4],
    "./merged-output"
)

Full Deployment Flow

🧠 From Training to Deployment

1. Train with QLoRA → adapter.safetensors (50MB)
2. Pick best checkpoint → checkpoint-300/
3. Merge adapter into base model → merged-model/ (14GB)
4. (Optional) Merge with other models → super-model/
5. Quantize to GGUF Q4_K_M → model.gguf (4GB)
6. Deploy with Ollama/vLLM → Ready!

🏭 Industry Standards

  • Always merge LoRA before deploying — Un-merged adapters add latency and complexity.
  • mergekit is the standard tool — Used by the entire open-source community for model merging.
  • SLERP for 2 models, TIES/DARE for 3+ — These methods handle conflicts between models better.
  • Open LLM Leaderboard — Many top models on HuggingFace are merges of other models.
  • Save checkpoints frequently — Disk is cheap, retraining is expensive. Save every 100-500 steps.
  • SafeTensors format — Industry standard for saving model weights (safer than pickle, faster to load).
  • Push to HuggingFace Hub — Standard way to share models. Use model.push_to_hub().

📝 Summary

  • Checkpoints = snapshots saved during training. Use load_best_model_at_end=True.
  • LoRA merging = combining adapter into base model for deployment. Use merge_and_unload().
  • Model merging = combining multiple fine-tuned models into one. Use mergekit.
  • Full pipeline: Train → Best checkpoint → Merge LoRA → (Optional: Model merge) → Quantize → Deploy
  • SLERP for 2 models, TIES/DARE for 3+ models

❌ Beginner Mistakes to Avoid

  • Not saving checkpoints — If training crashes at epoch 3, you lose everything. Save every 100-500 steps.
  • Deploying un-merged LoRA — Works but is slower. Always merge for production.
  • Merging incompatible models — You can only merge models with the SAME architecture and tokenizer.
  • Not testing after merge — Model merges can sometimes produce garbage. Always evaluate.
  • Keeping all checkpoints — Use save_total_limit=3 to avoid filling your disk (each checkpoint = model size).
