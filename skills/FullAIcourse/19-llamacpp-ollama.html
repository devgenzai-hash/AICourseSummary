llama.cpp & Ollama

Run AI models 100% locally on your computer — no internet, no API keys, no data leaving your machine. This is the foundation of local AI and privacy-first inference.

🏠 Daily Life Analogy

llama.cpp = a homemade espresso machine. You build it from parts, it's powerful and customizable, but takes effort to set up. Great for enthusiasts and developers.

Ollama = a Nespresso machine. Press one button, get great coffee. It uses llama.cpp under the hood, but wraps it in the simplest possible interface. Great for everyone.

Ollama: The Easiest Way

Getting Started (2 minutes):

# Install Ollama
# Windows/Mac: Download from https://ollama.com
# Linux: curl -fsSL https://ollama.com/install.sh | sh

# Pull and run a model (one command!)
# ollama run llama3.1:8b

# That's it! You're now chatting with an 8B model locally.
# No API key. No internet. No data leaving your machine.

Essential Ollama Commands:

# List available models
# ollama list

# Pull models (downloads to ~/.ollama/models)
# ollama pull llama3.1:8b           # Default Q4_K_M quantization
# ollama pull llama3.1:70b          # Large model (needs 48GB+)
# ollama pull qwen2.5:7b            # Chinese/English bilingual
# ollama pull codestral:22b         # Code-specialized
# ollama pull nomic-embed-text      # Embedding model

# Run with custom parameters
# ollama run llama3.1:8b --verbose  # Show token/sec stats

# Set system prompt
# ollama run llama3.1:8b "You are a pirate. Respond accordingly."

# Remove a model
# ollama rm llama3.1:8b

# Show model info
# ollama show llama3.1:8b

Using Ollama with Python (OpenAI-compatible API):

# Ollama exposes an OpenAI-compatible API on localhost:11434
# pip install openai
from openai import OpenAI

# Connect to local Ollama
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",  # Required but ignored
)

# Chat completion (same API as OpenAI!)
response = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[
        {"role": "system", "content": "You are a helpful coding assistant."},
        {"role": "user", "content": "Write a Python function to reverse a linked list"},
    ],
    temperature=0.7,
    max_tokens=500,
)
print(response.choices[0].message.content)

# Streaming (tokens appear as generated)
stream = client.chat.completions.create(
    model="llama3.1:8b",
    messages=[{"role": "user", "content": "Explain recursion simply"}],
    stream=True,
)
for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

Ollama Native API:

# Using Ollama's native Python library
# pip install ollama
import ollama

# Simple chat
response = ollama.chat(
    model="llama3.1:8b",
    messages=[{"role": "user", "content": "What is machine learning?"}]
)
print(response["message"]["content"])

# Generate embeddings
embedding = ollama.embed(model="nomic-embed-text", input="Hello world")
print(f"Embedding dimension: {len(embedding['embeddings'][0])}")

# Streaming
for chunk in ollama.chat(
    model="llama3.1:8b",
    messages=[{"role": "user", "content": "Write a poem"}],
    stream=True,
):
    print(chunk["message"]["content"], end="")

PARAMETER temperature 0.3
PARAMETER num_ctx 8192
PARAMETER top_p 0.9

# Set system prompt

proper error handling. Always explain your code with comments. Follow PEP 8."""

# Create the custom model:
# ollama create python-expert -f Modelfile
# ollama run python-expert

llama.cpp: Maximum Control

Using llama-cpp-python:

# pip install llama-cpp-python
# For GPU support: CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python
from llama_cpp import Llama

# Load a GGUF model
llm = Llama(
    model_path="./models/llama-3.1-8b-instruct-Q4_K_M.gguf",
    n_ctx=8192,          # Context window
    n_threads=8,         # CPU threads (set to your core count)
    n_gpu_layers=-1,     # -1 = offload ALL layers to GPU
    verbose=False,
)

# Chat completion (OpenAI-compatible)
output = llm.create_chat_completion(
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Explain Docker in simple terms"},
    ],
    max_tokens=500,
    temperature=0.7,
    top_p=0.9,
)
print(output["choices"][0]["message"]["content"])

# Streaming
for chunk in llm.create_chat_completion(
    messages=[{"role": "user", "content": "Write a haiku about AI"}],
    stream=True,
):
    delta = chunk["choices"][0]["delta"]
    if "content" in delta:
        print(delta["content"], end="")

Running as an OpenAI-compatible Server:

# Start llama.cpp as a server (same API as OpenAI)
# python -m llama_cpp.server --model ./models/model.gguf --n_gpu_layers -1 --port 8000

# Now any OpenAI-compatible code works!
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="dummy")
response = client.chat.completions.create(
    model="local-model",
    messages=[{"role": "user", "content": "Hello!"}]
)
print(response.choices[0].message.content)

🏭 Industry Standards

  • Ollama is the de-facto standard for local AI — Used by developers, CI/CD pipelines, and local AI apps.
  • OpenAI-compatible API is key — Write code once, swap between Ollama/OpenAI/vLLM with one config change.
  • GGUF is the universal local format — All local tools (Ollama, llama.cpp, LM Studio) use GGUF.
  • Q4_K_M is the default quantization — Ollama uses it by default. Best quality/size tradeoff.
  • GPU offloading matters — Even partial GPU offloading (some layers on GPU) dramatically improves speed.
  • Context window affects memory — Setting n_ctx higher uses more RAM. Only set what you need.

📝 Summary

  • Ollama = simplest way to run models locally. One command to start.
  • llama.cpp = maximum control. Use llama-cpp-python for Python apps.
  • Both expose OpenAI-compatible APIs — code is portable between providers.
  • Modelfile = customize model behavior, system prompt, parameters.
  • Everything runs locally — no data sent to the cloud, no API costs.

❌ Beginner Mistakes to Avoid

  • Not using GPU offloading — CPU-only inference is 5-20x slower. Set n_gpu_layers=-1 if you have a GPU.
  • Setting context too large — n_ctx=128000 will eat all your RAM. Start with 4096, increase as needed.
  • Running Ollama without checking it started — Run ollama serve first, then ollama run in another terminal.
  • Using base models instead of instruct — Always use "-instruct" or "-chat" variants for conversation.
  • Hardcoding OpenAI URLs — Use environment variables for base_url so you can switch providers easily.
