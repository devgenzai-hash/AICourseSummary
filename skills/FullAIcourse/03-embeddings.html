Embeddings

Embeddings are how AI understands meaning. They convert words, sentences, and documents into lists of numbers where similar things are close together. This is the foundation of search, RAG, and recommendation systems.

🏠 Daily Life Analogy

Embeddings are like GPS coordinates for meaning.

Imagine a magical map where every word has a location. "King" and "Queen" are close together (both royalty). "Dog" and "Cat" are close (both pets). "Dog" and "Algebra" are far apart (unrelated). An embedding is essentially a GPS coordinate — but instead of 2 dimensions (latitude, longitude), it uses 768 or 1536 dimensions to capture every nuance of meaning.

What Are Embeddings?

An embedding is a list of numbers (a vector) that represents the meaning of a piece of text. For example:

# These aren't real values, but show the concept
"cat"   → [0.2, 0.8, -0.1, 0.5, ...]  # 1536 numbers
"dog"   → [0.3, 0.7, -0.2, 0.4, ...]  # very similar to "cat"!
"car"   → [-0.5, 0.1, 0.9, -0.3, ...]  # very different from "cat"

The key property: similar meanings = similar numbers. We measure similarity using cosine similarity (a math formula that gives a score from -1 to 1, where 1 = identical meaning).

Why Embeddings Matter:

Use CaseHow Embeddings Help
Semantic SearchFind documents by meaning, not just keywords
RAGRetrieve relevant context for AI to use
Recommendations"Users who liked X also liked Y" (similar embeddings)
ClusteringGroup similar documents/topics automatically
DeduplicationFind near-duplicate content even if worded differently
ClassificationCategorize text by comparing to category embeddings

How Embeddings Work

An embedding model is a neural network trained specifically to compress text meaning into a fixed-size vector. The training process:

  1. Show similar text pairs: "The cat sat on the mat" ↔ "A feline rested on the rug"
  2. Train the model to give them similar vectors
  3. Show dissimilar pairs: "The cat sat on the mat" ↔ "Stock prices fell today"
  4. Train the model to give them different vectors
  5. After billions of examples, the model learns what "meaning" is

Production Code

OpenAI Embeddings (Industry Standard for Production)

# pip install openai numpy
from openai import OpenAI
import numpy as np

client = OpenAI()

def get_embedding(text, model="text-embedding-3-small"):
    """Get embedding vector for a text string."""
    response = client.embeddings.create(
        input=text,
        model=model
    )
    return response.data[0].embedding

def cosine_similarity(a, b):
    """Calculate similarity between two vectors (0 to 1)."""
    a, b = np.array(a), np.array(b)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Compare sentences by meaning
sentences = [
    "The cat sat on the mat",
    "A feline rested on the rug",      # Similar meaning!
    "Stock prices rose sharply today",  # Different meaning
]

embeddings = [get_embedding(s) for s in sentences]

# Compare similarities
print(f"'cat/mat' vs 'feline/rug': {cosine_similarity(embeddings[0], embeddings[1]):.3f}")
print(f"'cat/mat' vs 'stocks':      {cosine_similarity(embeddings[0], embeddings[2]):.3f}")
# Output: ~0.85 (very similar) vs ~0.15 (very different)

Free Local Embeddings with Sentence Transformers

# pip install sentence-transformers
from sentence_transformers import SentenceTransformer
import numpy as np

# Load model (downloads ~90MB first time, then cached)
model = SentenceTransformer("all-MiniLM-L6-v2")

# Embed multiple texts at once (much faster than one-by-one)
texts = [
    "How to train a machine learning model",
    "Steps for fine-tuning an AI system",
    "Best Italian restaurants in New York",
]

embeddings = model.encode(texts)
print(f"Shape: {embeddings.shape}")  # (3, 384) — 3 texts, 384 dimensions each

# Semantic search: find most similar to a query
query = "How do I fine-tune an LLM?"
query_embedding = model.encode([query])

# Calculate similarities
similarities = np.dot(embeddings, query_embedding.T).flatten()
for text, score in sorted(zip(texts, similarities), key=lambda x: x[1], reverse=True):
    print(f"  {score:.3f} | {text}")
# "Steps for fine-tuning" will rank highest!

Production Semantic Search Engine

# A complete mini search engine using embeddings
from sentence_transformers import SentenceTransformer
import numpy as np
import json

class SemanticSearchEngine:
    """Simple but production-ready semantic search."""

    def __init__(self, model_name="all-MiniLM-L6-v2"):
        self.model = SentenceTransformer(model_name)
        self.documents = []
        self.embeddings = None

    def add_documents(self, docs: list[str]):
        """Index a list of documents."""
        self.documents.extend(docs)
        # Batch encode for speed
        self.embeddings = self.model.encode(
            self.documents,
            show_progress_bar=True,
            batch_size=32,
            normalize_embeddings=True  # For cosine similarity
        )

    def search(self, query: str, top_k: int = 5) -> list[dict]:
        """Find top_k most relevant documents for a query."""
        query_emb = self.model.encode(
            [query], normalize_embeddings=True
        )
        # Cosine similarity via dot product (embeddings are normalized)
        scores = np.dot(self.embeddings, query_emb.T).flatten()
        top_indices = np.argsort(scores)[::-1][:top_k]

        results = []
        for idx in top_indices:
            results.append({
                "document": self.documents[idx],
                "score": float(scores[idx]),
                "index": int(idx)
            })
        return results

# Usage
engine = SemanticSearchEngine()
engine.add_documents([
    "Python is a programming language used for AI",
    "JavaScript runs in web browsers",
    "Fine-tuning adapts a pretrained model to new tasks",
    "Docker containers package applications",
    "Neural networks learn patterns from data",
])

results = engine.search("How do I customize an AI model?")
for r in results:
    print(f"  {r['score']:.3f} | {r['document']}")

🏭 Industry Standards

  • OpenAI embeddings — Most companies start here for simplicity and quality ($0.02 per 1M tokens)
  • Normalize embeddings — Always normalize for cosine similarity; dot product on normalized vectors = cosine similarity
  • Batch processing — Never embed one document at a time in production; batch for 10-100x speedup
  • Vector databases — For >10K documents, use ChromaDB/Pinecone/Qdrant instead of numpy (covered in Chapter 23)
  • Embedding dimension tradeoff — Higher dimensions = better quality but more storage/compute cost
  • Cache embeddings — Store computed embeddings; never re-embed the same text twice
  • Chunk before embedding — Embed paragraphs/chunks, not entire documents (embeddings lose info for very long text)

The Famous "King - Man + Woman = Queen" Example

Embeddings capture relationships between concepts. The classic example:

# Conceptually (actual vectors are more complex)
king   = [0.9, 0.8, 0.1]  # royalty + male
man    = [0.0, 0.8, 0.1]  # male
woman  = [0.0, 0.1, 0.8]  # female

result = king - man + woman
# result ≈ [0.9, 0.1, 0.8] ≈ "queen" (royalty + female)

This shows that embeddings don't just memorize words — they learn relationships and concepts.

📝 Summary

  • Embeddings convert text → list of numbers representing meaning
  • Similar meanings = similar number patterns (close in vector space)
  • Measured with cosine similarity (1 = identical, 0 = unrelated)
  • Used for: search, RAG, recommendations, clustering, deduplication
  • Typical sizes: 384 (fast/free) to 3072 (highest quality) dimensions
  • Production: OpenAI embeddings or open-source sentence-transformers

🧠 Mental Model

"cat" → [0.2, 0.8, -0.1, ...] → 📍 (GPS coordinate in meaning-space)

Similar meaning = nearby coordinates
Different meaning = far-apart coordinates

Embedding = GPS for meaning. Just as GPS tells you two restaurants are near each other geographically, embeddings tell you two sentences are near each other in meaning.

❌ Beginner Mistakes to Avoid

  • Embedding entire documents — Long text loses nuance. Chunk into paragraphs first.
  • Mixing embedding models — You can't compare embeddings from different models. They live in different "coordinate systems".
  • Not normalizing — If vectors aren't normalized, cosine similarity gives wrong results.
  • Re-embedding unchanged text — Same text always gives same embedding. Cache them!
  • Using word embeddings for sentences — Use sentence-transformers, not Word2Vec, for sentence/paragraph meaning.
