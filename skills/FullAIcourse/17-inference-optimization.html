Inference Optimization

How do companies serve millions of AI requests per second? Batching, speculative decoding, continuous batching, and more. The techniques that make production AI economically viable.

🏠 Daily Life Analogy

Batching = a bus vs a taxi. A taxi (single request) is fast for one person but expensive. A bus (batch) carries 50 people at once — each person's cost is 1/50th. The GPU is the vehicle; batching fills it up.

Speculative decoding = writing with a pencil first. You quickly draft sentences in pencil (small model), then check them with a fine pen (big model). If the draft is right (usually is), you save time. If wrong, erase and redo just that part.

Continuous batching = a conveyor belt sushi restaurant. New plates (requests) join the belt at any time, and finished plates leave whenever they're done. No waiting for everyone to finish together.

Batching Strategies

Static Batching (Simple):

# Static batching: Process multiple requests together
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "meta-llama/Llama-3.1-8B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, device_map="auto")

# Process 4 prompts at once (static batch)
prompts = [
    "What is Python?",
    "Explain gravity simply.",
    "Write a haiku about coding.",
    "What is 2+2?",
]

# Pad to same length for batching
tokenizer.pad_token = tokenizer.eos_token
inputs = tokenizer(prompts, return_tensors="pt", padding=True).to(model.device)

# Generate all at once (much faster than 4 separate calls!)
outputs = model.generate(**inputs, max_new_tokens=100)

for i, output in enumerate(outputs):
    text = tokenizer.decode(output, skip_special_tokens=True)
    print(f"Response {i+1}: {text}\n")

# Problem: Short responses must wait for the longest to finish!

Continuous Batching (Production):

# Continuous batching: New requests join as others finish
# This is what vLLM/TGI do internally

import asyncio
from dataclasses import dataclass
from typing import Optional

@dataclass
class Request:
    prompt: str
    max_tokens: int
    generated_tokens: int = 0
    output: str = ""
    done: bool = False

class ContinuousBatcher:
    """Simplified continuous batching scheduler."""
    
    def __init__(self, model, max_batch_size=32):
        self.model = model
        self.max_batch_size = max_batch_size
        self.waiting_queue = []
        self.active_batch = []
    
    def add_request(self, request: Request):
        """New request joins immediately (no waiting for batch to finish)."""
        self.waiting_queue.append(request)
    
    def step(self):
        """One generation step for all active requests."""
        # Remove finished requests
        self.active_batch = [r for r in self.active_batch if not r.done]
        
        # Add waiting requests to fill batch
        while self.waiting_queue and len(self.active_batch) < self.max_batch_size:
            self.active_batch.append(self.waiting_queue.pop(0))
        
        if not self.active_batch:
            return
        
        # Generate ONE token for all active requests simultaneously
        # (In reality, this is a single forward pass through the model)
        for req in self.active_batch:
            # next_token = model.forward(req.current_tokens)  # simplified
            req.generated_tokens += 1
            if req.generated_tokens >= req.max_tokens:
                req.done = True

# Key insight: Short responses leave immediately,
# freeing space for new requests to join mid-batch!

Speculative Decoding

Use a small, fast model to "guess" multiple tokens ahead, then verify with the big model in one forward pass.

# Speculative Decoding: 2-3x faster generation!
# Small model drafts, big model verifies

class SpeculativeDecoder:
    """Speculative decoding: draft + verify pattern."""
    
    def __init__(self, draft_model, target_model, num_speculative=5):
        self.draft = draft_model    # Small/fast (e.g., 1B model)
        self.target = target_model  # Large/accurate (e.g., 70B model)
        self.num_speculative = num_speculative  # Tokens to draft ahead
    
    def generate_step(self, context):
        """Generate tokens using speculative decoding."""
        
        # Step 1: Draft model quickly generates N tokens
        draft_tokens = []
        for _ in range(self.num_speculative):
            token = self.draft.predict_next(context)  # Fast!
            draft_tokens.append(token)
            context = context + [token]
        
        # Step 2: Target model verifies ALL draft tokens in ONE pass
        # (One forward pass for N tokens vs N forward passes normally!)
        verified = self.target.verify_batch(context, draft_tokens)
        
        # Step 3: Accept tokens until first disagreement
        accepted = []
        for draft, target_agrees in zip(draft_tokens, verified):
            if target_agrees:
                accepted.append(draft)  # Draft was correct!
            else:
                break  # Stop at first wrong token
        
        return accepted  # Usually 3-4 out of 5 are accepted!

# With transformers (built-in support):
from transformers import AutoModelForCausalLM, AutoTokenizer

# Load both models
target = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-70B-Instruct")
draft = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-70B-Instruct")
inputs = tokenizer("Explain quantum computing", return_tensors="pt")

# Speculative decoding with assistant model
outputs = target.generate(
    **inputs,
    max_new_tokens=200,
    assistant_model=draft,  # ← This enables speculative decoding!
)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

Other Optimization Techniques

Token Streaming:

# Streaming: Show tokens as they're generated (better UX)
from transformers import TextIteratorStreamer
from threading import Thread

streamer = TextIteratorStreamer(tokenizer, skip_special_tokens=True)

# Generate in a thread so we can stream output
generation_kwargs = {
    "input_ids": inputs["input_ids"],
    "max_new_tokens": 200,
    "streamer": streamer,
}
thread = Thread(target=model.generate, kwargs=generation_kwargs)
thread.start()

# Print tokens as they arrive (like ChatGPT does)
for text in streamer:
    print(text, end="", flush=True)

Structured Generation (Constrained Decoding):

# Force model to output valid JSON using outlines
# pip install outlines
import outlines

model = outlines.models.transformers("meta-llama/Llama-3.1-8B-Instruct")

# Define JSON schema
schema = {
    "type": "object",
    "properties": {
        "name": {"type": "string"},
        "age": {"type": "integer"},
        "skills": {"type": "array", "items": {"type": "string"}}
    },
    "required": ["name", "age", "skills"]
}

# Model is FORCED to output valid JSON matching this schema
generator = outlines.generate.json(model, schema)
result = generator("Create a developer profile for a senior Python engineer")
print(result)
# {"name": "Alex Chen", "age": 32, "skills": ["Python", "FastAPI", "ML"]}

Measuring Performance:

# Benchmark your inference setup
import time
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

class InferenceBenchmark:
    """Measure key inference performance metrics."""
    
    def __init__(self, model, tokenizer):
        self.model = model
        self.tokenizer = tokenizer
    
    def benchmark(self, prompt: str, max_new_tokens: int = 100, num_runs: int = 5):
        """Run benchmark and report metrics."""
        inputs = self.tokenizer(prompt, return_tensors="pt").to(self.model.device)
        input_length = inputs["input_ids"].shape[1]
        
        ttfts = []
        tps_list = []
        
        for _ in range(num_runs):
            # Measure TTFT (Time to First Token)
            start = time.perf_counter()
            
            with torch.no_grad():
                outputs = self.model.generate(
                    **inputs,
                    max_new_tokens=max_new_tokens,
                    do_sample=False,
                )
            
            total_time = time.perf_counter() - start
            output_tokens = outputs.shape[1] - input_length
            
            # Approximate TTFT (first token out of total)
            ttft = total_time / output_tokens  # Simplified
            tps = output_tokens / total_time
            
            ttfts.append(ttft)
            tps_list.append(tps)
        
        # Report
        print(f"📊 Inference Benchmark Results:")
        print(f"   Input tokens:  {input_length}")
        print(f"   Output tokens: {output_tokens}")
        print(f"   Avg TPS:       {sum(tps_list)/len(tps_list):.1f} tokens/sec")
        print(f"   Avg TTFT:      {sum(ttfts)/len(ttfts)*1000:.0f} ms")
        print(f"   GPU Memory:    {torch.cuda.max_memory_allocated()/1e9:.1f} GB")

# Usage
bench = InferenceBenchmark(model, tokenizer)
bench.benchmark("Explain the theory of relativity in simple terms")

🏭 Industry Standards

  • vLLM or TGI for production serving — Never use raw transformers.generate() in production.
  • Continuous batching is the default — All production systems use it. Static batching is only for benchmarks.
  • Streaming is expected — Users expect to see tokens appear immediately, like ChatGPT.
  • Target: 30+ TPS per user — Faster than reading speed. Below 10 TPS feels sluggish.
  • Speculative decoding for large models — Used by OpenAI, Anthropic, Google for their biggest models.
  • Structured output with Outlines/LMFE — Guaranteed valid JSON without retry loops.
  • Benchmark before and after every change — Measure TTFT, TPS, throughput, memory.

📝 Summary

  • Batching = process multiple requests simultaneously to maximize GPU utilization
  • Continuous batching = requests join/leave the batch dynamically (vLLM/TGI)
  • Speculative decoding = small model drafts, big model verifies (2-3x faster)
  • Streaming = show tokens as they generate (better UX)
  • Structured output = force valid JSON/format using constrained decoding
  • Key metrics: TTFT, TPS, Throughput, P99 latency

❌ Beginner Mistakes to Avoid

  • Using transformers.generate() in production — It's fine for testing, terrible for serving. Use vLLM or TGI.
  • Not streaming responses — Makes the app feel slow even if the model is fast. Always stream.
  • Ignoring TTFT — Users notice the delay before the first token more than generation speed.
  • Retry loops for JSON — If you need structured output, use outlines/LMFE, not "try again if JSON is invalid".
  • Not measuring before optimizing — Profile first, then optimize the actual bottleneck.
