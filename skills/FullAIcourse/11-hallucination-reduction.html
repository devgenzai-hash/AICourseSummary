Hallucination Reduction & Grounding

AI models confidently say wrong things. This chapter covers why hallucination happens, how to detect it, and production techniques to minimize it — the #1 problem in deployed AI systems.

🏠 Daily Life Analogy

Hallucination = a confident person who makes stuff up. Imagine asking someone a question and they always give an answer — even when they have no idea. They never say "I don't know." They just confidently invent plausible-sounding facts.

Grounding = requiring receipts. "Don't just tell me the answer — show me WHERE you found it." Like a student who must cite sources for every claim.

What Is Hallucination?

Hallucination = when a model generates text that is fluent and confident but factually incorrect or completely fabricated.

Types of Hallucination:

TypeExampleDanger Level
Factual"The Eiffel Tower is in London" (completely wrong fact)High
FabricationInventing a research paper that doesn't existVery High
ConflationMixing details from two different topics togetherMedium
Outdated"The current president is..." (from training data cutoff)Medium
NumericWrong statistics, dates, prices, measurementsHigh
Attribution"According to [source]..." when source doesn't say thatVery High

Why Models Hallucinate

  • They predict likely tokens, not true tokens. "Paris is the capital of..." → model predicts next likely word based on training patterns.
  • No connection to reality. Models don't "look up" facts. They pattern-match from training data.
  • Training on the internet. Internet has wrong information too. The model learned some of it.
  • Pressure to always answer. Models are trained to be helpful, not to say "I don't know."
  • Rare topics = more hallucination. Less training data on a topic = model fills gaps with plausible guesses.

Reduction Techniques

1. RAG (Retrieval-Augmented Generation)

The most effective technique. Give the model actual documents to reference.

# RAG: Ground answers in retrieved documents
from openai import OpenAI

client = OpenAI()

def answer_with_rag(question: str, retrieved_docs: list[str]) -> str:
    """Answer a question using only the provided documents."""

    context = "\n\n---\n\n".join(retrieved_docs)

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": """You are a helpful assistant. Answer questions based ONLY on the provided context.

RULES:
- If the answer is in the context, provide it with a citation [Doc X].
- If the answer is NOT in the context, say "I don't have enough information to answer this."
- NEVER make up information not found in the context.
- Quote relevant passages when possible."""},
            {"role": "user", "content": f"Context:\n{context}\n\nQuestion: {question}"}
        ],
        temperature=0.1  # Low temperature = less creative = less hallucination
    )
    return response.choices[0].message.content

# Example usage
docs = [
    "Our refund policy allows returns within 30 days of purchase.",
    "Shipping takes 3-5 business days for domestic orders."
]
answer = answer_with_rag("What is the refund policy?", docs)
print(answer)

2. Prompt Engineering for Factuality

# Prompting techniques that reduce hallucination

factual_system_prompt = """You are a factual assistant. Follow these rules strictly:

1. ONLY state facts you are highly confident about.
2. If you're unsure, say "I'm not certain about this, but..."
3. If you don't know, say "I don't have reliable information about this."
4. Distinguish between facts and opinions clearly.
5. When providing statistics or dates, qualify with "approximately" if unsure.
6. Never invent citations, URLs, or paper titles.
7. If asked about events after your training cutoff, state your limitations."""

# Chain-of-thought prompting (reduces hallucination by making model "think")
cot_prompt = """Before answering, think through this step by step:
1. What do I know about this topic from my training?
2. How confident am I (high/medium/low)?  
3. Are there aspects I'm uncertain about?

Then provide your answer, clearly marking any uncertain parts."""

3. Self-Consistency Check

# Generate multiple answers and check if they agree
from openai import OpenAI
from collections import Counter

client = OpenAI()

def self_consistency_check(question: str, n_samples: int = 5) -> dict:
    """Generate multiple answers and check agreement."""
    answers = []

    for _ in range(n_samples):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": question}],
            temperature=0.7  # Some variation to get different answers
        )
        answers.append(response.choices[0].message.content)

    # Check agreement using another LLM call
    check_prompt = f"""Given these {n_samples} answers to the question "{question}":

{chr(10).join(f'Answer {i+1}: {a}' for i, a in enumerate(answers))}

Do all answers agree on the key facts? 
Respond with:
- CONSISTENT: if all answers agree on the main facts
- INCONSISTENT: if answers contradict each other (likely hallucination)
- PARTIALLY CONSISTENT: if they mostly agree but differ on details"""

    check = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": check_prompt}],
        temperature=0
    )

    return {
        "answers": answers,
        "consistency": check.choices[0].message.content,
        "best_answer": answers[0]  # Use first answer if consistent
    }

result = self_consistency_check("When was the Treaty of Westphalia signed?")
print(result["consistency"])

4. Hallucination Detection

# Detect if a model response contains hallucinations
from openai import OpenAI

client = OpenAI()

def detect_hallucination(question: str, answer: str, context: str = "") -> dict:
    """Check if an answer contains hallucinated content."""

    prompt = f"""Analyze this AI response for potential hallucinations.

Question: {question}
AI Response: {answer}
{"Reference Context: " + context if context else "No reference context provided."}

Check for:
1. Factual claims that seem incorrect or unverifiable
2. Invented names, dates, statistics, or citations
3. Claims that contradict the provided context
4. Overly specific details that seem fabricated (exact percentages, fake URLs)

Rate the response:
- RELIABLE: No obvious hallucinations detected
- SUSPICIOUS: Contains claims that may be hallucinated  
- HALLUCINATED: Contains clearly false or fabricated information

Provide your rating and explain which specific claims are concerning."""

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0
    )

    return {
        "analysis": response.choices[0].message.content,
        "question": question,
        "answer": answer
    }

# Example: Check a potentially hallucinated response
result = detect_hallucination(
    question="Who invented the telephone?",
    answer="The telephone was invented by Alexander Graham Bell in 1876, based on his earlier research published in the Journal of Acoustic Sciences (1874)."
)
print(result["analysis"])
# The "Journal of Acoustic Sciences" doesn't exist — this is a hallucination!

🏭 Industry Standards

  • RAG is mandatory for production — No serious enterprise deploys LLMs without grounding in real data.
  • Temperature 0.0-0.3 for factual tasks — Only use higher temperature for creative generation.
  • Dual LLM pattern — One model generates, another validates. Catches most hallucinations.
  • "I don't know" training — Fine-tune your model to say "I don't know" by including examples in training data.
  • Guardrails — Tools like NeMo Guardrails add safety layers between LLM and user.
  • Human-in-the-loop — For high-stakes domains (medical, legal), always have human review before action.
  • Structured output — JSON mode with schemas prevents many hallucination types (e.g., invalid dates).

📝 Summary

  • Hallucination = model confidently outputs incorrect/fabricated information
  • Happens because models predict likely text, not true text
  • RAG is the most effective prevention (ground in real documents)
  • Low temperature + strict system prompt = easy wins
  • Self-consistency + fact-checking = catch remaining issues
  • For production: combine multiple techniques in layers

🧠 Mental Model

Hallucination Prevention Stack:
Layer 1: RAG (ground in documents)
Layer 2: Low temperature + structured output
Layer 3: System prompt with "say I don't know" rules
Layer 4: Self-consistency check (multiple generations)
Layer 5: Post-generation fact-checking LLM
Layer 6: Human review (for critical decisions)

❌ Beginner Mistakes to Avoid

  • Trusting model output as fact — NEVER deploy an LLM that makes claims without verification in high-stakes domains.
  • Using high temperature for factual queries — Temperature 0.7+ massively increases hallucination rate.
  • Thinking bigger models don't hallucinate — GPT-4 hallucinates less but still hallucinates. All models do.
  • Not testing for hallucination — Include "unanswerable" questions in your eval set to test if the model says "I don't know."
  • Skipping RAG because "the model should know this" — Even if trained on the info, retrieval is more reliable than memory.
