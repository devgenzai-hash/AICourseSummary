DPO & RLHF: Preference Alignment

SFT teaches a model WHAT to say. DPO/RLHF teaches it which answers are BETTER. This is how models go from "can follow instructions" to "gives actually good, safe, helpful responses" — the secret sauce of ChatGPT, Claude, and Gemini.

🏠 Daily Life Analogy

SFT = Teaching a student to write essays. "Here's a good essay. Write like this."

DPO/RLHF = A writing contest with judges. "Here are two essays on the same topic. Essay A is better because it's clearer and more accurate. Learn to write like A, not like B."

RLHF = Hiring a writing coach first. Train a "judge" (reward model) to score essays, then have the student practice and get scored repeatedly.

DPO = Skip the coach, learn directly from examples. "Just look at which essays won in past contests and learn the pattern directly."

Why Alignment After SFT?

After SFT, a model can follow instructions. But it might:

  • Give technically correct but unhelpful answers
  • Be too verbose or too brief
  • Not refuse dangerous requests
  • Not admit when it doesn't know something
  • Produce inconsistent quality

Alignment teaches the model: "Of all the possible correct answers, here's what a GOOD answer looks like vs a BAD one."

RLHF (Reinforcement Learning from Human Feedback)

The original alignment method (used by ChatGPT). Complex but powerful.

RLHF Pipeline:

  1. Step 1: Collect preferences. Humans rank model outputs (A better than B)
  2. Step 2: Train a reward model. Learns to predict which outputs humans prefer
  3. Step 3: RL optimization. Use PPO to optimize the model to get high reward scores
⚠️ RLHF is Complex

RLHF requires training 3 models simultaneously (policy, reward, reference). It's unstable, expensive, and hard to debug. That's why DPO was invented as a simpler alternative.

DPO (Direct Preference Optimization)

DPO is the modern, simpler alternative to RLHF. Same results, much easier to implement. It skips the reward model entirely.

AspectRLHFDPO
Models needed3 (policy + reward + reference)2 (policy + reference)
Training stabilityUnstable (RL is finicky)Stable (simple loss function)
ImplementationComplex (PPO algorithm)Simple (one training loop)
QualitySlightly higher ceiling95-100% of RLHF quality
Industry usageOpenAI, Anthropic (big labs)Everyone else (practical choice)
VRAM neededVery high (3 models in memory)High (2 models)

Production DPO Training

# Complete DPO training with TRL
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from trl import DPOTrainer, DPOConfig
from peft import LoraConfig
from datasets import load_dataset

# ===== 1. Load Model (start from your SFT model!) =====
model_name = "./my-sft-model"  # Or a public SFT model

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model = AutoModelForCausalLM.from_pretrained(
    model_name, quantization_config=bnb_config, device_map="auto"
)
tokenizer = AutoTokenizer.from_pretrained(model_name)
tokenizer.pad_token = tokenizer.eos_token

# ===== 2. LoRA Config for DPO =====
peft_config = LoraConfig(
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    task_type="CAUSAL_LM",
)

# ===== 3. Load Preference Dataset =====
# Must have columns: "prompt", "chosen", "rejected"
dataset = load_dataset("json", data_files="dpo_data.jsonl", split="train")

# ===== 4. DPO Training Config =====
dpo_config = DPOConfig(
    output_dir="./dpo-output",
    num_train_epochs=2,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=8,
    learning_rate=5e-5,      # Lower than SFT!
    beta=0.1,                # DPO temperature (how much to deviate from reference)
    lr_scheduler_type="cosine",
    warmup_ratio=0.1,
    bf16=True,
    logging_steps=10,
    save_strategy="epoch",
    max_length=1024,
    max_prompt_length=512,
)

# ===== 5. Train! =====
trainer = DPOTrainer(
    model=model,
    args=dpo_config,
    train_dataset=dataset,
    processing_class=tokenizer,
    peft_config=peft_config,
)

trainer.train()
trainer.save_model("./my-dpo-model")
print("✅ DPO training complete!")

GRPO (Group Relative Policy Optimization)

The newest technique (2024), used by DeepSeek. Instead of paired preferences, it generates multiple responses and ranks them as a group.

# GRPO — simpler than DPO, no need for pre-paired data
from trl import GRPOTrainer, GRPOConfig

# GRPO generates responses itself, then ranks them
# You just provide prompts + a reward function!

def reward_function(completions: list[str], prompts: list[str]) -> list[float]:
    """Score responses (higher = better)."""
    scores = []
    for completion in completions:
        score = 0.0
        # Example reward criteria:
        if len(completion) > 100: score += 1.0  # Not too short
        if len(completion) < 2000: score += 1.0  # Not too long
        if "```" in completion: score += 0.5  # Has code examples
        if "I don't know" not in completion: score += 0.5
        scores.append(score)
    return scores

grpo_config = GRPOConfig(
    output_dir="./grpo-output",
    num_train_epochs=1,
    per_device_train_batch_size=2,
    num_generations=4,  # Generate 4 responses per prompt, rank them
    learning_rate=1e-5,
    bf16=True,
)

# Dataset just needs prompts!
# dataset = [{"prompt": "Explain X..."}, {"prompt": "How do I..."}, ...]

trainer = GRPOTrainer(
    model=model,
    args=grpo_config,
    train_dataset=dataset,
    reward_funcs=reward_function,
    processing_class=tokenizer,
)
trainer.train()

When to Use Which Method

MethodBest ForData NeededComplexity
SFT onlyTeaching format/behaviorInstruction-response pairsLow
SFT → DPOImproving response quality after SFTSFT data + preference pairsMedium
SFT → GRPOWhen you have a reward signal but no paired dataSFT data + reward functionMedium
SFT → RLHFHighest quality alignment (big labs)SFT data + human rankingsVery High

🏭 Industry Standards

  • DPO has replaced RLHF for most teams — Simpler, more stable, nearly same quality.
  • Always do SFT before DPO — DPO improves a model that already works. It can't fix a model that can't follow instructions.
  • Beta = 0.1 — Standard DPO beta. Lower = stronger preference learning. Higher = stays closer to SFT model.
  • Learning rate for DPO: 5e-6 to 5e-5 — Lower than SFT to avoid catastrophic forgetting.
  • GRPO is the future — Used by DeepSeek-R1. Doesn't need pre-paired preferences.
  • Iterative DPO — Generate new responses after each DPO round and create new preference pairs. Repeat.

📝 Summary

  • Alignment = teaching models which responses are better (not just what to say, but HOW)
  • RLHF = complex (3 models, PPO), used by big labs
  • DPO = simple alternative (just chosen/rejected pairs), same quality, your go-to choice
  • GRPO = newest method, only needs prompts + reward function
  • Pipeline: Pre-train → SFT → DPO/RLHF (each stage builds on the previous)
  • Use TRL library's DPOTrainer for implementation

🧠 Mental Model

SFT: "Here's a good answer" → Model learns to generate acceptable answers
DPO: "Answer A is better than B" → Model learns what makes answers GREAT
GRPO: "Score these 4 answers" → Model learns from its own ranked outputs

Quality progression: Base → SFT (good) → DPO (great) → RLHF (best)

❌ Beginner Mistakes to Avoid

  • Doing DPO without SFT first — DPO assumes the model already follows instructions. Always SFT first.
  • Using too high a learning rate for DPO — DPO is a refinement step. Use 5-10x lower learning rate than SFT.
  • Low-quality preference pairs — If "chosen" and "rejected" are too similar, the model learns nothing.
  • Trying RLHF as a beginner — Start with DPO. RLHF requires expertise in RL training (reward hacking, mode collapse).
  • Not evaluating alignment — After DPO, test with adversarial prompts to verify the model actually improved.
