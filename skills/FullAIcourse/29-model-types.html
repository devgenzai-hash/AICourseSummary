All Model Types

Not all AI models are the same. Base models, instruct models, chat models, code models, vision models, MoE models — each is designed for different jobs. Know which to pick and when.

🏠 Daily Life Analogy

Base model = a university graduate. They have broad knowledge but no job training. They might ramble or be unpredictable.

Instruct model = a trained employee. They follow instructions clearly. "Write a summary" → they write a summary.

Chat model = a customer service rep. They're conversational, polite, multi-turn, and helpful.

Code model = a specialist programmer. They live and breathe code — autocomplete, debugging, and generation.

Base vs Instruct — The Key Difference

# Base model: just completes text (unpredictable for instructions)
# Input: "Write a Python function to sort a list"
# Base output: "of numbers. The function should take a list as input..."
# (It continues the text, doesn't follow the instruction!)

# Instruct model: follows instructions properly
# Input: "Write a Python function to sort a list"
# Instruct output: "def sort_list(lst): return sorted(lst)"

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

# This works great with instruct/chat models
response = client.chat.completions.create(
    model="llama3.1:8b",  # This is the instruct version
    messages=[{"role": "user", "content": "Write a Python function to sort a list"}],
)
print(response.choices[0].message.content)

# When to use BASE models:
# 1. As starting point for YOUR fine-tuning (SFT/DPO)
# 2. Creative text generation (novels, roleplay)
# 3. When you want to control behavior entirely through fine-tuning

Mixture of Experts (MoE)

🧠 MoE Mental Model

Traditional model: Every token goes through ALL 70B parameters
    → Slow, expensive

MoE model (e.g., Mixtral 8x7B):
    Total params: 47B (8 experts × ~7B each, shared layers)
    Active params per token: ~13B (only 2 experts activated)
    
    Token → Router → "This is a code token"
                   → Activates Expert 3 (code specialist)
                   → Activates Expert 7 (logic specialist)
                   → Other 6 experts sleep 💤

Result: Quality of 70B model, speed of 13B model!
# MoE models in practice — same API, just different characteristics

# Mixtral 8x7B: 47B total params, ~13B active
# Quality ≈ Llama-2-70B, Speed ≈ Llama-2-13B

# DeepSeek-V3: 671B total params, ~37B active per token
# One of the best open models, runs efficiently despite huge size

# Using MoE models via Ollama
response = client.chat.completions.create(
    model="mixtral:8x7b",  # MoE model
    messages=[{"role": "user", "content": "Explain quantum computing in 3 sentences"}],
)

# MoE pros: Better quality-to-speed ratio
# MoE cons: Higher VRAM (all experts loaded), less efficient for batching

Vision Language Models (VLMs)

# Using vision models to understand images
import base64

def describe_image(image_path: str) -> str:
    """Use a vision model to describe an image."""
    # Encode image to base64
    with open(image_path, "rb") as f:
        image_data = base64.b64encode(f.read()).decode("utf-8")
    
    # OpenAI-compatible vision API
    response = client.chat.completions.create(
        model="llava:7b",  # or "gpt-4o" for OpenAI
        messages=[{
            "role": "user",
            "content": [
                {"type": "text", "text": "Describe what you see in this image."},
                {"type": "image_url", "image_url": {
                    "url": f"data:image/jpeg;base64,{image_data}"
                }}
            ]
        }],
    )
    return response.choices[0].message.content

# Use cases for vision models:
# 1. Image description (alt text, captions)
# 2. Document OCR (read text from images/PDFs)
# 3. UI understanding (browser agents)
# 4. Chart/diagram analysis
# 5. Visual Q&A ("What color is the car?")

🏭 Industry Standards

  • Start with instruct models — 99% of applications use instruct/chat variants, not base models.
  • MoE is the future — Mixtral, DeepSeek-V3 prove MoE gives best quality/cost ratio.
  • Model size rule of thumb — 7B for simple tasks, 13-34B for complex reasoning, 70B+ for frontier quality.
  • Embedding models are separate — Never use chat models for embeddings. Use dedicated embedding models.
  • Reasoning models (o1, R1) — New category that "thinks longer" for complex problems. Higher cost but better accuracy.
  • Multimodal is standard now — GPT-4o, Claude 3.5, Gemini all handle text + images natively.

📝 Summary

  • Base: raw pre-trained, for fine-tuning. Instruct: follows commands. Chat: conversational.
  • Code models: specialized for programming. Vision: understands images.
  • MoE: multiple experts, only some activate per token (fast + smart).
  • Embedding: text → vector for search/RAG (separate from chat models).
  • Reasoning: new category that "thinks step by step" internally (o1, R1).
  • Pick based on task: chat for assistants, code for programming, base for fine-tuning.
