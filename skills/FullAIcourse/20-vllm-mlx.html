vLLM & MLX

vLLM: the production-grade inference engine for NVIDIA GPUs. MLX: Apple's framework for running models blazing fast on Mac. Two sides of the same coin — high-performance local inference.

🏠 Daily Life Analogy

vLLM = a professional commercial kitchen. Optimized to handle hundreds of orders simultaneously with maximum efficiency. Used by restaurants (companies) serving many customers.

MLX = a home kitchen designed by Apple. Beautiful, efficient, optimized specifically for your Mac hardware. Does fewer orders but each one is fast and effortless on Apple Silicon.

vLLM: Production Inference Engine

Why vLLM?

  • 2-4x faster than naive HuggingFace inference
  • PagedAttention — serves 2-4x more concurrent users
  • Continuous batching — no wasted GPU cycles
  • OpenAI-compatible API — drop-in replacement
  • Used by: Anyscale, Databricks, many startups

Quick Start:

# pip install vllm

# Start vLLM server (one command)
# vllm serve meta-llama/Llama-3.1-8B-Instruct --port 8000

# With quantization:
# vllm serve meta-llama/Llama-3.1-8B-Instruct \
#   --quantization awq \
#   --max-model-len 8192 \
#   --gpu-memory-utilization 0.9 \
#   --port 8000

Using vLLM from Python:

# Method 1: Offline batch inference (no server needed)
from vllm import LLM, SamplingParams

# Load model
llm = LLM(
    model="meta-llama/Llama-3.1-8B-Instruct",
    tensor_parallel_size=1,  # Number of GPUs
    gpu_memory_utilization=0.9,
    max_model_len=8192,
)

# Batch inference (processes all at once efficiently)
prompts = [
    "Explain Python decorators in 2 sentences.",
    "What is a REST API?",
    "Write a SQL query to find duplicate emails.",
    "Explain Docker vs Kubernetes.",
]

sampling_params = SamplingParams(
    temperature=0.7,
    max_tokens=200,
    top_p=0.9,
)

outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    print(f"Prompt: {output.prompt[:50]}...")
    print(f"Response: {output.outputs[0].text}\n")

vLLM as OpenAI-compatible Server:

# After starting: vllm serve meta-llama/Llama-3.1-8B-Instruct
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="token-abc123",  # Required but any value works
)

# Same code as OpenAI — just different base_url!
response = client.chat.completions.create(
    model="meta-llama/Llama-3.1-8B-Instruct",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "What are the SOLID principles?"},
    ],
    temperature=0.7,
    max_tokens=500,
    stream=True,
)

for chunk in response:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

Advanced vLLM Configuration:

# Production vLLM deployment
from vllm import LLM, SamplingParams
from vllm.engine.arg_utils import AsyncEngineArgs

# Multi-GPU with tensor parallelism
llm = LLM(
    model="meta-llama/Llama-3.1-70B-Instruct",
    tensor_parallel_size=4,      # Split across 4 GPUs
    gpu_memory_utilization=0.95,  # Use 95% of VRAM
    max_model_len=32768,         # Max context length
    enable_prefix_caching=True,  # Cache common prefixes
    dtype="auto",                 # Auto-detect best dtype
)

# Serving with Docker (production):
# docker run --runtime nvidia --gpus all \

#   -p 8000:8000 \
#   vllm/vllm-openai:latest \
#   --model meta-llama/Llama-3.1-8B-Instruct \
#   --gpu-memory-utilization 0.9

MLX: Apple Silicon Inference

Why MLX?

  • Optimized for Apple Silicon — Uses unified memory architecture (up to 192GB!)
  • NumPy-like API — Familiar for Python developers
  • Lazy evaluation — Only computes what's needed
  • Run 70B models on a MacBook — With M3/M4 Max 128GB
# pip install mlx-lm
from mlx_lm import load, generate

# Load a model (automatically downloads from HuggingFace)
model, tokenizer = load("mlx-community/Llama-3.1-8B-Instruct-4bit")

# Generate text
prompt = "Explain machine learning to a 5-year-old:"
response = generate(
    model, 
    tokenizer, 
    prompt=prompt,
    max_tokens=200,
    temp=0.7,
)
print(response)

MLX Chat with Streaming:

# Interactive chat with MLX
from mlx_lm import load, stream_generate
from mlx_lm.utils import apply_chat_template

model, tokenizer = load("mlx-community/Qwen2.5-7B-Instruct-4bit")

messages = [
    {"role": "system", "content": "You are a helpful coding assistant."},
    {"role": "user", "content": "Write a Python decorator for caching"},
]

# Apply chat template
prompt = apply_chat_template(tokenizer, messages)

# Stream tokens
for token in stream_generate(model, tokenizer, prompt, max_tokens=500):
    print(token, end="", flush=True)

MLX Fine-Tuning (LoRA on Mac!):

# Yes, you can fine-tune on a Mac with MLX!
# pip install mlx-lm

# Command-line fine-tuning:
# mlx_lm.lora \
#   --model mlx-community/Llama-3.1-8B-Instruct-4bit \
#   --data ./training-data \
#   --train \
#   --batch-size 4 \
#   --lora-layers 16 \
#   --iters 1000

# Training data format (JSONL):
# {"text": "### Instruction: ...\n### Response: ..."}

# After training, fuse the adapter:
# mlx_lm.fuse --model mlx-community/Llama-3.1-8B-Instruct-4bit --adapter-path ./adapters

MLX Server (OpenAI-compatible):

# Run MLX as an OpenAI-compatible server
# pip install mlx-lm[server]
# mlx_lm.server --model mlx-community/Llama-3.1-8B-Instruct-4bit --port 8080

# Then use with OpenAI client:
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1", api_key="mlx")
response = client.chat.completions.create(
    model="mlx-community/Llama-3.1-8B-Instruct-4bit",
    messages=[{"role": "user", "content": "Hello!"}]
)
print(response.choices[0].message.content)

🏭 Industry Standards

  • vLLM is the #1 production inference engine — Used by most companies serving open-source models.
  • TGI (Text Generation Inference) — HuggingFace's engine, used on Inference Endpoints.
  • MLX is growing fast on Mac — Apple investing heavily. Great for indie developers on Mac.
  • OpenAI-compatible API everywhere — All engines expose the same API. Write code once, deploy anywhere.
  • vLLM + Docker = production deployment — Standard pattern for self-hosted LLM inference.
  • Tensor parallelism with vLLM — Split model across GPUs for lower latency on large models.

📝 Summary

  • vLLM = production-grade GPU inference with continuous batching and PagedAttention
  • MLX = Apple Silicon inference and fine-tuning (LoRA on Mac!)
  • Both expose OpenAI-compatible APIs
  • Use vLLM for serving many users on NVIDIA GPUs
  • Use MLX for local development and training on Mac
  • Use Ollama for quick prototyping on any hardware

❌ Beginner Mistakes to Avoid

  • Using vLLM on Mac — vLLM requires NVIDIA GPUs. Use MLX or Ollama on Mac.
  • Not setting gpu_memory_utilization — Default 0.9 is good. Set lower if running other GPU tasks.
  • Ignoring tensor_parallel_size — If you have 4 GPUs, set tensor_parallel_size=4 for faster inference.
  • Using HF models directly with MLX — Convert to MLX format first. Use mlx-community models.
  • Running vLLM without Docker in production — Docker provides isolation, reproducibility, easy scaling.
