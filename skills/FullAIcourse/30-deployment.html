Deployment & Serving

You've trained your model — now how do you put it in production where real users can access it? Docker, FastAPI, load balancing, monitoring — the full deployment stack.

🏠 Daily Life Analogy

Training a model = cooking a meal at home. You experiment, taste, adjust. Deployment = opening a restaurant. Now you need a kitchen that handles 100 orders at once, consistent quality, health inspections (monitoring), and a menu (API).

The Deployment Stack

🧠 Production Architecture

Users → Load Balancer → API Gateway → FastAPI App → Model Server (vLLM/Ollama)
                              ↓                ↓              ↓
                        Rate Limiting    Auth/Logging    GPU Inference
                              ↓                ↓              ↓
                          Caching          Metrics      Health Checks

FastAPI LLM Service

# Production-ready FastAPI server for LLM inference
# pip install fastapi uvicorn openai pydantic

from fastapi import FastAPI, HTTPException, Depends
from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import StreamingResponse
from pydantic import BaseModel, Field
from openai import OpenAI
import time
import logging
from typing import Optional

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

app = FastAPI(title="LLM API Service", version="1.0")
app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_methods=["*"])

# Model client (connects to vLLM or Ollama backend)
llm_client = OpenAI(base_url="http://localhost:11434/v1", api_key="local")

# Request/Response models
class ChatRequest(BaseModel):
    message: str = Field(..., max_length=4000)
    system_prompt: Optional[str] = "You are a helpful assistant."
    model: str = "llama3.1:8b"
    temperature: float = Field(default=0.7, ge=0, le=2)
    max_tokens: int = Field(default=1000, le=4000)
    stream: bool = False

class ChatResponse(BaseModel):
    response: str
    model: str
    tokens_used: int
    latency_ms: float

# Health check
@app.get("/health")
async def health_check():
    return {"status": "healthy", "timestamp": time.time()}

# Main chat endpoint
@app.post("/chat", response_model=ChatResponse)
async def chat(request: ChatRequest):
    start = time.time()
    
    try:
        response = llm_client.chat.completions.create(
            model=request.model,
            messages=[
                {"role": "system", "content": request.system_prompt},
                {"role": "user", "content": request.message},
            ],
            temperature=request.temperature,
            max_tokens=request.max_tokens,
        )
        
        latency = (time.time() - start) * 1000
        logger.info(f"Request completed in {latency:.0f}ms")
        
        return ChatResponse(
            response=response.choices[0].message.content,
            model=request.model,
            tokens_used=response.usage.total_tokens,
            latency_ms=latency,
        )
    except Exception as e:
        logger.error(f"LLM error: {e}")
        raise HTTPException(status_code=500, detail=str(e))

# Streaming endpoint
@app.post("/chat/stream")
async def chat_stream(request: ChatRequest):
    async def generate():
        stream = llm_client.chat.completions.create(
            model=request.model,
            messages=[
                {"role": "system", "content": request.system_prompt},
                {"role": "user", "content": request.message},
            ],
            temperature=request.temperature,
            max_tokens=request.max_tokens,
            stream=True,
        )
        for chunk in stream:
            if chunk.choices[0].delta.content:
                yield chunk.choices[0].delta.content
    
    return StreamingResponse(generate(), media_type="text/plain")

# Run: uvicorn app:app --host 0.0.0.0 --port 8000 --workers 4

Docker Deployment

# Dockerfile for the FastAPI LLM service
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Run with multiple workers for concurrency
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "4"]

# docker-compose.yml — Full stack with model server
# docker-compose.yml
version: "3.8"
services:
  # Model server (vLLM for GPU production)
  model-server:
    image: vllm/vllm-openai:latest
    runtime: nvidia
    environment:
      - NVIDIA_VISIBLE_DEVICES=all
    command: >
      --model meta-llama/Llama-3.1-8B-Instruct
      --max-model-len 4096
      --gpu-memory-utilization 0.9
    ports:
      - "8001:8000"
    deploy:
      resources:
        reservations:
          devices:
            - capabilities: [gpu]
  
  # API service
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - MODEL_SERVER_URL=http://model-server:8000/v1
    depends_on:
      - model-server
  
  # Monitoring
  prometheus:
    image: prom/prometheus
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml

Monitoring & Metrics

# Add metrics to your LLM service
from prometheus_client import Counter, Histogram, generate_latest
from fastapi import Response

# Define metrics
REQUEST_COUNT = Counter("llm_requests_total", "Total LLM requests", ["model", "status"])
LATENCY = Histogram("llm_request_duration_seconds", "Request latency", ["model"])
TOKENS = Histogram("llm_tokens_used", "Tokens per request", ["model"])

# Track in your endpoint
@app.post("/chat")
async def chat_with_metrics(request: ChatRequest):
    start = time.time()
    try:
        result = await process_chat(request)
        REQUEST_COUNT.labels(model=request.model, status="success").inc()
        LATENCY.labels(model=request.model).observe(time.time() - start)
        TOKENS.labels(model=request.model).observe(result.tokens_used)
        return result
    except Exception:
        REQUEST_COUNT.labels(model=request.model, status="error").inc()
        raise

# Expose metrics endpoint for Prometheus
@app.get("/metrics")
async def metrics():
    return Response(content=generate_latest(), media_type="text/plain")

# Key metrics to track:
# 1. Request latency (p50, p95, p99)
# 2. Tokens per second (throughput)
# 3. Error rate
# 4. Queue depth (requests waiting)
# 5. GPU utilization & VRAM usage
# 6. Cost per request

Scaling Strategies

StrategyHowWhen
VerticalBigger GPU (A100 → H100)Single model needs more VRAM/speed
HorizontalMultiple replicas behind load balancerMore concurrent users
Model parallelismSplit model across GPUsModel too large for one GPU
CachingRedis cache for repeated queriesMany similar requests
BatchingGroup requests, process togetherHigh throughput needed
AutoscalingKubernetes HPA on GPU metricsVariable traffic patterns

🏭 Industry Standards

  • vLLM for production GPU serving — Continuous batching, PagedAttention, highest throughput.
  • Ollama for small teams — Easy setup, good for internal tools and prototypes.
  • Docker + Kubernetes for scale — Standard deployment platform for production AI services.
  • API gateway mandatory — Rate limiting, auth, logging before requests hit your model.
  • Health checks — /health endpoint checked every 10s. Auto-restart unhealthy containers.
  • Prometheus + Grafana — Standard monitoring stack. Alert on latency spikes and error rates.
  • Cost tracking — Track tokens used per user/request. GPU time is expensive.

📝 Summary

  • FastAPI = standard framework for LLM API services (async, fast, typed)
  • Docker = containerize everything for consistent deployment
  • vLLM/Ollama = model serving backend (separate from API layer)
  • Streaming = essential for chat UX (users see tokens as they generate)
  • Monitoring = Prometheus metrics (latency, errors, tokens, GPU usage)
  • Scale = horizontal replicas + caching + batching + autoscaling
