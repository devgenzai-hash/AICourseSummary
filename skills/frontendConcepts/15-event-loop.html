Event Loop (Macro vs Microtasks)

The single-threaded scheduling engine that makes async JavaScript possible — understanding task queues, microtask priority, and why Promise.then runs before setTimeout.

Advanced Concept Browser
🎠 Analogy: Restaurant Kitchen

The event loop is a single chef (main thread) processing orders. Macrotasks are regular customer orders (setTimeout, I/O callbacks) — processed one at a time between serving. Microtasks are "while you're at it" requests from the current order (Promise.then, queueMicrotask) — the chef finishes ALL of these before picking up the next customer's order. The chef never leaves microtasks pending.

The Problem: Single Thread, Many Async Operations

JavaScript has ONE thread for executing code. Yet it handles network requests, timers, user input, and animations simultaneously. The event loop is the scheduling mechanism that makes this possible without true parallelism.

How the Event Loop Works

  1. Execute current script (synchronous, top to bottom)
  2. Drain the microtask queue — ALL microtasks, including ones added during draining
  3. Render (if needed) — requestAnimationFrame, style calculation, layout, paint
  4. Pick ONE macrotask from the queue
  5. Go to step 2
// Execution order quiz — predict the output
console.log('1: Script start');

setTimeout(() => {
    console.log('2: setTimeout');  // Macrotask
}, 0);

Promise.resolve().then(() => {
    console.log('3: Promise.then');  // Microtask
}).then(() => {
    console.log('4: Chained .then');  // Microtask (queued by previous)
});

queueMicrotask(() => {
    console.log('5: queueMicrotask');  // Microtask
});

console.log('6: Script end');

// OUTPUT:
// 1: Script start
// 6: Script end        <-- Sync code finishes first
// 3: Promise.then     <-- Microtask queue drains
// 5: queueMicrotask   <-- More microtasks
// 4: Chained .then    <-- Microtask added during drain
// 2: setTimeout       <-- Finally, macrotask runs

Microtask Sources

  • Promise.then/catch/finally
  • queueMicrotask()
  • MutationObserver callbacks
  • async/await (after each await, continuation is a microtask)

Macrotask Sources

  • setTimeout / setInterval
  • setImmediate (Node.js)
  • I/O callbacks (network, file)
  • requestAnimationFrame (technically its own queue)
  • UI events (click, scroll — dispatched as tasks)
  • MessageChannel

The Danger: Microtask Starvation

// DANGER: Infinite microtask loop blocks EVERYTHING
function evilMicrotaskLoop() {
    Promise.resolve().then(() => {
        // This queues another microtask, which queues another...
        // The macrotask queue (setTimeout, rendering) NEVER gets reached
        // The page freezes completely — no paint, no input handling
        evilMicrotaskLoop();
    });
}
// Microtasks must ALL drain before the next render or macrotask
// So an infinite microtask loop = permanently frozen page

Where This Is Used in Production

  • React's batched state updates — React uses microtasks to batch multiple setState calls before committing to DOM.
  • Vue's nextTick — Internally uses Promise.then (microtask) to defer DOM reads until after pending reactive updates flush.
  • Node.js event loop — Has additional phases (timers, I/O poll, check) but same microtask-draining behavior between phases.

Common Mistakes

  • Expecting setTimeout(fn, 0) to run immediately — It runs after all microtasks AND the next render opportunity. Minimum delay is ~4ms in browsers.
  • Blocking rendering with Promise chains — Long chains of .then() all execute before the browser can paint.
  • Mixing async/await with event ordering — await yields to the microtask queue, not the macrotask queue. Other microtasks can interleave.

✅ You Truly Understand the Event Loop When...

Given any mix of setTimeout, Promise.then, queueMicrotask, and synchronous code, you can predict the exact execution order without running it.

🧪 Try This Challenge

Write a function yieldToMain() that pauses your work and lets the browser paint and handle events, then resumes. (Hint: you need to escape the microtask queue — use a macrotask mechanism like MessageChannel or scheduler.yield()).

🔗 Connect It

Event Loop connects to: Task Starvation (when microtasks block macrotasks), Time Slicing (breaking work into cooperative chunks), and Priority Inversion in Async Code (low-priority work starving high-priority input).
