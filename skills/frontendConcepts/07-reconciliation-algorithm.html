Frontend Concepts / Reconciliation Algorithm

Reconciliation Algorithm

How React determines the minimal set of DOM changes needed when your component tree updates — the diff algorithm at the heart of virtual DOM.

Advanced Concept Code
📝 Analogy: Editing a Document

Imagine you have two versions of a document. Instead of deleting the entire document and rewriting it, you find the differences (a word changed here, a paragraph added there) and apply only those changes. Reconciliation is React's "track changes" algorithm — it compares the old virtual tree to the new one and produces the minimum edit script for the real DOM.

The Problem: DOM Updates Are Expensive

Directly manipulating the DOM is slow because every change can trigger layout recalculation, repaint, and reflow. If your app updates 1000 list items but only 3 actually changed, you want to touch the DOM exactly 3 times — not 1000.

The general tree-diff problem is O(n³) — completely impractical. React's reconciliation uses two heuristics to achieve O(n):

  1. Different element types produce different trees — If a <div> becomes a <span>, React destroys the old subtree and builds a new one (no deep comparison)
  2. Keys identify stable elements across renders — Elements with the same key are the "same" element, just potentially moved or updated

The Algorithm Step by Step

// Simplified reconciliation logic

function reconcile(parentDom, oldFiber, newElement) {
    // CASE 1: Same type — update props, recurse on children
    if (oldFiber && oldFiber.type === newElement.type) {
        // Reuse the DOM node — just update changed attributes
        updateDomProperties(oldFiber.dom, oldFiber.props, newElement.props);
        // Recursively reconcile children
        reconcileChildren(oldFiber, newElement.props.children);
        return;
    }
    
    // CASE 2: Different type — destroy old, create new
    if (oldFiber && oldFiber.type !== newElement.type) {
        // Unmount old component tree entirely
        deleteFiber(oldFiber);
        // Create brand new DOM subtree
        createFiber(parentDom, newElement);
        return;
    }
    
    // CASE 3: New element, no old fiber — mount
    if (!oldFiber && newElement) {
        createFiber(parentDom, newElement);
        return;
    }
    
    // CASE 4: Old fiber, no new element — unmount
    if (oldFiber && !newElement) {
        deleteFiber(oldFiber);
        return;
    }
}

// Key-based child reconciliation (simplified)
function reconcileChildren(parentFiber, newChildren) {
    const oldChildren = parentFiber.children;
    const oldKeyMap = new Map();
    
    // Build map of old children by key for O(1) lookup
    oldChildren.forEach(child => {
        if (child.key !== null) {
            oldKeyMap.set(child.key, child);
        }
    });
    
    newChildren.forEach((newChild, index) => {
        let oldChild = null;
        
        if (newChild.key !== null) {
            // Key exists — find matching old child (possibly moved)
            oldChild = oldKeyMap.get(newChild.key);
        } else {
            // No key — match by index position (fragile!)
            oldChild = oldChildren[index];
        }
        
        reconcile(parentFiber.dom, oldChild, newChild);
    });
}
⚠️ Why Index Keys Are Dangerous

Using array index as key (key={index}) means React identifies elements by position, not identity. If you insert an item at the beginning of a list, React thinks EVERY element changed (because all indices shifted). This causes unnecessary re-renders and can break component state. Always use stable IDs.

Real-World Usage

  • React — Uses this algorithm in the Fiber reconciler. Each Fiber node stores the previous render's output for comparison.
  • Vue 3 — Uses a similar algorithm with additional optimizations: compiler-generated "patch flags" tell the runtime exactly which attributes might change.
  • Preact — Smaller implementation of the same algorithm, optimized for bundle size over edge-case performance.

✅ You Truly Understand Reconciliation When...

You can predict exactly which DOM nodes React will create, update, or destroy given a before/after component tree — and explain why keys change the answer.

Create a sortable list. First use key={index}, then switch to key={item.id}. Open React DevTools "Highlight Updates" to visualize the difference in what re-renders.
