CSS Containment

Telling the browser "this element's internals are independent" — enabling massive rendering optimizations by limiting the scope of layout, paint, and style recalculations.

Intermediate Performance CSS
📦 Daily-Life Analogy: Sealed Shipping Containers

Without containment, changing one item in a warehouse means rechecking the entire inventory. With CSS containment, each section is a sealed shipping container — the warehouse manager knows changes inside container #5 cannot possibly affect containers #1-4 or #6-10. This lets the browser skip recalculating everything else.

The Problem: Layout Is Global by Default

  • Changing one element's height can shift every sibling below it, affecting the entire document flow
  • Adding content to a div might change its parent's size, which changes the grandparent's layout, etc. (layout bubbles up)
  • Paint is unbounded — box-shadow, overflow visible content, and outlines can paint outside an element's bounds
  • Style recalculation — Changing a CSS class might invalidate styling for the entire subtree

CSS Containment lets you explicitly declare: "this subtree is independent — changes inside it do NOT affect anything outside."

The contain Property

ValueWhat It ContainsBrowser Optimization
contain: layoutLayout is independent — element doesn't affect external layoutSkip layout recalc for elements outside this subtree
contain: paintNothing paints outside element's boundsSkip paint for off-screen contained elements
contain: sizeElement's size is fixed regardless of childrenSkip layout entirely for this element during child changes
contain: styleCounters and quotes are scopedLimited optimization (mostly for correctness)
contain: strictAll of the above (layout + paint + size + style)Maximum optimization — element is fully isolated
contain: contentlayout + paint + style (NOT size)Safe default for most cases

Code: Practical Usage

/* Best use case: Virtual list items that are independent */
.list-item {
    contain: content; /* layout + paint + style containment */
    /* Browser knows: changing this item's content won't affect siblings */
    /* Result: Only THIS item re-layouts when its content changes */
}

/* Widget/card pattern — each card is isolated */
.dashboard-card {
    contain: strict; /* Full containment including size */
    width: 300px;
    height: 200px; /* Size MUST be explicit with contain: strict */
    /* Because size containment means: "my size won't change based on children" */
    /* If children overflow, they're clipped (like overflow: hidden) */
}

/* Off-screen content optimization */
.below-fold-section {
    contain: paint; /* Nothing in here paints outside bounds */
    /* Browser can skip painting entirely when off-screen */
    /* This is what content-visibility: auto uses internally */
}

content-visibility: The Killer Application

/* content-visibility: auto — the mega-optimization */
/* Combines containment with skip-rendering for off-screen content */
.article-section {
    content-visibility: auto;
    contain-intrinsic-size: auto 500px; /* Estimated size for scroll calculation */
    /* 
     * What this does:
     * 1. Off-screen: skips layout, paint, AND rendering entirely
     * 2. On-screen: renders normally
     * 3. Browser uses contain-intrinsic-size for scroll bar sizing
     * 
     * Result: A page with 100 articles renders as fast as one with 5
     * because off-screen articles are not rendered at all
     */
}

/* Real-world impact: Wikipedia measured 7x faster rendering with this */

Where This Is Used in Production

  • Chrome's built-in PDF viewer — Uses content-visibility: auto on pages not currently visible, dramatically reducing memory and render cost for 1000+ page documents.
  • Wikipedia — Tested content-visibility: auto on article sections, achieving 7x rendering speed improvement on long articles.
  • YouTube — Comment sections and recommendation lists use containment to prevent layout recalculation when new items load.

Common Mistakes

  • Using contain: size without explicit dimensions — The element collapses to 0×0 because the browser ignores children for sizing. Always set width/height with size containment.
  • Expecting contain: strict to work like overflow: hidden — It does clip overflow, but it also affects layout calculations. Test thoroughly.
  • Applying containment to inline elements — Containment requires a formatting context. It only works on block-level, flex, grid, or absolutely positioned elements.
  • Forgetting contain-intrinsic-size with content-visibility: auto — Without it, the scrollbar height is wrong (elements are 0 height when off-screen).

You can explain why adding contain: content to 500 list items makes inserting a new item at position #250 go from 50ms to 1ms (hint: layout recalculation stops at the containment boundary).
