Frontend Concepts / Prototype Pollution

Prototype Pollution

An attack where modifying Object.prototype (or any constructor's prototype) causes unexpected property values to appear on every object in the application — leading to logic bugs, DoS, or XSS.

Advanced Security JavaScript
🧬 Analogy: Contaminating the Water Supply

Every object in JavaScript inherits from Object.prototype — it's the shared water supply. Prototype pollution is like poisoning that supply. You don't need to target each house individually; once the supply is contaminated, every glass of water (every property lookup on any object) is affected. Even objects created after the pollution inherit the malicious properties.

The Problem: JavaScript's Prototype Chain

// JavaScript's property lookup walks the prototype chain:
const obj = {};
obj.toString; // Found on Object.prototype, not on obj itself

// If attacker can set: Object.prototype.isAdmin = true
// Then EVERY object appears to have isAdmin === true:
const user = {};
console.log(user.isAdmin); // true! (inherited from polluted prototype)

// This is catastrophic for code that checks:
if (user.isAdmin) { grantAdminAccess(); } // ← Grants access to everyone

How Prototype Pollution Happens

The Classic Vector: Recursive Merge/Extend

// Vulnerable deep merge function (common in utility libraries)
function deepMerge(target, source) {
    for (const key in source) {
        if (typeof source[key] === 'object' && source[key] !== null) {
            if (!target[key]) target[key] = {};
            deepMerge(target[key], source[key]);
        } else {
            target[key] = source[key]; // ← The vulnerability
        }
    }
    return target;
}

// Attacker-controlled input (from JSON body, query params, etc.):
const malicious = JSON.parse('{"__proto__": {"isAdmin": true}}');

// When merged into any object:
const config = {};
deepMerge(config, malicious);

// Now EVERY object in the application has isAdmin: true
const newUser = {};
console.log(newUser.isAdmin); // true — prototype is poisoned

// WHY: JSON.parse('{"__proto__": {...}}') creates an object where
// __proto__ is a regular property (not the actual prototype setter).
// But when deepMerge recurses into target["__proto__"], it writes to
// target.__proto__ which IS Object.prototype!

Other Pollution Vectors

// Vector 2: Path-based property assignment
function setByPath(obj, path, value) {
    const keys = path.split('.');
    let current = obj;
    for (let i = 0; i < keys.length - 1; i++) {
        if (!current[keys[i]]) current[keys[i]] = {};
        current = current[keys[i]];
    }
    current[keys[keys.length - 1]] = value;
}

// Attacker input: path = "__proto__.polluted", value = "yes"
setByPath({}, '__proto__.polluted', 'yes');
console.log({}.polluted); // "yes" — all objects polluted

// Vector 3: constructor.prototype traversal
// Even if you block "__proto__", attacker uses "constructor.prototype":
const payload = { "constructor": { "prototype": { "pwned": true } } };
// obj.constructor === Object, obj.constructor.prototype === Object.prototype

Fixed Merge Function

// SAFE deep merge — blocks prototype pollution vectors
function safeDeepMerge(target, source) {
    for (const key of Object.keys(source)) { // Object.keys: own properties only
        // Block the two known pollution paths
        if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
            continue; // Skip dangerous keys entirely
        }
        
        if (
            typeof source[key] === 'object' && 
            source[key] !== null &&
            !Array.isArray(source[key])
        ) {
            // Create with null prototype — immune to pollution
            if (!target[key]) target[key] = Object.create(null);
            safeDeepMerge(target[key], source[key]);
        } else {
            target[key] = source[key];
        }
    }
    return target;
}

// Alternative: Use Object.create(null) for all config objects
// These objects have NO prototype — pollution can't reach them
const safeConfig = Object.create(null);
safeConfig.name = 'app';
console.log(safeConfig.toString); // undefined (no prototype!)
⚠️ Pollution → XSS Gadgets

Prototype pollution alone isn't always exploitable. The real danger is finding a gadget — existing code that reads a property from an object and uses it in a dangerous way. Example: if a template engine checks options.escapeHTML and you pollute Object.prototype.escapeHTML = false, all HTML escaping is disabled → XSS. Popular gadgets exist in Lodash, jQuery, Handlebars, and Pug.

Where This Lives in Production

  • Lodash — CVE-2019-10744: _.defaultsDeep() was vulnerable. Fixed by blocking __proto__ in merge paths. One of the most widely-depended npm packages.
  • jQuery — $.extend(true, ...) was vulnerable through v3.3.1. Fixed in v3.4.0 by skipping __proto__ keys.
  • Express.js — qs query string parser had pollution via ?__proto__[admin]=true. Fixed with prototype-less objects.
  • Handlebars — CVE-2019-19919: Prototype pollution → RCE via template compilation gadgets.

Common Mistakes

  • Only blocking __proto__ — Forgetting constructor.prototype path. Both must be blocked.
  • Using for...in without hasOwnProperty — Iterates inherited (polluted) properties too.
  • Deep-cloning user input with vulnerable libraries — Cloning JSON from request bodies through pollutable paths.
  • Assuming Object.freeze prevents pollution — You must freeze Object.prototype itself, not just your objects. And freezing the prototype breaks many libraries.
  • Not using --frozen-intrinsics in Node.js — Node.js flag that freezes all built-in prototypes. Use in production for defense-in-depth.

✅ You Truly Understand Prototype Pollution When...

You can explain why JSON.parse('{"__proto__": {"x": 1}}').__proto__.x does NOT pollute the prototype (it creates an own property called __proto__), but passing that parsed object through a deep merge function DOES pollute it (the merge writes to target.__proto__ which triggers the setter).
