Frontend Concepts / Speculative Prerendering

Speculative Prerendering

The browser capability that renders entire pages BEFORE the user navigates to them — achieving near-instant page loads by speculating which link the user will click next.

Advanced Performance Navigation
🎬 Analogy: Pre-Rolling the Next Scene

A movie theater projectionist starts loading the next reel while the current one is playing. When the current scene ends, the transition is instant — the next scene was already prepared. Speculative prerendering loads and renders the next page in a hidden tab, so when the user clicks, it swaps in instantly.

The Problem: Navigation Latency Can't Be Optimized Away

// Even with perfect optimization, a page navigation still requires:
//
// 1. DNS lookup: 20-120ms (if not cached)
// 2. TCP connection: 50-200ms (1 RTT)
// 3. TLS handshake: 50-150ms (1-2 RTTs)
// 4. HTTP request + TTFB: 100-500ms
// 5. HTML download: 20-100ms
// 6. Parse + render: 100-500ms
// 7. Subresource download: 200-2000ms
//
// Total: 540ms-3570ms minimum — even for a fast site
//
// Speculative prerendering makes ALL of this happen BEFORE the click
// Result: near-0ms navigation time (just swap the hidden page in)

The Speculation Rules API (Modern Approach)

// The Speculation Rules API (Chrome 109+) is the modern replacement
// for the deprecated <link rel="prerender">

// Add speculation rules via a <script> tag in your HTML:
<script type="speculationrules">
{
    "prerender": [
        {
            "urls": ["/products", "/about", "/pricing"]
        }
    ]
}
</script>

// Or use pattern-based rules (more powerful):
<script type="speculationrules">
{
    "prerender": [
        {
            "where": {
                "and": [
                    { "href_matches": "/*" },
                    { "not": { "href_matches": "/logout" } },
                    { "not": { "href_matches": "/api/*" } },
                    { "not": { "selector_matches": ".no-prerender" } }
                ]
            },
            "eagerness": "moderate"
        }
    ],
    "prefetch": [
        {
            "where": { "href_matches": "https://external-site.com/*" },
            "eagerness": "conservative"
        }
    ]
}
</script>

// Eagerness levels control WHEN prerendering starts:
// "immediate" — Start as soon as rules are observed
// "eager" — Start soon (currently same as immediate)
// "moderate" — Start on hover (200ms+ hover intent)
// "conservative" — Start on pointerdown (just before click)

Prefetch vs Prerender: The Spectrum

// The Speculation Rules API supports two levels:
//
// PREFETCH: Download the page's main resource (HTML) only
// - Low cost: just one HTTP request
// - Saves: DNS + TCP + TLS + TTFB + HTML download
// - Doesn't save: parsing, rendering, subresources
// - Safe for cross-origin
//
// PRERENDER: Fully load and render the page in a hidden tab
// - High cost: full page load (all resources, JS execution)
// - Saves: EVERYTHING (navigation is instant)
// - Doesn't save: nothing (page is fully ready)
// - Same-origin only (security restriction)
//
// Decision matrix:
// High confidence user will navigate → prerender
// Medium confidence → prefetch
// Low confidence → don't waste resources
// Cross-origin → prefetch only (can't prerender cross-origin)

How Prerendering Works Internally

// When Chrome prerenders a page:
//
// 1. Creates a hidden "prerendering browsing context"
//    (similar to a hidden tab, but with restrictions)
//
// 2. Loads the full page: HTML, CSS, JS, images, fonts
//    All network requests use the same HTTP cache
//
// 3. Executes JavaScript (but with restrictions):
//    - document.visibilityState === 'hidden'
//    - No access to: localStorage, sessionStorage (deferred)
//    - No: alerts, notifications, gamepad, USB, Bluetooth
//    - No: media playback (audio/video paused)
//    - Fetch/XHR works normally
//
// 4. When user navigates: "activation" happens
//    - Hidden page becomes the active page
//    - visibilitychange event fires
//    - Deferred APIs become available
//    - Perceived navigation time: ~0ms

// Detecting if your page is being prerendered:
if (document.prerendering) {
    // Page is currently being prerendered (not yet activated)
    console.log('I am a prerendered page');
}

// React to activation (prerender → live):
document.addEventListener('prerenderingchange', () => {
    // Page was prerendered and user just navigated to it
    // NOW: start analytics, timers, interactions
    initAnalytics();
    startVideoPlayback();
});

// Safe pattern for analytics:
function whenActivated(callback) {
    if (!document.prerendering) {
        callback(); // Already active, run immediately
    } else {
        document.addEventListener('prerenderingchange', callback, { once: true });
    }
}

whenActivated(() => {
    // This runs only when the page is actually visible to the user
    performance.mark('page-activated');
    gtag('event', 'page_view');
});

Production Implementation: Smart Speculation

// Dynamic speculation rules based on user behavior
class SmartSpeculation {
    #rules = [];
    #scriptElement = null;

    constructor() {
        // Only works in supporting browsers
        if (!HTMLScriptElement.supports?.('speculationrules')) {
            console.log('Speculation Rules not supported');
            return;
        }
        this.#observeLinks();
    }

    #observeLinks() {
        // Prerender on hover intent (moderate eagerness equivalent)
        document.addEventListener('pointerenter', (e) => {
            const link = e.target.closest('a[href]');
            if (!link) return;
            if (!this.#isEligible(link)) return;
            
            // Debounce: only prerender after 200ms hover
            link._hoverTimer = setTimeout(() => {
                this.#addPrerenderRule(link.href);
            }, 200);
        }, { passive: true });

        document.addEventListener('pointerleave', (e) => {
            const link = e.target.closest('a[href]');
            if (link?._hoverTimer) {
                clearTimeout(link._hoverTimer);
            }
        }, { passive: true });
    }

    #isEligible(link) {
        const url = new URL(link.href, location.origin);
        
        // Same-origin only (cross-origin can't be prerendered)
        if (url.origin !== location.origin) return false;
        
        // Skip current page
        if (url.pathname === location.pathname) return false;
        
        // Skip pages with side effects
        if (link.hasAttribute('data-no-prerender')) return false;
        if (url.pathname.startsWith('/api/')) return false;
        if (url.pathname.includes('logout')) return false;
        if (url.pathname.includes('delete')) return false;
        
        // Respect data-saver preference
        if (navigator.connection?.saveData) return false;
        
        return true;
    }

    #addPrerenderRule(url) {
        // Limit to 2 prerendered pages (browser may limit further)
        if (this.#rules.length >= 2) {
            this.#rules.shift(); // Remove oldest
        }
        
        if (this.#rules.includes(url)) return;
        this.#rules.push(url);
        
        // Update the speculation rules script
        if (this.#scriptElement) {
            this.#scriptElement.remove();
        }
        
        this.#scriptElement = document.createElement('script');
        this.#scriptElement.type = 'speculationrules';
        this.#scriptElement.textContent = JSON.stringify({
            prerender: [{ urls: this.#rules }]
        });
        document.head.appendChild(this.#scriptElement);
    }
}

new SmartSpeculation();

Where This Lives in Production

  • Google Search — Prerenders the first search result when confidence is high (you'll notice instant navigation to the top result).
  • Chrome Address Bar — Prerenders URLs as you type when autocomplete confidence is high enough.
  • Shopify Hydrogen — Uses speculation rules with "moderate" eagerness on product links for instant product page transitions.
  • WordPress (Speculative Loading plugin) — Official plugin adds speculation rules to WordPress sites based on link proximity and visibility.

Trade-offs & Risks

ConcernDetailMitigation
Bandwidth wastePrerendering downloads full page resourcesUse "moderate"/"conservative" eagerness; respect saveData
Side effectsPrerendered page might trigger analytics, API callsGuard with document.prerendering check
Memory usageEach prerender keeps a full page in memoryBrowser limits concurrent prerenders (typically 1-2)
Stale contentPrerendered page may be outdated by activation timeShort-lived prerenders; invalidate on data change
Auth stateUser might log in/out between prerender and activationDon't prerender personalized/auth-gated pages

Common Mistakes

  • Prerendering pages with side effects — Form submissions, analytics events, purchase flows. Always check document.prerendering before side-effectful code.
  • Not respecting data-saver mode — Prerendering wastes bandwidth. Check navigator.connection.saveData.
  • Prerendering too many pages — Browsers limit concurrent prerenders. Over-specifying wastes resources and may cause eviction of useful prerenders.
  • Using the deprecated <link rel="prerender"> — This is no longer supported in Chrome. Use Speculation Rules API instead.
