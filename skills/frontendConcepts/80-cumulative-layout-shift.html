Cumulative Layout Shift (CLS)

The Core Web Vital that quantifies visual instability — measuring how much visible content unexpectedly moves during a page's lifetime, causing users to click the wrong button or lose their reading position.

Intermediate Core Web Vital Visual Stability
📰 Analogy: Reading a Newspaper on a Windy Day

Imagine reading a newspaper where paragraphs randomly shift position as ads load in. You're about to tap "Cancel" but the page jumps and you hit "Confirm Order" instead. CLS measures this chaos — the total area of content that moved multiplied by how far it moved.

The Problem: Unexpected Layout Shifts

// Common scenarios that cause layout shifts:
//
// 1. Image without dimensions loads → pushes content down
// 2. Ad banner injects above the fold → content jumps
// 3. Web font loads → text reflows (FOUT)
// 4. Dynamic content inserted above viewport → reading position lost
// 5. Cookie consent banner pushes page content
//
// Real user impact:
// - Misclicks (tapped wrong button after shift)
// - Lost reading position (scrolled back to find paragraph)
// - Rage quits (form resets after accidental navigation)

How CLS Is Calculated

// CLS formula per layout shift:
// layout shift score = impact fraction × distance fraction
//
// impact fraction = (area of viewport affected by shift) / (total viewport area)
// distance fraction = (max distance any element moved) / (viewport height or width)

// Example: A 200px tall element at top of a 800px viewport shifts down by 100px
//
// Impact fraction: element was in 200px area, now occupies 200px area 100px lower
//                  Union of old + new position = 300px of viewport height
//                  Impact = 300/800 = 0.375
//
// Distance fraction: moved 100px in 800px viewport = 0.125
//
// Shift score: 0.375 × 0.125 = 0.047

// CLS is NOT the sum of all shift scores!
// It uses a "session window" approach:
//
// Session window rules:
// - Max 1 second gap between shifts in same window
// - Max 5 seconds total window duration
// - CLS = the LARGEST session window value
//
// This prevents long-lived SPAs from accumulating infinite CLS

// Google thresholds:
// Good: ≤0.1 | Needs Improvement: 0.1-0.25 | Poor: >0.25

Measuring CLS with PerformanceObserver

let clsValue = 0;
let clsEntries = [];
let sessionValue = 0;
let sessionEntries = [];

const observer = new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
        // CRITICAL: Ignore shifts caused by user interaction
        // hadRecentInput = user clicked/tapped/typed within 500ms
        if (entry.hadRecentInput) continue;

        // Session window logic
        const firstSessionEntry = sessionEntries[0];
        const lastSessionEntry = sessionEntries[sessionEntries.length - 1];

        if (sessionValue &&
            entry.startTime - lastSessionEntry.startTime < 1000 &&
            entry.startTime - firstSessionEntry.startTime < 5000) {
            // Still in same session window
            sessionValue += entry.value;
            sessionEntries.push(entry);
        } else {
            // New session window
            sessionValue = entry.value;
            sessionEntries = [entry];
        }

        // CLS = largest session window
        if (sessionValue > clsValue) {
            clsValue = sessionValue;
            clsEntries = [...sessionEntries];
        }
    }
});

observer.observe({ type: 'layout-shift', buffered: true });

// Debug: identify WHAT shifted
document.addEventListener('visibilitychange', () => {
    if (document.visibilityState === 'hidden') {
        console.log(`CLS: ${clsValue}`);
        clsEntries.forEach(entry => {
            // entry.sources tells you WHICH elements moved
            entry.sources?.forEach(source => {
                console.log('Shifted element:', source.node);
                console.log('Previous rect:', source.previousRect);
                console.log('Current rect:', source.currentRect);
            });
        });
    }
});

Common Causes and Fixes

// CAUSE 1: Images without width/height attributes
// Browser can't reserve space before image loads → shift when it appears

// BAD:
<img src="hero.jpg" alt="Hero">

// GOOD: Always specify dimensions (browser calculates aspect ratio)
<img src="hero.jpg" alt="Hero" width="1200" height="600">

// ALSO GOOD: Use aspect-ratio in CSS
// .hero-img { aspect-ratio: 2/1; width: 100%; }


// CAUSE 2: Ads/embeds without reserved space

// BAD: Ad container collapses to 0 until ad loads
<div id="ad-slot"></div>

// GOOD: Reserve minimum space even if ad doesn't fill it
<div id="ad-slot" style="min-height: 250px;"></div>

// BEST: Use contain-intrinsic-size with content-visibility
// .ad-slot { content-visibility: auto; contain-intrinsic-size: 0 250px; }


// CAUSE 3: Web fonts causing text reflow (FOUT/FOIT)

// BAD: System font renders, then swaps to web font → layout shift
@font-face { font-family: 'Brand'; src: url('brand.woff2'); }

// GOOD: Use font-display: optional (no swap, no shift)
@font-face {
    font-family: 'Brand';
    src: url('brand.woff2') format('woff2');
    font-display: optional; // Use cached font or skip entirely
}

// ALSO: Preload critical fonts to reduce swap window
<link rel="preload" href="brand.woff2" as="font" type="font/woff2" crossorigin>

// ALSO: Use size-adjust to match fallback metrics to web font
@font-face {
    font-family: 'Brand-Fallback';
    src: local('Arial');
    size-adjust: 105%;   // Make Arial take same space as Brand font
    ascent-override: 95%;
    descent-override: 22%;
    line-gap-override: 0%;
}


// CAUSE 4: Dynamic content injected above viewport

// BAD: Banner inserted at top pushes everything down
document.body.insertBefore(banner, document.body.firstChild);

// GOOD: Use CSS transform instead (doesn't cause layout shift)
banner.style.transform = 'translateY(-100%)';
document.body.insertBefore(banner, document.body.firstChild);
requestAnimationFrame(() => {
    banner.style.transition = 'transform 0.3s';
    banner.style.transform = 'translateY(0)';
});

// GOOD: Use overlay/fixed positioning (doesn't shift content)
// .notification-banner { position: fixed; top: 0; z-index: 1000; }

Advanced: CLS Debugging Overlay

// Visual debugging tool: highlights elements that shift
function enableCLSDebugging() {
    const observer = new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
            if (entry.hadRecentInput) continue;
            if (entry.value < 0.001) continue; // Skip negligible shifts

            entry.sources?.forEach(source => {
                if (!source.node) return;
                
                // Flash red border on shifted element
                const el = source.node;
                el.style.outline = '3px solid red';
                el.style.outlineOffset = '-3px';
                
                // Show shift info as tooltip
                el.title = [
                    `Shift score: ${entry.value.toFixed(4)}`,
                    `From: ${JSON.stringify(source.previousRect)}`,
                    `To: ${JSON.stringify(source.currentRect)}`
                ].join('\n');
                
                // Clear after 2 seconds
                setTimeout(() => {
                    el.style.outline = '';
                    el.title = '';
                }, 2000);
            });
        }
    });
    
    observer.observe({ type: 'layout-shift', buffered: false });
    return observer; // Call .disconnect() to stop
}

Where This Lives in Production

  • Google Search Ranking — CLS is one of three Core Web Vitals affecting page experience ranking signal.
  • The Guardian — Reduced CLS from 0.25 to 0.05 by reserving ad slots and preloading fonts, resulting in measurable engagement increases.
  • Smashing Magazine — Uses aspect-ratio on all images and font-display: optional to maintain near-zero CLS.
  • YouTube — Reserves exact skeleton dimensions for video thumbnails, titles, and channel info to prevent shifts during lazy loading.

Common Mistakes

  • Testing CLS only on fast connections — Slow networks have longer load waterfalls, meaning more opportunities for late-loading content to cause shifts.
  • Ignoring SPA route transitions — Client-side navigation in SPAs can cause layout shifts that accumulate into CLS (session windows still apply).
  • Using font-display: swap without size-adjust — Swap guarantees text is visible early but causes shift when the real font loads if metrics differ.
  • Thinking transforms are free — Transforms don't cause layout shifts, but they also don't reserve space. Other content won't reflow around a transformed element.
  • Not accounting for responsive images — An image that's 1200x600 on desktop but fluid on mobile needs both width/height AND CSS to maintain aspect ratio.

✅ You Truly Understand CLS When...

You can look at a layout-shift PerformanceEntry, calculate its impact fraction and distance fraction manually, explain why the session window approach exists (for SPAs), and identify whether a shift was caused by late-loading content, font swap, or dynamic injection — then fix each one differently.

🧪 Try This Challenge

Build a page that intentionally has CLS > 0.5 (images without dimensions, injected banners, font swaps). Then fix it to CLS < 0.05 without removing any content. Verify using the CLS debugging overlay above.
