Frontend Concepts / Fiber Architecture

Fiber Architecture

React's internal data structure that represents the component tree as a linked list of 'fibers,' enabling interruptible rendering, priorities, and concurrent features.

Advanced Concept Code
🧬 Analogy: A To-Do List You Can Pause

The old React (stack reconciler) was like reading a book cover-to-cover — you couldn't bookmark your place and come back. Fiber is like a checklist where each item (component) is a separate card. You can stop after any card, handle an interruption, then pick up exactly where you left off. Each card points to the next one — it's a linked list of work units.

The Problem: Stack Recursion Can't Be Paused

React's pre-Fiber reconciler used the JavaScript call stack directly. When rendering a tree of 10,000 components:

  • It recursed into each component, one by one
  • The call stack grew deeper with each nested component
  • You cannot pause or resume a call stack — it must run to completion
  • Result: 200ms+ blocking the main thread

What a Fiber Is

// Each component instance becomes a Fiber node
// This is (simplified) what React stores internally

interface Fiber {
    // Identity
    type: Function | string;     // Component function or DOM tag ('div')
    key: string | null;           // Reconciliation key
    
    // Tree structure (linked list, not array of children)
    child: Fiber | null;          // First child
    sibling: Fiber | null;        // Next sibling
    return: Fiber | null;         // Parent (called "return" because it's where we return to)
    
    // State
    memoizedState: any;          // Hooks linked list (useState, useEffect, etc.)
    memoizedProps: object;        // Props from last render
    pendingProps: object;         // Props for this render
    
    // Work tracking
    flags: number;               // What effects to apply (Placement, Update, Deletion)
    lanes: number;               // Priority lanes (which updates affect this fiber)
    
    // Double buffering
    alternate: Fiber | null;      // The "other" version (current vs work-in-progress)
    
    // Output
    stateNode: DOMElement | null; // The actual DOM node (for host components)
}
💡 Double Buffering

React maintains TWO fiber trees simultaneously: the current tree (what's on screen) and the work-in-progress tree (what's being built). When rendering completes, React swaps them — the work-in-progress becomes current. This is like double buffering in games: you draw to a back buffer, then flip. The alternate pointer connects each fiber to its counterpart in the other tree.

The Work Loop: Traversal

// React traverses the Fiber tree using this pattern:
// 1. Go DOWN (child) — "begin work" on each fiber
// 2. When no more children, go SIDEWAYS (sibling)
// 3. When no more siblings, go UP (return)

function workLoop(fiber) {
    while (fiber) {
        // Process this fiber (render the component, diff props)
        const next = beginWork(fiber);
        
        if (next) {
            // Has child — go deeper
            fiber = next;
        } else {
            // No child — complete this fiber and look for sibling
            let current = fiber;
            while (current) {
                completeWork(current);
                if (current.sibling) {
                    fiber = current.sibling;
                    break;
                }
                // No sibling — go up to parent
                current = current.return;
            }
            if (!current) fiber = null; // Done!
        }
        
        // ⭐ KEY: We can stop here and resume later!
        if (shouldYield()) return;
    }
}

Real-World Usage

  • React 16+ — The Fiber reconciler replaced the stack reconciler. Every React app today runs on Fiber.
  • React DevTools — The component tree you see IS the Fiber tree. Hooks panel shows the memoizedState linked list.
  • React Native — Same Fiber architecture, different "host" layer. Fibers resolve to native views instead of DOM nodes.

✅ You Truly Understand Fiber When...

You can draw the linked-list traversal (child → sibling → return) for a given component tree and explain why this linked list (vs recursive call stack) enables interruptibility.

🧪 Try This Challenge

Open React DevTools, inspect a component, and find its Fiber node in the browser console using $r._debugOwner. Navigate the child, sibling, and return pointers to understand the tree structure.
