Web Components Interoperability

How custom elements interact with React, Vue, Angular, and Svelte — the friction points, data-passing patterns, and why frameworks still struggle with the platform's native component model.

Advanced Integration Cross-Framework
🌐 Daily-Life Analogy: International Diplomacy

Web Components speak the browser's native language (HTML/DOM). Frameworks like React, Vue, Angular are like countries with their own internal languages. Interoperability is the diplomacy — translating between "attributes" (HTML's way) and "props" (the framework's way), handling events that each side dispatches differently, and negotiating who controls what.

The Problem: Why Interop Is Hard

Custom elements speak the DOM API. Frameworks speak their own virtual/reactive API. The translation gaps:

  • Properties vs Attributes — Frameworks pass objects as props. HTML attributes are always strings. How do you pass {items: [{id: 1}]} to a custom element?
  • Event systems differ — React uses synthetic events, Vue uses v-on, Angular uses (output). Custom elements use native CustomEvent. These don't automatically bridge.
  • Children/slots mismatch — React's children prop vs Web Components' <slot> mechanism have different mental models.
  • Reactivity mismatch — Frameworks batch updates and diff. Custom elements respond to individual attribute/property changes synchronously.

Code: Using Web Components in React

// THE PROBLEM: React treats all custom element attributes as strings
// React <19 cannot set properties or listen to custom events natively

// ❌ BAD: This only sets the attribute (string), not the property (object)
function BadExample() {
    return <data-grid items={JSON.stringify(rows)} />; // Serialization overhead!
}

// ✅ GOOD: Use a ref to set properties and add event listeners
import { useRef, useEffect } from 'react';

function DataGridWrapper({ items, onRowSelect }) {
    const ref = useRef(null);
    
    useEffect(() => {
        const el = ref.current;
        if (!el) return;
        
        // Set complex data as a DOM property (bypasses attribute serialization)
        el.items = items;
        
        // Listen to custom events (React's synthetic event system doesn't handle these)
        const handler = (e) => onRowSelect(e.detail);
        el.addEventListener('row-select', handler);
        
        return () => el.removeEventListener('row-select', handler);
    }, [items, onRowSelect]);
    
    return <data-grid ref={ref} />;
}

// ✅ REACT 19+: Properties are set automatically when the prop exists on the element
// React 19 checks: if (propName in element) set as property, else set as attribute
function React19Example() {
    return <data-grid 
        items={rows}                          {/* Set as property (detected) */}
        onrow-select={(e) => handle(e.detail)} {/* Custom event listeners */}
    />;
}

Code: Using Web Components in Vue 3

<!-- Vue 3 has the best Web Component interop out of the box -->
<template>
    <!-- Vue auto-detects properties vs attributes -->
    <!-- If 'items' exists as a property on the element, Vue sets it as property -->
    <data-grid 
        :items="rows"
        :columns="columnConfig"
        @row-select="handleRowSelect"
    />
</template>

<script setup>
// Vue's compiler needs to know which tags are custom elements (not Vue components)
// Configure in vite.config.js:
// vue({ template: { compilerOptions: { isCustomElement: tag => tag.includes('-') } } })

import { ref } from 'vue';

const rows = ref([{ id: 1, name: 'Product A' }]);
const columnConfig = ref([{ field: 'name', header: 'Product' }]);

function handleRowSelect(event) {
    // Vue automatically unwraps CustomEvent — event IS the CustomEvent
    console.log(event.detail); // The row data from the custom element
}
</script>

Code: Building Framework-Agnostic Custom Elements

// Design pattern: Support BOTH attributes (HTML) and properties (JS)
// This makes your component work well with ALL frameworks

class SmartGrid extends HTMLElement {
    static get observedAttributes() { return ['page-size']; }

    // Property getter/setter — frameworks that set properties will use this
    get items() { return this._items || []; }
    set items(val) {
        this._items = val;
        this._render(); // Re-render when property changes
    }
    
    // Attribute → property reflection for simple values
    get pageSize() { return parseInt(this.getAttribute('page-size')) || 10; }
    set pageSize(val) { this.setAttribute('page-size', String(val)); }
    
    attributeChangedCallback(name, oldVal, newVal) {
        if (name === 'page-size' && this.isConnected) this._render();
    }

    // Dispatch custom events with detail — all frameworks can listen
    _emitRowSelect(row) {
        this.dispatchEvent(new CustomEvent('row-select', {
            detail: row,
            bubbles: true,     // Let it bubble for event delegation
            composed: true,    // Cross shadow DOM boundary
        }));
    }
}

Where This Is Used in Production

  • Adobe Spectrum Web Components — Adobe's design system ships as custom elements, consumed by React, Vue, and vanilla HTML across all Adobe products (Photoshop Web, Acrobat).
  • Ionic Framework — Ships UI components as Web Components (via Stencil), with thin React/Vue/Angular wrappers that handle the interop layer.
  • SAP UI5 Web Components — Enterprise components that work across React, Vue, and Angular without framework lock-in.

Common Mistakes

  • Only supporting attributes — If your component only reads attributes, frameworks must serialize objects to strings. Always implement property setters for complex data.
  • Not setting composed: true on events — Without it, events won't escape Shadow DOM boundaries, making them invisible to framework event listeners on the host.
  • Ignoring SSR — Custom elements require JavaScript to render. For SSR, use Declarative Shadow DOM (<template shadowrootmode="open">) or provide fallback content in slots.
  • Breaking React's controlled component model — React expects to be the single source of truth for form values. Custom elements that internally mutate state confuse React's reconciliation.

You can explain why passing an object as an attribute in React breaks (serialized to [object Object]), how Vue 3 auto-detects property vs attribute, and when you'd need composed: true on a custom event.
