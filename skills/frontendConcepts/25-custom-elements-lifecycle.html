Custom Elements Lifecycle

The precise sequence of callbacks the browser invokes as a custom element is created, connected, updated, and destroyed — and the subtle timing traps that catch most developers.

Intermediate Web Platform Browser API
🎭 Daily-Life Analogy: An Actor's Career

Think of a custom element as an actor. constructor() is when they're born and given a name. connectedCallback() is when they step onto the stage (the DOM). attributeChangedCallback() is when the director gives them a new costume mid-performance. disconnectedCallback() is when they exit the stage. And adoptedCallback() is the rare case where they transfer to a different theater (document).

The Problem: Why Lifecycle Callbacks Exist

Custom elements need to respond to changes in their environment:

  • When is it safe to access the DOM? — In the constructor, children may not exist yet
  • When should event listeners be added/removed? — Add on connect, remove on disconnect (prevents memory leaks)
  • How to react to attribute changes? — The browser needs a way to notify you when HTML attributes change
  • How to clean up resources? — Timers, WebSocket connections, observers need explicit teardown

The Complete Lifecycle

CallbackWhen CalledSafe OperationsUnsafe Operations
constructor() Element is created (before DOM insertion) Attach shadow root, set default state, set up internal data Read attributes, access children, add to DOM, dispatch events
connectedCallback() Element is inserted into DOM Read attributes, access children, fetch data, add listeners, start timers —
disconnectedCallback() Element is removed from DOM Remove listeners, cancel timers, close connections, cleanup Assume element is gone forever (it might be re-inserted)
attributeChangedCallback(name, old, new) An observed attribute changes Update internal state, re-render affected parts Trigger synchronous attribute changes on self (infinite loop)
adoptedCallback() Element moves to a new document (rare) Re-initialize document-specific references —

Code: Full Lifecycle Implementation

class DataFetcher extends HTMLElement {
    // CRITICAL: You MUST declare which attributes to observe
    // Without this, attributeChangedCallback will NEVER fire
    static get observedAttributes() {
        return ['src', 'interval'];
    }

    constructor() {
        super(); // MUST be first line — spec requirement
        
        // Safe: set up shadow DOM and internal state
        this.attachShadow({ mode: 'open' });
        this._pollTimer = null;
        this._abortController = null;
        
        // Safe: set up shadow DOM template (no attribute reads!)
        this.shadowRoot.innerHTML = `
            <style>
                :host { display: block; padding: 1rem; }
                .loading { opacity: 0.5; }
                .error { color: #ff4444; }
            </style>
            <div id="content"><slot>Loading...</slot></div>
        `;
        
        // UNSAFE here: this.getAttribute('src') — might not be set yet!
        // UNSAFE here: this.querySelector('...') — no children exist yet!
    }

    connectedCallback() {
        // NOW it's safe to read attributes — element is in the DOM
        console.log('Connected! src=', this.getAttribute('src'));
        
        // Start fetching data — only when actually in the document
        this._startPolling();
        
        // IMPORTANT: connectedCallback can fire MULTIPLE times
        // (element removed then re-inserted). Guard against double-init.
    }

    disconnectedCallback() {
        // CLEANUP: prevent memory leaks and orphaned network requests
        this._stopPolling();
        
        // Cancel any in-flight fetch requests
        if (this._abortController) {
            this._abortController.abort();
        }
        
        // NOTE: Element might be re-connected later (moved in DOM)
        // Don't null out state that's needed for re-connection
    }

    attributeChangedCallback(name, oldValue, newValue) {
        // Only fires for attributes listed in observedAttributes
        // TIMING TRAP: This fires BEFORE connectedCallback during parsing!
        // The parser sets attributes before connecting the element.
        
        if (oldValue === newValue) return; // No-op on same value
        
        switch (name) {
            case 'src':
                // Only fetch if we're connected (in the DOM)
                if (this.isConnected) {
                    this._fetchData(newValue);
                }
                break;
            case 'interval':
                if (this.isConnected) {
                    this._stopPolling();
                    this._startPolling();
                }
                break;
        }
    }

    adoptedCallback() {
        // Rare: fired when document.adoptNode() moves this to another document
        // Relevant for iframe communication or document fragments
        console.log('Moved to new document');
    }

    // --- Private methods ---
    _startPolling() {
        const interval = parseInt(this.getAttribute('interval')) || 30000;
        this._fetchData(this.getAttribute('src'));
        this._pollTimer = setInterval(() => {
            this._fetchData(this.getAttribute('src'));
        }, interval);
    }

    _stopPolling() {
        if (this._pollTimer) {
            clearInterval(this._pollTimer);
            this._pollTimer = null;
        }
    }

    async _fetchData(url) {
        if (!url) return;
        this._abortController = new AbortController();
        const content = this.shadowRoot.getElementById('content');
        
        try {
            content.classList.add('loading');
            const res = await fetch(url, { signal: this._abortController.signal });
            const data = await res.json();
            content.textContent = JSON.stringify(data, null, 2);
            content.classList.remove('loading', 'error');
        } catch (err) {
            if (err.name !== 'AbortError') {
                content.textContent = `Error: ${err.message}`;
                content.classList.add('error');
            }
        }
    }
}

customElements.define('data-fetcher', DataFetcher);

The Critical Timing Trap

⚠️ attributeChangedCallback Fires BEFORE connectedCallback

When the HTML parser encounters <data-fetcher src="/api/data">, the sequence is:

  1. constructor() — element created
  2. attributeChangedCallback('src', null, '/api/data') — parser sets attributes
  3. connectedCallback() — element inserted into DOM

If your attributeChangedCallback tries to access DOM context or sibling elements, it will fail. Always check this.isConnected before doing work that requires DOM context.

Where This Is Used in Production

  • Lit (Google) — Builds on these lifecycle callbacks to add reactive properties, batched updates, and a declarative template system. Every Lit component is a custom element.
  • Stencil (Ionic) — Compiles JSX components down to custom elements, mapping React-like lifecycle methods to the native callbacks.
  • GitHub's ViewComponent — Custom elements for interactive widgets, relying on connectedCallback for progressive enhancement of server-rendered HTML.

Common Mistakes

  • Forgetting static get observedAttributes() — Without it, attributeChangedCallback never fires. This is the #1 "why isn't my component updating" bug.
  • Doing work in constructor that needs attributes — Attributes aren't reliable in constructor. Defer to connectedCallback.
  • Not cleaning up in disconnectedCallback — Timers, observers, event listeners on window/document — all leak if not removed.
  • Assuming disconnectedCallback means destruction — Elements can be re-connected. Don't destroy state you'll need if re-inserted.
  • Not calling super() first — Spec requires it. Accessing this before super() throws.

✅ You Truly Understand Custom Elements Lifecycle When...

You can predict the exact sequence of lifecycle callbacks when a custom element is created via innerHTML, moved with appendChild, has an attribute changed, and is then removed — and explain why attributeChangedCallback fires before connectedCallback during parsing.
