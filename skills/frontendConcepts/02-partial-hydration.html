Frontend Concepts / Partial Hydration

Partial Hydration

The optimization that says: don't hydrate what doesn't need to be interactive. Only send JavaScript for components that actually have event handlers.

Intermediate Concept Performance
🏗️ Analogy: Wiring a House

Full hydration is like running electrical wires to every single wall in a house — even walls that will never have an outlet. Partial hydration is like an electrician who only wires the walls where you actually want outlets and switches. The other walls remain perfectly fine as-is — they just don't need electricity.

The Problem: Full Hydration is Wasteful

Consider a typical blog post page: 90% is static text, images, and layout. Only 10% is interactive (comment form, like button, share menu). With full hydration, you download and execute JavaScript for the entire page — including all that static content that will never change.

Partial hydration recognizes that most server-rendered content doesn't need client-side JavaScript. It only sends JS for the "interactive islands" on the page.

How Partial Hydration Works

  1. Server renders full HTML — The complete page is generated server-side
  2. Compiler/framework identifies interactive components — Either via directives or static analysis
  3. Only interactive component JS is sent — Static components get zero client JavaScript
  4. Hydration runs ONLY on interactive components — The rest of the DOM is left alone

Code: Astro's Partial Hydration

<!-- Astro uses "client directives" to mark what gets hydrated -->
<!-- This component sends ZERO JavaScript to the browser -->
<StaticHeader title="My Blog Post" />

<!-- This component gets hydrated immediately on page load -->
<SearchBar client:load />

<!-- This one hydrates only when it scrolls into the viewport -->
<CommentSection client:visible />

<!-- This hydrates only when the browser is idle (requestIdleCallback) -->
<RecommendedPosts client:idle />

<!-- This NEVER hydrates unless explicitly triggered by JS -->
<HeavyChart client:only="react" />

<!-- 
  Result: Instead of shipping 200KB of JS for the full page,
  you might ship only 15KB for just the interactive components.
  The blog post text, navigation, footer — all zero-JS static HTML.
-->

Implementation Pattern: Manual Partial Hydration

// A simplified partial hydration loader
// Only hydrates elements marked with data-hydrate attribute

async function partialHydrate() {
    // Find all elements that need hydration
    const islands = document.querySelectorAll('[data-hydrate]');
    
    for (const island of islands) {
        const componentName = island.dataset.hydrate;
        const strategy = island.dataset.strategy || 'load';
        
        switch (strategy) {
            case 'load':
                // Hydrate immediately
                await hydrateComponent(island, componentName);
                break;
                
            case 'visible':
                // Hydrate when element enters viewport
                const observer = new IntersectionObserver(
                    async ([entry]) => {
                        if (entry.isIntersecting) {
                            observer.disconnect();
                            await hydrateComponent(island, componentName);
                        }
                    }
                );
                observer.observe(island);
                break;
                
            case 'idle':
                // Hydrate when browser is idle
                requestIdleCallback(async () => {
                    await hydrateComponent(island, componentName);
                });
                break;
        }
    }
}

async function hydrateComponent(element, name) {
    // Dynamic import — only loads JS for this specific component
    const { default: Component } = await import(`./components/\${name}.js`);
    
    // Get serialized props from the HTML
    const props = JSON.parse(element.dataset.props || '{}');
    
    // Hydrate only this island — rest of page untouched
    hydrateRoot(element, <Component {...props} />);
}

partialHydrate();

Real-World Usage

  • Astro — The pioneer of partial hydration in modern frameworks. Uses "client directives" (client:load, client:visible, client:idle, client:media) to control when/if components hydrate.
  • Eleventy + Islands — Static site generator with opt-in island hydration via is-land web component.
  • Marko (eBay) — Automatically detects which components are interactive and only sends JS for those.

Trade-offs

AspectFull HydrationPartial Hydration
JS Bundle SizeAll components shippedOnly interactive components
Time to InteractiveSlower (hydrate everything)Faster (less work)
ComplexitySimple (everything hydrates)Requires explicit marking
State SharingEasy (single React tree)Hard (isolated islands)
Framework SupportAll frameworksAstro, Marko, Fresh

✅ You Truly Understand Partial Hydration When...

You can look at a page design and identify which components are "islands" that need JS vs pure static content, and explain why sharing state between islands is architecturally challenging.
