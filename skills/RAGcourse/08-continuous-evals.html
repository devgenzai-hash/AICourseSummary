Stage 8: Continuous Evaluations

Run adversarial queries, retrieval recall benchmarks, and hallucination tests continuously. Quality that isn't measured decays silently.

Advanced Production Code
🏠 Daily-Life Analogy: Factory Quality Control

Imagine a factory making car brakes. They don't just test the brakes once when they design them — they test every batch continuously:

  • Random samples tested every hour (regular evals)
  • Stress tests: "What happens at extreme temperatures?" (adversarial queries)
  • Comparison tests: "Are these as good as last month's batch?" (regression testing)
  • Customer complaints investigated immediately (user feedback loop)

Your RAG system needs the same continuous quality control. Models drift. Documents change. New queries emerge. Without continuous testing, quality degrades silently until something breaks catastrophically.

What Are Continuous Evaluations?

Continuous evals = automated tests that run regularly (hourly/daily/weekly) to verify your RAG system still works correctly. They catch problems before users do.

Three Types of Evaluation

Eval Type What It Tests How Often Example
Retrieval Evals Does the system find the right documents? Daily "For query X, is doc Y in top 5?"
Generation Evals Is the generated answer correct and grounded? Daily "Does the answer match the expected answer?"
Adversarial Evals Can we trick the system into hallucinating? Weekly "Query designed to confuse the system"

1. Retrieval Evaluation Metrics

Key Metrics Explained (Simple First)

Recall@K: "Out of all the relevant documents that exist, how many did we find in our top K results?"

If there are 5 relevant documents and our top-10 results contain 4 of them → Recall@10 = 80%

Precision@K: "Out of the K results we returned, how many are actually relevant?"

If our top-10 results have 7 relevant and 3 irrelevant → Precision@10 = 70%

MRR (Mean Reciprocal Rank): "On average, how high up is the first relevant result?"

If the first relevant result is at position 1 → RR = 1.0. At position 3 → RR = 0.33.

NDCG: "Are the most relevant results ranked at the top?" (considers relevance ordering)

from typing import List, Dict, Set

class RetrievalEvaluator:
    """Evaluate retrieval quality using standard IR metrics."""
    
    def recall_at_k(
        self, 
        retrieved_ids: List[str], 
        relevant_ids: Set[str], 
        k: int
    ) -> float:
        """What fraction of relevant docs did we find in top-k?"""
        top_k = set(retrieved_ids[:k])
        found = top_k.intersection(relevant_ids)
        return len(found) / len(relevant_ids) if relevant_ids else 0
    
    def precision_at_k(
        self, 
        retrieved_ids: List[str], 
        relevant_ids: Set[str], 
        k: int
    ) -> float:
        """What fraction of top-k results are actually relevant?"""
        top_k = retrieved_ids[:k]
        relevant_in_top_k = sum(1 for doc in top_k if doc in relevant_ids)
        return relevant_in_top_k / k
    
    def mrr(self, retrieved_ids: List[str], relevant_ids: Set[str]) -> float:
        """Mean Reciprocal Rank: how high is the first relevant result?"""
        for rank, doc_id in enumerate(retrieved_ids, 1):
            if doc_id in relevant_ids:
                return 1.0 / rank
        return 0.0
    
    def evaluate_query(
        self, 
        query: str, 
        retrieved: List[str], 
        relevant: Set[str]
    ) -> Dict:
        """Full evaluation for a single query."""
        return {
            "recall@5": self.recall_at_k(retrieved, relevant, 5),
            "recall@10": self.recall_at_k(retrieved, relevant, 10),
            "precision@5": self.precision_at_k(retrieved, relevant, 5),
            "precision@10": self.precision_at_k(retrieved, relevant, 10),
            "mrr": self.mrr(retrieved, relevant)
        }

2. Generation Evaluation

Automated Generation Metrics

class GenerationEvaluator:
    """Evaluate generated answer quality."""
    
    def __init__(self, nli_model, llm_judge):
        self.nli = nli_model
        self.judge = llm_judge
    
    def faithfulness_score(
        self, answer: str, context: str
    ) -> float:
        """
        Is the answer faithful to (supported by) the context?
        High score = answer only says things the context supports.
        """
        sentences = answer.split(".")
        supported = 0
        total = 0
        
        for sentence in sentences:
            if len(sentence.strip()) < 10:
                continue
            total += 1
            if self.nli.entails(context, sentence):
                supported += 1
        
        return supported / total if total > 0 else 0
    
    def answer_relevance(
        self, query: str, answer: str
    ) -> float:
        """Does the answer actually address the query?"""
        prompt = f"""Rate how well this answer addresses the question.
Score 0-1 (0=completely irrelevant, 1=perfectly addresses the question).
Only output the number.

Question: {query}
Answer: {answer}
Score:"""
        score = float(self.judge.generate(prompt).strip())
        return min(1.0, max(0.0, score))
    
    def hallucination_rate(
        self, answer: str, context: str
    ) -> float:
        """What % of the answer is NOT supported by context?"""
        return 1.0 - self.faithfulness_score(answer, context)

3. Adversarial Evaluation

Adversarial queries are questions specifically designed to trick the system into hallucinating. They test your system's weakest points.

ADVERSARIAL_TEST_CASES = [
    # Type 1: Questions about topics NOT in your documents
    {
        "query": "What is the company's Mars colonization policy?",
        "expected_behavior": "refuse",
        "reasoning": "No such policy exists. System should refuse."
    },
    
    # Type 2: Questions with false premises
    {
        "query": "When did we change the vacation policy to 30 days?",
        "expected_behavior": "correct_premise",
        "reasoning": "Policy is 20 days. System should correct the false premise."
    },
    
    # Type 3: Questions requiring inference beyond the text
    {
        "query": "Will the CEO approve my request?",
        "expected_behavior": "refuse",
        "reasoning": "Requires prediction, not factual retrieval."
    },
    
    # Type 4: Slightly modified facts (testing exact recall)
    {
        "query": "The policy says 25 vacation days, right?",
        "expected_behavior": "correct",
        "reasoning": "Should correct: actual policy says 20, not 25."
    },
    
    # Type 5: Ambiguous queries matching multiple conflicting docs
    {
        "query": "What are the working hours?",
        "expected_behavior": "present_multiple",
        "reasoning": "Different departments have different hours. Should present all."
    },
]

class AdversarialEvaluator:
    """Run adversarial tests to find hallucination vulnerabilities."""
    
    def run_adversarial_suite(
        self, 
        rag_pipeline,
        test_cases: List[Dict]
    ) -> Dict:
        """Run all adversarial test cases and report results."""
        results = []
        
        for test in test_cases:
            response = rag_pipeline.answer_query(test["query"])
            
            # Check if behavior matches expected
            actual_behavior = self._classify_behavior(response)
            passed = actual_behavior == test["expected_behavior"]
            
            results.append({
                "query": test["query"],
                "expected": test["expected_behavior"],
                "actual": actual_behavior,
                "passed": passed,
                "response": response
            })
        
        pass_rate = sum(1 for r in results if r["passed"]) / len(results)
        
        return {
            "pass_rate": pass_rate,
            "total_tests": len(results),
            "failures": [r for r in results if not r["passed"]],
            "results": results
        }

The Continuous Evaluation Pipeline

import schedule
from datetime import datetime

class ContinuousEvalPipeline:
    """
    Run evaluations on a schedule and alert on regressions.
    """
    
    def __init__(self, rag_pipeline, eval_dataset, alert_system):
        self.rag = rag_pipeline
        self.dataset = eval_dataset  # query → expected answer/behavior
        self.alerts = alert_system
        self.history = []  # Track metrics over time
    
    def run_daily_eval(self):
        """Daily evaluation: retrieval + generation metrics."""
        results = {
            "timestamp": datetime.now(),
            "retrieval": self._eval_retrieval(),
            "generation": self._eval_generation(),
            "hallucination_rate": self._eval_hallucination()
        }
        
        self.history.append(results)
        self._check_for_regressions(results)
        
        return results
    
    def run_weekly_adversarial(self):
        """Weekly adversarial testing."""
        adversarial = AdversarialEvaluator()
        results = adversarial.run_adversarial_suite(
            self.rag, ADVERSARIAL_TEST_CASES
        )
        
        if results["pass_rate"] < 0.9:
            self.alerts.send(
                severity="high",
                message=f"Adversarial test pass rate dropped to {results['pass_rate']:.0%}",
                details=results["failures"]
            )
        
        return results
    
    def _check_for_regressions(self, current):
        """Alert if metrics dropped compared to last run."""
        if len(self.history) < 2:
            return
        
        previous = self.history[-2]
        
        # Check retrieval regression
        recall_drop = (
            previous["retrieval"]["recall@10"] - 
            current["retrieval"]["recall@10"]
        )
        if recall_drop > 0.05:  # 5% drop
            self.alerts.send(
                severity="critical",
                message=f"Retrieval recall dropped by {recall_drop:.0%}"
            )
        
        # Check hallucination increase
        halluc_increase = (
            current["hallucination_rate"] - 
            previous["hallucination_rate"]
        )
        if halluc_increase > 0.02:  # 2% increase
            self.alerts.send(
                severity="critical",
                message=f"Hallucination rate increased by {halluc_increase:.0%}"
            )

Building Your Evaluation Dataset

💡 Golden Rule of Eval Datasets

Your eval dataset should contain: (1) queries that users actually ask, (2) the correct answer for each query, (3) which documents should be retrieved. Without this ground truth, you can't measure anything.

📊 At 10M Documents Scale
  • Eval dataset size: Minimum 200-500 queries covering diverse topics. Larger indexes need larger eval sets.
  • Eval cost: Running evals against an LLM-as-judge costs money. Budget $50-200/day for comprehensive evals at scale.
  • Regression risk: Ingesting new documents can break retrieval for existing queries. Always run evals after bulk ingestion.
  • Sampling: At 10M docs, you can't eval every possible query. Sample strategically: high-frequency queries + adversarial + edge cases.

🏢 What Production Systems Actually Do

  • RAGAS framework — Open-source framework with faithfulness, relevance, and context recall metrics
  • LangSmith (LangChain) — Traces + automated evals integrated into deployment pipeline
  • Braintrust / Arize — Commercial eval platforms with drift detection and alerting
  • LLM-as-Judge — Using GPT-4 to grade answer quality (common in production)
  • CI/CD integration: Evals run in PR pipelines — code can't merge if eval scores drop

📋 Summary

  • Quality unmeasured is quality that silently degrades — run evals continuously
  • Three eval types: retrieval (did we find the right docs?), generation (is the answer good?), adversarial (can we break it?)
  • Key metrics: Recall@K, Precision@K, MRR, Faithfulness, Hallucination Rate
  • Build a golden eval dataset with queries, expected answers, and relevant doc IDs
  • Alert immediately on regressions — a 5% recall drop or 2% hallucination increase is critical
  • Run daily retrieval/generation evals + weekly adversarial testing

❌ Beginner Mistakes to Avoid

  • Only testing once: "We tested before launch" — not enough. Things break over time as documents change and models update.
  • No ground truth dataset: You can't measure quality without knowing the right answers. Build your eval dataset FIRST.
  • Ignoring edge cases: Standard queries work fine. It's the weird, adversarial, out-of-scope queries that expose hallucination.
  • No alerting: Metrics in a dashboard nobody checks are useless. Set up automatic alerts for regressions.
  • Eval dataset drift: If your documents change but your eval dataset doesn't, your evals become meaningless. Update them together.
