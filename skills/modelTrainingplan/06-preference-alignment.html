Chapter 6: Stage 3 — Preference Alignment (DPO)

Teaching the model to prefer accurate, nuanced, respectful responses over shallow or incorrect ones using Direct Preference Optimization.

🤔 Why Do We Need Preference Alignment?

The Problem After SFT

After SFT, the model can answer questions about scriptures. But it may:

  • Give oversimplified answers when depth is needed
  • Hallucinate verses that don't exist
  • Present one school's interpretation as universal truth
  • Be disrespectful to certain traditions
  • Give verbose answers when conciseness is preferred

Preference alignment teaches the model which style of response is better — it learns to self-correct toward higher quality.

📐 How DPO Works (The Math)

🧮 DPO Mathematical Foundation

The DPO Loss Function:

# DPO Loss (simplified mathematical form):
# L_DPO = -E[log σ(β × (log π_θ(y_w|x)/π_ref(y_w|x) - log π_θ(y_l|x)/π_ref(y_l|x)))]

# Where:
#   x = prompt
#   y_w = preferred (chosen) response  
#   y_l = dispreferred (rejected) response
#   π_θ = our model (being trained)
#   π_ref = reference model (frozen copy of model before DPO)
#   β = temperature parameter (controls how much to deviate from reference)
#   σ = sigmoid function

Intuitive Explanation:

  1. The model computes how likely it would generate both the chosen and rejected response
  2. It compares this to how likely the reference model (itself before training) would generate them
  3. The loss pushes the model to increase probability of chosen responses and decrease probability of rejected ones
  4. β controls conservatism: higher β = less deviation from original behavior

Why DPO > RLHF:

AspectRLHFDPO
Reward model needed?Yes (separate model)No
Training stabilityUnstable (RL issues)Stable (supervised loss)
HyperparametersMany (PPO has ~15)Few (mainly β)
Compute costHigh (4 models in memory)Low (2 models)
QualityExcellentExcellent (often equal/better)

💻 Complete DPO Training Code

"""
Direct Preference Optimization (DPO) for Hindu Scripture Model
===============================================================
Aligns the SFT-trained model with human quality preferences.
Uses TRL's DPOTrainer with LoRA for memory efficiency.

Usage:
    python dpo_train.py

Hardware: 1x A100 40GB
Time: ~4-8 hours for 10K preference pairs
"""
import torch
from datasets import load_dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, PeftModel, prepare_model_for_kbit_training
from trl import DPOTrainer, DPOConfig

# ============================================
# CONFIGURATION
# ============================================
BASE_MODEL = "google/gemma-3-27b-it"
SFT_ADAPTER = "./checkpoints/sft_lora/final"  # Our SFT-trained adapter
DPO_DATASET = "./datasets/dpo_preference_data.jsonl"
OUTPUT_DIR = "./checkpoints/dpo_lora"

# DPO Hyperparameters
BETA = 0.1              # KL penalty coefficient (0.05-0.5, lower = more change)
LEARNING_RATE = 5e-7    # Very low LR for DPO (model is already good from SFT)
NUM_EPOCHS = 1          # Usually 1 epoch is enough for DPO
BATCH_SIZE = 2
GRADIENT_ACCUMULATION = 4
MAX_LENGTH = 2048

# ============================================
# STEP 1: Load Model (SFT checkpoint)
# ============================================
print("📦 Loading SFT model...")

tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
tokenizer.padding_side = "left"  # Required for DPO

# Load in 4-bit
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    BASE_MODEL,
    quantization_config=bnb_config,
    device_map="auto",
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2",
)

# Load SFT adapter and merge
print(f"📎 Loading SFT adapter: {SFT_ADAPTER}")
model = PeftModel.from_pretrained(model, SFT_ADAPTER)
model = model.merge_and_unload()
model = prepare_model_for_kbit_training(model)

# ============================================
# STEP 2: Configure LoRA for DPO
# ============================================
lora_config = LoraConfig(
    r=16,                    # Lower rank for DPO (smaller adjustments)
    lora_alpha=16,
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
)

# ============================================
# STEP 3: Load DPO Dataset
# ============================================
print("📊 Loading preference dataset...")

dataset = load_dataset("json", data_files=DPO_DATASET, split="train")
split = dataset.train_test_split(test_size=0.05, seed=42)

print(f"  Train: {len(split['train'])} preference pairs")
print(f"  Eval:  {len(split['test'])} preference pairs")

# Preview
example = split['train'][0]
print(f"\n  Example prompt: {str(example['prompt'])[:100]}...")
print(f"  Chosen (first 100): {str(example['chosen'])[:100]}...")
print(f"  Rejected (first 100): {str(example['rejected'])[:100]}...")

# ============================================
# STEP 4: DPO Training Configuration
# ============================================
training_args = DPOConfig(
    output_dir=OUTPUT_DIR,
    
    # DPO-specific
    beta=BETA,                          # KL penalty (how much to deviate from ref)
    loss_type=["sigmoid"],              # Standard DPO loss
    
    # Training
    num_train_epochs=NUM_EPOCHS,
    per_device_train_batch_size=BATCH_SIZE,
    per_device_eval_batch_size=BATCH_SIZE,
    gradient_accumulation_steps=GRADIENT_ACCUMULATION,
    
    # Optimizer (very conservative for DPO)
    learning_rate=LEARNING_RATE,
    lr_scheduler_type="cosine",
    warmup_ratio=0.1,
    weight_decay=0.01,
    max_grad_norm=1.0,
    optim="paged_adamw_8bit",
    
    # Precision & Memory
    bf16=True,
    gradient_checkpointing=True,
    max_length=MAX_LENGTH,
    
    # The reference model is automatically created from initial model state
    # No need to load separately when using LoRA
    
    # Logging
    logging_steps=10,
    report_to="wandb",
    run_name="gemma-scripture-dpo",
    
    # Saving
    eval_strategy="steps",
    eval_steps=100,
    save_strategy="steps",
    save_steps=100,
    save_total_limit=3,
    load_best_model_at_end=True,
    metric_for_best_model="eval_loss",
    
    seed=42,
)

# ============================================
# STEP 5: Train DPO
# ============================================
print("\n🚀 Starting DPO training...")

trainer = DPOTrainer(
    model=model,
    args=training_args,
    train_dataset=split["train"],
    eval_dataset=split["test"],
    processing_class=tokenizer,
    peft_config=lora_config,
)

# Train
result = trainer.train()

# Save
print("\n💾 Saving DPO model...")
trainer.save_model(f"{OUTPUT_DIR}/final")
tokenizer.save_pretrained(f"{OUTPUT_DIR}/final")

print(f"\n{'='*50}")
print(f"✅ DPO Training Complete!")
print(f"   Final Loss: {result.training_loss:.4f}")
print(f"   Saved to: {OUTPUT_DIR}/final")
print(f"{'='*50}")

📋 Preference Criteria for Hindu Scriptures

When creating preference data, what makes a response "chosen" vs "rejected"?

CriterionChosen ResponseRejected Response
Accuracy Correct verse numbers, proper attribution Wrong references, misattributed quotes
Depth Multiple perspectives, commentaries cited Surface-level, Wikipedia-like summary
Respectfulness Honors all traditions equally Dismissive of certain schools/traditions
Sanskrit inclusion Provides original Sanskrit with translation Only paraphrases, no original text
Nuance Acknowledges multiple interpretations Presents one view as absolute truth
Structure Well-organized, headers, numbered points Wall of text, no formatting
Honesty Admits uncertainty where applicable Makes up information confidently

🔄 Alternative Alignment Methods

📊 KTO (Kahneman-Tversky Optimization) — For Unpaired Data
"""
KTO: When you only have thumbs-up/thumbs-down labels (not paired preferences).
Useful if you have user feedback data but not side-by-side comparisons.
"""
from trl import KTOTrainer, KTOConfig

# KTO dataset format: just label each response as good/bad
# {"prompt": "...", "completion": "...", "label": true/false}

kto_config = KTOConfig(
    output_dir="./checkpoints/kto",
    learning_rate=5e-7,
    beta=0.1,
    num_train_epochs=1,
    bf16=True,
    gradient_checkpointing=True,
)

trainer = KTOTrainer(
    model=model,
    args=kto_config,
    train_dataset=kto_dataset,
    processing_class=tokenizer,
    peft_config=lora_config,
)
trainer.train()
🎯 ORPO (Odds Ratio Preference Optimization) — Combined SFT+DPO
"""
ORPO: Combines SFT and preference alignment in a single training step.
Simpler pipeline — no need for separate SFT then DPO stages.
Good for: When you want to skip the two-stage process.
"""
from trl import ORPOTrainer, ORPOConfig

orpo_config = ORPOConfig(
    output_dir="./checkpoints/orpo",
    learning_rate=8e-6,
    beta=0.1,           # Relative weight of preference loss
    num_train_epochs=2,
    bf16=True,
    gradient_checkpointing=True,
    max_length=2048,
)

# Uses same format as DPO (prompt, chosen, rejected)
trainer = ORPOTrainer(
    model=model,
    args=orpo_config,
    train_dataset=preference_dataset,
    processing_class=tokenizer,
    peft_config=lora_config,
)
trainer.train()
⚡ SimPO (Simple Preference Optimization) — No Reference Model
"""
SimPO: Eliminates the reference model entirely.
Uses length-normalized sequence probabilities as implicit reward.
Simpler and often equally effective as standard DPO.
"""
from trl import DPOTrainer, DPOConfig

# SimPO is accessed via DPO trainer with loss_type="sigmoid_norm"
simpo_config = DPOConfig(
    output_dir="./checkpoints/simpo",
    loss_type=["sigmoid_norm"],  # Length-normalized loss (SimPO)
    beta=2.0,                    # Higher beta for SimPO (recommended: 2.0-2.5)
    learning_rate=1e-6,
    num_train_epochs=1,
    bf16=True,
    gradient_checkpointing=True,
)

trainer = DPOTrainer(
    model=model,
    ref_model=None,  # No reference model needed!
    args=simpo_config,
    train_dataset=preference_dataset,
    processing_class=tokenizer,
    peft_config=lora_config,
)
trainer.train()

📊 DPO Training Metrics to Watch

"""
Key metrics during DPO training and what they mean:
"""
# rewards/chosen    — Average reward for preferred responses (should INCREASE)
# rewards/rejected  — Average reward for rejected responses (should DECREASE)
# rewards/margins   — Gap between chosen and rejected rewards (should INCREASE)
# rewards/accuracies — % of pairs where chosen reward > rejected (should be > 0.5)
# loss             — DPO loss (should decrease)

# Good training signs:
# ✅ rewards/margins increasing steadily
# ✅ rewards/accuracies > 0.7 by end of training  
# ✅ loss decreasing
# ✅ rewards/chosen going up while rewards/rejected going down

# Bad signs:
# ❌ rewards/accuracies stuck at 0.5 (model not learning preferences)
# ❌ rewards/margins negative (model is INVERTED — preferring rejected!)
# ❌ Loss increasing (learning rate too high, or data quality issue)
