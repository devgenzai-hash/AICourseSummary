🐛 Common Errors & Fixes

Out of Memory (OOM) Errors

💥 CUDA out of memory
# ERROR:
# torch.cuda.OutOfMemoryError: CUDA out of memory. 
# Tried to allocate 2.00 GiB (GPU 0; 24.00 GiB total capacity)

# FIXES (apply in order until resolved):

# Fix 1: Reduce batch size
per_device_train_batch_size = 1  # Minimum
gradient_accumulation_steps = 16  # Increase to maintain effective batch

# Fix 2: Enable gradient checkpointing
gradient_checkpointing = True  # Saves ~60% activation memory

# Fix 3: Reduce sequence length
max_seq_length = 1024  # Down from 4096

# Fix 4: Lower LoRA rank
r = 8  # Down from 32 or 64

# Fix 5: Use CPU offloading
optim = "paged_adamw_8bit"  # 8-bit optimizer
# Or in DeepSpeed config:
# "offload_optimizer": {"device": "cpu"}

# Fix 6: Clear CUDA cache before training
import torch
torch.cuda.empty_cache()
import gc
gc.collect()

# DEBUGGING: See what's using memory
print(torch.cuda.memory_summary())  # Detailed breakdown
💥 RuntimeError: Expected all tensors on same device
# ERROR:
# RuntimeError: Expected all tensors to be on the same device, 
# but found at least two devices, cuda:0 and cpu

# CAUSE: Mixed device placement with device_map="auto"

# Fix 1: Ensure LoRA targets are on same device
# This often happens with prepare_model_for_kbit_training
model = prepare_model_for_kbit_training(model)  # Must be called BEFORE adding LoRA

# Fix 2: Force single GPU
device_map = {"": 0}  # Force everything to GPU 0

# Fix 3: For multi-GPU, use device_map="auto" with proper offloading
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    device_map="auto",
    max_memory={0: "20GB", 1: "20GB", "cpu": "30GB"}
)
💥 ValueError: Tokenizer/Model mismatch
# ERROR:
# ValueError: The model's chat template expects certain special tokens
# OR: Index out of range in embedding layer

# CAUSE: Tokenizer has more tokens than model's embedding layer

# Fix: Always load tokenizer from SAME path as model
tokenizer = AutoTokenizer.from_pretrained(BASE_MODEL)  # Same as model!

# If you added special tokens during training:
# model.resize_token_embeddings(len(tokenizer))  # Match sizes

# For Gemma specifically — DON'T add new tokens unless necessary
# Gemma already has comprehensive token coverage

Training Issues

📉 Loss is NaN or exploding
# SYMPTOMS: loss becomes NaN or spikes to very high values

# Fix 1: Lower learning rate
learning_rate = 1e-5  # Try 10× lower

# Fix 2: Lower max_grad_norm
max_grad_norm = 0.5  # Down from 1.0

# Fix 3: Use BF16 instead of FP16
bf16 = True   # ✅ More stable
fp16 = False  # ❌ Can cause NaN with large models

# Fix 4: Increase warmup
warmup_ratio = 0.1  # Up from 0.03

# Fix 5: Check for bad data
# NaN can be caused by empty strings or corrupted examples
def filter_bad_examples(dataset):
    return dataset.filter(lambda x: 
        len(x["messages"]) > 0 and
        all(len(m["content"]) > 0 for m in x["messages"])
    )

# Fix 6: Disable Flash Attention (for debugging)
attn_implementation = "eager"  # Instead of "flash_attention_2"
📉 Loss not decreasing / model not learning
# SYMPTOMS: Loss stays flat or decreases very slowly

# Fix 1: Learning rate too LOW — increase it
learning_rate = 2e-4  # For QLoRA SFT, this is usually good

# Fix 2: LoRA rank too LOW — model can't learn enough
r = 64  # Up from 16

# Fix 3: Wrong target modules — make sure you're training the right layers
target_modules = [
    "q_proj", "k_proj", "v_proj", "o_proj",  # Attention
    "gate_proj", "up_proj", "down_proj",      # MLP
]

# Fix 4: Data issue — verify your data is being tokenized correctly
# Print what the model actually sees:
example = dataset[0]
tokens = tokenizer.apply_chat_template(example["messages"], return_tensors="pt")
print(tokenizer.decode(tokens[0][:200]))  # Check it looks right

# Fix 5: assistant_only_loss issue — make sure loss mask is correct
# If loss is computed on the full sequence (including prompts),
# it might be "learning" but not on the right tokens
# Set: assistant_only_loss=True in SFTConfig
📉 Model generating gibberish after training
# SYMPTOMS: Model outputs random tokens or repetitive nonsense

# CAUSE 1: Overfitting — trained too long
# Fix: Reduce epochs (1-3 for SFT), use early stopping
num_train_epochs = 1  # Start with 1 epoch

# CAUSE 2: Learning rate too high — catastrophic forgetting
# Fix: Lower LR significantly
learning_rate = 5e-5  # Try much lower

# CAUSE 3: Wrong chat template during inference
# Fix: Use the EXACT same template as training
messages = [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."}
]
inputs = tokenizer.apply_chat_template(
    messages, 
    add_generation_prompt=True,  # IMPORTANT: adds model's turn start
    return_tensors="pt"
)

# CAUSE 4: LoRA adapter not loaded correctly
# Fix: Verify adapter loads
from peft import PeftModel
model = PeftModel.from_pretrained(base_model, adapter_path)
print(model.print_trainable_parameters())  # Should show LoRA params

# CAUSE 5: Quantization issue during inference
# Fix: Match training quantization
# If trained in 4-bit, inference should also use 4-bit (or merge and use BF16)

DPO-Specific Issues

📉 DPO rewards/accuracies stuck at 0.5
# SYMPTOMS: Model not learning preferences — accuracy stays at 50%

# Fix 1: Data quality — chosen and rejected must be CLEARLY different
# Bad: slight wording differences
# Good: one is accurate with citations, other is wrong/shallow

# Fix 2: Beta too HIGH — model can't deviate from reference
beta = 0.05  # Lower from 0.1 (allows more change)

# Fix 3: Learning rate too LOW for DPO
learning_rate = 1e-6  # Try slightly higher (but still conservative)

# Fix 4: Prompt format mismatch
# The prompt in DPO data must match how the model was trained in SFT
# Include the same system prompt used during SFT

# Fix 5: Check that chosen responses are actually better
# Random spot-check: read 20 examples, verify chosen > rejected

📊 Monitoring Training with W&B

"""
Setting up Weights & Biases for training monitoring.
Gives you real-time loss curves, gradient norms, learning rates, etc.
"""
import wandb

# 1. Login (one-time)
# wandb login YOUR_API_KEY

# 2. Training args include W&B config
training_args = SFTConfig(
    ...
    report_to="wandb",
    run_name="gemma-scripture-sft-v2",  # Descriptive name
    
    # Optional: group related runs
    # Set via environment variable:
    # os.environ["WANDB_PROJECT"] = "hindu-scripture-model"
    # os.environ["WANDB_ENTITY"] = "your-team"
)

# 3. Key metrics to watch during training:

# FOR CPT:
# - train/loss: Should decrease steadily (target: < 2.0 for domain text)
# - eval/loss: Should track train loss (gap = overfitting)
# - train/learning_rate: Verify warmup + cosine schedule

# FOR SFT:
# - train/loss: Should decrease to 0.5-1.5 range
# - eval/loss: Watch for divergence from train (overfitting signal)
# - generation_samples: Qualitative check every N steps

# FOR DPO:
# - rewards/margins: Should INCREASE (chosen - rejected gap)
# - rewards/accuracies: Should be > 0.7 by end
# - train/loss: Should decrease

# FOR GRPO:
# - reward/mean: Average reward should increase
# - reward/std: Should decrease (model converging on good outputs)
# - kl_divergence: Should stay bounded (not diverging too far)

# 4. Custom logging
class WandbGenerationCallback:
    """Log sample generations to W&B for qualitative monitoring."""
    
    def __init__(self, tokenizer, test_prompts, log_every=500):
        self.tokenizer = tokenizer
        self.test_prompts = test_prompts
        self.log_every = log_every
    
    def on_step_end(self, args, state, control, model=None, **kwargs):
        if state.global_step % self.log_every != 0:
            return
        
        table = wandb.Table(columns=["step", "prompt", "generation"])
        
        model.eval()
        for prompt in self.test_prompts[:5]:
            # Generate and log...
            messages = [{"role": "user", "content": prompt}]
            inputs = self.tokenizer.apply_chat_template(
                messages, add_generation_prompt=True, return_tensors="pt"
            ).to(model.device)
            
            import torch
            with torch.no_grad():
                outputs = model.generate(inputs, max_new_tokens=200, do_sample=False)
            response = self.tokenizer.decode(outputs[0][inputs.shape[-1]:], skip_special_tokens=True)
            
            table.add_data(state.global_step, prompt, response)
        
        wandb.log({"generations": table}, step=state.global_step)
        model.train()

✅ Production Readiness Checklist

Pre-Training Checklist
  • ☐ Data cleaned and deduplicated
  • ☐ Data split into train/eval (no leakage)
  • ☐ Tested training script with 100 examples first (dry run)
  • ☐ W&B project set up for monitoring
  • ☐ GPU memory estimated and verified
  • ☐ Checkpoint saving configured (don't lose progress)
Post-Training Checklist
  • ☐ Eval loss lower than starting point
  • ☐ No training artifacts (repetition, mode collapse)
  • ☐ Generated outputs pass manual quality check (10+ examples)
  • ☐ Domain benchmark accuracy improved
  • ☐ Citation accuracy > 80%
  • ☐ No disrespectful or harmful outputs in stress testing
  • ☐ Performance in other languages (Hindi) maintained
Pre-Deployment Checklist
  • ☐ Model merged and tested (inference without errors)
  • ☐ Quantized version produces acceptable quality
  • ☐ API endpoint responds correctly
  • ☐ Rate limiting configured
  • ☐ Input validation (max length, encoding)
  • ☐ Monitoring/alerting set up
  • ☐ Fallback behavior for errors
  • ☐ Model card / documentation written
