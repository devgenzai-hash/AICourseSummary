Intermediate Pattern Design Pattern

Strategy

Defining a family of interchangeable algorithms — encapsulate each one, and let the client swap them at runtime without changing the code that uses them.

💡 Real-World Analogy

Think of choosing a route to work — you can drive, take the bus, ride a bike, or walk. The destination is the same, but the algorithm for getting there differs. On a sunny day you bike; when it rains you drive; if traffic is jammed you take the metro. You swap strategies based on conditions — your “commute context” doesn’t change, only the strategy plugged into it. That’s the Strategy pattern: same goal, interchangeable approaches.

What Is the Strategy Pattern?

  • Intent: Define a family of algorithms, encapsulate each one, and make them interchangeable — the algorithm varies independently from clients that use it
  • Classification: Behavioral pattern (GoF) — controls which algorithm an object uses
  • Also known as: Policy pattern
  • Core idea: Composition over inheritance — instead of subclassing to change behavior, inject a strategy object
  • Open/Closed Principle: Add new algorithms without modifying existing code — just create a new strategy class

Eliminating Conditional Chains

  • Problem: Code littered with if/elif/else chains that select behavior based on a type or mode
  • Symptom: Every new variant requires modifying the same function — violates Open/Closed Principle
  • Solution: Replace conditionals with a strategy interface — each branch becomes its own strategy class
  • Result: The context delegates to whichever strategy is injected — no conditionals needed
  • Testing: Each strategy is independently unit-testable without instantiating the full context

Context + Strategy Interface

  • Context: The class that uses a strategy — holds a reference to the strategy interface, delegates work to it
  • Strategy interface: Defines the contract (method signature) that all concrete strategies must implement
  • Concrete strategies: Each implements the interface with a different algorithm
  • Client: Creates the appropriate strategy and injects it into the context
  • Runtime swap: The context can switch strategies at any point via a setter or constructor

First-Class Functions as Strategies

  • In Python, functions are objects — you can pass a function directly instead of wrapping it in a class
  • For simple strategies (single method), a callable replaces the entire class hierarchy
  • sorted(data, key=strategy_func) is the Strategy pattern with zero boilerplate
  • Use classes when strategies have state or multiple methods; use functions for stateless single-method strategies

Python Sorting Strategies

from abc import ABC, abstractmethod
from typing import List, Protocol


# ═══════════════════════════════════════════════════
# Strategy interface using Protocol (structural typing)
# ═══════════════════════════════════════════════════

class SortStrategy(Protocol):
    """Any callable that sorts a list in-place."""

    def sort(self, data: List[int]) -> List[int]:
        ...


# ═══════════════════════════════════════════════════
# Concrete strategies
# ═══════════════════════════════════════════════════

class BubbleSort:
    """O(n²) — simple but slow for large datasets."""

    def sort(self, data: List[int]) -> List[int]:
        arr = data[:]
        n = len(arr)
        for i in range(n):
            for j in range(n - i - 1):
                if arr[j] > arr[j + 1]:
                    arr[j], arr[j + 1] = arr[j + 1], arr[j]
        return arr


class QuickSort:
    """O(n log n) average — fast, general-purpose."""

    def sort(self, data: List[int]) -> List[int]:
        if len(data) <= 1:
            return data
        pivot = data[len(data) // 2]
        left = [x for x in data if x < pivot]
        middle = [x for x in data if x == pivot]
        right = [x for x in data if x > pivot]
        return self.sort(left) + middle + self.sort(right)


# ═══════════════════════════════════════════════════
# Context — delegates sorting to the injected strategy
# ═══════════════════════════════════════════════════

class Sorter:
    def __init__(self, strategy: SortStrategy):
        self._strategy = strategy

    def set_strategy(self, strategy: SortStrategy) -> None:
        """Swap algorithm at runtime."""
        self._strategy = strategy

    def sort(self, data: List[int]) -> List[int]:
        return self._strategy.sort(data)


# Usage — swap strategies without changing Sorter code
sorter = Sorter(BubbleSort())
print(sorter.sort([5, 2, 8, 1]))  # [1, 2, 5, 8]

sorter.set_strategy(QuickSort())
print(sorter.sort([5, 2, 8, 1]))  # [1, 2, 5, 8]

Payment Processing Strategies

from dataclasses import dataclass
from typing import Protocol


# ═══════════════════════════════════════════════════
# Strategy interface for payment processing
# ═══════════════════════════════════════════════════

class PaymentStrategy(Protocol):
    def pay(self, amount: float) -> str:
        ...


@dataclass
class CreditCardPayment:
    card_number: str
    cvv: str

    def pay(self, amount: float) -> str:
        masked = "****" + self.card_number[-4:]
        return f"Charged ${amount:.2f} to card {masked}"


@dataclass
class PayPalPayment:
    email: str

    def pay(self, amount: float) -> str:
        return f"Sent ${amount:.2f} via PayPal to {self.email}"


@dataclass
class CryptoPayment:
    wallet_address: str

    def pay(self, amount: float) -> str:
        return f"Transferred ${amount:.2f} in crypto to {self.wallet_address[:8]}..."


# ═══════════════════════════════════════════════════
# Context — checkout uses whatever payment is injected
# ═══════════════════════════════════════════════════

class Checkout:
    def __init__(self, payment: PaymentStrategy):
        self._payment = payment

    def process(self, amount: float) -> str:
        return self._payment.pay(amount)


# Client picks strategy based on user choice
checkout = Checkout(CreditCardPayment("4111111111111234", "123"))
print(checkout.process(99.99))
# → Charged $99.99 to card ****1234

Compression Strategy — gzip / lz4 / zstd

import gzip
import zlib
from typing import Callable


# ═══════════════════════════════════════════════════
# Function-based strategies (no class needed)
# ═══════════════════════════════════════════════════

def gzip_compress(data: bytes) -> bytes:
    """High ratio, slower speed."""
    return gzip.compress(data, compresslevel=9)


def zlib_compress(data: bytes) -> bytes:
    """Balanced ratio and speed."""
    return zlib.compress(data, level=6)


def fast_compress(data: bytes) -> bytes:
    """Minimal compression, maximum speed."""
    return zlib.compress(data, level=1)


# ═══════════════════════════════════════════════════
# Context accepts any Callable[[bytes], bytes]
# ═══════════════════════════════════════════════════

class FileArchiver:
    def __init__(self, compress: Callable[[bytes], bytes]):
        self._compress = compress

    def archive(self, data: bytes) -> bytes:
        compressed = self._compress(data)
        ratio = len(compressed) / len(data) * 100
        print(f"Compressed: {len(data)}B → {len(compressed)}B ({ratio:.1f}%)")
        return compressed


# Swap compression strategy with a single argument
archiver = FileArchiver(gzip_compress)
archiver.archive(b"Hello world! " * 1000)

archiver = FileArchiver(fast_compress)
archiver.archive(b"Hello world! " * 1000)

Route Planning Strategy

from dataclasses import dataclass
from typing import Protocol


@dataclass
class Route:
    path: str
    duration_min: int
    cost: float


class RouteStrategy(Protocol):
    def calculate(self, origin: str, dest: str) -> Route:
        ...


class FastestRoute:
    def calculate(self, origin: str, dest: str) -> Route:
        return Route(
            path=f"{origin} → Highway → {dest}",
            duration_min=20, cost=5.00
        )


class CheapestRoute:
    def calculate(self, origin: str, dest: str) -> Route:
        return Route(
            path=f"{origin} → Local roads → {dest}",
            duration_min=45, cost=0.00
        )


class ScenicRoute:
    def calculate(self, origin: str, dest: str) -> Route:
        return Route(
            path=f"{origin} → Coast road → Park → {dest}",
            duration_min=60, cost=2.50
        )


# Navigator context — strategy is swappable
class Navigator:
    def __init__(self, strategy: RouteStrategy):
        self._strategy = strategy

    def navigate(self, origin: str, dest: str) -> Route:
        return self._strategy.calculate(origin, dest)


nav = Navigator(FastestRoute())
print(nav.navigate("Home", "Office"))
# → Route(path='Home → Highway → Office', duration_min=20, cost=5.0)

🏭 Industry Applications

  • Python sorted(key=...): The key parameter is a strategy function — you pass different key extractors to change sort behavior without modifying the sorting algorithm
  • Java Comparator: Collections.sort(list, comparator) — the Comparator is a strategy object that defines ordering
  • Passport.js: Authentication strategies (LocalStrategy, GoogleStrategy, JWTStrategy) — swap auth mechanisms without changing route handlers
  • E-commerce pricing: Different pricing strategies (bulk discount, loyalty tier, seasonal sale) injected into the checkout pipeline at runtime
  • Serialization: JSON, MessagePack, Protobuf — serialize the same object differently by swapping the serializer strategy

📋 Summary

  • Strategy encapsulates interchangeable algorithms behind a common interface
  • The context delegates work to a strategy — it doesn’t know which concrete algorithm runs
  • Eliminates conditional logic — each branch becomes its own strategy class or function
  • In Python, first-class functions often replace the full class hierarchy for simple strategies
  • Follows Open/Closed Principle — add new strategies without modifying existing code

⚠️ Common Mistakes

  • Over-engineering: Using the pattern for a single algorithm that will never change — only use Strategy when you genuinely have multiple interchangeable behaviors
  • Leaking strategy details: The context should not know which specific strategy is running — if it checks the strategy type, you’ve broken the abstraction
  • Ignoring first-class functions: In Python/JavaScript, wrapping a single function in a class just to satisfy the pattern adds unnecessary complexity
  • Forgetting shared state: If strategies need access to context state, you must pass it explicitly — strategies should not reach into the context’s internals
