Beginner Pattern Design Pattern

Builder

Constructing complex objects step by step — separating the construction process from the representation so the same building logic can create different configurations.

💡 Real-World Analogy

Think of building a custom burger at a restaurant. You don’t get a random burger — you choose step by step: first the bun (brioche or sesame), then the patty (beef, chicken, or veggie), then toppings (lettuce, tomato, pickles), then the sauce (ketchup, mayo, special sauce). Each step is optional, and you build up your perfect burger one choice at a time. The cashier (Director) might suggest a “classic combo” that picks standard options for you, but you can always customize. The Builder pattern works the same way — constructing complex objects one attribute at a time.

What Is the Builder Pattern?

  • Intent: Separate the construction of a complex object from its representation, allowing the same construction process to create different representations
  • Classification: Creational pattern (GoF) — controls how complex objects are assembled
  • Key idea: Instead of a constructor with 10+ parameters, provide a step-by-step interface to set each piece
  • Fluent interface: Each setter method returns self, enabling method chaining: builder.set_x().set_y().build()
  • Immutability: The final object is often immutable — all configuration happens in the builder, then a frozen object is produced

When to Use Builder

  • Many optional parameters: When a constructor would need 5+ parameters and most are optional
  • Telescoping constructor problem: When you’d otherwise need multiple constructor overloads with different parameter combinations
  • Immutable objects: When the final object shouldn’t be modified after creation but needs complex setup
  • Step-by-step construction: When the object must be built in stages (e.g., parsing a document, assembling a query)
  • Multiple representations: When the same building process should create different output formats (HTML vs Markdown vs PDF)

Builder Components

The Builder Interface

  • Declares step methods for setting each part of the product
  • Each method returns self for chaining (fluent interface)
  • Has a build() or get_result() method that produces the final object
  • May include a reset() method to prepare for building another object

The Director (Optional)

  • Encapsulates a specific construction sequence — defines the order of build steps
  • Knows which steps to call and in what order for common configurations
  • The client doesn’t need to know the build details — just asks the Director for a preset
  • Optional — the client can call builder steps directly if they want full control

Builder vs Telescoping Constructors

  • Telescoping: Query(table, cols, where, order, limit, offset, join, group, having) — unreadable, error-prone
  • Builder: QueryBuilder().table("users").where("age > 18").limit(10).build() — self-documenting
  • Builder makes invalid states harder to represent and the code reads like English

Python Implementation — SQL Query Builder

from typing import List, Optional


# ═══════════════════════════════════════════════════
# The Product — an immutable SQL query
# ═══════════════════════════════════════════════════

class SQLQuery:
    """Immutable SQL query object — constructed only by the builder."""

    def __init__(self, sql: str, params: tuple):
        self._sql = sql
        self._params = params

    @property
    def sql(self) -> str:
        return self._sql

    @property
    def params(self) -> tuple:
        return self._params

    def __repr__(self):
        return f"SQLQuery({self._sql!r}, params={self._params})"


# ═══════════════════════════════════════════════════
# The Builder — fluent interface for constructing queries
# ═══════════════════════════════════════════════════

class QueryBuilder:
    """
    Builds SQL SELECT queries step-by-step.
    Each method returns self for method chaining.
    """

    def __init__(self):
        self._table: Optional[str] = None
        self._columns: List[str] = ["*"]
        self._conditions: List[str] = []
        self._params: List = []
        self._order_by: Optional[str] = None
        self._limit: Optional[int] = None
        self._offset: Optional[int] = None
        self._joins: List[str] = []

    def table(self, name: str) -> "QueryBuilder":
        """Set the FROM table."""
        self._table = name
        return self

    def select(self, *columns: str) -> "QueryBuilder":
        """Set columns to select."""
        self._columns = list(columns)
        return self

    def where(self, condition: str, *params) -> "QueryBuilder":
        """Add a WHERE condition with parameters."""
        self._conditions.append(condition)
        self._params.extend(params)
        return self

    def join(self, table: str, on: str) -> "QueryBuilder":
        """Add a JOIN clause."""
        self._joins.append(f"JOIN {table} ON {on}")
        return self

    def order_by(self, column: str, direction: str = "ASC") -> "QueryBuilder":
        """Set ORDER BY clause."""
        self._order_by = f"{column} {direction}"
        return self

    def limit(self, count: int) -> "QueryBuilder":
        """Set LIMIT."""
        self._limit = count
        return self

    def offset(self, count: int) -> "QueryBuilder":
        """Set OFFSET for pagination."""
        self._offset = count
        return self

    def build(self) -> SQLQuery:
        """Validate and construct the final immutable query."""
        if not self._table:
            raise ValueError("Table is required — call .table() first")

        parts = [f"SELECT {', '.join(self._columns)}"]
        parts.append(f"FROM {self._table}")

        for join in self._joins:
            parts.append(join)

        if self._conditions:
            parts.append(f"WHERE {' AND '.join(self._conditions)}")

        if self._order_by:
            parts.append(f"ORDER BY {self._order_by}")

        if self._limit is not None:
            parts.append(f"LIMIT {self._limit}")

        if self._offset is not None:
            parts.append(f"OFFSET {self._offset}")

        sql = " ".join(parts)
        return SQLQuery(sql, tuple(self._params))


# ═══════════════════════════════════════════════════
# Usage — fluent, readable query construction
# ═══════════════════════════════════════════════════

query = (
    QueryBuilder()
    .table("users")
    .select("id", "name", "email")
    .where("age > ?", 18)
    .where("active = ?", True)
    .join("orders", "orders.user_id = users.id")
    .order_by("name")
    .limit(20)
    .offset(40)
    .build()
)

print(query.sql)
# SELECT id, name, email FROM users JOIN orders ON orders.user_id = users.id
# WHERE age > ? AND active = ? ORDER BY name ASC LIMIT 20 OFFSET 40
print(query.params)  # (18, True)

HTTP Request Builder with Director

from dataclasses import dataclass, field
from typing import Dict, Optional


# ═══════════════════════════════════════════════════
# Product — immutable HTTP request
# ═══════════════════════════════════════════════════

@dataclass(frozen=True)
class HttpRequest:
    method: str
    url: str
    headers: Dict[str, str] = field(default_factory=dict)
    body: Optional[str] = None
    timeout: int = 30
    retries: int = 0


# ═══════════════════════════════════════════════════
# Builder — step-by-step request assembly
# ═══════════════════════════════════════════════════

class HttpRequestBuilder:
    """Fluent builder for HTTP requests."""

    def __init__(self):
        self._method = "GET"
        self._url = ""
        self._headers: Dict[str, str] = {}
        self._body: Optional[str] = None
        self._timeout = 30
        self._retries = 0

    def method(self, method: str) -> "HttpRequestBuilder":
        self._method = method.upper()
        return self

    def url(self, url: str) -> "HttpRequestBuilder":
        self._url = url
        return self

    def header(self, key: str, value: str) -> "HttpRequestBuilder":
        self._headers[key] = value
        return self

    def json_body(self, body: str) -> "HttpRequestBuilder":
        self._body = body
        self._headers["Content-Type"] = "application/json"
        return self

    def timeout(self, seconds: int) -> "HttpRequestBuilder":
        self._timeout = seconds
        return self

    def retries(self, count: int) -> "HttpRequestBuilder":
        self._retries = count
        return self

    def build(self) -> HttpRequest:
        if not self._url:
            raise ValueError("URL is required")
        return HttpRequest(
            method=self._method,
            url=self._url,
            headers=dict(self._headers),
            body=self._body,
            timeout=self._timeout,
            retries=self._retries,
        )


# ═══════════════════════════════════════════════════
# Director — knows how to build common request types
# ═══════════════════════════════════════════════════

class RequestDirector:
    """Encapsulates common request construction sequences."""

    def __init__(self, base_url: str, api_key: str):
        self._base_url = base_url
        self._api_key = api_key

    def build_auth_get(self, path: str) -> HttpRequest:
        """Pre-configured authenticated GET request."""
        return (
            HttpRequestBuilder()
            .method("GET")
            .url(f"{self._base_url}{path}")
            .header("Authorization", f"Bearer {self._api_key}")
            .header("Accept", "application/json")
            .timeout(10)
            .retries(3)
            .build()
        )

    def build_auth_post(self, path: str, body: str) -> HttpRequest:
        """Pre-configured authenticated POST request."""
        return (
            HttpRequestBuilder()
            .method("POST")
            .url(f"{self._base_url}{path}")
            .header("Authorization", f"Bearer {self._api_key}")
            .json_body(body)
            .timeout(30)
            .retries(1)
            .build()
        )


# Usage with Director
director = RequestDirector("https://api.example.com", "sk-abc123")
get_req = director.build_auth_get("/users")
post_req = director.build_auth_post("/users", '{"name": "Alice"}')

print(f"GET:  {get_req.method} {get_req.url}")
print(f"POST: {post_req.method} {post_req.url}, body={post_req.body}")

🏭 Industry Practice

SQLAlchemy Query Building: SQLAlchemy’s ORM uses a fluent builder interface — session.query(User).filter(User.age > 18).order_by(User.name).limit(10). Each method returns a new query object (immutable chaining), allowing you to build complex SQL without string concatenation or injection risks.

Django ORM QuerySets: Django’s QuerySets are lazy builders — User.objects.filter(active=True).exclude(age__lt=18).order_by("name"). They don’t hit the database until evaluated, letting you compose queries across multiple functions before execution.

Protocol Buffers: Google’s protobuf uses builders in Java/C++ — Person.newBuilder().setName("Alice").setAge(30).build(). The builder validates that required fields are set and produces an immutable protobuf message. In Python, protobuf uses direct assignment but the principle is the same.

StringBuilder / StringBuffer: Java’s StringBuilder is a classic builder — appending strings one at a time is more efficient than concatenation and produces the final string with .toString(). Python’s equivalent is joining a list: "".join(parts).

📋 Key Takeaways

  • Builder separates object construction from representation — build complex objects step by step
  • Method chaining (fluent interface) makes code self-documenting: each step reads like English
  • The Director encapsulates common build sequences — clients don’t need to know every step
  • Builder naturally produces immutable objects — all mutation happens during building, then freezes
  • Solves the telescoping constructor problem — no more constructors with 10+ positional arguments
  • Validation happens at build() time — you can check all invariants before creating the object

🧠 Mental Model

Think of Builder as an order form. You fill in fields one at a time, in any order. When you’re done, you submit the form (call .build()) and get back a finished product. The form validates everything before processing — if required fields are missing, it rejects the submission.

⚠️ Common Mistakes

  • Forgetting to return self: If a builder method doesn’t return self, the chain breaks and returns None. Every setter method must end with return self to enable fluent chaining. One missing return silently breaks the entire chain.
  • No validation in build(): Calling build() without checking required fields produces an invalid object. Always validate invariants — if table is required, raise a clear error in build() rather than producing a broken query that fails at runtime.
  • Mutable builder reuse without reset: If you reuse a builder instance without resetting its state, the second object inherits leftover configuration from the first build. Either create a new builder for each product or call reset() after build().
  • Over-engineering simple objects: Using a Builder for a class with 2–3 parameters is unnecessary ceremony. A simple constructor or dataclass with defaults is clearer. Builder shines when you have 5+ optional parameters or complex construction logic.

🎯 Exercises

  1. Build a Pizza: Create a PizzaBuilder with methods for size(), crust(), sauce(), add_topping(), and build(). The build() method should validate that size and crust are set (required) while sauce and toppings are optional. Create a PizzaDirector with presets like margherita() and pepperoni().
  2. Email Builder: Implement an EmailBuilder that constructs email messages with to(), cc(), bcc(), subject(), body(), attach(), and build(). Validate that “to” and “subject” are required. Support method chaining and produce a frozen dataclass as output.
  3. Immutable Config: Build a ConfigBuilder that reads from environment variables, .env files, and command-line args (in that priority order). Each .from_env(), .from_file(path), .from_args() call layers on more config. The final build() merges all sources and returns a frozen config object.
  4. HTML Tag Builder: Create a builder that constructs HTML elements: Tag("div").id("main").class_("container").attr("data-x", "1").child(Tag("p").text("Hello")).build(). The build() method should return a properly nested HTML string. Support arbitrary nesting depth.
