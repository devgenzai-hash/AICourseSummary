System Design/ Futures, Promises & Async/Await

Futures, Promises & Async/Await

A way to say 'start this task now, I will collect the result later.' The foundation of non-blocking programming in every modern language.

Intermediate Pattern Code
Ordering Food at a Restaurant

Future/Promise: You order food (submit a task). The waiter gives you a buzzer (the Future object). You can go do other things. When the buzzer goes off, your food is ready (result available).

Async/Await: Same restaurant, but you say "I will wait here but let other customers order while my food cooks." You pause (await), others proceed, and you resume when ready.

Futures: A Placeholder for a Result

from concurrent.futures import ThreadPoolExecutor, Future
import time

def slow_api_call(user_id):
    time.sleep(2)
    return {"id": user_id, "name": f"User {user_id}"}

executor = ThreadPoolExecutor(max_workers=4)

# Submit returns a Future immediately (non-blocking)
future = executor.submit(slow_api_call, 42)
print(f"Is done? {future.done()}")  # False — still running

# Do other work while waiting...
print("Doing other things...")

# Block until result is ready
result = future.result(timeout=5)  # Waits up to 5s
print(f"Got: {result}")

# Callback approach (don't block at all)
def on_complete(fut):
    print(f"Callback received: {fut.result()}")

future2 = executor.submit(slow_api_call, 99)
future2.add_done_callback(on_complete)

Async/Await: Cooperative Multitasking

import asyncio

async def fetch_user(user_id):
    print(f"Fetching user {user_id}...")
    await asyncio.sleep(1)  # Non-blocking sleep (simulates I/O)
    return {"id": user_id, "name": f"User {user_id}"}

async def fetch_order(order_id):
    await asyncio.sleep(1.5)
    return {"order": order_id, "total": 99.99}

async def main():
    # Run BOTH concurrently — total time: 1.5s (not 2.5s!)
    user, order = await asyncio.gather(
        fetch_user(1),
        fetch_order(100)
    )
    print(f"User: {user}, Order: {order}")

asyncio.run(main())

Futures vs Async/Await

FeatureFutures (ThreadPool)Async/Await
Concurrency modelMulti-threaded (OS threads)Single-threaded (event loop)
Overhead per task~1MB (thread stack)~1KB (coroutine frame)
Max concurrency~1000 threads~100,000 coroutines
Best forCPU-bound, blocking I/O libsMany I/O-bound tasks
ComplexitySimpler (familiar threading)Requires async ecosystem

Error Handling in Async

async def risky_operation():
    await asyncio.sleep(1)
    raise ValueError("Something went wrong")

async def safe_main():
    try:
        result = await risky_operation()
    except ValueError as e:
        print(f"Caught: {e}")

    # With gather: exceptions are returned, not raised
    results = await asyncio.gather(
        fetch_user(1),
        risky_operation(),
        return_exceptions=True
    )
    for r in results:
        if isinstance(r, Exception):
            print(f"Failed: {r}")
        else:
            print(f"Success: {r}")

Industry Usage

  • FastAPI — async/await for handling thousands of concurrent HTTP requests
  • Node.js — Entire runtime built on Promises and async/await
  • Rust tokio — Async runtime handling millions of concurrent connections
  • Java CompletableFuture — Chainable futures with thenApply(), thenCompose()

📝 Summary

  • Future: a placeholder for a result that will be available later
  • Async/await: cooperative multitasking on a single thread (event loop)
  • Futures use real OS threads (~1MB each); coroutines use ~1KB each
  • Use asyncio.gather() to run multiple async operations concurrently
  • Futures for blocking libraries; async for I/O-heavy async-compatible code
  • Always handle exceptions in futures (they are swallowed silently otherwise)

🧠 Mental Model

FUTURE: submit(task) → [Future: pending...] ... do other work ... future.result() → [Future: DONE] → actual result ASYNC/AWAIT: Event Loop: ─── run A ─── A awaits (pauses) ─── run B ─── B awaits ─── resume A ─── Single thread, multiple tasks interleaved at await points. Sequential: |--A (1s)--|--B (1s)--| = 2s total Concurrent: |--A--| |--B--| = 1s total (overlapping I/O)

❌ Common Beginner Mistakes

  • Blocking inside async function — time.sleep() blocks the entire event loop! Use await asyncio.sleep().
  • Not awaiting coroutines — Calling async_func() without await = coroutine never runs.
  • Mixing sync and async — Calling sync blocking code inside async without run_in_executor().
  • Forgetting to check future exceptions — Exceptions in futures are lost unless you call .result().

🏋 Hands-On Exercise

  1. Submit 10 tasks to ThreadPoolExecutor. Use as_completed() to print results as they finish.
  2. Rewrite the same with asyncio: 10 async tasks with asyncio.gather().
  3. Benchmark: ThreadPoolExecutor vs asyncio for 1000 simulated HTTP requests.
  4. Implement a timeout: cancel a future if it takes more than 3 seconds.
