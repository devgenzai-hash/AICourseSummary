Intermediate Pattern Design Pattern

Decorator

Adding new behavior dynamically by wrapping objects in layers — composition over inheritance for extending functionality without modifying existing code.

💡 Real-World Analogy

Think of adding toppings to ice cream. You start with a base scoop of vanilla. Then you add a layer of chocolate sauce — now you have vanilla + chocolate. Then sprinkles on top — vanilla + chocolate + sprinkles. Each topping wraps the previous creation, adding its own feature without changing what’s underneath. You can stack any combination in any order. The Decorator pattern works the same way — each decorator wraps the previous object, adding behavior while preserving the original interface.

What Is the Decorator Pattern?

  • Intent: Attach additional responsibilities to an object dynamically — a flexible alternative to subclassing
  • Classification: Structural pattern (GoF) — controls how objects are composed
  • Key principle: Composition over inheritance — wrap rather than extend
  • Interface preservation: The decorator has the same interface as the wrapped object — clients can’t tell the difference
  • Stackable: Multiple decorators can wrap each other in any order, each adding one concern

When to Use Decorator

  • Cross-cutting concerns: Logging, timing, caching, authentication, retry logic — behaviors that apply to many functions/classes
  • Single Responsibility: Keep each decorator focused on one concern (logging OR caching, not both)
  • Runtime flexibility: When you need to add/remove behavior at runtime, not compile time
  • Avoiding class explosion: Instead of LoggedCachedAuthenticatedService, stack three decorators
  • Open/Closed Principle: Extend behavior without modifying the original class

Python @ Decorators vs GoF Decorator

Python’s @ Syntax (Function Decorators)

  • Python’s @decorator syntax is syntactic sugar for func = decorator(func)
  • Wraps a function/method with additional behavior — same concept, simpler syntax
  • Most common in Python: @staticmethod, @property, @lru_cache, @login_required
  • Works on functions, methods, and classes

GoF Decorator Pattern (Class-Based)

  • A class that wraps another object of the same interface, adding behavior before/after delegation
  • Both the decorator and the wrapped object implement the same abstract interface
  • More verbose than Python’s @ syntax but works for objects with multiple methods
  • Used in Java I/O streams: new BufferedReader(new InputStreamReader(new FileInputStream(file)))
Aspect Python @ Decorator GoF Decorator (Class) Inheritance
Mechanism Function wrapping Object composition Class extension
Granularity Single function/method Entire object interface Entire class
Stacking Multiple @ stacked Nested wrappers Deep hierarchies
Runtime flexibility Applied at definition Applied at runtime Fixed at compile time
Combinatorial Any combination Any combination Class per combo (explosion)

Python Function Decorators — Practical Examples

import time
import functools
from typing import Any, Callable, Dict


# ═══════════════════════════════════════════════════
# DECORATOR 1: Timing / Performance measurement
# ═══════════════════════════════════════════════════

def timer(func: Callable) -> Callable:
    """Measure and print execution time of a function."""

    @functools.wraps(func)
    def wrapper(*args, **kwargs) -> Any:
        start = time.perf_counter()
        result = func(*args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"  [{func.__name__}] took {elapsed:.4f}s")
        return result

    return wrapper


# ═══════════════════════════════════════════════════
# DECORATOR 2: Simple caching (memoization)
# ═══════════════════════════════════════════════════

def cache(func: Callable) -> Callable:
    """Cache function results based on arguments."""
    _cache: Dict[tuple, Any] = {}

    @functools.wraps(func)
    def wrapper(*args, **kwargs) -> Any:
        key = (args, tuple(sorted(kwargs.items())))
        if key not in _cache:
            _cache[key] = func(*args, **kwargs)
            print(f"  [{func.__name__}] MISS — computed and cached")
        else:
            print(f"  [{func.__name__}] HIT — returned from cache")
        return _cache[key]

    wrapper.clear_cache = lambda: _cache.clear()
    return wrapper


# ═══════════════════════════════════════════════════
# DECORATOR 3: Retry with exponential backoff
# ═══════════════════════════════════════════════════

def retry(max_attempts: int = 3, backoff: float = 1.0):
    """Retry a function on exception with exponential backoff."""

    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper(*args, **kwargs) -> Any:
            last_exception = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_exception = e
                    wait = backoff * (2 ** (attempt - 1))
                    print(f"  [{func.__name__}] attempt {attempt} failed: {e}")
                    print(f"  Retrying in {wait:.1f}s...")
                    time.sleep(wait)
            raise last_exception

        return wrapper
    return decorator


# ═══════════════════════════════════════════════════
# DECORATOR 4: Authentication check
# ═══════════════════════════════════════════════════

def require_auth(role: str = "user"):
    """Check that the caller has the required role."""

    def decorator(func: Callable) -> Callable:
        @functools.wraps(func)
        def wrapper(*args, **kwargs) -> Any:
            # In real code, check request context or token
            current_user = kwargs.get("user", {})
            user_role = current_user.get("role", "anonymous")

            if user_role != role and user_role != "admin":
                raise PermissionError(
                    f"Requires '{role}' role, got '{user_role}'"
                )
            print(f"  [{func.__name__}] auth passed (role={user_role})")
            return func(*args, **kwargs)

        return wrapper
    return decorator


# ═══════════════════════════════════════════════════
# Stacking decorators — each adds one concern
# ═══════════════════════════════════════════════════

@timer
@cache
def expensive_query(user_id: int) -> Dict:
    """Simulates a slow database query."""
    time.sleep(0.1)  # simulate latency
    return {"id": user_id, "name": "Alice", "email": "alice@example.com"}


@retry(max_attempts=3, backoff=0.1)
@require_auth(role="admin")
def delete_user(user_id: int, user: Dict = None) -> str:
    """Delete a user — requires admin role, retries on failure."""
    return f"User {user_id} deleted"


# Demo
print("=== Stacked Decorators ===")
print("First call (cache miss):")
expensive_query(42)
print("Second call (cache hit):")
expensive_query(42)
print()
print("Admin delete:")
delete_user(1, user={"role": "admin"})

Class-Based Decorator — Wrapping a Service

from abc import ABC, abstractmethod
import time
import logging


# ═══════════════════════════════════════════════════
# Component interface — shared by both core and decorators
# ═══════════════════════════════════════════════════

class DataService(ABC):
    """Interface for data retrieval services."""

    @abstractmethod
    def get_data(self, key: str) -> str:
        ...

    @abstractmethod
    def set_data(self, key: str, value: str) -> None:
        ...


# ═══════════════════════════════════════════════════
# Concrete component — the core service
# ═══════════════════════════════════════════════════

class DatabaseService(DataService):
    """Real database service — the object being decorated."""

    def __init__(self):
        self._store = {}

    def get_data(self, key: str) -> str:
        time.sleep(0.05)  # simulate DB latency
        return self._store.get(key, "")

    def set_data(self, key: str, value: str) -> None:
        time.sleep(0.05)
        self._store[key] = value


# ═══════════════════════════════════════════════════
# Base decorator — delegates to wrapped service
# ═══════════════════════════════════════════════════

class ServiceDecorator(DataService):
    """Base decorator — wraps a DataService and delegates."""

    def __init__(self, wrapped: DataService):
        self._wrapped = wrapped

    def get_data(self, key: str) -> str:
        return self._wrapped.get_data(key)

    def set_data(self, key: str, value: str) -> None:
        self._wrapped.set_data(key, value)


# ═══════════════════════════════════════════════════
# Decorator 1: Logging
# ═══════════════════════════════════════════════════

class LoggingDecorator(ServiceDecorator):
    """Adds logging around every operation."""

    def get_data(self, key: str) -> str:
        print(f"  [LOG] get_data('{key}')")
        result = super().get_data(key)
        print(f"  [LOG] get_data → '{result}'")
        return result

    def set_data(self, key: str, value: str) -> None:
        print(f"  [LOG] set_data('{key}', '{value}')")
        super().set_data(key, value)


# ═══════════════════════════════════════════════════
# Decorator 2: Caching
# ═══════════════════════════════════════════════════

class CachingDecorator(ServiceDecorator):
    """Adds an in-memory cache layer."""

    def __init__(self, wrapped: DataService):
        super().__init__(wrapped)
        self._cache = {}

    def get_data(self, key: str) -> str:
        if key in self._cache:
            print(f"  [CACHE] HIT for '{key}'")
            return self._cache[key]
        print(f"  [CACHE] MISS for '{key}'")
        result = super().get_data(key)
        self._cache[key] = result
        return result

    def set_data(self, key: str, value: str) -> None:
        self._cache[key] = value  # update cache
        super().set_data(key, value)  # write through


# ═══════════════════════════════════════════════════
# Stacking decorators at runtime
# ═══════════════════════════════════════════════════

# Build the decorator stack: Logging → Caching → Database
db = DatabaseService()
cached_db = CachingDecorator(db)
service = LoggingDecorator(cached_db)

# Client uses the same interface regardless of decorators
print("=== Class-Based Decorator Stack ===")
service.set_data("user:1", "Alice")
print()
service.get_data("user:1")  # cache hit
print()
service.get_data("user:2")  # cache miss → hits DB

🏭 Industry Practice

Python functools.wraps: The standard library’s @functools.wraps(func) is itself a decorator that preserves the wrapped function’s name, docstring, and signature. Without it, decorated functions lose their identity — help(my_func) would show the wrapper’s docstring instead of the original’s.

Java I/O Streams: Java’s I/O is built entirely on the Decorator pattern — new BufferedReader(new InputStreamReader(new FileInputStream("file.txt"))). Each wrapper adds one capability: byte→char conversion, buffering, etc. You compose exactly what you need.

Express.js Middleware: Express middleware functions are decorators for HTTP handlers. Each middleware wraps the next, adding authentication, logging, CORS headers, body parsing. app.use(cors()); app.use(auth()); app.use(logger()) — stacked decorators.

Django View Decorators: Django’s @login_required, @permission_required, @cache_page(300) are decorators that wrap view functions with cross-cutting concerns. They check auth, cache responses, or rate-limit without touching the view logic.

📋 Key Takeaways

  • Decorator adds behavior dynamically by wrapping objects — composition over inheritance
  • Each decorator is single-responsibility — one concern per decorator (logging, caching, auth)
  • Decorators are stackable in any order — avoiding the class explosion of inheritance
  • Python’s @ syntax is the function-level version; GoF Decorator is the object-level version
  • Always use @functools.wraps in Python decorators to preserve function metadata
  • Decorator preserves the interface — unlike Adapter (converts) or Facade (simplifies)

🧠 Mental Model

Think of decorators as Russian nesting dolls (matryoshka). The innermost doll is your core function. Each outer doll adds a layer — paint, glitter, varnish — without changing the doll inside. When you “open” a decorated function, the call passes through each layer (outer → inner), executes the core, then returns through each layer (inner → outer).

      ...

⚠️ Common Mistakes

  • Forgetting @functools.wraps: Without @functools.wraps(func), the decorated function loses its __name__, __doc__, and __module__. Debugging becomes impossible because stack traces show “wrapper” instead of the real function name. Always use it.
  • Order confusion with stacked decorators: @A @B def f() means f = A(B(f)) — B wraps f first, then A wraps the result. The topmost decorator is the outermost layer. Getting this wrong means auth checks happen after the function runs, or caching wraps the wrong thing.
  • Decorators with side effects on import: If your decorator does heavy work (connecting to databases, starting threads) at decoration time rather than call time, importing the module triggers those side effects. Decorators should be lightweight — defer heavy work to the first call.
  • Breaking the interface contract: A class-based decorator must implement all methods of the interface it wraps. If you only override get_data() but forget set_data(), calls to set_data() bypass your decorator entirely, leading to inconsistent behavior (e.g., cache never invalidated on writes).

🎯 Exercises

  1. Rate limiter decorator: Write a @rate_limit(calls=5, period=60) decorator that raises an exception if a function is called more than N times within a time window. Track calls with timestamps and clean up expired entries. Test that the 6th call within 60 seconds raises RateLimitExceeded.
  2. Validation decorator: Create a @validate_types decorator that checks function arguments match their type annotations at runtime. Use inspect.signature to get parameter types and raise TypeError with a helpful message if any argument doesn’t match. Ignore parameters without annotations.
  3. Class-based encryption decorator: Implement an EncryptionDecorator(DataService) that encrypts values on set_data() and decrypts on get_data(). Use a simple cipher (XOR or base64 for demo). Stack it with the CachingDecorator and verify that the cache stores encrypted values while get_data() returns plaintext.
  4. Decorator composition framework: Build a compose_decorators(*decorators) function that takes multiple decorator functions and returns a single combined decorator. Example: @compose_decorators(timer, cache, retry(3)) should be equivalent to stacking all three. Handle both simple decorators and decorator factories (decorators with arguments).
