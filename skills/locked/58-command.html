Intermediate Pattern Design Pattern

Command

Encapsulating a request as an object — letting you parameterize clients with different requests, queue or log requests, and support undoable operations.

💡 Real-World Analogy

Think of a restaurant order ticket. The waiter writes down your order (the command object), passes it to the kitchen. The kitchen doesn’t need to know who ordered or when — it just executes the ticket. Orders can be queued (busy night), logged (receipt), prioritized (VIP table), or even cancelled before cooking starts. The ticket decouples the customer from the chef — that’s the Command pattern: encapsulate an action so it can be stored, forwarded, and undone.

What Is the Command Pattern?

  • Intent: Encapsulate a request as an object, thereby letting you parameterize clients, queue requests, log them, and support undo
  • Classification: Behavioral pattern (GoF) — turns a method call into a first-class object
  • Also known as: Action, Transaction
  • Key insight: By reifying (making into an object) a request, you gain the ability to store, serialize, replay, and reverse it
  • Participants: Command (interface), ConcreteCommand, Receiver (does the work), Invoker (triggers the command), Client (creates commands)

Undo/Redo Support

  • Each command stores enough state to reverse its effect — the undo() method restores previous state
  • Command history: Maintain a stack of executed commands — pop and undo to reverse, push to a redo stack
  • Memento integration: For complex state, commands can store a snapshot (memento) before executing
  • Granularity: Each command should represent one atomic, undoable action — not a batch of unrelated changes
  • Limitation: Not all operations are reversible (sending an email, deleting a database) — use compensating commands instead

Command Queuing & Scheduling

  • Deferred execution: Commands are objects — you can store them in a queue and execute later (task schedulers, job queues)
  • Priority queues: Commands can carry metadata (priority, timestamp) for ordering
  • Retry logic: Failed commands can be re-queued with backoff — the command object persists across attempts
  • Distributed systems: Serialize commands to JSON/Protobuf and send across network boundaries

Macro Commands (Composite)

  • A macro command is a command that contains a list of sub-commands — executing it runs all sub-commands in sequence
  • Undoing a macro undoes all sub-commands in reverse order
  • Combines Command pattern with Composite pattern — treat a group of commands as a single command
  • Use case: “Format Document” = remove trailing spaces + fix indentation + sort imports

Command Logging for Replay

  • Persist every command to a log (event store) — replay the log to reconstruct state from scratch
  • Foundation of event sourcing — the log IS the source of truth, not the current state
  • Enables time-travel debugging, audit trails, and crash recovery
  • Database write-ahead logs (WAL) are command logs — replay to recover after crash

Text Editor with Undo/Redo

from abc import ABC, abstractmethod
from typing import List


# ═══════════════════════════════════════════════════
# Command interface
# ═══════════════════════════════════════════════════

class Command(ABC):
    @abstractmethod
    def execute(self) -> None:
        ...

    @abstractmethod
    def undo(self) -> None:
        ...


# ═══════════════════════════════════════════════════
# Receiver — the actual text buffer
# ═══════════════════════════════════════════════════

class TextBuffer:
    def __init__(self):
        self._content: str = ""

    @property
    def content(self) -> str:
        return self._content

    def insert(self, position: int, text: str) -> None:
        self._content = self._content[:position] + text + self._content[position:]

    def delete(self, position: int, length: int) -> str:
        deleted = self._content[position:position + length]
        self._content = self._content[:position] + self._content[position + length:]
        return deleted


# ═══════════════════════════════════════════════════
# Concrete commands
# ═══════════════════════════════════════════════════

class InsertCommand(Command):
    def __init__(self, buffer: TextBuffer, position: int, text: str):
        self._buffer = buffer
        self._position = position
        self._text = text

    def execute(self) -> None:
        self._buffer.insert(self._position, self._text)

    def undo(self) -> None:
        self._buffer.delete(self._position, len(self._text))


class DeleteCommand(Command):
    def __init__(self, buffer: TextBuffer, position: int, length: int):
        self._buffer = buffer
        self._position = position
        self._length = length
        self._deleted_text: str = ""

    def execute(self) -> None:
        self._deleted_text = self._buffer.delete(self._position, self._length)

    def undo(self) -> None:
        self._buffer.insert(self._position, self._deleted_text)


# ═══════════════════════════════════════════════════
# Invoker — manages command history for undo/redo
# ═══════════════════════════════════════════════════

class Editor:
    def __init__(self):
        self.buffer = TextBuffer()
        self._history: List[Command] = []
        self._redo_stack: List[Command] = []

    def execute(self, command: Command) -> None:
        command.execute()
        self._history.append(command)
        self._redo_stack.clear()  # new action invalidates redo

    def undo(self) -> None:
        if self._history:
            cmd = self._history.pop()
            cmd.undo()
            self._redo_stack.append(cmd)

    def redo(self) -> None:
        if self._redo_stack:
            cmd = self._redo_stack.pop()
            cmd.execute()
            self._history.append(cmd)


# Usage
editor = Editor()
editor.execute(InsertCommand(editor.buffer, 0, "Hello "))
editor.execute(InsertCommand(editor.buffer, 6, "World"))
print(editor.buffer.content)  # "Hello World"

editor.undo()
print(editor.buffer.content)  # "Hello "

editor.redo()
print(editor.buffer.content)  # "Hello World"

Task Queue with Command Objects

from collections import deque
from typing import Protocol
import time


# ═══════════════════════════════════════════════════
# Command protocol — any object with execute()
# ═══════════════════════════════════════════════════

class Task(Protocol):
    def execute(self) -> str:
        ...


class SendEmailTask:
    def __init__(self, to: str, subject: str):
        self.to = to
        self.subject = subject

    def execute(self) -> str:
        return f"Email sent to {self.to}: '{self.subject}'"


class GenerateReportTask:
    def __init__(self, report_type: str):
        self.report_type = report_type

    def execute(self) -> str:
        return f"Generated {self.report_type} report"


class CleanupTask:
    def __init__(self, directory: str):
        self.directory = directory

    def execute(self) -> str:
        return f"Cleaned up {self.directory}"


# ═══════════════════════════════════════════════════
# Invoker — processes queued commands sequentially
# ═══════════════════════════════════════════════════

class TaskQueue:
    def __init__(self):
        self._queue: deque[Task] = deque()
        self._log: list[str] = []

    def enqueue(self, task: Task) -> None:
        self._queue.append(task)

    def process_all(self) -> list[str]:
        results = []
        while self._queue:
            task = self._queue.popleft()
            result = task.execute()
            self._log.append(result)
            results.append(result)
        return results

    @property
    def log(self) -> list[str]:
        return self._log[:]


# Queue commands and process later
queue = TaskQueue()
queue.enqueue(SendEmailTask("dev@example.com", "Deploy complete"))
queue.enqueue(GenerateReportTask("weekly-metrics"))
queue.enqueue(CleanupTask("/tmp/builds"))

for result in queue.process_all():
    print(result)
# → Email sent to dev@example.com: 'Deploy complete'
# → Generated weekly-metrics report
# → Cleaned up /tmp/builds

Macro Command (Composite)

from typing import List


# ═══════════════════════════════════════════════════
# Macro command — groups multiple commands as one
# ═══════════════════════════════════════════════════

class MacroCommand(Command):
    """Execute multiple commands as a single undoable unit."""

    def __init__(self, commands: List[Command]):
        self._commands = commands

    def execute(self) -> None:
        for cmd in self._commands:
            cmd.execute()

    def undo(self) -> None:
        # Undo in reverse order
        for cmd in reversed(self._commands):
            cmd.undo()


# Usage — "Format Document" macro
editor = Editor()
editor.execute(InsertCommand(editor.buffer, 0, "  hello  world  "))

# Create a macro that does multiple operations
macro = MacroCommand([
    DeleteCommand(editor.buffer, 0, 2),   # remove leading spaces
    DeleteCommand(editor.buffer, 12, 2),  # remove trailing spaces
])

editor.execute(macro)
print(editor.buffer.content)  # "hello  world"

# Single undo reverses the entire macro
editor.undo()
print(editor.buffer.content)  # "  hello  world  "

🏭 Industry Applications

  • Redux actions: Every action is a command object — { type: 'ADD_TODO', payload: {...} } — stored, replayed, and time-traveled via Redux DevTools
  • Git commands: Each commit is a command with enough information to be replayed (cherry-pick) or reversed (revert) — the reflog is a command history
  • Database WAL: Write-ahead logs record every write command — replay the log to recover state after a crash
  • GUI undo systems: Photoshop, VS Code, and every text editor use command stacks — Ctrl+Z pops and undoes the last command
  • CQRS: Command Query Responsibility Segregation — separate the write model (commands) from the read model (queries) for scalability

📋 Summary

  • Command turns a request into an object — decoupling the sender from the receiver
  • Enables undo/redo by storing executed commands and reversing them
  • Commands can be queued, logged, serialized, and replayed — foundation of event sourcing
  • Macro commands group sub-commands into a single undoable unit
  • The pattern trades simplicity for flexibility — use it when you need history, queuing, or decoupling

⚠️ Common Mistakes

  • Forgetting undo state: A command that doesn’t store enough information to reverse itself — always capture the “before” state at execute time
  • Unbounded history: Storing every command forever leads to memory leaks — cap the history size or periodically checkpoint and discard old commands
  • Non-atomic macros: If a macro partially executes and one sub-command fails, the system is in an inconsistent state — implement rollback for the already-executed sub-commands
  • Overusing the pattern: Simple direct method calls don’t need command objects — only use when you need undo, queuing, logging, or decoupling

🎯 Exercises

  1. Drawing app: Create commands for DrawCircle, DrawRect, ChangeColor. Implement undo/redo that removes/restores shapes from a canvas list.
  2. File system commands: Build CreateFile, DeleteFile, RenameFile commands with full undo support. Test that undo(delete) restores content.
  3. Transaction system: Implement Transfer(from, to, amount) as a command. Support undo (reverse transfer) and logging for audit trail.
  4. Command serialization: Serialize commands to JSON, store them, then deserialize and replay to reconstruct state from an empty starting point.
