System Design/ Leader Election

Leader Election

Choosing one node to coordinate work so the cluster doesn't behave like a group project with no owner. Someone must be in charge.

Advanced Concept Distributed
🏠 Daily-Life Analogy: The Group Project Captain

Imagine 5 people working on a school project. Without a captain, chaos happens:

  • Two people write the same section
  • Nobody submits the final version
  • Everyone assumes someone else is handling the deadline

So they elect a captain. The captain assigns work, collects results, and submits the final version. If the captain gets sick, the group quickly picks a new captain and continues.

In distributed systems, this captain is called the leader. The process of picking the captain is leader election.

Why Do We Need Leader Election?

Many distributed systems need ONE node to be "special" — the coordinator. Without a leader:

  • Split brain: Two nodes both think they're in charge → conflicting decisions
  • Duplicate work: Multiple nodes process the same task
  • No coordination: Who decides the order of operations? Who handles the write?

What the Leader Does

SystemWhat the Leader Does
Database (e.g., MongoDB)Accepts all writes, replicates to followers
KafkaPartition leader handles all reads/writes for that partition
KubernetesController manager leader runs all control loops
Raft consensusLeader proposes values, coordinates log replication
Distributed cronLeader decides which node runs each scheduled job

Algorithm 1: Bully Election

The simplest leader election algorithm. Every node has a unique ID (number). The rule is simple: the node with the highest ID always wins.

import time
import random

class BullyNode:
    """Implements the Bully Election Algorithm"""

    def __init__(self, node_id, all_nodes):
        self.id = node_id
        self.all_nodes = all_nodes  # List of all node IDs in cluster
        self.leader = None
        self.is_alive = True

    def start_election(self):
        """Start an election when we detect the leader is dead"""
        print(f"Node {self.id}: Starting election!")

        # Send "ELECTION" message to all nodes with HIGHER IDs
        higher_nodes = [n for n in self.all_nodes if n > self.id]

        if not higher_nodes:
            # I have the highest ID → I am the leader!
            self.declare_victory()
            return

        # Ask higher nodes if they're alive
        responses = []
        for node_id in higher_nodes:
            response = self.send_election_message(node_id)
            if response:
                responses.append(node_id)

        if not responses:
            # No higher node responded → I win!
            self.declare_victory()
        else:
            # Higher node exists → wait for them to declare victory
            print(f"Node {self.id}: Higher node(s) responded. Waiting...")

    def declare_victory(self):
        """Announce to everyone: I am the new leader"""
        self.leader = self.id
        print(f"Node {self.id}: I AM THE NEW LEADER! 👑")
        # Broadcast COORDINATOR message to all nodes
        for node_id in self.all_nodes:
            if node_id != self.id:
                self.send_coordinator_message(node_id)

    def send_election_message(self, target_id):
        """Simulate sending election message (returns True if node is alive)"""
        # In real system: network call with timeout
        return target_id in self.all_nodes  # Simplified

    def send_coordinator_message(self, target_id):
        print(f"Node {self.id} → Node {target_id}: I'm your new leader")


# Simulation
all_nodes = [1, 2, 3, 4, 5]
# Node 5 (leader) dies. Node 3 detects it and starts election.
node3 = BullyNode(3, [1, 2, 3, 4])  # Node 5 removed (dead)
node3.start_election()  # Node 4 will respond → Node 4 becomes leader

Algorithm 2: Ring Election

Nodes are arranged in a logical ring. When a node detects the leader is dead, it sends an election message around the ring. Each node adds its ID. The highest ID wins.

class RingElection:
    """Ring-based leader election"""

    def __init__(self, nodes):
        self.nodes = sorted(nodes)  # Nodes arranged in a ring
        self.leader = None

    def elect(self, initiator):
        """Initiator starts election, message goes around the ring"""
        print(f"Node {initiator} starts ring election")

        # Election message collects all alive node IDs as it travels
        election_msg = [initiator]
        current = self._next_node(initiator)

        # Pass message around the ring
        while current != initiator:
            print(f"  Message at Node {current}, candidates so far: {election_msg}")
            election_msg.append(current)
            current = self._next_node(current)

        # Message returned to initiator — pick highest ID
        self.leader = max(election_msg)
        print(f"Election complete! Leader: Node {self.leader} 👑")

    def _next_node(self, node_id):
        idx = self.nodes.index(node_id)
        return self.nodes[(idx + 1) % len(self.nodes)]

ring = RingElection([1, 2, 3, 4, 5])
ring.elect(3)  # Node 3 initiates → Node 5 wins

Algorithm 3: Raft Leader Election (Industry Standard)

Raft is the most practical leader election algorithm used in production. It uses terms (numbered rounds) and heartbeats.

import random
import time
from enum import Enum

class State(Enum):
    FOLLOWER = "follower"
    CANDIDATE = "candidate"
    LEADER = "leader"

class RaftNode:
    """Simplified Raft leader election"""

    def __init__(self, node_id, cluster_size):
        self.id = node_id
        self.state = State.FOLLOWER
        self.current_term = 0        # Election epoch (increases each election)
        self.voted_for = None         # Who I voted for this term
        self.votes_received = 0
        self.cluster_size = cluster_size
        self.leader_id = None

        # Random election timeout (prevents everyone voting at once)
        self.election_timeout = random.uniform(150, 300)  # ms

    def start_election(self):
        """Called when election timeout fires (no heartbeat from leader)"""
        self.state = State.CANDIDATE
        self.current_term += 1
        self.voted_for = self.id  # Vote for myself
        self.votes_received = 1
        print(f"Node {self.id}: Starting election for term {self.current_term}")
        # Request votes from all other nodes
        return self._request_votes()

    def _request_votes(self):
        """Send RequestVote RPC to all other nodes"""
        # In real Raft: send (term, candidateId, lastLogIndex, lastLogTerm)
        return {
            "type": "RequestVote",
            "term": self.current_term,
            "candidate_id": self.id
        }

    def receive_vote(self, granted):
        """Handle vote response"""
        if granted:
            self.votes_received += 1
            # Need majority to win (e.g., 3 out of 5)
            majority = (self.cluster_size // 2) + 1
            if self.votes_received >= majority:
                self.become_leader()

    def become_leader(self):
        self.state = State.LEADER
        self.leader_id = self.id
        print(f"Node {self.id}: Won election for term {self.current_term}! 👑")
        # Start sending heartbeats to maintain leadership

    def receive_heartbeat(self, leader_id, term):
        """Leader sends periodic heartbeats to prevent new elections"""
        if term >= self.current_term:
            self.state = State.FOLLOWER
            self.current_term = term
            self.leader_id = leader_id
            # Reset election timeout (leader is alive!)

    def handle_vote_request(self, candidate_id, term):
        """Decide whether to vote for a candidate"""
        if term > self.current_term and self.voted_for is None:
            self.voted_for = candidate_id
            self.current_term = term
            return True   # Grant vote
        return False  # Deny vote

Leader Election via Distributed Lock (Practical Approach)

In practice, many systems use an external coordination service (like Zookeeper or etcd) for leader election:

# Leader election using Redis (practical production approach)
import redis
import time
import uuid

class RedisLeaderElection:
    """Simple leader election using Redis SET NX (set if not exists)"""

    def __init__(self, redis_client, election_key, ttl=10):
        self.redis = redis_client
        self.key = election_key
        self.ttl = ttl  # Leader lease duration in seconds
        self.node_id = str(uuid.uuid4())  # Unique identity for this node

    def try_become_leader(self):
        """Attempt to become leader (returns True if successful)"""
        # SET NX = "Set if Not eXists" — atomic operation
        # Only succeeds if no one else holds the lock
        acquired = self.redis.set(
            self.key,
            self.node_id,
            nx=True,      # Only set if key doesn't exist
            ex=self.ttl   # Auto-expire after TTL seconds
        )
        return acquired is not None

    def renew_leadership(self):
        """Leader must renew before TTL expires (heartbeat)"""
        current_holder = self.redis.get(self.key)
        if current_holder and current_holder.decode() == self.node_id:
            self.redis.expire(self.key, self.ttl)
            return True
        return False  # Lost leadership!

    def am_i_leader(self):
        current_holder = self.redis.get(self.key)
        return current_holder and current_holder.decode() == self.node_id

    def step_down(self):
        """Voluntarily give up leadership"""
        if self.am_i_leader():
            self.redis.delete(self.key)

# Usage: Each node runs this loop
def leader_election_loop(redis_client):
    election = RedisLeaderElection(redis_client, "myapp:leader")

    while True:
        if election.am_i_leader():
            # I'm the leader — do leader work
            do_leader_work()
            election.renew_leadership()
        else:
            # Try to become leader
            if election.try_become_leader():
                print("I'm the new leader! 👑")
            else:
                print("Someone else is leader. Standing by...")

        time.sleep(5)  # Check every 5 seconds

The Split-Brain Problem

Split Brain: The worst thing that can happen — TWO nodes both believe they are the leader. This causes conflicting writes, data corruption, and chaos.

Causes of split brain:

  • Network partition separates the leader from some followers
  • Followers think leader is dead → elect new leader
  • Old leader is still alive on the other side of the partition
  • Now you have TWO leaders! Both accept writes → data diverges

Solutions:

  • Fencing tokens: Each leader gets a monotonically increasing token. Requests with old tokens are rejected.
  • Lease-based leadership: Leader must renew its lease. If it can't (due to partition), it steps down.
  • Majority quorum: Raft/Paxos require majority vote — can't get majority on both sides of a partition.

Real-World Leader Election

  • Kubernetes — Uses etcd (Raft) for controller manager leader election
  • Apache Kafka — Uses Zookeeper (ZAB) for partition leader election
  • MongoDB — Replica set uses a Raft-like protocol to elect primary
  • Redis Sentinel — Monitors Redis masters, elects new master on failure
  • Google Chubby — Uses Paxos for lock service / leader election

📝 Summary

  • Leader election picks ONE node to coordinate work in a distributed system
  • Without a leader: duplicate work, conflicting decisions, split brain
  • Bully algorithm: highest ID wins (simple but not partition-safe)
  • Raft: uses terms, timeouts, and majority votes (production-grade)
  • Practical: use Redis/etcd/Zookeeper for leader election via distributed locks
  • Split brain = two leaders = disaster. Solve with fencing tokens, leases, or quorum.

🧠 Mental Model

Normal operation: [Leader 👑] ──heartbeat──→ [Follower] ──heartbeat──→ [Follower] ──heartbeat──→ [Follower] Leader dies: [Leader 💀] [Follower] ← "No heartbeat for 300ms!" [Follower] ← "Let's vote!" [Follower] Election: [Dead] [Candidate] → "Vote for me! Term 2" [Voter] → "OK, you have my vote" [Voter] → "OK, you have my vote" Result: [New Leader 👑] ← Got majority (2/3 votes) Starts sending heartbeats immediately

❌ Common Beginner Mistakes

  • Not handling split brain — If you build leader election without fencing, network partitions WILL cause two leaders.
  • Using timestamps for ordering — Clocks drift. Use logical clocks (terms) instead of wall-clock time.
  • Building your own instead of using etcd/Zookeeper — Leader election is extremely hard to get right. Use battle-tested tools.
  • No leader health check — If the leader hangs (doesn't crash but stops responding), followers must detect this and re-elect.
  • Same election timeout for all nodes — This causes everyone to start elections simultaneously. Use randomized timeouts (Raft's key insight).
