Intermediate Security Pattern

OAuth 2.0

Delegated authorization — letting third-party apps access user resources without sharing credentials.

💡 Analogy

A valet key — gives limited access to your car (drive only, no trunk) without handing over your master key. The valet can move your car but cannot open the glove box or trunk. OAuth works the same way: you grant an application specific, limited permissions without ever revealing your password.

Core Concepts

OAuth 2.0 Roles

Role Description Example
Resource Owner The user who owns the data and grants access You (the GitHub user)
Client The application requesting access on behalf of the user A CI/CD tool requesting repo access
Authorization Server Issues tokens after authenticating the resource owner GitHub’s OAuth server
Resource Server Hosts the protected resources, validates tokens GitHub API (api.github.com)

Grant Types

Grant Type Use Case Security Level
Authorization Code Server-side web apps with a backend High — code exchanged server-to-server
Authorization Code + PKCE SPAs, mobile apps, public clients High — prevents code interception
Client Credentials Machine-to-machine, no user context Medium — requires secure secret storage
Refresh Token Obtaining new access tokens without re-auth High — rotated on each use

Scopes & Tokens

Scopes define the boundaries of access — like read:user, repo:write, or openid profile email. The authorization server issues two types of tokens:

  • Access Token — short-lived (minutes to hours), sent with each API request
  • Refresh Token — long-lived, used to obtain new access tokens without user interaction

OpenID Connect (OIDC)

OIDC is an identity layer built on top of OAuth 2.0. While OAuth handles authorization (what can you access?), OIDC adds authentication (who are you?) by introducing an ID token — a JWT containing user identity claims.

Implementation

Authorization Code Flow with PKCE

import hashlib
import secrets
import base64
import urllib.parse
from dataclasses import dataclass, field
from typing import Optional
import time


class PKCEChallenge:
    """Generate PKCE code verifier and challenge for public clients."""

    def __init__(self):
        # Generate a cryptographically random verifier (43-128 chars)
        self.verifier = secrets.token_urlsafe(32)
        self.challenge = self._compute_challenge()

    def _compute_challenge(self) -> str:
        # S256: BASE64URL(SHA256(code_verifier))
        digest = hashlib.sha256(self.verifier.encode("ascii")).digest()
        return base64.urlsafe_b64encode(digest).rstrip(b"=").decode("ascii")


@dataclass
class OAuthConfig:
    client_id: str
    client_secret: Optional[str]  # None for public clients
    authorize_url: str
    token_url: str
    redirect_uri: str
    scopes: list = field(default_factory=list)


class OAuthClient:
    """OAuth 2.0 Authorization Code flow with PKCE support."""

    def __init__(self, config: OAuthConfig):
        self.config = config
        self.pkce = None
        self.state = None

    def build_authorization_url(self, use_pkce: bool = True) -> str:
        # Generate state parameter to prevent CSRF
        self.state = secrets.token_urlsafe(16)

        params = {
            "response_type": "code",
            "client_id": self.config.client_id,
            "redirect_uri": self.config.redirect_uri,
            "scope": " ".join(self.config.scopes),
            "state": self.state,
        }

        if use_pkce:
            self.pkce = PKCEChallenge()
            params["code_challenge"] = self.pkce.challenge
            params["code_challenge_method"] = "S256"

        return f"{self.config.authorize_url}?{urllib.parse.urlencode(params)}"

    def exchange_code_for_token(self, code: str, state: str) -> dict:
        # Verify state matches to prevent CSRF attacks
        if state != self.state:
            raise ValueError("State mismatch — possible CSRF attack")

        payload = {
            "grant_type": "authorization_code",
            "code": code,
            "redirect_uri": self.config.redirect_uri,
            "client_id": self.config.client_id,
        }

        # Confidential clients include client_secret
        if self.config.client_secret:
            payload["client_secret"] = self.config.client_secret

        # Public clients include PKCE verifier
        if self.pkce:
            payload["code_verifier"] = self.pkce.verifier

        # POST to token endpoint (use httpx/requests in production)
        return payload  # Send as POST body

Scope Validation Middleware

from functools import wraps


class ScopeValidator:
    """Validate that an access token has the required scopes."""

    def __init__(self, token_scopes: list[str]):
        self.granted = set(token_scopes)

    def has_scope(self, required: str) -> bool:
        # Support hierarchical scopes: "repo:write" implies "repo:read"
        if required in self.granted:
            return True
        # Check parent scope
        parent = required.rsplit(":", 1)[0]
        return f"{parent}:write" in self.granted

    def require_all(self, scopes: list[str]) -> bool:
        return all(self.has_scope(s) for s in scopes)


def require_scopes(*scopes: str):
    """Decorator to enforce scope requirements on endpoints."""
    def decorator(func):
        @wraps(func)
        def wrapper(request, *args, **kwargs):
            token_scopes = request.auth.get("scope", "").split()
            validator = ScopeValidator(token_scopes)
            if not validator.require_all(list(scopes)):
                raise PermissionError(
                    f"Insufficient scope. Required: {scopes}"
                )
            return func(request, *args, **kwargs)
        return wrapper
    return decorator


# Usage
@require_scopes("repo:read", "user:email")
def get_user_repos(request):
    return {"repos": ["project-a", "project-b"]}

    """Manages access and refresh token lifecycle."""

    def __init__(self, access_token: str, refresh_token: str, expires_in: int):
        self.access_token = access_token
        self.refresh_token = refresh_token
        self.expires_at = time.time() + expires_in
        self.token_url = ""
        self.client_id = ""

    @property
    def is_expired(self) -> bool:
        # Add 30s buffer to avoid edge-case expiry during request
        return time.time() >= (self.expires_at - 30)

🏭 Industry Implementations

  • Google OAuth — supports Authorization Code + PKCE, incremental consent, and offline access via refresh tokens
  • GitHub OAuth — used by CI/CD tools and IDE extensions; scopes like repo, read:org, workflow
  • Keycloak — open-source identity provider with full OAuth 2.0 + OIDC; supports realm-based multi-tenancy
  • Auth0 — managed identity platform; provides universal login, social connections, and machine-to-machine grants
  • Okta — enterprise SSO with OAuth 2.0, supports workforce and customer identity
  • Azure AD (Entra ID) — Microsoft’s identity platform; supports multi-tenant apps, conditional access, and managed identities

📋 Summary

  • OAuth 2.0 separates authorization from authentication — it delegates access without sharing credentials
  • Four roles: Resource Owner, Client, Authorization Server, Resource Server
  • Authorization Code + PKCE is the recommended flow for all modern clients (web, mobile, SPA)
  • Scopes define the boundary of what a token can access — principle of least privilege
  • Access tokens are short-lived; refresh tokens provide long-lived sessions with rotation
  • OIDC extends OAuth with an identity layer — the ID token (JWT) carries user claims

⚠️ Common Mistakes

  • Storing tokens in localStorage — vulnerable to XSS attacks; use httpOnly cookies or secure in-memory storage instead
  • Skipping state parameter validation — opens the door to CSRF attacks where an attacker can force a victim to authorize their account
  • Using Implicit Grant for new apps — deprecated in OAuth 2.1; always use Authorization Code + PKCE instead
  • Overly broad scopes — requesting more permissions than needed violates least privilege and erodes user trust
