Intermediate API Concept

Reverse Proxy

A server that sits in front of your backend servers, intercepting client requests and forwarding them to the appropriate origin — providing SSL termination, caching, compression, and security without clients ever knowing the backend exists.

💡 Real-World Analogy

Think of a receptionist who answers your company’s phone. External callers dial one number and reach the receptionist, who then routes the call to the right employee. Callers never learn direct extension numbers, can’t bypass the receptionist to access internal lines, and the receptionist can screen calls, take messages, or redirect to voicemail. A reverse proxy works the same way — clients see one public address, never knowing which backend server actually handles their request.

Forward Proxy vs Reverse Proxy

Forward Proxy

  • Sits in front of clients — intercepts outgoing requests from your network
  • The server doesn’t know who the real client is (client anonymity)
  • Used for: content filtering, bypassing geo-restrictions, corporate firewalls, caching for clients
  • Example: A company proxy that blocks social media sites during work hours

Reverse Proxy

  • Sits in front of servers — intercepts incoming requests from the internet
  • The client doesn’t know which server actually handled the request (server anonymity)
  • Used for: SSL termination, caching, load balancing, security, compression
  • Example: nginx receiving all traffic for api.company.com and forwarding to internal services

What Reverse Proxies Do

SSL/TLS Termination

  • The proxy handles all HTTPS encryption/decryption — backend servers communicate over plain HTTP internally
  • Centralizes certificate management — renew certs in one place, not on every server
  • Offloads CPU-intensive TLS handshakes from application servers
  • Internal traffic can still use TLS (re-encryption) for defense-in-depth, but it’s optional

Response Caching

  • Cache frequently-requested responses at the proxy level — backends never see repeated requests
  • Respects cache headers: Cache-Control, ETag, Last-Modified
  • Dramatically reduces backend load for static assets and rarely-changing API responses
  • Cache invalidation via purge APIs when content changes

Compression

  • Compresses responses with gzip/brotli before sending to clients
  • Backends send uncompressed data internally (faster, less CPU), proxy compresses at the edge
  • Reduces bandwidth costs and improves page load times (especially for text-heavy responses)

Security

  • IP hiding: Backend server IPs are never exposed to the internet
  • DDoS protection: The proxy absorbs attack traffic before it reaches your servers
  • WAF (Web Application Firewall): Inspect and block malicious requests (SQL injection, XSS)
  • Rate limiting: Throttle abusive clients at the edge
  • Header sanitization: Remove or rewrite headers that could expose internal architecture

Reverse Proxy vs Load Balancer vs API Gateway

  • These three have overlapping responsibilities — many tools do all three (nginx, Envoy, Traefik)
  • Reverse Proxy: Core function is forwarding requests and hiding backends. Adds caching, compression, SSL
  • Load Balancer: Core function is distributing traffic across multiple instances of the same service
  • API Gateway: Core function is API-level concerns — auth, rate limiting, request transformation, aggregation
  • In practice: nginx acts as all three simultaneously for many deployments

Python Implementation

import time
import hashlib
import gzip
from dataclasses import dataclass, field
from typing import Dict, Optional, Tuple
from collections import OrderedDict


# ═══════════════════════════════════════════════════
# Request / Response models
# ═══════════════════════════════════════════════════

@dataclass
class ProxyRequest:
    method: str
    path: str
    headers: Dict[str, str] = field(default_factory=dict)
    body: Optional[str] = None
    client_ip: str = "203.0.113.1"


@dataclass
class ProxyResponse:
    status: int
    body: str
    headers: Dict[str, str] = field(default_factory=dict)
    cached: bool = False
    compressed: bool = False


# ═══════════════════════════════════════════════════
# Response Cache (LRU)
# ═══════════════════════════════════════════════════

class ResponseCache:
    def __init__(self, max_size: int = 100, default_ttl: int = 300):
        self.max_size = max_size
        self.default_ttl = default_ttl
        self._cache: OrderedDict[str, Tuple[ProxyResponse, float]] = OrderedDict()

    def _cache_key(self, request: ProxyRequest) -> str:
        return f"{request.method}:{request.path}"

    def get(self, request: ProxyRequest) -> Optional[ProxyResponse]:
        key = self._cache_key(request)
        if key not in self._cache:
            return None
        response, expires_at = self._cache[key]
        if time.time() > expires_at:
            del self._cache[key]
            return None
        # Move to end (most recently used)
        self._cache.move_to_end(key)
        response.cached = True
        return response

    def put(self, request: ProxyRequest, response: ProxyResponse, ttl: Optional[int] = None):
        if request.method != "GET":
            return  # Only cache GET requests
        key = self._cache_key(request)
        expires_at = time.time() + (ttl or self.default_ttl)
        self._cache[key] = (response, expires_at)
        if len(self._cache) > self.max_size:
            self._cache.popitem(last=False)  # Evict LRU

    def purge(self, path: str):
        key = f"GET:{path}"
        if key in self._cache:
            del self._cache[key]


# ═══════════════════════════════════════════════════
# SSL Termination (conceptual)
# ═══════════════════════════════════════════════════

class SSLTerminator:
    def __init__(self, cert_path: str, key_path: str):
        self.cert_path = cert_path
        self.key_path = key_path
        self.handshakes_handled = 0

    def terminate(self, request: ProxyRequest) -> ProxyRequest:
        """Strip TLS, forward as plain HTTP internally."""
        self.handshakes_handled += 1
        # In reality: decrypt TLS, extract HTTP request
        request.headers["X-Forwarded-Proto"] = "https"
        request.headers["X-Forwarded-For"] = request.client_ip
        return request


# ═══════════════════════════════════════════════════
# Compression Layer
# ═══════════════════════════════════════════════════

class Compressor:
    MIN_SIZE = 1024  # Don't compress responses smaller than 1KB
    COMPRESSIBLE_TYPES = {"text/html", "application/json", "text/css", "text/javascript"}

    def should_compress(self, request: ProxyRequest, response: ProxyResponse) -> bool:
        accepts = request.headers.get("Accept-Encoding", "")
        content_type = response.headers.get("Content-Type", "")
        return (
            "gzip" in accepts
            and len(response.body) >= self.MIN_SIZE
            and content_type in self.COMPRESSIBLE_TYPES
        )

    def compress(self, response: ProxyResponse) -> ProxyResponse:
        original_size = len(response.body)
        compressed = gzip.compress(response.body.encode())
        response.headers["Content-Encoding"] = "gzip"
        response.headers["Content-Length"] = str(len(compressed))
        response.compressed = True
        print(f"  Compressed: {original_size}B → {len(compressed)}B")
        return response


# ═══════════════════════════════════════════════════
# Reverse Proxy
# ═══════════════════════════════════════════════════

class ReverseProxy:
    def __init__(self):
        self.cache = ResponseCache(max_size=50, default_ttl=60)
        self.ssl = SSLTerminator("/etc/ssl/cert.pem", "/etc/ssl/key.pem")
        self.compressor = Compressor()
        self.backends: Dict[str, str] = {}
        self.blocked_ips: set = set()

    def register_backend(self, path_prefix: str, backend_url: str):
        self.backends[path_prefix] = backend_url

    def block_ip(self, ip: str):
        self.blocked_ips.add(ip)

    def _forward_to_backend(self, request: ProxyRequest) -> ProxyResponse:
        """Simulate forwarding request to a backend server."""
        for prefix, backend in sorted(
            self.backends.items(), key=lambda x: len(x[0]), reverse=True
        ):
            if request.path.startswith(prefix):
                return ProxyResponse(
                    status=200,
                    body=f'{{"backend": "{backend}", "path": "{request.path}"}}',
                    headers={"Content-Type": "application/json"}
                )
        return ProxyResponse(status=502, body='{"error": "No backend available"}')

    def handle_request(self, request: ProxyRequest) -> ProxyResponse:
        """Full reverse proxy request pipeline."""

        # Step 1: Security — block banned IPs
        if request.client_ip in self.blocked_ips:
            return ProxyResponse(status=403, body='{"error": "Forbidden"}')

        # Step 2: SSL termination
        request = self.ssl.terminate(request)

        # Step 3: Check cache
        cached = self.cache.get(request)
        if cached:
            print(f"  CACHE HIT: {request.path}")
            return cached

        # Step 4: Forward to backend
        response = self._forward_to_backend(request)

        # Step 5: Cache the response
        if response.status == 200:
            self.cache.put(request, response)

        # Step 6: Compress if supported
        if self.compressor.should_compress(request, response):
            response = self.compressor.compress(response)

        # Step 7: Add proxy headers
        response.headers["X-Proxy"] = "reverse-proxy-v1"
        response.headers["X-Cache"] = "MISS"
        return response


# ═══════════════════════════════════════════════════
# Demo: Reverse proxy in action
# ═══════════════════════════════════════════════════

proxy = ReverseProxy()
proxy.register_backend("/api", "http://app-server:8080")
proxy.register_backend("/static", "http://cdn-origin:9090")
proxy.block_ip("10.0.0.99")

print("=== Reverse Proxy Demo ===")
print()

# Normal request → forwarded to backend
req1 = ProxyRequest(method="GET", path="/api/users",
                    headers={"Accept-Encoding": "gzip"})
resp1 = proxy.handle_request(req1)
print(f"Request 1: status={resp1.status}, cached={resp1.cached}")

# Same request again → served from cache
resp2 = proxy.handle_request(req1)
print(f"Request 2: status={resp2.status}, cached={resp2.cached}")

# Blocked IP → rejected
bad_req = ProxyRequest(method="GET", path="/api/admin", client_ip="10.0.0.99")
resp3 = proxy.handle_request(bad_req)
print(f"Blocked IP: status={resp3.status}")

# Static asset → routed to CDN origin
static_req = ProxyRequest(method="GET", path="/static/logo.png")
resp4 = proxy.handle_request(static_req)
print(f"Static: backend={resp4.body}")

print(f"\nSSL handshakes handled: {proxy.ssl.handshakes_handled}")

🏭 Industry Practice

nginx: The de facto standard reverse proxy. Powers over 30% of all websites. Its event-driven architecture handles tens of thousands of concurrent connections with minimal memory. Configuration is declarative — define upstream blocks for backends, location blocks for routing rules, and proxy_pass for forwarding.

Caddy: A modern reverse proxy with automatic HTTPS. It obtains and renews TLS certificates from Let’s Encrypt without any configuration. Its Caddyfile syntax is simpler than nginx configs. Ideal for smaller deployments where zero-config TLS is the primary requirement.

Cloudflare: A globally-distributed reverse proxy (CDN). All traffic flows through Cloudflare’s edge network before reaching your origin server. Provides DDoS protection, WAF, caching, and performance optimization. Your origin server’s IP is hidden from the internet entirely.

Varnish: A reverse proxy specialized for HTTP caching. Stores responses in memory and serves them at wire speed without touching the backend. Uses VCL (Varnish Configuration Language) to define complex caching rules. Wikipedia uses Varnish to serve millions of page views from cache.

📋 Key Takeaways

  • A reverse proxy sits in front of servers (hides backends), while a forward proxy sits in front of clients (hides clients)
  • SSL termination at the proxy centralizes certificate management and offloads TLS overhead from application servers
  • Response caching at the proxy layer can eliminate 80–90% of backend requests for cacheable content
  • Reverse proxies provide security by hiding server IPs, blocking malicious traffic, and sanitizing headers
  • Reverse proxy, load balancer, and API gateway overlap significantly — tools like nginx do all three
  • Compression at the proxy reduces bandwidth without requiring application-level changes

🧠 Mental Model

Think of a reverse proxy as a bodyguard for your servers. The public only ever interacts with the bodyguard. The bodyguard checks credentials, blocks threats, and decides whether to handle the request himself (cache hit) or pass it through to the person behind him (backend).

⚠️ Common Mistakes

  • Not forwarding client IP: The backend sees the proxy’s IP instead of the real client. Always set X-Forwarded-For and X-Real-IP headers so backends can log and rate-limit based on the actual client address. Without this, all requests appear to come from one IP.
  • Caching authenticated responses: If the proxy caches a response that contains user-specific data, other users may receive it. Never cache responses with Authorization headers or Set-Cookie unless you’re certain they’re safe. Respect Cache-Control: private and no-store directives.
  • Ignoring WebSocket connections: Standard reverse proxy configs break WebSocket upgrades. You must explicitly configure Upgrade and Connection header forwarding. Without this, real-time features (chat, notifications) silently fail after the initial HTTP handshake.
  • Timeout mismatches: The proxy times out before the backend finishes processing (e.g., proxy timeout 30s, backend needs 60s for a report). Always configure proxy timeouts to exceed your slowest backend operation, or use async processing with webhooks for long tasks.
