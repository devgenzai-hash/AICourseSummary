RAG Course / Ingest & Normalize

Stage 1: Ingest & Normalize Documents

The foundation of everything. If garbage goes in, garbage comes out — no matter how smart your AI is.

Beginner Concept 10M Scale
🏠 Daily-Life Analogy: The Mail Room

Imagine you work in a huge company with 10 million pieces of mail arriving every day — letters, packages, emails printed out, faxes, sticky notes, voice recordings transcribed on napkins.

Before anyone can find anything useful, someone in the mail room has to:

  • Remove duplicates — "Wait, we got this same letter 3 times"
  • Put everything in the same format — Type up the napkin notes, scan the faxes
  • Label everything — Who sent it? When? What department? What topic?
  • Keep old versions — "The policy changed last month, keep both versions"

Without this mail room doing its job, nobody in the company can find anything. The ingestion stage IS that mail room for your RAG system.

What Is Document Ingestion?

Ingestion is the process of taking raw documents from various sources and preparing them so your AI system can actually search through them effectively. Think of it as "food preparation" before cooking — you wash, peel, chop, and organize ingredients before you start cooking.

In a RAG system, your documents might come from:

  • PDFs (company reports, research papers, manuals)
  • Word documents (memos, proposals, meeting notes)
  • Emails (customer conversations, internal communications)
  • Web pages (knowledge bases, documentation sites)
  • Databases (product catalogs, customer records)
  • Slack/Teams messages (discussions, decisions)
  • Code repositories (documentation, README files)

Each of these comes in a different format, with different structures, and varying quality. Normalization means converting ALL of them into one clean, consistent format that your system can work with.

How It Works: The 4 Steps

Step 1: Remove Duplicates (Deduplication)

Simple explanation: Don't keep 5 copies of the same document. It wastes storage and confuses search results.

Why it matters at scale: At 10M documents, duplicates are inevitable. The same memo gets forwarded 50 times. The same PDF gets uploaded to 3 different systems. Without dedup, your retrieval returns the same information multiple times, wasting precious context window space.

Technical Deep Dive: Deduplication Methods

Exact Deduplication (Hash-based)

Create a unique fingerprint (hash) of each document. If two documents have the same fingerprint, they're identical.

import hashlib

def get_doc_hash(content: str) -> str:
    """Create a unique fingerprint for a document."""
    # Normalize whitespace first
    normalized = " ".join(content.split()).lower().strip()
    return hashlib.sha256(normalized.encode()).hexdigest()

# Usage
seen_hashes = set()
unique_docs = []

for doc in all_documents:
    doc_hash = get_doc_hash(doc.content)
    if doc_hash not in seen_hashes:
        seen_hashes.add(doc_hash)
        unique_docs.append(doc)
    else:
        print(f"Duplicate found: {doc.title}")

Limitation: If even one character is different (like a typo fix), it's considered a different document.

Near-Duplicate Detection (MinHash/SimHash)

For documents that are almost the same (like different versions or slight reformats), we use fuzzy matching.

MinHash works like this: break the document into small pieces (shingles), then use mathematical magic to quickly estimate how similar two documents are without comparing every word.

from datasketch import MinHash, MinHashLSH

def create_minhash(text, num_perm=128):
    """Create a MinHash signature for near-duplicate detection."""
    m = MinHash(num_perm=num_perm)
    # Break text into 3-word chunks (shingles)
    words = text.lower().split()
    for i in range(len(words) - 2):
        shingle = " ".join(words[i:i+3])
        m.update(shingle.encode('utf8'))
    return m

# Create an LSH index for fast lookup
lsh = MinHashLSH(threshold=0.8, num_perm=128)

for doc_id, doc in enumerate(documents):
    mh = create_minhash(doc.content)
    # Check if a near-duplicate already exists
    duplicates = lsh.query(mh)
    if not duplicates:
        lsh.insert(f"doc_{doc_id}", mh)
    else:
        print(f"Near-duplicate of {duplicates[0]}: {doc.title}")

threshold=0.8 means documents sharing 80%+ content are considered duplicates.

Step 2: Standardize Formats (Normalization)

Simple explanation: Convert everything into the same clean text format, regardless of whether it started as a PDF, Word doc, or web page.

What we standardize:

  • Text encoding — Everything becomes UTF-8 (a universal character standard)
  • Line breaks — Consistent paragraph separators
  • Headers/structure — Preserve section hierarchy
  • Tables — Convert to a parseable format
  • Special characters — Remove or normalize weird symbols
import re
from typing import Dict

def normalize_document(raw_text: str, source_type: str) -> Dict:
    """Normalize any document into a clean, consistent format."""
    
    # 1. Fix encoding issues
    text = raw_text.encode('utf-8', errors='replace').decode('utf-8')
    
    # 2. Normalize whitespace (keep paragraph breaks)
    text = re.sub(r'[ \t]+', ' ', text)  # Multiple spaces → one space
    text = re.sub(r'\n{3,}', '\n\n', text)  # Max 2 newlines
    
    # 3. Remove control characters
    text = re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f]', '', text)
    
    # 4. Normalize quotes and dashes
    text = text.replace('\u2018', "'").replace('\u2019', "'")
    text = text.replace('\u201c', '"').replace('\u201d', '"')
    text = text.replace('\u2014', '—')
    
    return {
        "content": text.strip(),
        "char_count": len(text),
        "source_type": source_type,
        "is_valid": len(text.strip()) > 50  # Skip near-empty docs
    }

Step 3: Extract Metadata

Simple explanation: Metadata is "data about data." It's the label on the box telling you what's inside, who put it there, and when.

Critical metadata fields for RAG:

Step 4: Maintain Version History

Simple explanation: When a document gets updated, don't delete the old version. Keep both. Your system needs to know what the policy was last month versus today.

Why this matters for RAG:

  • A user might ask "What was our vacation policy in 2024?" — you need the old version
  • If a document is wrong, you need to trace back to when the error was introduced
  • Regulatory compliance often requires keeping historical records
  • You can detect conflicting information across versions
class VersionedDocumentStore:
    """Store documents with full version history."""
    
    def __init__(self):
        self.documents = {}  # doc_id → list of versions
    
    def ingest(self, doc_id: str, content: str, metadata: dict):
        """Add or update a document, preserving history."""
        if doc_id not in self.documents:
            self.documents[doc_id] = []
        
        version_num = len(self.documents[doc_id]) + 1
        
        version_entry = {
            "version": version_num,
            "content": content,
            "metadata": metadata,
            "ingested_at": datetime.now(),
            "is_latest": True
        }
        
        # Mark previous version as not latest
        if self.documents[doc_id]:
            self.documents[doc_id][-1]["is_latest"] = False
        
        self.documents[doc_id].append(version_entry)
    
    def get_latest(self, doc_id: str):
        """Get the most recent version of a document."""
        if doc_id in self.documents:
            return self.documents[doc_id][-1]
        return None
    
    def get_version_at_date(self, doc_id: str, target_date: datetime):
        """Get the version that was current at a specific date."""
        if doc_id not in self.documents:
            return None
        for version in reversed(self.documents[doc_id]):
            if version["ingested_at"] <= target_date:
                return version
        return None

The Chunking Problem

After normalizing, you need to break documents into chunks — smaller pieces that can be individually searched and retrieved. This is one of the most important decisions in RAG.

📖 Analogy: Library Books vs. Index Cards

Imagine searching a library. You wouldn't pull out an entire 500-page book every time someone asks a question. Instead, you'd point them to the exact chapter, or even the exact paragraph.

Chunks are those specific paragraphs. Small enough to be precise, big enough to contain complete thoughts.

Chunking Strategies

Strategy How It Works Best For Chunk Size
Fixed-size Cut every N characters/tokens Simple docs, uniform content 256-512 tokens
Semantic Split at natural paragraph/section boundaries Well-structured documents Varies (200-1000 tokens)
Recursive Try to split by sections, then paragraphs, then sentences Mixed content types Target 512, flexible
Sliding window Overlapping chunks (like tiles overlapping) When context crosses chunk boundaries 512 with 50-100 overlap
Document-aware Use document structure (headings, sections) Technical docs, legal docs Varies by section 
from typing import List, Dict

def chunk_document(
    text: str,
    chunk_size: int = 512,
    overlap: int = 50,
    metadata: Dict = None
) -> List[Dict]:
    """
    Split a document into overlapping chunks.
    
    chunk_size: maximum number of words per chunk
    overlap: number of words shared between adjacent chunks
    """
    words = text.split()
    chunks = []
    start = 0
    chunk_index = 0
    
    while start < len(words):
        end = start + chunk_size
        chunk_text = " ".join(words[start:end])
        
        chunk = {
            "chunk_id": f"{metadata['source_id']}_chunk_{chunk_index}",
            "content": chunk_text,
            "chunk_index": chunk_index,
            "start_word": start,
            "end_word": min(end, len(words)),
            "metadata": metadata  # Inherit parent document metadata
        }
        chunks.append(chunk)
        
        start = end - overlap  # Slide window with overlap
        chunk_index += 1
    
    return chunks
📊 At 10M Documents Scale

The math: 10M documents × ~10 chunks per document = 100M chunks in your index. This means:

  • Deduplication must be fast — O(1) lookup with hash sets, not O(n²) comparisons
  • Processing must be parallelized — use distributed workers (Celery, Ray, Spark)
  • Storage must be efficient — compressed storage, tiered (hot/warm/cold)
  • Ingestion must be incremental — process new/changed docs only, not re-process everything
  • You need a pipeline, not a script — with retry logic, dead letter queues, monitoring

The Complete Ingestion Pipeline

class IngestionPipeline:
    """
    Production-grade document ingestion pipeline.
    Handles 10M+ docs with dedup, normalization, 
    metadata extraction, chunking, and versioning.
    """
    
    def __init__(self, vector_store, doc_store):
        self.vector_store = vector_store
        self.doc_store = doc_store
        self.seen_hashes = set()  # For dedup
    
    def process_document(self, raw_doc: Dict) -> Dict:
        """Full pipeline for one document."""
        
        # Step 1: Parse raw content based on type
        text = self.extract_text(raw_doc)
        
        # Step 2: Normalize
        normalized = normalize_document(text, raw_doc["source_type"])
        
        # Step 3: Dedup check
        doc_hash = get_doc_hash(normalized["content"])
        if doc_hash in self.seen_hashes:
            return {"status": "duplicate", "hash": doc_hash}
        self.seen_hashes.add(doc_hash)
        
        # Step 4: Extract metadata
        metadata = extract_metadata(raw_doc, raw_doc["source_system"])
        
        # Step 5: Version management
        self.doc_store.ingest(
            doc_id=metadata.source_id,
            content=normalized["content"],
            metadata=metadata.__dict__
        )
        
        # Step 6: Chunk the document
        chunks = chunk_document(
            text=normalized["content"],
            chunk_size=512,
            overlap=50,
            metadata=metadata.__dict__
        )
        
        # Step 7: Store chunks in vector store (for Stage 2)
        self.vector_store.upsert(chunks)
        
        return {
            "status": "ingested",
            "doc_id": metadata.source_id,
            "chunks_created": len(chunks),
            "version": metadata.version
        }

🏢 What Production Systems Actually Do

  • Unstructured.io — Popular open-source library for parsing 25+ file formats into clean text
  • Apache Tika — Battle-tested document parser used by enterprises for PDFs, Office docs, etc.
  • LangChain/LlamaIndex — Provide document loaders and chunking strategies out of the box
  • Custom pipelines — Most 10M+ doc systems build custom Airflow/Dagster pipelines with domain-specific logic
  • Incremental processing — Change Data Capture (CDC) to only process new/updated documents

📋 Summary

  • Ingestion is the foundation — bad input = bad retrieval = hallucination
  • Deduplicate to avoid wasting context window space on repeated information
  • Normalize ALL formats into one clean standard — consistent structure enables consistent search
  • Rich metadata enables filtering, scoring, and citation (critical for later stages)
  • Version history lets you answer time-sensitive questions and track document changes
  • Chunking strategy directly impacts retrieval quality — too small loses context, too big loses precision

🧠 Mental Model

Raw Docs (PDFs, Emails, Web, DBs) ↓ [DEDUP] — Remove copies ↓ [NORMALIZE] — Clean & standardize ↓ [METADATA] — Label everything ↓ [VERSION] — Track history ↓ [CHUNK] — Break into searchable pieces ↓ Ready for Retrieval (Stage 2) →

Think of it as: A factory assembly line. Raw materials come in messy. They leave clean, labeled, organized, and ready for use.

❌ Beginner Mistakes to Avoid

  • Skipping dedup: "I'll just index everything" — then your retrieval returns the same info 5 times, wasting context
  • Ignoring metadata: Without metadata, you can't cite sources, filter by date, or score confidence
  • Fixed-size chunks only: Cutting mid-sentence destroys meaning. Use semantic boundaries when possible
  • No overlap between chunks: Important context at chunk boundaries gets lost without overlap
  • Re-processing everything: At 10M docs, you MUST do incremental updates or processing takes days
  • Not validating output: Always check chunk quality — empty chunks, encoding errors, or truncated content are common
