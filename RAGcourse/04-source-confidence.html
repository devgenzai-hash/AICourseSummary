Stage 4: Source Confidence Scoring

Not all retrieved information is equally trustworthy. Score every chunk before letting it influence the AI's answer.

Intermediate Concept Production
🏠 Daily-Life Analogy: Trusting News Sources

Imagine you need to know today's weather forecast. You check 5 sources:

  • ✅ The national weather service (official, updated hourly) — HIGH confidence
  • ✅ A reliable weather app (verified data, updated recently) — HIGH confidence
  • ⚠️ A tweet from a stranger (no credentials, posted 2 hours ago) — MEDIUM confidence
  • ❌ A blog post from 2019 (old, no recent data) — LOW confidence
  • ❌ A random forum comment with no source — VERY LOW confidence

You wouldn't trust all 5 equally. You'd weight the official sources heavily and mostly ignore the forum comment. Source confidence scoring does exactly this for your RAG system.

What Is Source Confidence Scoring?

After retrieval gives you the top 10-20 relevant chunks, you don't just blindly feed them all to the AI. Instead, you score each chunk's trustworthiness based on multiple signals:

  • Freshness: How recent is this information?
  • Trust level: How reliable is the source?
  • Overlap/Agreement: Do multiple sources say the same thing?
  • Retrieval consistency: Does this chunk keep appearing for similar queries?

The key principle: Low-confidence context should NEVER heavily influence generation. If you're not sure a source is reliable, don't let the AI treat it as gospel truth.

The 4 Scoring Dimensions

1. Freshness Score

Simple: Newer information is usually more accurate than old information. A policy from 2024 beats a policy from 2019.

Technical: Exponential decay function based on document age. More recent = higher score.

from datetime import datetime
import math

def freshness_score(
    doc_date: datetime,
    half_life_days: int = 180
) -> float:
    """
    Score document freshness using exponential decay.
    
    half_life_days: after this many days, score drops to 0.5
    A 6-month half-life means:
      - Today's doc: 1.0
      - 6 months old: 0.5
      - 1 year old: 0.25
      - 2 years old: 0.0625
    """
    age_days = (datetime.now() - doc_date).days
    
    if age_days <= 0:
        return 1.0
    
    # Exponential decay: score = 0.5^(age/half_life)
    score = math.pow(0.5, age_days / half_life_days)
    
    return round(score, 4)

# Examples:
# Document from today → 1.0
# Document from 6 months ago → 0.5
# Document from 2 years ago → 0.0625
⚠️ Freshness Isn't Always King

Some documents DON'T decay: legal contracts, scientific constants, historical facts. Adjust half-life by document type. A company policy should decay (policies change). A math formula should not.

2. Trust Level Score

Simple: Some sources are more authoritative than others. An official company policy beats a Slack message.

# Trust levels mapped to scores
TRUST_SCORES = {
    "official_policy": 1.0,      # Approved company documents
    "verified_kb": 0.95,        # Knowledge base articles (reviewed)
    "published_doc": 0.9,       # Published documentation
    "meeting_notes": 0.7,       # Meeting minutes (context-dependent)
    "email": 0.6,              # Email threads (informal)
    "slack_message": 0.5,       # Chat messages (casual, may be wrong)
    "draft": 0.3,              # Draft documents (not finalized)
    "user_comment": 0.2,        # User-generated comments (unverified)
    "unknown": 0.1,            # Source unknown (dangerous)
}

def trust_score(source_type: str, is_verified: bool = False) -> float:
    """Get trust score based on source type."""
    base_score = TRUST_SCORES.get(source_type, 0.1)
    
    # Verified sources get a boost
    if is_verified:
        base_score = min(1.0, base_score + 0.1)
    
    return base_score

3. Overlap/Agreement Score

Simple: If 4 out of 5 retrieved chunks say the same thing, that information is probably correct. If only 1 chunk says something and the others disagree, be careful.

from collections import Counter

def overlap_score(
    chunk: Dict,
    all_retrieved_chunks: List[Dict],
    similarity_threshold: float = 0.8
) -> float:
    """
    Score based on how many other chunks agree with this one.
    
    If multiple independent sources say the same thing,
    confidence goes UP. If a chunk contradicts others,
    confidence goes DOWN.
    """
    agreeing_chunks = 0
    total_other_chunks = len(all_retrieved_chunks) - 1
    
    if total_other_chunks == 0:
        return 0.5  # Can't assess overlap with one chunk
    
    for other_chunk in all_retrieved_chunks:
        if other_chunk["chunk_id"] == chunk["chunk_id"]:
            continue
        
        # Check semantic similarity between chunks
        similarity = cosine_similarity(
            chunk["embedding"], other_chunk["embedding"]
        )
        
        if similarity >= similarity_threshold:
            agreeing_chunks += 1
    
    # More agreement = higher score
    return agreeing_chunks / total_other_chunks

4. Retrieval Consistency Score

Simple: If a chunk keeps appearing as relevant for similar queries over time, it's probably genuinely useful. If it only appears once for a weird query, it might be a fluke.

class ConsistencyTracker:
    """Track how consistently chunks are retrieved over time."""
    
    def __init__(self):
        self.retrieval_history = {}  # chunk_id → list of (query, timestamp, rank)
    
    def record_retrieval(self, chunk_id: str, query: str, rank: int):
        """Record that this chunk was retrieved for this query."""
        if chunk_id not in self.retrieval_history:
            self.retrieval_history[chunk_id] = []
        self.retrieval_history[chunk_id].append({
            "query": query,
            "timestamp": datetime.now(),
            "rank": rank
        })
    
    def consistency_score(self, chunk_id: str) -> float:
        """
        Higher score if chunk is consistently retrieved 
        (not just a one-time fluke).
        """
        history = self.retrieval_history.get(chunk_id, [])
        
        if len(history) == 0:
            return 0.5  # No history, neutral
        
        if len(history) == 1:
            return 0.6  # First time, slightly positive
        
        # Average rank position (lower rank = more relevant)
        avg_rank = sum(h["rank"] for h in history) / len(history)
        
        # More retrievals + better ranks = higher consistency
        retrieval_count_factor = min(1.0, len(history) / 10)
        rank_factor = 1.0 / (1 + avg_rank / 10)
        
        return 0.5 * retrieval_count_factor + 0.5 * rank_factor

Combining All Scores

def compute_confidence_score(
    chunk: Dict,
    all_chunks: List[Dict],
    consistency_tracker: ConsistencyTracker,
    weights: Dict = None
) -> float:
    """
    Compute final confidence score for a retrieved chunk.
    
    Combines freshness, trust, overlap, and consistency
    into a single 0-1 score.
    
    Returns:
        float: confidence score between 0.0 (don't trust) and 1.0 (fully trust)
    """
    if weights is None:
        weights = {
            "freshness": 0.25,
            "trust": 0.35,
            "overlap": 0.20,
            "consistency": 0.20
        }
    
    # Calculate each dimension
    scores = {
        "freshness": freshness_score(chunk["metadata"]["updated_at"]),
        "trust": trust_score(chunk["metadata"]["source_type"]),
        "overlap": overlap_score(chunk, all_chunks),
        "consistency": consistency_tracker.consistency_score(chunk["chunk_id"])
    }
    
    # Weighted combination
    final_score = sum(
        scores[dim] * weights[dim] 
        for dim in weights
    )
    
    # Attach detailed scores for observability
    chunk["confidence"] = {
        "overall": round(final_score, 4),
        "breakdown": scores
    }
    
    return final_score


# Usage in the pipeline:
def score_and_filter_chunks(
    chunks: List[Dict],
    min_confidence: float = 0.4
) -> List[Dict]:
    """Score all chunks and remove low-confidence ones."""
    scored_chunks = []
    
    for chunk in chunks:
        score = compute_confidence_score(chunk, chunks, tracker)
        
        if score >= min_confidence:
            scored_chunks.append(chunk)
        else:
            # Log that we're dropping a low-confidence chunk
            log_dropped_chunk(chunk, score, reason="below_threshold")
    
    # Sort by confidence (highest first)
    scored_chunks.sort(
        key=lambda x: x["confidence"]["overall"], 
        reverse=True
    )
    
    return scored_chunks
📊 At 10M Documents Scale

Why confidence scoring is critical at scale:

  • With 10M docs, you'll inevitably have outdated, conflicting, or low-quality content in your retrieval results
  • Without confidence scoring, the LLM treats a 5-year-old draft the same as today's official policy
  • At scale, contradictions are common — confidence scoring helps resolve them by trusting authoritative sources
  • Low-confidence chunks waste precious context window tokens — remove them to make room for better content
🚨 Critical Rule

Low-confidence context should NEVER heavily influence generation. If a chunk scores below your threshold (e.g., 0.4), either remove it from the context entirely or explicitly mark it as "unverified" in the prompt to the LLM.

🏢 What Production Systems Actually Do

  • Enterprise RAG systems — Assign trust tiers at ingestion time (Gold/Silver/Bronze sources)
  • Google's approach — PageRank-style authority scoring for internal documents
  • Financial systems — Only allow "verified" sources to influence answers about regulations
  • Common threshold: Drop chunks below 0.3-0.5 confidence, weight remaining chunks by their score
  • Audit trail: Log every confidence decision for compliance and debugging

📋 Summary

  • Not all retrieved chunks are equally trustworthy — score them before feeding to the LLM
  • Four dimensions: freshness (how new), trust (how authoritative), overlap (do others agree), consistency (reliable over time)
  • Combine dimensions with weighted scoring into a single 0-1 confidence value
  • Drop chunks below your confidence threshold — they're more likely to cause hallucination
  • This stage is the bridge between "good retrieval" and "safe generation"

🧠 Mental Model

Retrieved Chunks (from Stage 3): Chunk A: Official policy, updated today → Confidence: 0.95 ✅ USE Chunk B: KB article, 3 months old → Confidence: 0.82 ✅ USE Chunk C: Slack message, 1 year old → Confidence: 0.45 ⚠️ USE WITH CAUTION Chunk D: Draft doc, 2 years old, unverified → Confidence: 0.18 ❌ DROP Chunk E: Unknown source, contradicts others → Confidence: 0.12 ❌ DROP After scoring: Only A, B, C go to the LLM. C gets marked as "lower confidence" in the prompt. D and E are removed — they'd cause hallucination.

Think of it as: A fact-checker sitting between retrieval and the AI. They verify sources before the AI writes its answer.

❌ Beginner Mistakes to Avoid

  • Treating all sources equally: "It was retrieved so it must be good" — NO. Retrieval finds relevant content, not necessarily trustworthy content.
  • Only using freshness: A new document from an unverified source isn't automatically trustworthy. Balance all 4 dimensions.
  • Too aggressive filtering: Setting threshold too high (0.9) might drop useful context. Start at 0.3-0.4 and tune based on results.
  • Not logging dropped chunks: Always log what you drop and why. It's crucial for debugging when users say "the system should have known X."
  • Static scores: Confidence should be dynamic. A document's trust score might change if it gets verified or flagged as outdated.
