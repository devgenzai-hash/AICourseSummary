Stage 9: Caching & Memory Layer

Cache high-frequency queries and retrieval paths to slash latency and improve output consistency.

Intermediate Advanced Code 10M Scale
🏠 Daily-Life Analogy: Speed Dial on Your Phone

You call your mom every day. Do you type her full phone number each time? No — you use speed dial or favorites. The phone remembers the number so you don't have to look it up again.

Similarly, if 50 employees ask "What's the vacation policy?" every week, why would your RAG system search through 10 million documents each time? It should remember the answer from the first time and serve it instantly for the next 49 people.

Caching = speed dial for your RAG system. Remember common answers so you don't repeat expensive work.

What Is Caching in RAG?

Caching means storing the results of expensive operations so you can reuse them quickly next time. In a RAG pipeline, there are multiple things you can cache:

Cache Layer What It Stores Saves Time On Typical Savings
Query embedding cache Embeddings for previously seen queries Embedding API call (~100ms) ~100ms per cached query
Retrieval cache Retrieved chunk sets for previous queries Full retrieval pipeline (~200-500ms) ~300ms per cached query
Answer cache Complete generated answers LLM generation (~1-5 seconds) ~2-3 seconds per cached query
Semantic cache Answers for semantically similar (not exact) queries Everything above ~3 seconds + broader hit rate

1. Exact Query Cache

Simplest approach: If someone asks the exact same question that's been asked before, return the cached answer.

import hashlib
import json
from datetime import datetime, timedelta

class ExactQueryCache:
    """
    Cache exact query → answer pairs.
    Fast but only hits on identical queries.
    """
    
    def __init__(self, redis_client, ttl_hours: int = 24):
        self.redis = redis_client
        self.ttl = timedelta(hours=ttl_hours)
    
    def _cache_key(self, query: str) -> str:
        """Create a consistent cache key from a query."""
        # Normalize: lowercase, strip whitespace, remove punctuation
        normalized = query.lower().strip()
        return f"rag:exact:{hashlib.sha256(normalized.encode()).hexdigest()}"
    
    def get(self, query: str) -> Dict or None:
        """Check if we have a cached answer for this exact query."""
        key = self._cache_key(query)
        cached = self.redis.get(key)
        
        if cached:
            result = json.loads(cached)
            result["cache_hit"] = True
            return result
        
        return None
    
    def set(self, query: str, result: Dict):
        """Store a result in cache."""
        key = self._cache_key(query)
        result["cached_at"] = datetime.now().isoformat()
        self.redis.setex(
            key, 
            int(self.ttl.total_seconds()), 
            json.dumps(result)
        )
    
    def invalidate_for_document(self, doc_id: str):
        """
        When a document is updated, invalidate all cached 
        answers that cited it.
        """
        # Find all cache entries that reference this document
        affected_keys = self.redis.smembers(f"rag:doc_refs:{doc_id}")
        for key in affected_keys:
            self.redis.delete(key)

2. Semantic Cache (The Smart Approach)

Problem with exact cache: "What's the vacation policy?" and "How many vacation days do we get?" are the same question with different words. Exact cache misses this.

Semantic cache: If a new query is semantically similar enough to a previously answered query, serve the cached answer.

import numpy as np

class SemanticCache:
    """
    Cache that matches semantically similar queries.
    
    "What's the vacation policy?" → cached answer
    "How many days off do employees get?" → SAME cached answer (similar meaning)
    """
    
    def __init__(self, embedding_model, similarity_threshold: float = 0.92):
        self.embedder = embedding_model
        self.threshold = similarity_threshold
        self.cache_entries = []  # List of (embedding, query, result)
        self.cache_embeddings = None  # Numpy array for fast similarity
    
    def get(self, query: str) -> Dict or None:
        """Find a cached answer for a semantically similar query."""
        if not self.cache_entries:
            return None
        
        # Embed the incoming query
        query_embedding = self.embedder.embed(query)
        
        # Compare against all cached query embeddings
        similarities = np.dot(self.cache_embeddings, query_embedding) / (
            np.linalg.norm(self.cache_embeddings, axis=1) * 
            np.linalg.norm(query_embedding)
        )
        
        # Find the most similar cached query
        best_idx = np.argmax(similarities)
        best_similarity = similarities[best_idx]
        
        if best_similarity >= self.threshold:
            cached_entry = self.cache_entries[best_idx]
            result = cached_entry["result"].copy()
            result["cache_hit"] = True
            result["cache_similarity"] = float(best_similarity)
            result["original_query"] = cached_entry["query"]
            return result
        
        return None
    
    def set(self, query: str, result: Dict):
        """Add a new entry to the semantic cache."""
        embedding = self.embedder.embed(query)
        
        self.cache_entries.append({
            "query": query,
            "embedding": embedding,
            "result": result,
            "created_at": datetime.now()
        })
        
        # Rebuild the embedding matrix
        self.cache_embeddings = np.array(
            [e["embedding"] for e in self.cache_entries]
        )
⚠️ Semantic Cache Pitfall

Threshold too low (0.8): "What's the vacation policy?" might match "What's the termination policy?" — similar structure, completely different answer! This causes WRONG cached answers to be served.

Threshold too high (0.98): Only nearly identical queries hit cache. Very few cache hits — low value.

Sweet spot: 0.90-0.95 for most domains. Always log cache hits for manual review.

3. Conversation Memory

Memory is different from caching. Cache stores previous Q&A pairs. Memory stores conversation context so follow-up questions work.

class ConversationMemory:
    """
    Short-term memory for multi-turn conversations.
    Allows follow-up questions to reference previous context.
    
    User: "What's the vacation policy?"
    AI: "Employees get 20 days..."
    User: "What about for remote workers?" ← needs memory of context
    """
    
    def __init__(self, max_turns: int = 10):
        self.conversations = {}  # session_id → history
        self.max_turns = max_turns
    
    def add_turn(self, session_id: str, query: str, answer: str, chunks_used: List):
        """Record a conversation turn."""
        if session_id not in self.conversations:
            self.conversations[session_id] = []
        
        self.conversations[session_id].append({
            "query": query,
            "answer": answer,
            "chunks": chunks_used,
            "timestamp": datetime.now()
        })
        
        # Keep only last N turns to prevent context overflow
        if len(self.conversations[session_id]) > self.max_turns:
            self.conversations[session_id] = \
                self.conversations[session_id][-self.max_turns:]
    
    def get_context(self, session_id: str) -> str:
        """Get conversation history formatted for the LLM prompt."""
        history = self.conversations.get(session_id, [])
        
        if not history:
            return ""
        
        formatted = "Previous conversation:\n"
        for turn in history[-5:]:  # Last 5 turns
            formatted += f"User: {turn['query']}\nAssistant: {turn['answer']}\n\n"
        
        return formatted
    
    def rewrite_query(self, session_id: str, current_query: str, llm) -> str:
        """
        Rewrite a follow-up query to be self-contained.
        
        "What about for remote workers?" 
        → "What is the vacation policy for remote workers?"
        """
        context = self.get_context(session_id)
        
        if not context:
            return current_query
        
        rewrite_prompt = f"""Given this conversation history:
{context}

The user now asks: "{current_query}"

Rewrite this as a standalone question that doesn't need 
the conversation history to understand. Only output the 
rewritten question, nothing else.

Standalone question:"""
        
        return llm.generate(rewrite_prompt).strip()

4. Cache Invalidation (The Hard Problem)

🚨 "There are only two hard things in computer science: cache invalidation and naming things."

If a document gets updated but your cache still serves the old answer, users get stale (wrong) information. Cache invalidation is critical.

class SmartCacheManager:
    """
    Cache manager with intelligent invalidation.
    Invalidates cached answers when source documents change.
    """
    
    def __init__(self, exact_cache, semantic_cache):
        self.exact = exact_cache
        self.semantic = semantic_cache
        # Track which docs are referenced by which cache entries
        self.doc_to_cache_map = {}  # doc_id → set of cache keys
    
    def on_document_updated(self, doc_id: str):
        """
        Called when a document is updated in the index.
        Invalidates all cached answers that used this document.
        """
        affected_keys = self.doc_to_cache_map.get(doc_id, set())
        
        for cache_key in affected_keys:
            self.exact.delete(cache_key)
            self.semantic.delete(cache_key)
        
        # Clear the mapping
        self.doc_to_cache_map[doc_id] = set()
        
        print(f"Invalidated {len(affected_keys)} cache entries for doc {doc_id}")
    
    def on_answer_generated(self, query: str, result: Dict, source_doc_ids: List[str]):
        """Track which documents are used by cached answers."""
        cache_key = self.exact._cache_key(query)
        
        # Map each source doc to this cache entry
        for doc_id in source_doc_ids:
            if doc_id not in self.doc_to_cache_map:
                self.doc_to_cache_map[doc_id] = set()
            self.doc_to_cache_map[doc_id].add(cache_key)
        
        # Store in caches
        self.exact.set(query, result)
        self.semantic.set(query, result)
📊 At 10M Documents Scale
  • Cache hit rates: Enterprise RAG typically sees 30-60% cache hit rate. This means 30-60% of queries are answered in <50ms instead of 2-5 seconds.
  • Cost savings: Each LLM call costs $0.01-0.10. At 10K queries/day, 50% cache hit saves $50-500/day in LLM costs alone.
  • Consistency bonus: Cached answers are identical every time — no variance from LLM non-determinism.
  • Cache size planning: With semantic cache at 10K unique queries, ~40MB of embeddings + ~200MB of cached answers = easily fits in Redis.
  • TTL strategy: Fast-changing docs (Slack) → 1hr TTL. Stable docs (policies) → 24-72hr TTL.

🏢 What Production Systems Actually Do

  • GPTCache — Open-source semantic cache library for LLM applications
  • Redis + vector search — Redis 7+ supports vector similarity for semantic caching
  • Cloudflare AI Gateway — Automatic caching layer for LLM API calls
  • Enterprise pattern: Multi-tier: L1 (exact, in-memory) → L2 (semantic, Redis) → L3 (full pipeline)
  • Smart invalidation: Document change events (webhooks) trigger targeted cache purges

📋 Summary

  • Caching avoids repeating expensive retrieval + generation for common queries
  • Three cache layers: exact (fast, limited), semantic (smart, broader), answer (complete)
  • Semantic cache uses embedding similarity to match rephrased questions to existing answers
  • Cache invalidation is critical — stale cache = wrong answers served confidently
  • Conversation memory enables multi-turn interactions with query rewriting
  • At enterprise scale: 30-60% cache hit rate, saving seconds of latency and significant cost

🧠 Mental Model

Query arrives: "What's the vacation policy?" Step 1: Check exact cache → Miss ❌ Step 2: Check semantic cache → Hit! ✅ (Similar to previously answered "How many days off do we get?") Similarity: 0.94 > threshold 0.92 Step 3: Return cached answer (50ms total) vs. Without cache: Embed query (100ms) → Search (200ms) → Rerank (200ms) → Generate (2000ms) → Verify (200ms) = 2700ms total Speedup: 54x faster with cache hit Cost: $0.00 vs $0.05 per query

Think of it as: A receptionist who remembers frequent visitors. "Oh, you're here for the vacation form? I already have it ready — saved you a trip to the filing cabinet."

❌ Beginner Mistakes to Avoid

  • No TTL (expiration): Cache entries without expiration serve stale data forever. Always set TTLs.
  • No invalidation: When documents update, old cached answers become WRONG. Connect document updates to cache purges.
  • Semantic threshold too low: Serving the answer for "vacation policy" when the user asks "termination policy" — similar embedding, completely wrong answer.
  • Caching errors: If a query fails or triggers fallback, don't cache that failure. Only cache confident, verified answers.
  • No cache metrics: Track hit rate, miss rate, and staleness. A cache nobody hits is wasted infrastructure.
