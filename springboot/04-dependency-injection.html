Dependency Injection Internals

How Spring resolves, wires, and injects dependencies at the bytecode level — the machinery behind @Autowired

🔌 The Wiring Analogy

Think of Spring DI as an electrical contractor wiring a building. The blueprint (BeanDefinition) says "this office needs a power outlet here." The contractor (AutowiredAnnotationBeanPostProcessor) reads the blueprint, finds the correct wire gauge (type matching), labels (qualifiers), and connects the circuit. The office occupant (your bean) never needs to know where the power plant is — they just flip the switch.

1. How @Autowired Works Internally

The @Autowired annotation is processed by AutowiredAnnotationBeanPostProcessor, which implements SmartInstantiationAwareBeanPostProcessor. This processor is registered automatically when you use annotation-based configuration.

The Processing Pipeline

🔍 Key Insight

AutowiredAnnotationBeanPostProcessor operates at TWO phases: (1) metadata collection during postProcessMergedBeanDefinition and (2) actual injection during postProcessProperties. The metadata is cached so repeated lookups are avoided.

// Phase 1: Metadata collection (called once per bean type)
@Override
public void postProcessMergedBeanDefinition(
        RootBeanDefinition beanDefinition,
        Class<?> beanType,
        String beanName) {

    // Find all @Autowired fields and methods
    InjectionMetadata metadata = findAutowiringMetadata(beanName, beanType, null);
    metadata.checkConfigMembers(beanDefinition);
}

// Phase 2: Actual injection (called for each bean instance)
@Override
public PropertyValues postProcessProperties(
        PropertyValues pvs,
        Object bean,
        String beanName) {

    InjectionMetadata metadata = findAutowiringMetadata(beanName, bean.getClass(), pvs);
    metadata.inject(bean, beanName, pvs);
    return pvs;
}

Internal: findAutowiringMetadata

private InjectionMetadata findAutowiringMetadata(
        String beanName, Class<?> clazz, PropertyValues pvs) {

    // Cache key is the bean name or class name
    String cacheKey = (beanName != null ? beanName : clazz.getName());
    InjectionMetadata metadata = this.injectionMetadataCache.get(cacheKey);

    if (InjectionMetadata.needsRefresh(metadata, clazz)) {
        synchronized (this.injectionMetadataCache) {
            metadata = this.injectionMetadataCache.get(cacheKey);
            if (InjectionMetadata.needsRefresh(metadata, clazz)) {
                // Walk the class hierarchy, collecting injection points
                metadata = buildAutowiringMetadata(clazz);
                this.injectionMetadataCache.put(cacheKey, metadata);
            }
        }
    }
    return metadata;
}

buildAutowiringMetadata: The Discovery Engine

private InjectionMetadata buildAutowiringMetadata(Class<?> clazz) {
    List<InjectionMetadata.InjectedElement> elements = new ArrayList<>();
    Class<?> targetClass = clazz;

    do {
        List<InjectionMetadata.InjectedElement> currElements = new ArrayList<>();

        // Scan all declared fields
        ReflectionUtils.doWithLocalFields(targetClass, field -> {
            MergedAnnotation<?> ann = findAutowiredAnnotation(field);
            if (ann != null) {
                if (Modifier.isStatic(field.getModifiers())) {
                    return; // Static fields are NEVER injected
                }
                boolean required = determineRequiredStatus(ann);
                currElements.add(new AutowiredFieldElement(field, required));
            }
        });

        // Scan all declared methods
        ReflectionUtils.doWithLocalMethods(targetClass, method -> {
            Method bridgedMethod = BridgeMethodResolver.findBridgedMethod(method);
            MergedAnnotation<?> ann = findAutowiredAnnotation(bridgedMethod);
            if (ann != null && method.equals(
                    ClassUtils.getMostSpecificMethod(method, clazz))) {
                boolean required = determineRequiredStatus(ann);
                currElements.add(new AutowiredMethodElement(method, required, pd));
            }
        });

        elements.addAll(0, currElements);
        targetClass = targetClass.getSuperclass(); // Walk up hierarchy
    } while (targetClass != null && targetClass != Object.class);

    return InjectionMetadata.forElements(elements, clazz);
}
⚠️ Static Fields Are Silently Skipped

Spring never injects into static fields. There's no error — the annotation is simply ignored. This is a common source of null pointer bugs in production code.

2. The Resolution Algorithm: Type → Qualifier → Name

When Spring encounters an injection point, it uses DefaultListableBeanFactory.doResolveDependency() to find the matching bean. The algorithm follows a strict priority order:

🧠 Resolution Order (Highest to Lowest Priority)

  1. By Type — Find all beans assignable to the injection point's declared type
  2. By Qualifier — If multiple candidates, filter by @Qualifier annotation
  3. By @Primary — If still ambiguous, prefer beans marked @Primary
  4. By Priority — Compare @Priority (javax.annotation) ordering
  5. By Name — Match the field/parameter name against bean names

Internal: doResolveDependency

public Object doResolveDependency(
        DependencyDescriptor descriptor,
        String beanName,
        Set<String> autowiredBeanNames,
        TypeConverter typeConverter) {

    // Step 1: Find all candidates by type
    Map<String, Object> matchingBeans = findAutowireCandidates(
        beanName, type, descriptor);

    if (matchingBeans.isEmpty()) {
        if (isRequired(descriptor)) {
            raiseNoMatchingBeanFound(type, descriptor);
        }
        return null;
    }

    String autowiredBeanName;
    Object instanceCandidate;

    if (matchingBeans.size() > 1) {
        // Step 2: Determine which single candidate to use
        autowiredBeanName = determineAutowireCandidate(matchingBeans, descriptor);

        if (autowiredBeanName == null) {
            if (isRequired(descriptor)) {
                throw new NoUniqueBeanDefinitionException(type, matchingBeans.keySet());
            }
            return null;
        }
        instanceCandidate = matchingBeans.get(autowiredBeanName);
    } else {
        // Single match — use it directly
        Map.Entry<String, Object> entry = matchingBeans.entrySet().iterator().next();
        autowiredBeanName = entry.getKey();
        instanceCandidate = entry.getValue();
    }

    // Resolve the actual bean instance (might be a Class reference)
    return (instanceCandidate instanceof Class)
        ? descriptor.resolveCandidate(autowiredBeanName, type, this)
        : instanceCandidate;
}

determineAutowireCandidate: The Tiebreaker

protected String determineAutowireCandidate(
        Map<String, Object> candidates,
        DependencyDescriptor descriptor) {

    Class<?> requiredType = descriptor.getDependencyType();

    // Priority 1: Check for @Primary
    String primaryCandidate = determinePrimaryCandidate(candidates, requiredType);
    if (primaryCandidate != null) {
        return primaryCandidate;
    }

    // Priority 2: Check for @Priority (highest priority = lowest number)
    String priorityCandidate = determineHighestPriorityCandidate(candidates, requiredType);
    if (priorityCandidate != null) {
        return priorityCandidate;
    }

    // Priority 3: Fallback to name matching
    for (Map.Entry<String, Object> entry : candidates.entrySet()) {
        String candidateName = entry.getKey();
        if (matchesBeanName(candidateName, descriptor.getDependencyName())) {
            return candidateName;
        }
    }

    return null; // No match → NoUniqueBeanDefinitionException
}
💡 Name Fallback Explained

If you have two beans of type DataSource named "primaryDS" and "analyticsDS", and your field is private DataSource analyticsDS, Spring will match by field name as a last resort — no @Qualifier needed.

Why Constructor Injection is Preferred

// ✅ PREFERRED: Constructor injection
@Service
public class OrderService {

    private final PaymentGateway paymentGateway;
    private final InventoryService inventoryService;
    private final NotificationService notificationService;

    // Single constructor → Spring auto-detects, no @Autowired needed
    public OrderService(
            PaymentGateway paymentGateway,
            InventoryService inventoryService,
            NotificationService notificationService) {
        this.paymentGateway = paymentGateway;
        this.inventoryService = inventoryService;
        this.notificationService = notificationService;
    }
}

// ❌ AVOID: Field injection — hides dependencies, untestable without Spring
@Service
public class OrderService {

    @Autowired
    private PaymentGateway paymentGateway; // can't be final!

    @Autowired
    private InventoryService inventoryService;
}
🔑 Since Spring 4.3

If a class has exactly ONE constructor, Spring uses it for injection automatically — no @Autowired annotation required. With multiple constructors, you must annotate the preferred one with @Autowired.

How Constructor Injection Works Internally

// Inside ConstructorResolver.autowireConstructor()
public BeanWrapper autowireConstructor(
        String beanName, RootBeanDefinition mbd,
        Constructor<?>[] chosenCtors, Object[] explicitArgs) {

    // 1. Sort constructors by parameter count (greedy: most params first)
    AutowireUtils.sortConstructors(candidates);

    for (Constructor<?> candidate : candidates) {
        // 2. For each parameter, resolve the dependency
        Class<?>[] paramTypes = candidate.getParameterTypes();
        Object[] args = new Object[paramTypes.length];

        for (int i = 0; i < paramTypes.length; i++) {
            // Resolve each argument via the DI resolution algorithm
            args[i] = resolveAutowiredArgument(
                methodParam, beanName, autowiredBeanNames, converter);
        }

        // 3. Instantiate via constructor
        bw.setBeanInstance(instantiate(beanName, mbd, candidate, args));
    }
    return bw;
}

4. @Qualifier and @Primary Resolution Order

🧠 Resolution Priority (When Multiple Beans Match by Type)

Priority Mechanism Scope Use Case
1 (Highest) @Qualifier Per injection point Explicit selection at the consumer
2 @Primary Per bean definition Default choice among candidates
3 @Priority Per bean definition Ordered preference
4 (Lowest) Field/param name Per injection point Implicit fallback

@Qualifier Overrides @Primary

@Configuration
public class DataSourceConfig {

    @Bean
    @Primary  // Default choice when no qualifier is specified
    public DataSource primaryDataSource() {
        return new HikariDataSource(primaryConfig());
    }

    @Bean
    @Qualifier("analytics")
    public DataSource analyticsDataSource() {
        return new HikariDataSource(analyticsConfig());
    }
}

@Service
public class ReportService {

    private final DataSource dataSource;

    // @Qualifier WINS over @Primary — gets analyticsDataSource
    public ReportService(@Qualifier("analytics") DataSource dataSource) {
        this.dataSource = dataSource;
    }
}

@Service
public class UserService {

    private final DataSource dataSource;

    // No qualifier → @Primary kicks in → gets primaryDataSource
    public UserService(DataSource dataSource) {
        this.dataSource = dataSource;
    }
}
⚠️ Multiple @Primary = Runtime Error

If two beans of the same type are both marked @Primary, Spring throws NoUniqueBeanDefinitionException at startup. There can only be ONE primary bean per type in a single application context.

5. Optional Dependencies

Spring provides multiple patterns for declaring that a dependency might not exist at runtime:

@Service
public class NotificationService {

    // Pattern 1: @Autowired(required = false)
    // Field is left null if no bean found
    @Autowired(required = false)
    private SmsGateway smsGateway;

    // Pattern 2: Optional<T> (Java 8+)
    // Wraps presence/absence cleanly
    private final Optional<SlackIntegration> slackIntegration;

    // Pattern 3: ObjectProvider<T> (Spring's own)
    // Lazy resolution + stream support for multiple beans
    private final ObjectProvider<WebhookHandler> webhookHandlers;

    public NotificationService(
            Optional<SlackIntegration> slackIntegration,
            ObjectProvider<WebhookHandler> webhookHandlers) {
        this.slackIntegration = slackIntegration;
        this.webhookHandlers = webhookHandlers;
    }

    public void sendAlert(String message) {
        // Optional: Check presence
        slackIntegration.ifPresent(slack -> slack.post(message));

        // ObjectProvider: Stream over all registered handlers
        webhookHandlers.orderedStream()
            .forEach(handler -> handler.dispatch(message));

        // ObjectProvider: Get with fallback
        WebhookHandler primary = webhookHandlers.getIfAvailable(
            () -> new NoOpWebhookHandler());
    }
}
Pattern Null Safe Lazy Multi-Bean Best For
required=false ❌ Null if absent ❌ Eager ❌ Single Legacy code
Optional<T> ✅ Empty Optional ❌ Eager ❌ Single Clean functional code
ObjectProvider<T> ✅ getIfAvailable ✅ On-demand ✅ orderedStream() Framework/library code
💡 How Optional<T> is Resolved Internally

When Spring sees Optional<SomeBean>, it uses DependencyDescriptor.increaseNestingLevel() to unwrap the generic, resolves the inner type, and wraps the result in Optional.ofNullable(). No special post-processor is needed — this logic is baked into doResolveDependency().

6. @Lazy Injection — Proxy-Based Deferred Resolution

When @Lazy is placed on an injection point, Spring does NOT inject the actual bean. Instead, it creates a CGLIB proxy that intercepts the first method call and only then resolves the real bean from the container.

@Service
public class PaymentProcessor {

    private final FraudDetectionEngine fraudEngine;

    // FraudDetectionEngine is expensive to initialize (ML model loading)
    // @Lazy creates a proxy — actual bean created on FIRST USE
    public PaymentProcessor(@Lazy FraudDetectionEngine fraudEngine) {
        this.fraudEngine = fraudEngine;
        // At this point, fraudEngine is a CGLIB proxy, NOT the real instance
    }

    public void processPayment(Payment payment) {
        if (payment.getAmount() > 10000) {
            // FIRST call to proxy → triggers actual bean creation
            fraudEngine.analyze(payment); // proxy.intercept() → getBean()
        }
    }
}

Internal Proxy Mechanism

// Inside ContextAnnotationAutowireCandidateResolver
public Object getLazyResolutionProxyIfNecessary(
        DependencyDescriptor descriptor, String beanName) {

    if (isLazy(descriptor)) {
        return buildLazyResolutionProxy(descriptor, beanName);
    }
    return null;
}

private Object buildLazyResolutionProxy(
        DependencyDescriptor descriptor, String beanName) {

    BeanFactory beanFactory = this.beanFactory;

    // Create a TargetSource that resolves on first access
    TargetSource ts = new TargetSource() {
        @Override
        public Object getTarget() {
            // This is called on FIRST method invocation on the proxy
            Object target = beanFactory.doResolveDependency(descriptor, beanName, null, null);
            if (target == null) {
                throw new NoSuchBeanDefinitionException(descriptor.getDependencyType());
            }
            return target;
        }
    };

    // Create CGLIB proxy for classes, JDK proxy for interfaces
    ProxyFactory pf = new ProxyFactory();
    pf.setTargetSource(ts);
    pf.addInterface(descriptor.getDependencyType());
    return pf.getProxy(classLoader);
}
⚠️ @Lazy Pitfalls
  • Startup errors deferred — If the lazy bean has a misconfiguration, you won't know until first use in production
  • Circular dependency workaround — @Lazy on one side of a constructor circular dependency breaks the cycle by injecting a proxy
  • Proxy identity — fraudEngine.getClass() returns the CGLIB proxy class, not the actual class. Use AopUtils.getTargetClass()

7. The Reflection Code: Field.setAccessible + Field.set

For field injection, Spring uses raw Java reflection to bypass access modifiers and directly set private field values. Here's the actual code path:

// AutowiredAnnotationBeanPostProcessor$AutowiredFieldElement.inject()
private class AutowiredFieldElement extends InjectionMetadata.InjectedElement {

    private final boolean required;
    private volatile boolean cached;
    private volatile Object cachedFieldValue;

    @Override
    protected void inject(Object bean, String beanName, PropertyValues pvs) {
        Field field = (Field) this.member;
        Object value;

        if (this.cached) {
            // Cached resolution for prototype beans (same metadata, new instance)
            value = resolvedCachedArgument(beanName, this.cachedFieldValue);
        } else {
            // Full resolution through the DI algorithm
            DependencyDescriptor desc = new DependencyDescriptor(field, this.required);
            desc.setContainingClass(bean.getClass());

            Set<String> autowiredBeanNames = new LinkedHashSet<>(1);
            TypeConverter typeConverter = beanFactory.getTypeConverter();

            value = beanFactory.resolveDependency(
                desc, beanName, autowiredBeanNames, typeConverter);

            // Cache for future prototype instantiations
            synchronized (this) {
                this.cachedFieldValue = desc;
                this.cached = true;
            }
        }

        if (value != null) {
            // THE CRITICAL LINE: bypass Java access control
            ReflectionUtils.makeAccessible(field);  // → field.setAccessible(true)
            field.set(bean, value);                   // → directly sets the value
        }
    }
}

ReflectionUtils.makeAccessible — The Access Bypass

// org.springframework.util.ReflectionUtils
public static void makeAccessible(Field field) {
    if ((!Modifier.isPublic(field.getModifiers()) ||
         !Modifier.isPublic(field.getDeclaringClass().getModifiers()) ||
         Modifier.isFinal(field.getModifiers())) &&
        !field.isAccessible()) {

        field.setAccessible(true); // Disables Java access checks
    }
}

// What this means at the JVM level:
// 1. The SecurityManager check is bypassed
// 2. private/protected/package-private modifiers are ignored
// 3. The JIT can no longer inline field access (minor perf cost)
// 4. Module system (Java 9+) may still block access → --add-opens required
⚠️ Java Module System Impact (Java 9+)

With the module system, setAccessible(true) throws InaccessibleObjectException unless the module is opened. That's why Spring Boot adds JVM flags like --add-opens java.base/java.lang=ALL-UNNAMED. This is why constructor injection (which doesn't need reflection to set fields) is even more preferred on modern JVMs.

Setter Injection Reflection Path

// AutowiredMethodElement.inject() — similar but uses Method.invoke()
@Override
protected void inject(Object bean, String beanName, PropertyValues pvs) {
    Method method = (Method) this.member;
    Object[] arguments = resolveMethodArguments(method, bean, beanName);

    if (arguments != null) {
        ReflectionUtils.makeAccessible(method);
        method.invoke(bean, arguments); // Calls the setter
    }
}

8. Industry Pattern: Custom Qualifier Annotations

In large codebases with multiple implementations of the same interface, string-based @Qualifier("name") becomes fragile — typos cause runtime errors. The industry solution is custom qualifier annotations that provide compile-time safety.

Step 1: Define Custom Qualifier

import java.lang.annotation.*;
import org.springframework.beans.factory.annotation.Qualifier;

@Target({ElementType.FIELD, ElementType.METHOD,
         ElementType.PARAMETER, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Qualifier  // ← This meta-annotation is what makes it work!
public @interface PaymentMethod {
    PaymentType value();
}

public enum PaymentType {
    CREDIT_CARD, BANK_TRANSFER, CRYPTO, DIGITAL_WALLET
}

Step 2: Annotate Implementations

public interface PaymentProcessor {
    PaymentResult process(Payment payment);
}

@Service
@PaymentMethod(PaymentType.CREDIT_CARD)
public class CreditCardProcessor implements PaymentProcessor {
    @Override
    public PaymentResult process(Payment payment) {
        // Stripe/Adyen integration
    }
}

@Service
@PaymentMethod(PaymentType.CRYPTO)
public class CryptoProcessor implements PaymentProcessor {
    @Override
    public PaymentResult process(Payment payment) {
        // Web3 wallet integration
    }
}

@Service
@PaymentMethod(PaymentType.BANK_TRANSFER)
public class BankTransferProcessor implements PaymentProcessor {
    @Override
    public PaymentResult process(Payment payment) {
        // ACH/SEPA integration
    }
}

Step 3: Inject with Type Safety

@Service
public class CheckoutService {

    private final PaymentProcessor creditCardProcessor;
    private final PaymentProcessor cryptoProcessor;

    public CheckoutService(
            @PaymentMethod(PaymentType.CREDIT_CARD) PaymentProcessor creditCardProcessor,
            @PaymentMethod(PaymentType.CRYPTO) PaymentProcessor cryptoProcessor) {
        this.creditCardProcessor = creditCardProcessor;
        this.cryptoProcessor = cryptoProcessor;
    }
}

How Custom Qualifiers are Resolved Internally

// Inside QualifierAnnotationAutowireCandidateResolver
protected boolean checkQualifier(
        BeanDefinitionHolder bdHolder,
        Annotation annotation,
        TypeConverter typeConverter) {

    Class<? extends Annotation> type = annotation.annotationType();

    // Check if the annotation itself is meta-annotated with @Qualifier
    if (!AnnotationUtils.isQualifierAnnotation(type)) {
        return true; // Not a qualifier, skip
    }

    // Compare ALL annotation attributes (e.g., value = PaymentType.CRYPTO)
    Map<String, Object> attributes =
        AnnotationUtils.getAnnotationAttributes(annotation);

    for (Map.Entry<String, Object> entry : attributes.entrySet()) {
        String attributeName = entry.getKey();
        Object expectedValue = entry.getValue();

        // Get the corresponding attribute from the candidate bean's annotation
        Annotation candidateAnnotation = getQualifierAnnotation(bdHolder, type);
        Object actualValue = AnnotationUtils.getValue(candidateAnnotation, attributeName);

        if (!expectedValue.equals(actualValue)) {
            return false; // Attribute mismatch → not a match
        }
    }
    return true; // All attributes match!
}
💡 Advanced Pattern: Map Injection for Strategy Pattern

For runtime dynamic dispatch (e.g., selecting processor based on user request), inject all implementations into a Map:

@Service
public class DynamicPaymentRouter {

    private final Map<String, PaymentProcessor> processors;

    // Spring auto-populates: key=bean name, value=bean instance
    public DynamicPaymentRouter(Map<String, PaymentProcessor> processors) {
        this.processors = processors;
        // {"creditCardProcessor": CreditCardProcessor@abc,
        //  "cryptoProcessor": CryptoProcessor@def, ...}
    }

    public PaymentResult route(String method, Payment payment) {
        PaymentProcessor processor = processors.get(method + "Processor");
        if (processor == null) {
            throw new UnsupportedPaymentMethodException(method);
        }
        return processor.process(payment);
    }
}

🎯 Key Takeaways

  • AutowiredAnnotationBeanPostProcessor is the engine — it scans for @Autowired, @Value, and @Inject at two phases: metadata collection and injection
  • Resolution order: Type → Qualifier → Primary → Priority → Name fallback
  • Constructor injection is preferred: immutability, testability, no reflection needed for field setting, fails fast on missing dependencies
  • @Qualifier overrides @Primary — @Primary is the default; @Qualifier is the explicit override
  • ObjectProvider<T> is the most powerful optional pattern: lazy, safe, supports multiple beans
  • @Lazy creates a CGLIB proxy that resolves the real bean on first method invocation — defers errors too
  • Field injection uses reflection: Field.setAccessible(true) + Field.set() — bypasses access control, breaks with Java modules
  • Custom qualifier annotations provide compile-time safety for multi-implementation scenarios — meta-annotate with @Qualifier
