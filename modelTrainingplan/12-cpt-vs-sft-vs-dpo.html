CPT vs SFT vs DPO — Complete Deep Dive Comparison

Understanding the fundamental differences between all three training stages — what each does, why it exists, what data it needs, what happens when you skip it, and how they perform individually vs together.

🎓 The University Analogy (Non-Technical)

Think of training an AI model like educating a student:

StageUniversity AnalogyWhat Happens
Base Model (Pre-trained) A brilliant student who has read millions of books in many languages Knows general knowledge, grammar, facts — but hasn't specialized
CPT (Continued Pre-Training) Sending the student to study Sanskrit texts in a library for 6 months Absorbs domain knowledge — can now complete sentences about scriptures
SFT (Supervised Fine-Tuning) Having a tutor teach them how to answer questions and explain concepts Learns the FORMAT of helpful responses — question→answer pattern
DPO (Preference Alignment) A panel of experts grading their answers: "This answer is better than that one" Learns WHICH responses are better — accuracy, depth, tone refinement
🔑 Key Insight

CPT = Knowledge (what does the model know?)
SFT = Behavior (how does it respond?)
DPO = Quality (how good are its responses?)

🔬 Fundamental Technical Differences

What Each Stage Optimizes

AspectCPTSFTDPO
Objective Function Next token prediction on raw text Next token prediction on assistant responses only Preference optimization (chosen vs rejected)
What It Learns Domain vocabulary, concepts, patterns, facts How to format responses, follow instructions Which responses are better quality
Loss Function Cross-entropy on ALL tokens Cross-entropy on ASSISTANT tokens only DPO loss: log-probability ratio of chosen vs rejected
Analogy Reading a textbook cover-to-cover Practicing answering exam questions Getting feedback on which answers scored higher
Changes to Model Internal representations, embeddings, knowledge Output distribution — how it structures responses Fine-grained preference between response styles

The Mathematical Difference

# ============================================
# CPT Loss: Predict every next token
# ============================================
# Input:  "The Bhagavad Gita teaches that karma yoga..."
# Loss on: [The] [Bhagavad] [Gita] [teaches] [that] [karma] [yoga] ...
#           ↑      ↑          ↑       ↑         ↑       ↑       ↑
#      ALL tokens contribute to the loss

L_CPT = -1/N × Σ log P(token_i | token_1, ..., token_{i-1})


# ============================================
# SFT Loss: Only predict assistant's response
# ============================================
# Input:  [System: You are a scholar] [User: What is karma?] [Assistant: Karma means...]
# Loss on: [ignored]                   [ignored]              [Karma] [means] [...]
#                                                               ↑       ↑       ↑
#                                                         ONLY assistant tokens

L_SFT = -1/M × Σ log P(assistant_token_j | all_previous_tokens)
# Where M = number of assistant tokens only


# ============================================
# DPO Loss: Compare chosen vs rejected
# ============================================
# Input: Prompt + Chosen response + Rejected response
# The model learns: P(chosen) should be HIGHER than P(rejected)

L_DPO = -log σ(β × [log π_θ(y_chosen|x)/π_ref(y_chosen|x) 
                    - log π_θ(y_rejected|x)/π_ref(y_rejected|x)])

# Where:
#   π_θ = our model being trained
#   π_ref = frozen reference model (model before DPO)
#   β = controls how much deviation is allowed
#   σ = sigmoid function

📊 Dataset Format Comparison

CPT Dataset Format

# CPT format: Just raw text. No structure. No questions or answers.
# The model reads it like reading a book.

# Example 1: Plain scripture text
{"text": "अथातो धर्मजिज्ञासा। The Bhagavad Gita, composed as part of the Mahabharata, presents a dialogue between Prince Arjuna and Lord Krishna on the battlefield of Kurukshetra. The text addresses fundamental questions about duty (dharma), action (karma), knowledge (jnana), and devotion (bhakti). In Chapter 2, Verse 47, Krishna instructs: कर्मण्येवाधिकारस्ते मा फलेषु कदाचन। मा कर्मफलहेतुर्भूर्मा ते सङ्गोऽस्त्वकर्मणि॥ This verse establishes the foundation of Karma Yoga..."}

# Example 2: Commentary text
{"text": "Shankaracharya's commentary on the Mandukya Upanishad explains the four states of consciousness: Vaishvanara (waking), Taijasa (dreaming), Prajna (deep sleep), and Turiya (the fourth, transcendent state). The Mandukya Karika by Gaudapada further elaborates..."}

# Example 3: Philosophical discourse
{"text": "सांख्यदर्शन के अनुसार प्रकृति और पुरुष दो मूल तत्व हैं। प्रकृति जड़ है किन्तु सक्रिय है, जबकि पुरुष चेतन है किन्तु निष्क्रिय है। इन दोनों के संयोग से सृष्टि होती है..."}

# System prompt + User question + Assistant answer.

This is the foundational verse of Karma Yoga. Krishna teaches Arjuna that one should focus on righteous action without attachment to outcomes..."}

DPO Dataset Format

# DPO format: Same prompt with TWO responses — one better (chosen), one worse (rejected).
# The model learns to prefer the chosen style over the rejected style.

# Example 1: Accuracy preference
{
    "prompt": [
        {"role": "system", "content": "You are a Hindu scripture scholar."},
        {"role": "user", "content": "Who spoke the Bhagavad Gita?"}
    ],
    "chosen": [
        {"role": "assistant", "content": "The Bhagavad Gita is primarily spoken by Lord Krishna (श्रीकृष्ण) to Arjuna on the battlefield of Kurukshetra. However, the text has multiple narrators:\n\n1. **Sanjaya** narrates the dialogue to King Dhritarashtra (frame narrative)\n2. **Krishna** speaks most of the verses (574 out of 700)\n3. **Arjuna** asks questions and speaks some verses\n4. **Dhritarashtra** speaks the opening verse\n\nThe Gita is found in the Bhishma Parva (Book 6) of the Mahabharata, chapters 25-42."}
    ],
    "rejected": [
        {"role": "assistant", "content": "The Bhagavad Gita was spoken by Krishna to Arjuna before a big battle. It's a holy book of Hinduism."}
    ]
}

# Example 2: Depth preference
{
    "prompt": [
        {"role": "system", "content": "You are a Hindu scripture scholar."},
        {"role": "user", "content": "What is Maya?"}
    ],
    "chosen": [
        {"role": "assistant", "content": "Maya (माया) is one of the most complex concepts in Hindu philosophy, understood differently across schools:\n\n**Advaita Vedanta (Shankara):**\nMaya is the cosmic illusion that makes the one Brahman appear as the manifold world. It is neither real (sat) nor unreal (asat) — it is 'mithya' (apparently real). Shankara uses the rope-snake analogy: just as a rope is mistaken for a snake in darkness, Brahman is mistaken for the world due to Maya.\n\nमूल श्लोक (Vivekachudamani 108):\n*ब्रह्म सत्यं जगन्मिथ्या जीवो ब्रह्मैव नापरः*\n\n**Vishishtadvaita (Ramanuja):**\nMaya is not illusion but the REAL creative power (shakti) of God. The world is real — it is the body of Brahman.\n\n**Dvaita (Madhva):**\nMaya is the Lord's power of creation, not illusion. The world is genuinely real and distinct from God.\n\n**In the Gita (7.14):**\n*दैवी ह्येषा गुणमयी मम माया दुरत्यया*\n'This divine Maya of Mine, consisting of the three gunas, is difficult to overcome.'"}
    ],
    "rejected": [
        {"role": "assistant", "content": "Maya means illusion in Hinduism. It refers to the idea that the world is not real. Hindus believe that everything we see is Maya and only Brahman is real. This concept is central to Hindu philosophy and is discussed in many texts."}
    ]
}

# Example 3: Respectfulness preference
{
    "prompt": [
        {"role": "system", "content": "You are a Hindu scripture scholar."},
        {"role": "user", "content": "Are Hindu gods just myths?"}
    ],
    "chosen": [
        {"role": "assistant", "content": "This is a question that involves different perspectives and frameworks of understanding:\n\n**Within the tradition:** Hindu deities are understood as real manifestations of the divine. The Puranas describe them as actual beings, while Vedantic philosophy sees them as aspects of the one Brahman. For millions of practitioners, these are living presences in their spiritual lives.\n\n**Scholarly perspective:** Historians of religion study these narratives as sacred literature that encodes deep philosophical truths, cultural values, and psychological insights. The stories function as teaching vehicles (upadesha).\n\n**The Hindu philosophical view itself is nuanced:**\n- Nirguna Brahman (formless absolute) is beyond all names and forms\n- Saguna Brahman (with attributes) manifests as various deities for the benefit of devotees\n- This is not 'myth vs reality' but different levels of truth (paramarthika vs vyavaharika)\n\nThe Rig Veda itself says (1.164.46): *एकं सद्विप्रा बहुधा वदन्ति* — 'Truth is one; the wise call it by many names.'"}
    ],
    "rejected": [
        {"role": "assistant", "content": "Hindu gods are mythological figures from ancient stories. Like Greek or Norse mythology, they are fictional characters created by ancient people to explain natural phenomena before science existed. Modern scholars consider them myths, though some Hindus still believe in them."}
    ]
}

🧠 What Each Stage Changes Inside the Model

CPT: Changes the Model's Knowledge

# BEFORE CPT: Ask the model about a specific verse
# Model: "I'm not sure about the exact Sanskrit text..." (vague, generic)

# AFTER CPT: Same question
# Model: "कर्मण्येवाधिकारस्ते मा फलेषु कदाचन..." (knows the actual content)

# What changed internally:
# - Token embeddings for Sanskrit/Hindi words are now more meaningful
# - Attention patterns recognize scripture-specific patterns
# - MLP layers encode factual relationships (which verse is in which chapter)
# - The model's "world model" now includes scripture domain knowledge

SFT: Changes the Model's Behavior

# BEFORE SFT (after CPT): Give it a question
# Input: "What is dharma?"
# Model: "dharma is a concept in hinduism and buddhism that refers to the cosmic order
#          and individual duty the word comes from the root dhr meaning to hold..." 
#          (rambling, no structure, doesn't stop, no formatting)

# AFTER SFT: Same question
# Model: "Dharma (धर्म) has multiple interconnected meanings in Hindu philosophy:
#          
#          1. **Cosmic Order (Rta)** — The underlying principle that maintains...
#          2. **Individual Duty (Svadharma)** — One's personal obligations based on...
#          3. **Righteousness** — Moral and ethical conduct...
#          
#          The Bhagavad Gita (18.66) emphasizes..."
#          (structured, helpful, proper formatting, knows when to stop)

# What changed internally:
# - Output distribution shifted toward structured response patterns
# - Model learned to START responses helpfully (not with filler)
# - Model learned to STOP at appropriate points
# - Attention now prioritizes the user's question when generating

DPO: Changes the Model's Quality Judgment

# BEFORE DPO (after SFT): Ask a nuanced question
# Model: "Advaita Vedanta says the world is an illusion (maya). Brahman is the 
#          only reality." (correct but oversimplified, only one perspective)

# AFTER DPO: Same question  
# Model: "The concept of Maya differs across philosophical schools:
#          
#          **Advaita (Shankara):** Maya is 'mithya' — neither real nor unreal...
#          **Vishishtadvaita (Ramanuja):** The world is real, as it is the body of Brahman...
#          **Dvaita (Madhva):** Maya is God's genuine creative power...
#          
#          Original Sanskrit (Vivekachudamani 108):
#          ब्रह्म सत्यं जगन्मिथ्या जीवो ब्रह्मैव नापरः"
#          (nuanced, multi-perspective, includes Sanskrit, scholarly)

# What changed internally:
# - Model now prefers generating nuanced over simplistic responses
# - Probability of citing sources increased
# - Probability of dismissive/shallow content decreased
# - Response "quality distribution" shifted toward preferred style

⚠️ What Happens When You Skip a Stage?

❌ Skip CPT (do only SFT + DPO)

Impact of Skipping CPT
AspectEffectSeverity
Domain knowledgeModel relies only on pre-training knowledge (may not know specific verses)🟡 Medium-High
Sanskrit/Hindi fluencyIf base model already handles these languages (Gemma does), impact is lower🟡 Medium
Verse accuracyMore hallucination of verses — model doesn't "know" the actual texts deeply🔴 High
Response qualitySFT+DPO still teaches format and preferences — responses look good but may be factually weaker🟡 Medium
When acceptableIf the base model already has decent coverage of your domain (e.g., Gemma already knows common Gita verses)—

Verdict: Skip CPT if your domain is well-represented in the base model's training data. For niche topics (specific commentaries, rare Upanishads, Sanskrit philosophical texts), CPT is critical.

❌ Skip SFT (do only CPT + DPO)

Impact of Skipping SFT — MOST DAMAGING
AspectEffectSeverity
Response formatModel cannot format responses properly — rambles, doesn't answer the question🔴 Critical
Instruction followingModel ignores user intent — just generates text continuation🔴 Critical
DPO effectivenessDPO CANNOT work well without SFT — the model needs to produce coherent responses BEFORE you can compare them🔴 Critical
Conversation abilityNo multi-turn capability — model doesn't understand the chat format🔴 Critical
When acceptableAlmost NEVER — unless the base model is already instruction-tuned (like gemma-it)—

Verdict: NEVER skip SFT unless you're starting from an instruct-tuned model. If using gemma-3-27b-it (already instruction-tuned), you can skip SFT and go directly to DPO — but only because someone already did SFT for you.

❌ Skip DPO (do only CPT + SFT)

Impact of Skipping DPO — Least Damaging
AspectEffectSeverity
Response qualityResponses are helpful but may lack nuance, depth, or preferred style🟢 Low-Medium
HallucinationModel may still hallucinate verse references (SFT alone doesn't fix this)🟡 Medium
Tone/styleLess polished — may sometimes be too verbose, too brief, or slightly off-tone🟢 Low
SafetyNo alignment against disrespectful or incorrect responses🟡 Medium
When acceptableFor prototypes, internal tools, or when preference data is unavailable—

Verdict: CPT + SFT alone gives you a functional, knowledgeable model. DPO is the "polish" — important for production but not strictly necessary for a working prototype.

🔬 What If You Only Do ONE Stage?

Only CPT (No SFT, No DPO)

# Result: A model that KNOWS scriptures but can't CONVERSE about them

# Input: "What is the meaning of dharma?"
# Output: "What is the meaning of dharma? This question has been explored by numerous
#          scholars across centuries. The Mahabharata states that dharma is subtle
#          (dharmasya tattvam nihitam guhayam). In the context of Manusmriti Chapter 1..."
#          [continues indefinitely, never directly answers, just generates related text]

# Why this happens:
# - CPT teaches the model to CONTINUE text, not to ANSWER questions
# - It's like a student who has read all the books but never practiced writing essays
# - The model becomes a "scripture text generator" not a "scripture assistant"

# When this is useful:
# ✅ Text completion/generation
# ✅ Creating synthetic training data
# ✅ As foundation for subsequent SFT
# ❌ NOT useful as a chatbot or Q&A system

Only SFT (No CPT, No DPO)

# Result: A model that can CONVERSE but may lack deep domain knowledge

# Input: "Explain the Pancha Kosha theory from Taittiriya Upanishad"
# Output: "The Pancha Kosha (Five Sheaths) theory describes five layers of human 
#          existence: Annamaya (physical), Pranamaya (vital), Manomaya (mental), 
#          Vijnanamaya (intellectual), and Anandamaya (bliss).
#          
#          [Might get basic facts right from pre-training knowledge]
#          [But may not know the specific verses from Taittiriya Upanishad]
#          [May hallucinate verse numbers it doesn't actually know]"

# Why this happens:
# - The base model has SOME knowledge from pre-training
# - SFT taught it HOW to respond but didn't add NEW knowledge
# - It's like teaching someone answer formats without giving them the textbook

# When this is useful:
# ✅ General knowledge Q&A (topics well-covered in pre-training)
# ✅ Quick prototype/demo
# ✅ When base model already has good domain coverage
# ❌ Deep domain expertise requires CPT first

Only DPO (No CPT, No SFT)

# Result: Almost completely broken — DPO REQUIRES a model that can already generate responses

# Input: "What is karma?"
# Output: [Likely gibberish, repetition, or text completion — NOT a response]

# Why this happens:
# - DPO compares two responses and teaches the model to prefer one
# - But if the model can't generate coherent responses in the first place,
#   there's nothing meaningful to "prefer"
# - It's like asking a student to grade exam papers when they haven't 
#   learned to write yet

# When this is useful:
# ❌ NEVER useful alone on a base (non-instruct) model
# ✅ ONLY works on an already instruction-tuned model (like gemma-it)
# 
# Exception: If you start from gemma-3-27b-it (already SFT'd by Google):
#   DPO alone on top of this = valid approach for alignment

🌍 Real-World Scenarios

Scenario 1: "I want a chatbot that accurately answers Gita questions"

Recommended: CPT → SFT → DPO

  • CPT: Feed it all 700 verses + commentaries (Shankara, Ramanuja, Madhva) + modern interpretations. This ensures it KNOWS the exact verses.
  • SFT: Create 20,000 Q&A pairs about the Gita (verse meanings, philosophy, context).
  • DPO: Create 5,000 preference pairs where "chosen" has correct verse numbers and "rejected" has wrong/hallucinated ones.

Expected result: Model cites correct verses 90%+ of the time, provides multiple commentarial perspectives, responds in user's language.

Scenario 2: "Quick prototype for a hackathon"

Recommended: SFT only (on instruct model)

  • Start from gemma-3-12b-it (already instruction-tuned)
  • Create 1,000-2,000 high-quality scripture Q&A pairs
  • Train QLoRA SFT for 3 hours

Expected result: Decent responses about well-known topics. Will struggle with obscure references but handles common questions well.

Scenario 3: "Model must handle rare Sanskrit texts"

Recommended: Heavy CPT → SFT → DPO

  • CPT: CRITICAL — feed it 5+ GB of Sanskrit texts, commentaries, rare Upanishads, Darshana Shastras. Multiple epochs.
  • SFT: Create examples in Sanskrit itself, not just about Sanskrit.
  • DPO: Prefer responses that use correct Sanskrit grammar and proper sandhi.

Expected result: Model understands and generates grammatically correct Sanskrit, knows rare texts that aren't in standard training data.

Scenario 4: "Existing instruct model gives shallow answers, need better quality"

Recommended: DPO only (on instruct model)

  • Start from gemma-3-27b-it
  • Create 5,000-10,000 preference pairs: chosen = deep scholarly response, rejected = shallow response
  • Train DPO for 4-6 hours

Expected result: Same knowledge but better response quality — more nuanced, better structured, includes Sanskrit, cites sources.

❌ Common Misconceptions

MisconceptionReality
"SFT teaches the model new knowledge" SFT primarily teaches format and behavior, not facts. New knowledge comes from CPT. SFT examples do add some knowledge but it's not the primary mechanism.
"DPO makes the model smarter" DPO doesn't add intelligence or knowledge. It teaches the model to select better responses from what it already knows. Think of it as improving judgment, not knowledge.
"More CPT data is always better" Low-quality CPT data (badly OCR'd, corrupted, duplicate) can HURT the model. Quality > quantity. A clean 1GB dataset beats a noisy 10GB dataset.
"I need all three stages" Many production models use only 1-2 stages. If starting from an instruct model (-it), you might only need DPO. If your domain is well-known, skip CPT.
"DPO and SFT do the same thing" They're fundamentally different. SFT shows the model "here's what a good response looks like." DPO shows it "this response is BETTER than that response." SFT is absolute, DPO is comparative.
"CPT requires a non-instruct model" You CAN do CPT on instruct models. But it may slightly degrade instruction-following ability, which you'd recover during SFT.
"Higher LoRA rank = better results" Higher rank means more trainable parameters, which can overfit on small datasets. Match rank to your data size: r=16 for DPO (small data), r=64 for CPT (large data).

📋 Final Summary

🎯 The One-Paragraph Summary

CPT injects new domain knowledge into the model (teaches it WHAT scriptures say). SFT teaches the model how to behave as a helpful assistant (teaches it HOW to respond). DPO refines quality by teaching preferences (teaches it WHICH responses are better). Each stage builds on the previous one. CPT without SFT gives you a text generator, not an assistant. SFT without CPT gives you a helpful assistant with potentially shallow domain knowledge. DPO without SFT gives you nothing useful. The full pipeline (CPT→SFT→DPO) gives you a knowledgeable, helpful, and high-quality domain expert.
