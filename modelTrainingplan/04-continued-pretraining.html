Chapter 4: Stage 1 — Continued Pre-Training (CPT)

Domain Adaptive Pre-Training: Teaching Gemma to deeply understand Hindu scriptures by training on your raw text corpus.

🧠 What is Continued Pre-Training?

The Concept (Non-Technical)

Gemma was pre-trained on general internet text — it knows a bit about everything. Continued Pre-Training (CPT), also called Domain Adaptive Pre-Training (DAPT), is like sending it to a specialized university. You feed it your entire scripture corpus and let it read all of it, learning the vocabulary, writing patterns, facts, and structure of Hindu philosophical texts.

The Technical Explanation

CPT continues the original causal language modeling objective on domain-specific data. The model learns to predict the next token given previous tokens, but now exclusively on your scripture corpus. This:

  • Adapts the model's internal representations to the scripture domain
  • Improves tokenization efficiency for Sanskrit/Hindi terms
  • Injects factual knowledge (verses, stories, philosophical concepts)
  • Teaches the writing style and structure of scriptural texts
⚠️ When to Skip CPT

CPT is optional if:

  • Your domain data is small (<100MB)
  • The base model already performs well on your domain
  • You have limited compute budget (CPT is the most expensive stage)

In those cases, skip directly to SFT (Chapter 5). But for the best results on Hindu scriptures — especially Sanskrit content — CPT significantly improves quality.

📋 Two Approaches: Full Fine-Tune vs LoRA

Approach Memory Quality Speed Cost Recommended For
Full Fine-Tune ~200 GB (27B model) Best Slow $$$ Production models, large corpus (5GB+)
LoRA ~20 GB (QLoRA) Very Good Fast $ Experimentation, smaller corpus, budget-limited

💻 Code: CPT with LoRA (Recommended Start)

"""
Continued Pre-Training with LoRA on Hindu Scripture Corpus
===========================================================
This script trains the Gemma model on raw scripture text using
LoRA for memory efficiency. Can run on a single A100 40GB GPU.

Usage:
    python cpt_lora.py

Requirements:
    pip install torch transformers trl peft bitsandbytes datasets accelerate
"""
import torch
from datasets import load_dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer, SFTConfig

# ============================================
# CONFIGURATION
# ============================================
MODEL_NAME = "google/gemma-3-27b-it"  # or "google/gemma-3-12b-it" for less VRAM
DATASET_PATH = "./datasets/cpt_corpus.jsonl"
OUTPUT_DIR = "./checkpoints/cpt_lora"

# Hyperparameters
LEARNING_RATE = 2e-5
NUM_EPOCHS = 2
BATCH_SIZE = 2
GRADIENT_ACCUMULATION = 8  # Effective batch = 2 * 8 = 16
MAX_SEQ_LENGTH = 2048
WARMUP_STEPS = 100

# ============================================
# STEP 1: Load Tokenizer
# ============================================
print("Loading tokenizer...")
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)

# Set padding token (Gemma uses eos_token for padding)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token
    tokenizer.pad_token_id = tokenizer.eos_token_id

# ============================================
# STEP 2: Load Model in 4-bit (QLoRA)
# ============================================
print("Loading model in 4-bit precision...")

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",          # NormalFloat4 quantization
    bnb_4bit_compute_dtype=torch.bfloat16,  # Compute in BF16
    bnb_4bit_use_double_quant=True,      # Nested quantization for extra savings
)

model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    quantization_config=bnb_config,
    device_map="auto",
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2",  # Use Flash Attention for speed
)

# Prepare for k-bit training (fixes some layers for gradient computation)
model = prepare_model_for_kbit_training(model)

# ============================================
# STEP 3: Configure LoRA
# ============================================
print("Configuring LoRA adapters...")

lora_config = LoraConfig(
    r=64,                    # Rank — higher = more capacity but more memory
    lora_alpha=32,           # Scaling factor (usually r/2 or r)
    lora_dropout=0.05,       # Dropout for regularization
    bias="none",             # Don't train bias terms
    task_type="CAUSAL_LM",   # Causal language modeling
    target_modules=[          # Which layers to add LoRA to
        "q_proj",    # Query projection (attention)
        "k_proj",    # Key projection (attention)
        "v_proj",    # Value projection (attention)
        "o_proj",    # Output projection (attention)
        "gate_proj", # Gate in FFN (SwiGLU)
        "up_proj",   # Up projection in FFN
        "down_proj", # Down projection in FFN
    ],
)

model = get_peft_model(model, lora_config)

# Print trainable parameters
model.print_trainable_parameters()
# Output: trainable params: 167,772,160 || all params: 27,227,128,832 || trainable%: 0.62%

# ============================================
# STEP 4: Load Dataset
# ============================================
print("Loading dataset...")

dataset = load_dataset("json", data_files=DATASET_PATH, split="train")
print(f"Dataset size: {len(dataset)} examples")

# For CPT, we use the "text" field directly (language modeling)
# The SFTTrainer handles tokenization automatically

# ============================================
# STEP 5: Configure Training
# ============================================
training_args = SFTConfig(
    output_dir=OUTPUT_DIR,
    
    # Training schedule
    num_train_epochs=NUM_EPOCHS,
    per_device_train_batch_size=BATCH_SIZE,
    gradient_accumulation_steps=GRADIENT_ACCUMULATION,
    
    # Optimizer
    learning_rate=LEARNING_RATE,
    lr_scheduler_type="cosine",         # Cosine decay schedule
    warmup_steps=WARMUP_STEPS,
    weight_decay=0.01,
    optim="paged_adamw_8bit",           # Memory-efficient optimizer
    
    # Precision
    bf16=True,                          # BFloat16 training
    
    # Memory optimization
    gradient_checkpointing=True,        # Trade compute for memory
    max_seq_length=MAX_SEQ_LENGTH,
    packing=True,                       # Pack multiple short texts into one sequence
    
    # Logging
    logging_steps=10,
    logging_dir=f"{OUTPUT_DIR}/logs",
    
    # Saving
    save_strategy="steps",
    save_steps=500,
    save_total_limit=3,                 # Keep only last 3 checkpoints
    
    # Evaluation
    eval_strategy="steps",
    eval_steps=500,
    
    # Misc
    report_to="wandb",                  # Log to Weights & Biases
    run_name="gemma-scripture-cpt",
    seed=42,
    
    # Dataset
    dataset_text_field="text",          # Column name in our JSONL
)

# ============================================
# STEP 6: Create Trainer and Train
# ============================================
print("Starting training...")

trainer = SFTTrainer(
    model=model,
    args=training_args,
    train_dataset=dataset,
    processing_class=tokenizer,
)

# Train!
train_result = trainer.train()

# Save final model
print("Saving final model...")
trainer.save_model(f"{OUTPUT_DIR}/final")
tokenizer.save_pretrained(f"{OUTPUT_DIR}/final")

# Print results
print(f"\n{'='*50}")
print(f"Training complete!")
print(f"Final loss: {train_result.training_loss:.4f}")
print(f"Model saved to: {OUTPUT_DIR}/final")
print(f"{'='*50}")

💻 Code: Full Fine-Tune with DeepSpeed (Maximum Quality)

🔍 Full Fine-Tune Code (Requires Multi-GPU)
"""
Full parameter Continued Pre-Training with DeepSpeed ZeRO-3
============================================================
Requires: 4-8x A100 80GB GPUs
Gives: Best possible domain adaptation quality

Usage:
    accelerate launch --config_file deepspeed_config.yaml cpt_full.py
"""
import torch
from datasets import load_dataset
from transformers import (
    AutoTokenizer, 
    AutoModelForCausalLM,
    TrainingArguments,
    Trainer,
    DataCollatorForLanguageModeling
)

# Configuration
MODEL_NAME = "google/gemma-3-27b-pt"  # Use PRE-TRAINED (not instruct) for CPT
DATASET_PATH = "./datasets/cpt_corpus.jsonl"
OUTPUT_DIR = "./checkpoints/cpt_full"
MAX_SEQ_LENGTH = 4096

# Load tokenizer and model (full precision for full fine-tune)
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype=torch.bfloat16,
    attn_implementation="flash_attention_2",
)

# Load and tokenize dataset
dataset = load_dataset("json", data_files=DATASET_PATH, split="train")

def tokenize_function(examples):
    """Tokenize text for causal language modeling."""
    return tokenizer(
        examples["text"],
        truncation=True,
        max_length=MAX_SEQ_LENGTH,
        padding=False,
    )

tokenized_dataset = dataset.map(
    tokenize_function,
    batched=True,
    remove_columns=dataset.column_names,
    num_proc=8
)

# Data collator (handles dynamic padding and label creation)
data_collator = DataCollatorForLanguageModeling(
    tokenizer=tokenizer,
    mlm=False  # Causal LM, not masked LM
)

# Training arguments for DeepSpeed
training_args = TrainingArguments(
    output_dir=OUTPUT_DIR,
    num_train_epochs=1,
    per_device_train_batch_size=1,
    gradient_accumulation_steps=32,   # Effective batch = 4 GPUs * 1 * 32 = 128
    learning_rate=1e-5,               # Lower LR for full fine-tune
    lr_scheduler_type="cosine",
    warmup_ratio=0.05,
    weight_decay=0.01,
    bf16=True,
    gradient_checkpointing=True,
    logging_steps=5,
    save_strategy="steps",
    save_steps=200,
    save_total_limit=2,
    deepspeed="./configs/ds_zero3.json",  # DeepSpeed config
    report_to="wandb",
    run_name="gemma-scripture-cpt-full",
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset,
    data_collator=data_collator,
)

trainer.train()
trainer.save_model(f"{OUTPUT_DIR}/final")

⚙️ Hyperparameter Guide

Parameter LoRA Value Full FT Value Explanation
Learning Rate 2e-5 1e-5 How fast the model learns. Too high = unstable. Too low = slow.
Epochs 2-3 1-2 Number of times to read the entire dataset. More for small datasets.
Batch Size (effective) 16-32 64-128 Number of examples processed before updating weights.
Max Seq Length 2048 4096 Maximum tokens per training example. Longer = more context but more memory.
Warmup Steps 100 200 Gradual increase of learning rate at start. Prevents early instability.
Weight Decay 0.01 0.01 L2 regularization to prevent overfitting.
LoRA Rank (r) 64 N/A Capacity of LoRA adapters. Higher = more expressive but more memory.
LoRA Alpha 32 N/A Scaling factor. Typically r/2 or r. Affects learning magnitude.

📊 Monitoring Training

"""
Monitor CPT training with Weights & Biases.
Look for these key metrics:
"""
# What to watch during training:

# 1. TRAINING LOSS — Should decrease steadily
#    - Good: Starts ~3.0, ends ~1.5-2.0
#    - Bad: Stays flat, spikes, or increases

# 2. LEARNING RATE — Should follow cosine curve
#    - Warmup → peak → gradual decay

# 3. GRADIENT NORM — Should be stable
#    - Good: Stays below 1.0 (with grad clipping)
#    - Bad: Frequent spikes above 5.0

# Setup W&B logging
import wandb
wandb.init(
    project="gemma-scripture-finetuning",
    name="cpt-lora-v1",
    config={
        "model": "google/gemma-3-27b-it",
        "method": "LoRA",
        "lora_r": 64,
        "learning_rate": 2e-5,
        "epochs": 2,
        "dataset_size": "5GB",
        "stage": "CPT"
    }
)

# Custom callback to log perplexity
from transformers import TrainerCallback
import math

class PerplexityCallback(TrainerCallback):
    """Log perplexity (exp(loss)) which is more interpretable."""
    
    def on_log(self, args, state, control, logs=None, **kwargs):
        if logs and "loss" in logs:
            perplexity = math.exp(logs["loss"])
            wandb.log({"perplexity": perplexity}, step=state.global_step)

✅ Validating CPT Results

"""
After CPT, verify the model has learned domain knowledge.
Quick sanity check before proceeding to SFT.
"""
from transformers import AutoModelForCausalLM, AutoTokenizer, pipeline
from peft import PeftModel
import torch

def validate_cpt_model(base_model: str, adapter_path: str):
    """Test CPT model with domain-specific prompts."""
    
    # Load base + LoRA adapter
    tokenizer = AutoTokenizer.from_pretrained(base_model)
    model = AutoModelForCausalLM.from_pretrained(
        base_model,
        torch_dtype=torch.bfloat16,
        device_map="auto"
    )
    model = PeftModel.from_pretrained(model, adapter_path)
    
    # Create text generation pipeline
    gen = pipeline("text-generation", model=model, tokenizer=tokenizer)
    
    # Test prompts — model should complete these with scripture knowledge
    test_prompts = [
        "धर्मक्षेत्रे कुरुक्षेत्रे",                    # Should continue Gita 1.1
        "The Bhagavad Gita teaches that",              # Should discuss teachings
        "According to the Upanishads, Brahman is",     # Should describe Brahman
        "कर्मण्येवाधिकारस्ते",                          # Should continue Gita 2.47
        "The eight limbs of yoga as described by Patanjali are", # Should list ashtanga
    ]
    
    print("=" * 60)
    print("CPT Validation — Domain Knowledge Check")
    print("=" * 60)
    
    for prompt in test_prompts:
        output = gen(
            prompt,
            max_new_tokens=100,
            temperature=0.3,
            do_sample=True,
            top_p=0.9
        )
        completion = output[0]['generated_text'][len(prompt):]
        print(f"\n📝 Prompt: {prompt}")
        print(f"✍️  Completion: {completion[:200]}")
        print("-" * 40)


# Run validation
validate_cpt_model(
    base_model="google/gemma-3-27b-it",
    adapter_path="./checkpoints/cpt_lora/final"
)
✅ What Good CPT Results Look Like
  • Model completes Sanskrit verses correctly
  • Uses appropriate Hindu philosophical terminology
  • Generates coherent text about scripture topics
  • Training loss decreased by 30-50% from start
  • Perplexity on held-out scripture text is lower than base model
❌ Signs of Problems
  • Loss not decreasing: Learning rate too low, or data quality issues
  • Loss spiking: Learning rate too high, reduce by 2-5x
  • Gibberish output: Model collapsed — reduce LR, increase warmup
  • Memorization: Model repeats training data verbatim — add dropout, reduce epochs

➡️ Next Steps After CPT

Once CPT is complete and validated, your model has deep domain knowledge. But it can't yet follow instructions — it just generates text continuations. The next step (Chapter 5: SFT) teaches it to have conversations and answer questions.
